# ADR-064 — Source-bound private shop preparation

Date: 2026-10-23
Status: Accepted for local candidate implementation; live qualification and activation remain open.

## Context

The owner requested Nexscope eCommerce skills to support agentic customer shops. The existing
online-presence service cannot build an operating shop, and developer skill installation adds
no tenant tool authority. Pikar already has a governed document workflow runner and candidate
pack registry. Existing goods functions lack persistent catalogue/order and provider adapters.

## Decision

Add `shop-preparation` as a separate curated document pack, initially a dormant candidate.
Reuse only `searchVault` and the existing `saveAsDocument` final-reply binding. Prepare the
complete private listing/copy/source/missing-facts/launch package from actual owned evidence
and genuine human statements. Do not invoke another writing model or create a second runner.

The adaptation cites the existing immutable Nexscope snapshot at
`ee0fb29433d02ccc22e3e6cea9ab4586d49fd42e`, preserving its MIT notice. Admit MIT provenance
only for this exact pack's source identity, notice, timestamp and adapted body hash. Verify
actual candidate body bytes at publication and candidate activation. Do not broaden the
existing license list or change another pack's provenance policy.

Use existing provenance, exact fixture evaluation and native browser planes before activation.
New heuristic claim guards must reject known unsourced commercial claims; they are bounded
scorer checks, not a proof of arbitrary narrative truth. Native source/quality review remains
required. Existing pack bodies, fixture hashes and activation behavior remain unchanged.

## Consequences

The user can eventually receive a saved preparation package through the normal qualified
workflow library. Its output is not a live catalogue, checkout or operational integration.
No new external grant, merchant credential, inventory/order read, payment/refund action,
customer send, fulfillment operation, database table or standing consent is introduced.

Public checkout remains code-owned unavailable under ADR-062. Unattended reads/preparation
remain subject to ADR-046; publication and other external writes retain their existing exact
approval controls. Real merchant-direct Stripe/PayPal, durable state, signed events, inventory
and physical/digital fulfillment remain53-03 work with their own evidence and authorization.
