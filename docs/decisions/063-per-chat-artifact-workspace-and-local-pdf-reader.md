# ADR-063: Per-chat artifact tabs and a local PDF reader

- **Status**: **Accepted** — 2026-10-21, owner requested the artifact workspace and approved implementation.
- **Supersedes**: ADR-036 decision 4's browser-plugin PDF iframe and its rejection of PDF.js for this surface. ADR-062 already supersedes the older PPTX output restriction. The earlier records and receipts remain historical evidence.
- **Preserves**: tenant/thread ownership, selected-only file capabilities, original bytes, optional capped projections, explicit retrieval promotion, existing spending and publishing approval rules. This is a reading workspace, not an arbitrary Office editor.

## Context

The workspace previously chose a single current card/media canvas. A PDF iframe delegated its controls and appearance to a browser plugin, which varied across environments and did not provide a consistent reading surface. The owner requested a ChatGPT-inspired workspace with separate outputs for a conversation, readable documents, slides, spreadsheets, images, videos and media-batch collections. Multiple outputs must remain discoverable without replacing work or opening every file's bearer capability.

## Decision

1. **One conversation has a Work tab and bounded artifact tabs.** The output inventory combines independently paginated document, root-plan/attachment, campaign and scoped-reference streams. Listing returns metadata, not file URLs or document bodies. Closing a tab only changes the view; the output browser can reopen it. At most 30 artifact tabs are open. New completions can follow the newest output until an explicit selection; a deliberate selection remains while later results are marked unread. Loading older history must not masquerade as new production.
2. **References are never authority.** Selected resolution and download recheck tenant plus the exact conversation relationship. Saved tab keys are untrusted input. Session storage contains only bounded tab references and UI preferences, namespaced by owner subject and conversation; no content, originals, credentials or bearer URLs are stored there. The owner namespace is a storage partition, not an authentication check. Unavailable/deleted outputs show a truthful fallback. Existing Vault queries retain their own tenant guards.
3. **Reuse one reading canvas.** `ArtifactViewer` loads content for the selected owned Vault metadata; `ArtifactViewerBody` accepts already-authorized attachment/fixture data. Neither imports cards or the workspace controller. Safe Markdown/plain text, scriptless same-spec slides, capped worksheet grids, images and native video controls share a toolbar and explicit original download. The pane owns its scroll and can be expanded by the workspace. Uploaded Office without a projection offers its original; no third-party viewer URL receives a tenant file.
4. **Render actual PDF pages with pinned PDF.js 6.4.299.** The selected original is fetched with omitted credentials and no referrer, with a 32 MiB cap enforced against declared and actual streamed bytes. Only the current page is rendered. Raster area is bounded to 16 million pixels, dimensions to 8192 pixels and display dimensions to 10,000 pixels; zoom is bounded. Source/page changes cancel owned work, abort old reads and destroy loading tasks. Page/zoom/Fit controls and an actual text layer provide consistent reading and selection.
5. **Keep PDF support assets local and execution surfaces absent.** The build/development command synchronizes only the installed version's worker, CMaps, standard fonts and WASM into ignored versioned public assets. There is no CDN worker. The reader instantiates canvas and text only: XFA is disabled, annotations are disabled in the renderer, and it creates no scripting manager, form layer or external-link annotations. PDF.js 6.4.299 removed the obsolete `isEvalSupported` option; do not claim to set it. Inspection of the pinned worker found no `eval`/`new Function` execution path. The dependency and local asset version must agree.
6. **Represent previews honestly.** Generated Markdown/PDF documents may default to the comfortable Reading view and expose Original PDF. Uploaded PDFs display actual original pages even when extracted text exists. Slide HTML is code-owned layout from the same validated specification, not exact Office rendering. Worksheet grids disclose omitted rows, columns and sheets and are read-only; formatting, calculations and chart fidelity belong to the original workbook. A missing preview never removes a good original.
7. **Campaigns are collections, not a second production engine.** Their tab displays existing item states, reviews and owned downloads, preserving exact approval, spend admission, retry and uncertain-outcome gates. An individual item can open its existing plan view. A JSON manifest plus individual downloads is not a ZIP archive and must not be called a complete archive download.

## Evidence and qualification limits

Focused local tests exercise byte caps/cancellation, current-page rendering, local assets, text-layer controls, format fallbacks, source changes, read-only grids and downloads. Edge fixture QA rendered both pages of an actual synthetic PDF, changed page/zoom, inspected the text layer, and exercised Reading/slides/chart/worksheet views at wide and 420-pixel widths with no page-level overflow or external requests. This fixture is not an authenticated hosted product session.

Local Microsoft PowerPoint 15.0 opened the generated seven-layout deck, exported all seven slide PNGs and a PDF, identified one native chart and one native table, and preserved a native title edit through save/reopen. All seven native PNGs were visually inspected. The isolated automation instance closed; no user presentation was opened. This does not qualify every accepted input, chart-data editing, current registry behavior or hosted original downloads. Workbook native qualification and the measured media comparison are recorded separately in Phase 53.

The primary Phase 48 programme and its historical qualification chain remain unchanged. Phase 53 stays partial; there is no deployment, paid generation/evaluation, seed/activation, publishing consent or owner quality acceptance implied by this decision.

Primary implementation references: [PDF.js 6.4.299 release](https://github.com/mozilla/pdf.js/releases/tag/v6.4.299), [PDF.js API](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib.html), and the exact installed package types/source. Future dependency changes must recheck worker assets, browser cancellation, text placement and supported execution options.
