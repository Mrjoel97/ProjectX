# Phase 03.2 Plan 04: Cockpit Name-Resolution Turn Summary

**Wires the deterministic name-resolution loop into the cockpit: a recipients segment with no `@` becomes a NAME that triggers a bounded, refs-only `gmail.search`→`rankCandidates`→`writeCandidates` turn BEFORE any draft (DECISION #2, one LLM call); `resolveRecipients` folds the picked contact, wipes the transient candidates, and threads the resolved display name ONLY into the drafter's "Hi <name>," greeting — degrading gracefully to an ask on a read-auth failure.**

## Performance

- **Duration:** ~35 min
- **Tasks:** 3
- **Files modified:** 5 (2 source, 2 test, 1 playbook)

## Accomplishments
- `parseAnswer` recipients now segments on comma / the word "and" only, so a multi-word NAME survives as one token; documented the accepted space-separated-emails behavior break with an explicit regression test.
- `toIntentState` (now exported) projects the transient `candidates`→`pendingResolution`, `pendingValid`, and `greetingName` so a resolution card persists across turns and the greeting survives to the draft.
- `sendCockpitMessage` runs the resolution turn on an unresolved name: `internal.gmail.search` per name → `rankCandidates` (`@pikar/core`) → `internal.plans.writeCandidates`, then saves a "pick a contact" message — all BEFORE `proposeEmailPlan` (no LLM tool-loop, DECISION #2).
- Read-time auth failure (`{ok:false}`) inserts a `gmail_reconnect` notification AND falls back to asking for the address directly — never dead-ends. Zero matches after `gmail.search`'s one widen also falls back to asking.
- `resolveRecipients` (a `tenantAction` with an explicit `Promise<{threadId}>` return type) builds the `resolution` Answer, folds held `pendingValid` + picked addresses into recipients, captures `greetingName`, `clearCandidates` wipes on pick, then runs the shared `advance` tail to draft/propose.
- Extracted the shared `advance(ctx, tid, planId, state)` tail (explicit return type) reused by both actions; `draftCockpit` gained an optional `greetingName` arg that prepends a "Hi <name>," greeting instruction — passing the display name ONLY (never a header hint).
- Governance tests: `llmRedaction` now asserts the `mailbox.searched` audit payload is exactly `{ queryHash, resultCount }` (no raw name/address/subject/messageId) and that `draftCockpit`'s code surface carries `greetingName` only (no `lastSubject`/`lastDateMs`/`count`/`matches`); `cockpit.test` covers the resolve fold + `clearCandidates` wipe.

## Decisions Made
- **Comma/"and" segmentation, not whitespace** — a multi-word name must stay one token for resolution; space-separated emails are an accepted break (Pitfall 3) that bounces to the existing re-ask.
- **`resolve_recipients`/`defer_group` parse as recipients** — a typed reply while a card shows is a re-resolution or the explicit addresses; this also restored `parseAnswer` switch exhaustiveness that Plan 01 broke by growing `NextQuestion` (a latent backend typecheck break this plan fixed).
- **The resolve fold is unit-tested at the seam** — `resolveRecipients` reaches `cockpitAgent.saveMessage` (agent component unregistered in this repo's `convex-test`, same limit as `sendCockpitMessage`), so the fold is asserted via `toIntentState` + `applyAnswer(resolution)` plus a driveable `clearCandidates` wipe test, mirroring the existing executePlan gate-test approach.

**1. [Rule 1 - Bug] Comma-mixed test used a no-`@` token that is now a NAME, not an invalid**
- **Found during:** Task 1
- **Issue:** The plan's mandated "separate comma-based mixed case" (`"good@x.com, not-an-email"` → `invalid=["not-an-email"]`) is impossible under Plan 01's classification: a no-`@` token (`not-an-email`) is now a NAME to resolve (`pendingResolution`), not an invalid. Same self-contradiction the 03.2-01 executor logged (`"nope"`→name).
- **Fix:** Used a genuinely malformed has-`@` token (`"good@x.com, bad@"`) to preserve the mixed valid/invalid coverage intent — `bad@` has `@` but fails `isValidEmail` → bounces. Documented the reasoning in a test comment.
- **Files modified:** `packages/backend/convex/cockpit.test.ts`
- **Commit:** `0f6c501`
