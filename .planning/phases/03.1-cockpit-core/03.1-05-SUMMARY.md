# Phase 03.1 Plan 05: Cockpit Structural Shell Summary

Two-pane resizable `/dashboard/workspace` cockpit (chat ~30% / workspace ~70%) under the
existing `(app)` auth gate, with a native CSS-grid divider that is keyboard-accessible and
persists per-user in localStorage, a Gmail-connected gate on the composer, and two SC1
Playwright specs plus the repo's first auth (storageState) harness.

## What shipped

- **SplitPane.tsx** — `display: grid; grid-template-columns: <pct>% 6px 1fr`. The 6px handle
  is `role="separator"` (`aria-orientation=vertical`, `aria-valuenow/min/max`, `tabIndex=0`,
  `cursor: col-resize`). Drag uses Pointer Events with `setPointerCapture` (no window-level
  listener bookkeeping); ArrowLeft/ArrowRight nudge ±2%. Both drag and nudge clamp each pane
  to ≥20% (20–80%). Persistence: `localStorage["cockpit.split.<userId>"]`, where `<userId>`
  is the Convex Auth JWT `sub` read client-side via `useAuthToken` — no backend round-trip
  and no new query. Lazy `useState` initializer reads on mount; an effect re-reads when the
  token resolves (anon → userId).
- **workspace/page.tsx** — hosts `<SplitPane>` with a "Conversation" pane (placeholder
  composer, `{/* chat pane — plan 08 */}`) and a "Workspace" pane ("No artifacts yet",
  `{/* card list — plan 08 */}`). The composer is gated behind `api.gmailAuth.gmailStatus`:
  `undefined` → "Loading…"; connected → composer; not connected → a teal `var(--teal-600)`
  "Connect Gmail to start planning" CTA linking to `/connect-gmail`. The **panels always
  render** — only the composer is gated — so the shell never blocks on mailbox state.
- **layout.tsx** — one NAV entry `{ href: "/dashboard/workspace", label: "Workspace" }`. The
  `<Authenticated>` gate and every existing NAV link are untouched (the cockpit inherits the
  18c8442 client-token fix for free).
- **E2E** — `cockpit-render` (both pane headings + handle visible; gate resolves to composer
  OR CTA, no eternal spinner) and `cockpit-split` (default 30% → drag to far-left clamps at
  20% and proves it moved → ArrowRight nudge +2% → reload persists via `aria-valuenow`). Both
  run signed-in via the new `auth.setup.ts` storageState project wired into
  `playwright.config.ts`; the saved state is git-ignored.

- **Found during:** Task 1
- **Issue:** The plan says "get userId from the existing identity/auth context used elsewhere
  in the shell" — but no such context/query exists client-side, and adding a backend query

- **Files:** `apps/web/app/(app)/dashboard/workspace/SplitPane.tsx`

concern** (Convex `SITE_URL` / auth env on the deployment, not `.env.local`) — outside this
plan's file scope and unsafe to change mid parallel-wave. Fix-attempt limit reached (3
attempts: port correction, user seeding, flow debug). The live E2E green is the proper job of
the phase verify-work gate (as with the smoke scripts), which runs against a fully-configured
stack + seeded user. No cockpit code change is implicated — typecheck and spec discovery are
both clean.
