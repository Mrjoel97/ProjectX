Build the evaluation engine as a §1 thin adapter: it carries the prior scorecard forward, grounds via the
existing vaultGroundHydrated, loads the framework rubric skill body, runs the pure diagnose() from plan 01,
assembles findings+citations+confidence+gaps onto a durable evaluations row, emits a refs-only audit, and
an activity step. This satisfies BEVL-01's grounded-assessment + no-prose-in-audit + SC #5 isolation, AND
the LOCKED "vault-first, then ask, then store" loop (the durable scorecard is updated each run, not rebuilt
from null).

NOT a vaultDocuments doc-kind. Rationale: CONTEXT locks "keep history, show latest" + a structured
history[] trail that BEVL-03's recurring review consumes; a table gives a clean latest-per-framework
query and first-class isolation index without parse-on-read. The schema line is append-only (no migration).

Purpose: the one place that turns grounded user data + carried-forward answers + method into a scorecard/findings row.
Output: evaluations table + evaluations.ts engine (carry-forward + recordScorecardAnswer) + isolation test + playbook.
</objective>
