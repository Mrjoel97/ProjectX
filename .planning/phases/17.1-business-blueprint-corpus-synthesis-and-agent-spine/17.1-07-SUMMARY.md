### Required Mutation Proof

The correct implementation was temporarily replaced with the disproved entry-0 design: the live
Blueprint document id, title, and spine were unshifted into `docIds` / `titles` / `chunks`, and the
fourth field was dropped.

- `vaultGround.test.ts` turned **4 tests red**: missing `spine: null`, retrieval budget grew to
  8,445, the full-object shape lost its fourth field, and Blueprint presence grew the retrieval
  arrays.
- `searchVaultSpine.test.ts` turned **2 tests red**: the no-match became “Grounded in 1
  document(s)” and the Blueprint leaked into a matching search result.
- The correct source was restored byte-identically, then both suites returned green.

This directly covers validation items 16, 17, 18, 19, and 21 rather than trusting comments.

## Decisions Made

- Kept the Blueprint outside every retrieval array and budget. It is standing context, not a search
  result, so search semantics and cockpit source accounting need no accommodation.
- Used `blueprint.liveForTenant` for the evaluation's real document id. A synthetic id would create
  dead provenance links in the UI.
- Reordered already-retrieved profile seeds only when a Blueprint is present. This enforces D5
  without changing the no-Blueprint path.
- Counted voice document passages independently from the prepended spine so standing context never
  consumes a retrieval slot.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Moved already-retrieved profile seeds ahead of the Blueprint**

- **Found during:** Task 2 GREEN.
- **Issue:** The existing `fresh` filter prepended only profile documents absent from retrieval. If
  the profile was already a retrieval hit, it stayed behind the newly prepended Blueprint, allowing
  a derived number to beat the user's typed number and own provenance.
- **Fix:** On the Blueprint path only, remove profile seed ids from the existing arrays and rebuild
  them as profile seeds → Blueprint → remaining retrieval. The no-Blueprint branch retains the
  original `fresh` behavior byte-for-byte.
