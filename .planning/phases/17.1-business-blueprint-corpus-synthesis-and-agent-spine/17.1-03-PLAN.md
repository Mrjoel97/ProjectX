Add to `packages/core/src/blueprint.ts`:

```ts
export type BlueprintDiffRow =
  | { kind: "addition"; field: BlueprintField; derived: BlueprintEntry }
  | { kind: "contradiction"; field: BlueprintField; stated: BlueprintEntry; derived: BlueprintEntry };

/**
 * Precedence is CODE, never a prompt (D5). There is deliberately NO branch in this function that
 * assigns a derived entry over a stated one — that absence IS the guarantee, in the same way
 * `businessProfile.ts:78` records "there is deliberately no branch that auto-commits a persona".
 * The model is never shown `live` and is never asked to merge anything.
 */
export function mergeBlueprint(
  stated: Partial<Record<BlueprintField, BlueprintEntry>>,
  derived: Partial<Record<BlueprintField, BlueprintEntry>>,
  live?: BusinessBlueprint | null,
): { blueprint: BusinessBlueprint; diff: BlueprintDiffRow[] };
```

The rule, per field, iterating `BLUEPRINT_FIELDS` (so it is total):
1. `stated[f]` present ⇒ `blueprint[f] = stated[f]`. If `derived[f]` also exists and its values
   differ, push a `contradiction` row. **Never** change the value.
2. `stated[f]` absent and `derived[f]` present ⇒ `blueprint[f] = derived[f]`, and push an `addition`
   row **only if** `live?.[f]` does not already carry the same values.
3. Neither ⇒ `blueprint[f] = live?.[f] ?? null`. A rebuild must not blank a field the previous
   blueprint had just because this run's probes came back empty; carrying it forward keeps the
   blueprint monotone and keeps `diff` empty on an identical rebuild.
4. `stated[f]` present and equal to `live[f]` ⇒ no row.

**Contradiction rows deliberately RE-SURFACE on every rebuild.** Do NOT build decline-tracking: the
user asked for this rebuild, and a standing contradiction between what they typed and what their
documents say is worth showing again. Say so in a `ponytail:` comment naming the ceiling ("a
per-row 'dismissed' set is the upgrade path if this becomes noise") so nobody adds the machinery
speculatively — and so item 29's "identical rebuild ⇒ empty diff" is understood as being about a
run where derived AGREES with stated, which is the case the test constructs.

Value comparison is order-sensitive element equality over the trimmed `values` arrays. Write one
small `sameValues(a, b)` helper and use it everywhere — three ad-hoc comparisons is how the
addition and contradiction branches end up disagreeing.

**Only TWO diff kinds — do not add a third for "derived changed".** `addition` covers it, and the
doc comment says why (see `<behavior>`). Bump `docs/playbooks/onboarding.md`'s `Last verified`.

```ts
/** Target ≈ 2500 chars. Budgeted OUTSIDE `vaultGround.ts`'s TOTAL_CHAR_CAP (8000), which stays
 *  entirely for retrieval results — the spine is not a search result and must not compete with
 *  them for budget. */
export const SPINE_CHAR_CAP = 2500;

/**
 * The standing-context block BOTH seams inject verbatim: the cockpit turn prompt (`llm.ts`) and
 * `vaultGroundHydrated`'s `spine` return field. ONE renderer, so the two seams cannot drift.
 *
 * NOT the same bytes as `serializeBlueprint`: this one carries a READ-TIME staleness count, which
 * is exactly why it must not be what gets stored (determinism, and therefore the diff and the
 * contentHash dedup, would break).
 */
export function renderSpine(
  blueprint: BusinessBlueprint,
  opts: { unincorporatedCount: number },
): string;
```

Shape — a labelled block the model reads as CONTEXT, not as an instruction (mirror the
`<vault_context>` fence idiom already used at `llm.ts:1386`):
```
<business_blueprint>
This is the user's business. Facts marked [stated] are the user's own words — do not second-guess
them. Facts marked [source: …] were inferred from that document — cite it when you lean on it.

- Name: Acme Ltd [stated]
- Stage: pre-launch idea [stated]
- Offering: … [source: Pricing deck.pdf]
…
⚠ 7 documents have been added since this was confirmed — it may be missing something.
</business_blueprint>
```

Rules:
- Iterate `BLUEPRINT_FIELDS`; skip `null` fields entirely (a sparse blueprint renders short).
- Truncate each field's rendered value at `FIELD_SPEC[f].cap`. Truncation must be visible (`…`)
  rather than silent.
- After building the string: `if (out.length > SPINE_CHAR_CAP) throw new Error(...)`. This can only
  fire if the per-field caps were mis-set — it is a code-bug tripwire, not a runtime path.
- The staleness line is emitted iff `unincorporatedCount > 0`. Its wording must let the agent SAY it
  is missing something rather than assert into the gap — that is the stated purpose of the line.
- Use the plain `- <Label>: ` prefix, never `- **<Label>:** `.
