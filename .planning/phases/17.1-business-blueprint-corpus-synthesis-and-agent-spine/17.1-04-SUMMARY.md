# Phase 17.1 Plan 04: Blueprint Read Plane Summary

**A tenant-isolated, fail-open Blueprint read plane now resolves the live document in two reads, ranks graph entities through an index, computes bounded Stage-1 drift as a real set difference, and renders the one capped spine both downstream seams consume.**

## Accomplishments

- `liveForTenant` reads the tenant's one `tenantProfiles.by_tenant` row and then calls
  `ctx.db.get(blueprintDocId)`. It never scans `vaultDocuments`, validates tenant ownership, kind and
  non-empty text, and returns `null` for the absent-row, absent-pointer, deleted-document,
  invalid-document and cross-tenant states.
- `topEntities` pins `tenantId` in `graphNodes.by_tenant_degree`, orders descending by the remaining
  degree key and takes 20. The test seeds 25 tenant-A nodes plus a higher-degree tenant-B node and
  proves both the cap/order and isolation.
- `spineForTenant` reuses the same private live-row reader, deserializes through `@pikar/core`,
  computes drift against the live profile source IDs, and renders through the one `renderSpine`.
  No live blueprint or any unexpected blueprint failure returns `null`.
- Stage-1 drift is a set difference, not arithmetic subtraction: three ready documents and two
  stale/deleted recorded IDs correctly report three unincorporated documents. Processing documents
  and the blueprint row itself do not count; a draft cannot change the live signal.

## Decisions Made

- Factored the two-read lookup into a plain private helper. Calling the registered query through
  `ctx.runQuery` would add a transaction hop, while duplicating it would let the two exports drift.
- Passed the already-read live source IDs into the drift helper. This satisfies the stronger plan
  invariant—same profile row, never the draft—without rereading `tenantProfiles`.
- Kept the bounded scan at 100 whole ready rows and documented its actual ceiling. Convex has no
  projection, so the read includes text; the future counter belongs on `tenantProfiles` and must be
  maintained when ingest reaches ready, after the currently active vault-ingest lane is stable.
