# Phase 17.1 Plan 03: Precedence, the Citation Gate and the Spine Summary

**The three pure functions that carry Phase 17.1's guarantees: an invented citation drops the claim, a typed value has no branch that can overwrite it, and one capped renderer produces the standing-context block both seams inject — all three testable in ~2 seconds with no model and no network.**

## Accomplishments

- **D5 is now a structural property, not a promise.** `mergeBlueprint` has no branch that assigns a
  derived entry over a stated one; a contradicting candidate raises a `contradiction` ROW and changes
  nothing. The proof is not the one hand-picked `targetCustomer` case the owner asked for (that is
  there too, VALIDATION item 2) — it is a loop over the whole closed field set asserting
  `stated[f]` present ⇒ `blueprint[f] === stated[f]`, so it survives someone adding a twelfth field.
  **Mutation-verified: `out[field] = candidate ?? typed` ⇒ 3 RED including the property; reverted ⇒
  green.** The model is never shown `live` and is never asked to merge anything.
- **An invented citation costs the model the whole field.** `validateCandidates` drops a candidate
  whose `sourceIndex` is out of range, the strict-schema `-1` sentinel, or a non-integer — all in
  the SAME branch, as CONTEXT requires — and drops one naming an unknown field or a
  `derivable: false` field, so **a model cannot rename the business, reclassify the tier, or write
  the entity graph.** Narrowing is a membership test against `BLUEPRINT_FIELDS`, never a cast, and
  `field` is typed `string` on the way in precisely because it is untrusted. **Drops are REPORTED**
  (`{ field, reason }`), because VALIDATION L2 calls 0 drops and 8 drops both signals on the real
  corpus and neither is observable if the gate swallows them.
- **The two-kind diff falls out of D5 rather than out of UI taste.** `addition` (blank → value) is
  non-destructive BY CONSTRUCTION ⇒ one Accept, defaulted ON. `contradiction` (typed ≠ derived) is
  the only destructive case ⇒ per-item, defaulted OFF, carrying both values and the derived source
  so the surface never re-derives that distinction. **A CHANGED derived value stays an `addition`** —
  a contradiction is only ever raised against content the USER typed, and a changed inference
  replaces a system inference, so there is nothing to lose by accepting it fast. That sentence is in
  the `BlueprintDiffRow` doc comment and pinned by its own test.
- **The drift contract holds: an identical rebuild produces an empty diff.** Rule 3 of the merge
  (neither stated nor derived ⇒ carry `live` forward) is what makes it true — a rebuild whose probes
  came back empty must not blank a field the blueprint already had, or every sparse rebuild would
  read as drift.
- **The spine's size guarantee is arithmetic, and its assertion has been seen to fire.**
  `renderSpine` caps each field's WHOLE RENDERED LINE at `FIELD_SPEC[f].cap`, so the worst case is
  `sum(cap)` + fixed framing. **Measured: 2294 chars of the 2500 budget for a blueprint whose every
  field carries a 10,000-char value AND a 70-char source title — 206 spare.** The over-cap `throw` is
  a code-bug tripwire, and **raising `offering`'s cap to 1000 made it fire (`3052 chars, over
  SPINE_CHAR_CAP`), 3 RED, reverted green.**

## Decisions Made

- **`FIELD_SPEC[f].cap` is the budget of the WHOLE RENDERED LINE, not of the value.** 17.1-01 read it
  as a value cap summing to 2280 and noted "~220 left for labels" inside the ≈2500 budget. That
  arithmetic does not close: eleven labels (126 chars) + the `- `/`: `/space scaffolding (55) +
  eleven `[source: …]` markers (unbounded, and 70 chars for a realistic long file name) + the block's
  own fence, intro paragraph and staleness line (~325) put the pathological render at ~2765 —
  **the tripwire would have fired on a legitimate max-size blueprint.** Line-level capping fixes it
  structurally: `line.length ≤ cap` is guaranteed per field, so the total is `sum(cap) + framing`,
  both constants. CONTEXT explicitly assigns "per-field char-cap constants" to Claude's discretion,
  and `cap` has **no consumer outside `renderSpine`** (verified: `FIELD_SPEC` appears in exactly two
  source files, both this module and its test) — so the blast radius is zero.
- **New caps sum to 1960** (name 80, oneLineDescription 220, stage 80, tier 60, offering 240,
  targetCustomer 200, revenueModel 200, bindingConstraint 200, primaryGoals 240, knownConstraints
  240, entities 200). Worst-case render **measured at 2294**, not estimated. `tier` had to rise from
  20 to 60 because `- Tier: solopreneur [stated]` is 28 chars — a 20-char LINE budget is not
  satisfiable, which is itself evidence the value-level reading was the wrong one.
- **The source title is clipped to 40 chars inside the marker, and the marker wins budget over the
  value.** The marker is the load-bearing half of the line — it is what tells the agent whether a
  fact is settled or challengeable — so a 200-character file name costs the VALUE room rather than
  overflowing the block.
- **A duplicate candidate for an already-filled field is skipped silently, not reported.** First
  wins (`evaluations.ts:271`'s documented rule — ONE rule in the codebase). A duplicate is not a
  validation failure: the field DID make it in, so reporting it as "dropped" would inflate the count
  VALIDATION L2 reads as the citation gate's signal.
- **An all-null blueprint renders, and does not throw.** The plan allowed either; the pinned choice
  is a fence containing `- (nothing confirmed about this business yet)`, because `renderSpine` sits
  on the grounding path and a sparse-start tenant (Phase 11's whole point) must not crash it.
- **No decline-tracking for contradictions** — they re-surface on every rebuild, marked with a
  `ponytail:` comment naming the ceiling and the upgrade path (a per-row dismissed set). The user
  asked for the rebuild, and a standing disagreement between what they typed and what their
  documents say is worth showing again.
