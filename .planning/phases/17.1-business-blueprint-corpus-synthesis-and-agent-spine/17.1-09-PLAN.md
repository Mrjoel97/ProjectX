**The split (from D5 — not UI taste):**
- **Additions** (blank → value + citation) are non-destructive by construction ⇒ ONE Accept applies
  them all, **defaulted ON**. Render them as a grouped list showing field, new value and source
  document, with a single group control. Do not make the user tick 30 boxes to accept obvious gap
  fills.
- **Contradictions** (typed ≠ derived) are the ONLY destructive case ⇒ **individually checkboxed,
  defaulted OFF**, shown SIDE BY SIDE: the user's typed value on one side, the document-derived
  value and its source on the other. Use a native `fieldset`/`legend` + `input[type=checkbox]` so
  checked state, group semantics and keyboard handling come from the platform.
- Each row carries a visible TEXT label of its kind. Colour alone is forbidden (`BRAND.md:110-117`).
- State the consequence in the UI plainly: ticking a contradiction changes the BLUEPRINT, not the
  profile text above — the user edits their own profile in the card above if they want that. The
  backend deliberately does not rewrite typed profile content from a checkbox.
- Confirm submits `{ acceptedContradictions: [...ticked field names] }`. **Discard calls
  `api.blueprint.discardDraft`** (plan 08). It is not optional and it is not "just navigate away":
  `blueprintState` gives `draft` precedence over `live`, so a user who does not confirm would
  otherwise never see their live blueprint again.
