## Symptom

Runs `294a80bc` (bounded `--only 01-happy-single` diagnostic) and `72a43b32` (full unfiltered)
both died on the FIRST chat call with the strict closed token
`EVAL_MODEL_RESPONSE_FAILED_CONSERVATIVE_HTTP_400`. The five `seedCorpus` embedding calls on the
same key succeeded (observed USD 0.00000392), and the same day's earlier runs (`2ae07dfd`,
`558761d8`, case-24 retry) had chat calls reaching real verdicts through cases 1–23.

## 2026-09-21 request-shape hypothesis (not a verified root cause)

`evalBudgetModel`'s `transformParams` attaches `providerOptions.openrouter` = golden wire options.
The installed `@openrouter/ai-sdk-provider@3.0.0` **spreads every key of
`providerOptions.openrouter` into the TOP-LEVEL request body**
(`dist/internal/index.js` `doGenerate`: `args = { ...getArgs(options), ...restOpenrouterOptions }`).

`goldenChatWireOptions` (and the non-golden `evalContext` branch) emitted:

- `n: 1` — **`n` is not in OpenRouter's documented chat-completions body schema**, and the live
  endpoint's `supported_parameters` for `openai/gpt-4o-mini-2024-07-18` (checked via
  `/endpoints`, status 0, uptime 100% 30m/5m/1d) does not advertise it;
- combined with `provider.require_parameters: true`, which routes only to endpoints supporting
  **every supplied parameter** — so the request matched NO endpoint and OpenRouter returned
  HTTP 400.

The embedding body (`goldenEmbeddingRequest`) contains no `n`, which is exactly why embeddings
succeeded while every chat call failed. The timeline also fits: the passing runs predate the
current golden-wire-options shape; `72a43b32` was its first full exposure.
ADR-029's lesson ("the models catalogue is not the API surface") applies to parameters as well:
catalogued model, live endpoint, unroutable request.

## Repair (repository-controlled, offline-tested)

1. `packages/cost/src/goldenProviderBudget.ts` — `goldenChatWireOptions` drops `n: 1` and
   `transforms: []` (no longer a documented body parameter); keeps `max_tokens`, `plugins: []`
   (documented), and the `provider` routing block. Intent unchanged: no fallbacks, no extra fees,
   ceiling-enforced pricing, exact `max_tokens`.
2. `packages/backend/convex/lib/evalBudgetModel.ts` — the non-golden `evalContext` branch drops
   the same two keys (same spread mechanism, same failure class) and now carries the constraint
   comment pointing at the incident.
3. Regression pins: `packages/cost/src/goldenProviderBudget.test.ts` asserts every emitted key is
   in the closed list of OpenRouter's documented chat body parameters and that `n`/`transforms`
   are absent; `packages/backend/convex/evalBudgetModel.test.ts` asserts the same on the captured
   wire body.
