# Phase 17.1 Plan 09: Profile Blueprint Confirmation Surface Summary

**A brand-token profile card now makes the D2 gate operable: users can build or rebuild a cited
Blueprint, inspect all four states, accept non-destructive gaps in one click, and opt destructive
contradictions in one at a time.**

## Accomplishments

- Added one self-contained Blueprint card to `/dashboard/profile` without changing the business
  shape or narrative card bodies. The page diff is 7 additions / 4 replacements: one import, one
  mount, and exports on the four existing shared style helpers.
- Rendered `none`, `live`, `live_stale`, and draft-review states from one
  `api.blueprint.blueprintState` query. Build/rebuild is a real disabled long-action button with a
  polite status region and recoverable kill-switch/budget language.
- Rendered confirmed Blueprint values as a ruled structured report. Stated values say **Your own
  words**; derived values name their source. The stale banner is a neutral `--ink-soft` stripe and
  never spends approval amber.
- Implemented the D5 diff split: additions use one default-on group and one confirm click;
  contradictions are native, individually default-off checkboxes with typed and document-derived
  values side by side.
- Wired both `confirmBlueprint` and `discardDraft`, including plain language that selections update
  the Blueprint rather than the editable profile text above.
- Added a non-vacuous source scan whose anchors, brand checks, visible labels, and safe default
  rules were all exercised, including the required planted-`defaultChecked` mutation.

## Decisions Made

- **A declined additions group blocks confirmation.** The backend deliberately accepts all
  non-destructive additions and exposes selection only for contradictions. Disabling confirm when
  the group is unchecked keeps the UI truthful; **Discard draft** is the supported way to reject
  the proposal as a whole.
- **The existing profile page remains the style source.** The four established style objects are
  exported and reused, avoiding duplicated token values and leaving both existing card bodies
  unchanged.
- **Status copy never exposes governed reason codes.** Kill-switch, budget, no-draft, and ordinary
  failures are translated into recoverable language that also states whether anything changed.
