**activateSkill now refuses gated candidates without a version-pinned green eval run (EVAL_GATE, fail-closed), seedSkills publishes gated edits as candidates instead of auto-activating them, and the dead executive-agent.classifier is de-seeded with an archiveSkill retirement flip**

## Accomplishments

- **The gate (EVAL-01's deploy half):** a `candidate` version of a gated skill (`GATED_SKILLS` = cockpit-agent, document-drafter) throws `EVAL_GATE` from `activateSkill` unless its `evidence` JSON proves `pass === true` AND `skillVersions[name] === version`. Absent, unparseable, failing, or stale (wrong-version-pin) evidence all refuse — fail closed.
- **Rollback structurally exempt:** `archived`/`rolled_back` targets were active before and activate on status alone — a broken eval harness can never block a mid-incident rollback. Non-gated skills are untouched by the gate.
- **Pitfall 1 closed:** `seedSkills` no longer auto-activates gated edits — a changed gated body lands as `candidate` vN with the active row untouched; idempotent against the NEWEST row so repeated dev boots mint exactly one candidate. Non-gated publish-and-activate and first-seed bootstrap (v1 active) are byte-compatible with before.
- **Pitfall 5 closed:** `executive-agent.classifier` removed from the seeds array (a re-seed cannot resurrect an archived row) + `archiveSkill` internalMutation for the live one-off flip (runs in plan 05's checkpoint).
- **Plumbing for plans 03/04:** `getSkillVersion` (version-pinned read, any status) and `recordEvalEvidence` (evidence-only patch, refs/counts-only JSON per §4).
- skills.test.ts 30/30 green; backend source typechecks clean; check-playbooks exit 0.
