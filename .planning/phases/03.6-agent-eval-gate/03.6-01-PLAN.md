<objective>
Make skill activation stop being blind at the choke point: gate `activateSkill` on recorded passing eval evidence for never-before-active (candidate) versions of gated skills, make `seedSkills` publish gated-skill edits as candidates instead of auto-activating them (RESEARCH Pitfall 1 — without this the gate is decorative), add the evidence writer + version-pinned skill lookup the eval runner needs, and archive the dead `executive-agent.classifier` skill (with its seeds-array entry removed so the next dev boot cannot resurrect it — Pitfall 5).

Purpose: EVAL-01's gate half. Activation is the behavior-deploy mechanism; after this plan a gated skill edit can only go live through a recorded green eval run, while rollback stays structurally exempt and always works mid-incident.
Output: gated `activateSkill` + `recordEvalEvidence` + `getSkillVersion` + candidate-publishing `seedSkills` + archived classifier, all convex-test covered.
</objective>
