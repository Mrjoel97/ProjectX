## Validation Architecture

**Test-first stance:** every defect above is a behaviour that unit/component tests can pin. The phase's own risk is "green tests over broken capability" (recorded project memory: phase 19 shipped 22/22 green with the feature broken) — so validation pairs each mechanism test with a behaviour assertion at the observable surface.

1. **Terminal-state invariant tests (convex-test, packages/backend):** for each `batchToRender` refusal reason, drive `renderReel` and assert `renderStatus === "failed"` with the matching `renderReason` — table-driven over all seven refusal classes (D1). Assert the retrier path records a terminal when the action throws post-`markRendering` (D2, via onComplete handler unit test).
2. **Watchdog tests:** seed stuck rows (`submitted` older than threshold, `rendering` stale, `transcribing` stale, `collecting` stale) → run the sweep handler → assert terminals + notification rows; assert fresh rows untouched (threshold boundary cases) (D3, D4).
3. **Vault persistence tests:** image generation success → `vaultDocuments` row exists with kind `"image"` and tenant scoping; reel render terminal saves when captions pending; caption-burn re-points; `resetPlan` clears `reelVaultDocId` (regression for D7); second image on a plan with one succeeded job is accepted (D8).
4. **Approvals component tests (apps/web vitest):** success produces a persistent visible outcome that survives list removal; refusal notice renders above the actions; image plans either show no Approve or the image arm succeeds (whichever is planned) (D9, D10).
5. **Card rendering tests:** memo card output contains rendered heading elements, not literal `#`; sources block renders title+URL+date when sources present, absent otherwise (D11).
6. **Env manifest drift test extension:** the drift test enumerates `requireEnvMedia("X")` call sites (or the names move to literal reads) so `MEDIA_RENDER_URL` etc. are covered; dead `FAL_WEBHOOK_SECRET` entry removed and its absence asserted (D12).
7. **One live smoke (deferred to UAT):** a real reel run through approve → render → vault on dev, adjudicated by the owner — this is the behaviour-level check that no unit suite can fake; it doubles as the first owner-adjudicated assembled reel (the phase 33 gate never covered one).
8. **Baseline discipline:** run the focused suites from `packages/backend` (not repo root) and baseline before trusting any mutation run (recorded memory).
