# Phase 25.1 Plan 05: Memo Rendering & Research Sources Summary

**The product of a paid research turn now reads as a document with checkable references: the memo body renders through the existing Markdown renderer instead of showing the reader literal `#` and `**`, and the pages the specialist actually retrieved — already computed, deduped, billed for and written into the vault — finally reach the card, while the audit plane still learns nothing but a count.**

## Performance

- **Duration:** ~70 min (12:05 → 13:15 UTC+3)
- **Tasks:** 2, both TDD — 4 commits (RED/GREEN per task)
- **Files modified:** 10 · created: 1
- **Cost:** $0 (no model calls, no live deployment)

## Accomplishments

- **D11a — the sources travelled everywhere except the place a human reads.** `sourcesFromToolOutput` builds them from the search tool's own RESULT parts, `governedDispatch` returns them, `persistResearchFindings` writes them into the vault document — and `dispatchAndLand` then dropped them one hop short of the plan row. Worse, the vault terminal is **skipped entirely on a zero-search run and swallowed on a persist failure**, so the one surface that always exists (the card) was the one surface with no provenance at all. `plans.sources` (`{title, url, retrievedAt}[]`, optional, additive) now lands with the body it attributes.
- **The §4 boundary held, and is now proven rather than asserted.** The `dispatch.test.ts` §4 scan walks every audit row of a real research run looking for the source URLs — but it did so on a run where the plan row never received them, so "no URL reached the audit plane" was true of a run in which no URL went anywhere. The test now stages the landing and finishes by asserting the URLs **are** on the plan row. Same run, both halves: content plane yes, audit plane no.
- **The write door was chosen, not defaulted.** `sources` is deliberately **not** a `patchPlan` arg. `patchPlan` is what the model's cockpit tools write through; a source list is a claim that particular pages were read. It goes in by direct `ctx.db.patch` from `landSpecialistResult`, whose args come from the internal dispatch action the model cannot reach — the same rule `plans.ts` already writes down for `calendarEventId`/`calendarRunId`.
- **D11b — the memo card renders.** `MemoCardBody` replaces a `white-space: pre-wrap` paragraph with the **existing** `MarkdownDocument` in its `compact` form (no second renderer, no tokenizer change) and adds the references block: one row per page, title as the link, the URL as readable text, and that source's own retrieval date. No sources ⇒ no block. An empty title (a real shape — `sourcesFromToolOutput` defaults it to `""`) links the URL instead of rendering a blank anchor.
- **D11c — the approvals gate stopped showing markup, in TWO places.** `previewText` strips headings/bullets/emphasis, collapses the blank lines and *then* cuts at `PREVIEW_CHARS`. The second place was found by the first fix: `titleFor` builds a memo's headline from `plan.body.split("\n")[0]`, which is that body's markdown H1 — so the card TITLE carried the marker one element above the preview being fixed. One strip, both sites.
- **11 new tests, 9 of them against real markup.** `apps/web` 453 passed (was 443); backend blast-radius 364 passed.

**One vacuous assertion was caught and fixed by mutation F7.** The headline test first asserted `toContain("Pricing findings</h3>")` — which matches the DEFECT too, because `># Pricing findings</h3>` contains that substring. It stayed green with the strip removed and only the preview test reddened. Tightened to `">Pricing findings</h3>"` (the leading `>` is the whole assertion), after which F7 reddens both. The general rule, now in `dashboard-pages.md`: when the defect ADDS a prefix, the pin must contain the delimiter, or it cannot see the difference.

**Mutation B5 is the finding worth carrying forward.** Leaking the source URLs into an audit payload reddens `dispatch.test.ts`'s runtime §4 scan — and leaves `llmRedaction.test.ts` **fully green**, because that static scan bans the identifiers `reply|body|text|output` by name and knows nothing about a URL. The static pin is not cover for this class; the runtime scan over real rows is. Recorded in `cockpit.md`.

## Deviations from Plan

### 1. [Rule 1 — root cause, sibling caller] `titleFor` carried the same defect one element up

- **Found during:** Task 2, by the preview test still failing on `# Pricing` after the preview itself was fixed.
- **Issue:** `titleFor` builds a memo's card headline from `plan.body.split("\n")[0]` — the body's markdown H1 — so the approvals card TITLE printed `# Pricing findings`.
- **Fix:** the same `previewText` strip, at both sites. Plus a dedicated headline test.
- **Why it counts:** the plan named exactly one preview site (`:583-586`). Fixing only that would have left the louder of the two defects on screen.

### 2. [Rule 2 — provenance safety] `plans.ts` `resetPlan` clears `sources` (a file outside the plan's list)

- **Found during:** Task 1, writing the schema comment.
- **Issue:** `landSpecialistResult` only writes `sources` when non-empty, so a reset-then-re-land with no search would leave the previous run's references under a new body.
- **Fix:** one line in `resetPlan`, asserted in the same dispatch test (land → reset → gone).

### 3. [Rule 3 — a stale comment that argued against the change] `dispatch.ts:1096-1098`

The doc comment on `persistResearchFindings` said the sources were deliberately NOT threaded through `landSpecialistResult` "through a mutation with no business knowing about them". That reasoning is now reversed for the plan row, so the comment was rewritten rather than left to contradict the code below it.

### 4. `evaluations.ts` was normalised from CRLF to LF on disk

Its working copy was entirely CRLF while `HEAD` stores LF, which made `biome check` print the whole file as a formatting error and hid any real diagnostic. Git normalises on add either way, so the committed content is unchanged and `git diff --stat` stayed at 19 insertions.

### 5. Commit granularity: RED and GREEN per task, four commits

Both tasks were independently RED-able, so unlike 25.1-04 they were not merged.
