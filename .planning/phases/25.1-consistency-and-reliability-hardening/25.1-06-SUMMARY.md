# Phase 25.1 Plan 06: Env Manifest, Dead fal Code, the Sora ADR and a Visible DLQ Summary

**Three hygiene defects closed and two plan premises corrected: the readiness screen can now see the media env names that were reading it green while renders stalled, an authenticated write path that no provider could ever call is deleted after its caller set was proved empty hop by hop, the provider cutover nobody wrote down is on disk as ADR-024, and the operator can finally see the dead letters that belong to somebody else.**

## Performance

- **Duration:** ~135 min

- **Files:** 24 modified · 1 created
- **Cost:** $0 (no model calls, no live deployment)

## Accomplishments

### D12 — the drift scan could not see the way this codebase actually reads a media env var

`ENV_MANIFEST` listed `MEDIA_RENDER_SECRET` and a dead `FAL_WEBHOOK_SECRET` for media, and the guard that keeps it honest scanned only for a literal `process.env.X`. **Every media name is read through `requireEnvMedia("X")` — a `process.env[name]` lookup behind a helper — so the scan was blind to all of them.** `MEDIA_RENDER_URL` is the sharp one: it is read *inside the scheduled `renderReel` action*, so unset it throws where no user is waiting and the plan sits at `rendering` for ever while `/admin` reports the deployment ready.

The fix is a second regex over the same file walk, matching the call sites' string literals. Two details are load-bearing:

- It matches the **string literal**, not a `[A-Z_]` shape, because `Video_and_image_API_Key` is Alibaba's own mixed-case name and a shape rule would have dropped exactly one of the three.
- The new test asserts those names are **NOT** reachable as a literal `process.env.X` anywhere. Without that half the extension could become redundant and its deletion would go unnoticed; with it, removing the extension reds.

`MEDIA_RENDER_URL`, `WAN_API_BASE_URL` and `Video_and_image_API_Key` are now classified. **`MEDIA_SANDBOX_SNAPSHOT_ID` deliberately is not** — see Deviation 1.

### D14 — the fal webhook is deleted, and the caller set was proved empty before it was

The plan asked for removal of "dead" code. 25.1-01 refused to act on a false premise; this one verified the premise before acting, hop by hop:

| Hop | Finding |
| --- | --- |
| Who mints the callback URL? | Nobody. `submitLine`'s third parameter was already `_webhookUrl?` — **unused** — and its one caller passes two arguments. Nothing has minted a `fal_webhook` URL since ADR-017. |
| Who calls the resolver? | `internal.mediaComplete.resolveJob` had exactly ONE caller: the route. |
| Who reads the secret? | `process.env.FAL_WEBHOOK_SECRET` had exactly ONE reader: `resolveJob`. |

**So the route's only reachable caller was somebody holding `FAL_WEBHOOK_SECRET`** — for whom it offered an outbound `fetch` to a caller-named URL and a mutation that writes a terminal `succeeded` onto a `mediaJobs` row. That is not conservatism, it is an unused authenticated write path. Gone: the route, the HMAC path segment, the ±300 s replay window, the SSRF host allow-list, `ASSET_PATH`/`INLINE_ASSET`/`moderationOf`/`actualOf`/`errorCode`, `resolveJob`, the manifest entry — 217 lines out of `http.ts`, 55 out of `mediaComplete.ts`, 941 out of `media.test.ts`.

**`FAL_FIXTURE` survives.** Its name is a fossil but the seam is live and still keeps the offline suites at $0 — asserted, so a future cull cannot take it by name-matching.

**ADR-024** records the OpenAI provider (Sora 2 720p 4 s, GPT Image 2, tts-1, whisper-1, with the endpoints and the price pins) and supersedes ADR-017's visual half and its open-ended "retain the old callback *temporarily*" clause. It names the one consequence a reader would otherwise carry away wrong: ADR-017 says *"it does not receive prompts for visual jobs"*, and that sentence is **false** as of this cutover.

### D13 — the operator can now see dead letters that are not his

`deadLetters.listAll` is an `ownerQuery` over the `by_status` index that had existed since 02-06 **with no reader**: `status: "new"`, newest first, default 50, server ceiling 200, `take(cap + 1)` so `truncated` is known rather than guessed. The projection is a pinned key set and the payload passes through byte-identical. `/ops` gains an owner-only **Dead letters — all tenants** section, gated by *mounting* per the page's own rule, showing reason code, age, tenant/workflow/correlation refs and the payload behind a `<details>`.

**Read-only by construction, and asserted as such:** `markResolved` stays a `tenantMutation`, and a source scan bans any `ownerMutation` on the module. Seeing another tenant's failure and being able to act on it are two decisions; only the first has been made.

## Deviations from Plan

### 1. [Rule 4-adjacent, decided on evidence] `MEDIA_SANDBOX_SNAPSHOT_ID` is NOT in the manifest — the plan's must_have is wrong

- **Found during:** Task 1, grepping for the readers before writing the entry.
- **Issue:** The plan's `artifacts` block requires "MEDIA_RENDER_URL and MEDIA_SANDBOX_SNAPSHOT_ID in ENV_MANIFEST". The **only** reader of `MEDIA_SANDBOX_SNAPSHOT_ID` in the entire repo is `apps/web/app/api/media/render/route.ts` — a **Vercel** variable that no Convex process can read.
- **Why compliance would be a defect:** `envCheck` runs in the Convex deployment. Listing a web-build name makes it report missing on every healthy deployment, and a readiness screen that cries wolf is worse than one blind spot. The repo had already reached this conclusion and written it into `env.ts` for `NEXT_PUBLIC_CONVEX_URL` — *"the drift test's dead-entry check caught it being listed here"*. Adding it would also have reddened "no manifest entry is dead" immediately.
- **What was done instead** (the plan's own CONTEXT note sanctions this): `deploy-production.yml:114` already asserts it beside `NEXT_PUBLIC_CONVEX_URL` and `MEDIA_RENDER_SECRET`, and `production-beta.md` now names it, says where its coverage lives, and says where its absence actually bites — the render route returns `not_configured`, which is not in `TRANSIENT_RENDER_CODES` and goes straight to a dead letter, i.e. onto the surface D13 just built.

### 2. [Rule 3 — the two drift directions are one atomic edit] `FAL_WEBHOOK_SECRET` was delisted in Task 2, not Task 1

The plan put "assert FAL_WEBHOOK_SECRET is absent from the manifest" in Task 1 and the deletion of its reader in Task 2. The drift test checks **both** directions, so delisting a still-read name reds "every consumed name is classified", and deleting a still-listed reader reds "no manifest entry is dead". They are one commit or the suite is red in between. The absence assertion also got stronger than the plan asked: it pins that the name is **unread in source**, not merely delisted — the manifest-only version would pass against a codebase that still had the route.

### 3. [Rule 1 — root cause across siblings] Five stale references outside the plan's file list

Deleting the route left five comments citing code that no longer exists. Each was rewritten, not left to contradict the source: `contacts.ts` ×2 (the unsubscribe token cited "the `convex/http.ts` fal-webhook pattern" and `resolveJob`'s rules — it is now the **last living copy** of that pattern and says so self-containedly), `plans.ts` (`reel_in_flight` explained itself by "fal will call back to `/fal/callback/*`" — the hazard survives, the callback does not), `schema.ts` (the "no stored `callbackHash`" deviation outlived its subject), and `media.ts` ×2.

### 4. [Rule 1] Two guards went red and both were RIGHT to

- `microsoftAuth.test.ts` pins the `http.route(` count exactly. 8 → 7, updated with a note: **a route disappearing is exactly as worth noticing as one appearing**, which is why the pin is a pin.
- `skills.test.ts`'s "no long inline prompt string literals in convex/" (>200 chars) fired on a `whatBreaks` string. It is not a prompt, but the rule is a good general one and the long version belonged in the playbook, where it already was. Shortened.
- `isolation.test.ts`'s self-growing owner surface caught `deadLetters.listAll` as the 16th owner endpoint and the 6th module — and gave it an automatic OWNER_REQUIRED case for free.

### 5. [Rule 1 — a guard that had never matched its own documentation] `tenantSkillReview.test.ts`'s panel slice

- **Found during:** Task 3, by the BRAND hex pin going red over `#dc2626` — a colour belonging to a **different component**.
- **Issue:** the slice's doc comment says "from its declaration to the next top-level one"; the code sliced to `export default function OpsPage`, swallowing anything declared in between. Two new declarations landed in that gap.
- **Fix:** the slice now really does stop at the next top-level declaration. Pre-existing latent bug, revealed rather than caused.

### 6. [Task-3 discovery] The D13 research premise was two-thirds wrong

*"No consumer, no listing surface, no re-drive."* `deadLetters.listNew` + `newCount` have existed since 02-06 and `/ops` has rendered them with a Mark-resolved button ever since. Only "no re-drive" was true (and re-drive is deliberately deferred). D13 shipped as the operator's **cross-tenant** read — the genuine gap — and the corrected premise is written into `audit-dead-letter.md` so the next reader does not re-derive it.

### 7. [Task-2 discovery, deferred not acted on] The Wan poller's retention has silently expired

`pollWanTask` is scheduled **only by its own retry** (capped at 60 attempts ≈ 10 minutes); no submit path enqueues it. Its reachability depended entirely on Convex's scheduler queue at the moment of the ADR-017 cutover, which drained within minutes of 2026-08-13. It is dead in the same sense the fal route was. **Not removed** — the plan named it as the thing not to break, and unlike the route it has no HTTP surface and no external caller, so it is a dead-code question and not a security one. Logged as deferred item 5, recorded in ADR-024 §3, and both its env names are now classified so their absence is at least honest.

### 8. Two shared files carry FOREIGN uncommitted hunks

`schema.ts` (a 50-line table index) and `docs/playbooks/cockpit.md` (a `calendar.test.ts` watch-gate entry). `git add` stages a whole file and `git stash` is banned in this tree, so 25.1-05's dance was repeated: snapshot → `git checkout --` → reapply only my block → stage → commit → restore the snapshot. `git diff --cached --stat` was inspected before the commit and showed only this plan's lines; both foreign hunks are back in the working tree, unstaged, at their original sizes (5 and 50 insertions).

### 9. `mediaComplete.ts` was normalised CRLF → LF on disk

Its working copy was entirely CRLF while `HEAD` stores LF, which made `biome check` print the whole file as one formatting error and hid every real diagnostic. Git normalises on add, so the committed content is unchanged — `git diff --stat` stayed at 10 insertions / 55 deletions across the normalisation.
