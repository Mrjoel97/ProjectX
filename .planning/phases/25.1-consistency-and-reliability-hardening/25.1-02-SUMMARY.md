# Phase 25.1 Plan 02: Stuck-Work Watchdog Summary

**One 30-minute cron now terminalizes every severed scheduler chain — a dead poll chain, an un-re-evaluated render trigger, a stranded transcript, and a specialist dispatch that died leaving its plan card invisible — each with a per-class reason code and one in-app notification, and each with a mutation-proven exclusion so live work is never swept.**

- **Duration:** ~55 min (including verification of the inherited draft suite)
- **Tasks:** 2 (task 1 TDD: RED + GREEN commits)

## Accomplishments

- **D3 closed.** `reliabilitySweep.sweepStuckMediaJobs` fails a `submitted` job whose poll chain is provably gone (>45 min; the poll cap is 180×10s = 30 min) by routing it through `mediaComplete.landResult` — so it reconciles its spend, writes its one `media.landed` audit line, and cascades into the render trigger, which terminalizes the plan as `incomplete_batch` through the ordinary path.
- **D3 closed on the plan row.** `sweepStuckPlans` terminalizes a stale `renderStatus: "rendering"` or armed `"pending"` (>60 min) as `watchdog_render_timeout`, and a stranded `captionStatus: "transcribing"` (>30 min) as `watchdog_caption_timeout` — never touching `renderStatus` on the caption path, so a failed burn leaves a rendered reel standing.
- **D4 closed.** A `collecting` + `kind: "memo"` row — the dispatch-owned discriminator `plans.stageResearchPlan` already uses — with no live scheduled dispatch becomes `proposed` with an honest system-voice body. `PlanCard` renders only at `proposed`, so a plan that was invisible for ever is a card the user can read and re-ask from.
- **The exclusions are the load-bearing half, and all of them are mutation-proven:** un-armed `pending` (no batch), a batch with a line still in flight, the fix-menu deck hold (`hasAssetSource`), a caption legitimately waiting on a reel still rendering, an automatic retry (`renderRetriedAt`), a MANUAL retry (its `media.render_retry_manual` audit row — `retryRender` stamps no plan field, so that row is its only clock), a live scheduled dispatch, and every threshold boundary.
- `crons.ts` gained its fifth job and the count is now pinned by a test; three playbooks carry the invariants.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The inherited RED suite was VACUOUS on the in-flight guard**
- **Found during:** Task 1 (mutation-checking the module the draft suite was written against)
- **Issue:** Deleting `if (inFlight(jobs)) return false;` — the guard that stops the plan sweep terminalizing a reel whose provider line may still land — left the **entire suite green**. Both "in flight" tests seeded the in-flight job with `updatedAt: now - 1_000`, i.e. FRESH, so the staleness clock decided them and the guard was never exercised. A long Sora video legitimately sits at `submitted` for a long time; without the guard the plan sweep would terminalize its plan while a landing was still coming.
- **Fix:** Both tests now seed the in-flight job STALE by the clock, so only the in-flight guard can save it. Both mutations now redden.
- **Files modified:** `packages/backend/convex/reliabilitySweep.test.ts`
- **Committed in:** `8183ff8`

**2. [Rule 1 - Bug] The inherited suite dropped the plan's collecting THRESHOLD**
- **Found during:** Task 1 (reading the draft against the plan's must_haves)
- **Issue:** The draft's D4 design used the scheduler-liveness probe alone and seeded a FRESH row expecting it to be swept — contradicting the plan's must_have "Fresh (under-threshold) rows are never touched" and its stated `collecting > 30 min`. Threshold-alone is also unsafe on its own (plan rows are RECYCLED — `resetPlan` keeps the old `createdAt`, so a row staged a minute ago can look a week old), so the honest design is BOTH: the clock as a cheap pre-filter that keeps a `_scheduled_functions` scan off every plan in the table, and liveness as the decider.
- **Fix:** Added `COLLECTING_STALL_MS` (pinned by the constants test), aged the two D4 fixtures — including the live-dispatch one, which would otherwise have passed on the clock alone and proven nothing — and added a boundary test.
- **Files modified:** `packages/backend/convex/reliabilitySweep.test.ts`, `packages/backend/convex/reliabilitySweep.ts`
- **Committed in:** `8183ff8` / `089378a`

**3. [Rule 3 - Blocking] `_generated/api.d.ts` regenerated by hand (file not in the plan's list)**
- **Found during:** Task 2 (backend `tsc`)
- **Issue:** `internal.reliabilitySweep` does not exist until codegen runs, so `crons.ts`, the module and the test all failed to typecheck. `npx convex codegen` refuses to run without a local backend on :3210.
- **Fix:** Added the two lines codegen would emit, in codegen's alphabetical position. The file also carried an uncommitted catch-up entry for `calendarEvents` (committed source since 17-09, never re-generated) — that is codegen catching up with the repo, not another lane's work, so it went in the same commit.
- **Committed in:** `28925cc`

**4. [Rule 2 - Missing critical] Per-class reason codes instead of the plan's single `watchdog_timeout`**
- **Found during:** Task 1
- **Issue:** The plan's behaviour text names `renderReason: "watchdog_timeout"` while its own transposition-hardening requirement demands that swapping two terminals' reasons reddens a test — impossible with one shared literal.
- **Fix:** Three distinct codes (`watchdog_submit_timeout`, `watchdog_render_timeout`, `watchdog_caption_timeout`), pinned as distinct and asserted exactly at each terminal.
