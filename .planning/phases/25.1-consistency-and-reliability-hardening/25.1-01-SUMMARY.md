## Accomplishments

- D1 closed: all twelve refusal paths through `batchToRender` (non-contiguous indices, bad seconds, unknown kind, stale_inputs, vault doc missing/foreign/non-video, unrenderable card, out-of-deck blockIndex, sum≠target, in-flight batch, empty batch) end at `renderStatus:"failed"` + the exact class reason + one refs-only dead letter — `retryRender`'s failed-only precondition is reachable after every refusal.

## Decisions Made

- Reused `recordRender`'s failure arm for the refusal terminal rather than minting a new mutation (plan's own instruction; refusal codes are non-transient so the 33-04 auto-retry is never bought by a refusal).
- Chose INLINE terminalization for the non-JSON 200 (plan offered throw-and-let-retrier vs inline): a retry re-buys a sandbox to learn the same thing, violating the 20-16 money rule.
- `render_crashed`/`render_canceled`/`route_bad_response` are new reason codes; the canvas needs no change — `failureClause` falls back to the generic clause and renders the raw code as `detailCode`.
