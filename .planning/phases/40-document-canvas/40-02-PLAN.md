# 40-02 — A real `.xlsx` on both planes, taught by the body

**Source:** `40-RESEARCH.md` §1.1, §3 step 2b, §6 decisions 1 and 3 (owner: both planes; body bump
through the gate).

## Tasks

1. **Core:** `XLSX_MIME`, `FORMAT.xlsx`, `DocFormat` gains `"xlsx"`; `markdownToSheets(markdown)` from
   `tokenizeMarkdown` — each `table` token becomes `{ name: nearest preceding heading ?? "Sheet N",
   rows: [header, ...rows] }`; `[]` when no table. Tests: `formatSpec` pin becomes the three-entry set;
   filename ext; two tables under two headings; no table → `[]`.
2. **Skill row:** `SPREADSHEET_DRAFTER_SKILL = "spreadsheet-drafter"` (UNGATED — the content-drafter
   rationale verbatim: no golden fixture reaches the drafting path); body v1 asks for titled pipe tables
   only (first row = header, ≤ 12 columns, numbers as plain numbers, one heading per table, no prose,
   no images/links/code); `.md` + regenerated constant + seed list entry. `draftDocument` skillName
   union gains the literal; its SMOKE branch returns a two-column table when the skill is the
   spreadsheet drafter (the e2e needs a table to render).
3. **Email plane:** `generateAttachment` enum `["pdf","html","xlsx"]` ("xlsx when the user asks for a
   spreadsheet or a table to work in"); `renderAndStore` picks the spreadsheet drafter for xlsx and
   renders `sheetsToXlsx(markdownToSheets(md))`; a draft with no table is a render failure with its own
   sentence ("no table in the draft — ask for the columns"). `regenerateAttachment` passes the
   original's format (derived from `existing[i].mimeType` via `FORMAT`). Delivery untouched (MIME passes
   through; the Graph 3 MiB refusal stays).
4. **Vault plane:** `createDocument.form` gains `"sheet"` (description: "sheet = a spreadsheet they will
   work in — a price list, a schedule, a tracker"); bytes = xlsx stored with `XLSX_MIME`;
   `insertCreatedDoc` / `patchCreatedDoc` form unions widen and derive `storedMimeType` from `form`
   (`sheet` → `XLSX_MIME`, `long` → PDF, `short` → none; kind for `sheet` = `created_document`);
   `vaultSources.form` union widens (schema + `vaultSources.ts` + the llm.ts write at ~4190);
   `FORM_LABEL.sheet = "SPREADSHEET"`; ContentView `bytesLabel` maps `XLSX_MIME` → "XLSX"; the tool
   description says "markdown with a PDF (`long`) or a real spreadsheet (`sheet`) — never PowerPoint,
   Word or slides" (the pinned fragment survives). `vaultDocText` returns `storedMimeType` too (40-03
   needs it and it is metadata).
5. **Body v3 of `cockpit-agent`:** the routing paragraph (a table to WORK IN → `format: "xlsx"` on the
   attachment or `form: "sheet"` on the document), the attachments block ("adds one PDF" → "adds one
   document — a PDF unless the user asked for a web page (`html`) or a spreadsheet (`xlsx`)"), the
   standalone block (`form` triple), the format caveat (a real `.xlsx` exists; PowerPoint/Word still do
   not). Header `(v2)` → `(v3)`. Then on the local deployment: `seedSkills` → candidate v-next →
   `pnpm eval:golden --skill cockpit-agent@<v>` (46 cases) → `activateSkill`. Prod activation → G19.
6. **Tests:** `cockpitTools.test.ts` — xlsx attachment ref `{mimeType: XLSX_MIME, filename *.xlsx}` whose
   bytes read back through `sheetRows` with the fixture's header; no-table draft → `attachmentError`
   with the new sentence and no ref; regenerate keeps `html`/`xlsx`; `createDocument form:"sheet"` →
   `storedMimeType === XLSX_MIME` and `vaultSources.form === "sheet"`. `createdDocs.test.ts` — the
   sheet case beside the pinned long/short cases. `outputCard.test.ts` — the description pins updated to
   the new sentences. e2e `cockpit-attachment.spec.ts` — a second ATTACH topic with `format=xlsx` (the
   SMOKE grammar the spec already uses) asserting a `/\.xlsx$/` link beside the untouched `/\.pdf$/`
   pins.
7. **Docs:** cockpit.md (`DocFormat` sentence at ~5609, the CKPT-02 chain block, the createDocument
   forms), skill-registry.md (the new ungated row + the v3 gate evidence), dashboard-pages.md
   (`bytesLabel`), `xlsText.ts`/`sheets.ts` ponytail notes.
