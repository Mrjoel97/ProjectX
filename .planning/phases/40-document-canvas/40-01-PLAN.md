# 40-01 — Sheet grids: structured rows at ingest, rendered in the vault preview

**Source:** `40-RESEARCH.md` §1.3, §3 step 2a, §6 decision 4 (owner: structured rows at ingest).

## Tasks

1. **`packages/vault/src/sheets.ts`** (SUBPATH module, SheetJS static import, never on the barrel):
   `sheetRows(bytes): SheetPreview` — container gate (`ole2|zip`, the xlsText rule) → `read(bytes,
   {type:"array"})` → per sheet `utils.sheet_to_json(ws, {header:1, raw:false, defval:"", blankrows:false})`
   as formatted strings → caps `SHEET_ROWS_CAP=200`, `SHEET_COLS_CAP=30`, `SHEET_COUNT_CAP=10`,
   `SHEETS_BYTES_CAP=256 KiB` (JSON length, whole-sheet granularity) → `{ sheets: [{name, rows,
   totalRows}], sheetCount }`; throws `sheets_parse_failed: …` on an unreadable workbook, returns a
   zero-sheet preview when no sheet has a value (caller decides). `sheetsToXlsx(sheets)` — the writer
   for 40-02, in the same module: `aoa_to_sheet` → `book_append_sheet` (names sanitised to ≤31 chars,
   no `[]:*?/\`, de-duplicated) → `write(wb, {bookType:"xlsx", type:"buffer", Props: epoch dates})` →
   `Uint8Array`; throws on zero sheets. One test file: fixture built with the writer, read back through
   `sheetRows` (names, formatted values, totals, caps), plus the STATIC-import source scan copied from
   `xlsText.test.ts:173-190`.
2. **Schema:** `vaultSheets` table `{ tenantId, docId: v.id("vaultDocuments"), sheets: [{name, rows:
   string[][], totalRows}], sheetCount, createdAt }` with `.index("by_doc", ["tenantId", "docId"])`.
   Separate table BY DESIGN: the grid read budget counts `vaultDocuments.text` bytes only
   (`constants.ts:44,56`), so a per-row field would silently break that bound.
3. **`vault.ts`:** `internal.vault.upsertSheets` (replace-by-docId — Retry re-runs the rail, so the
   write is idempotent), `api.vault.vaultDocSheets` (tenantQuery, single doc, returns the row or null —
   the grid never rides the list projection), and the cascade: wherever a vault document's row is
   removed, its `vaultSheets` row goes too (find the remove site; grep `db.delete` on vaultDocuments).
4. **`vaultExtract.ts`:** on the `zip` rail when `xl/workbook.xml` was the marker, and on `legacy_xls`,
   call `sheetRows(bytes)` in its own try — a failure leaves `sheets` undefined and NEVER fails the
   document; after `ingestExtractedText`, `upsertSheets` when ≥ 1 sheet. Audit payload stays counts-only
   (`sheetCount`, capped rows) — §4. `extractOfficeText` returns `{ text, kind? }` or the action re-sniffs
   the marker; pick the smaller diff. Test: an .xlsx fixture (built with `sheetsToXlsx`) reaches the seam
   with a `vaultSheets` row whose first sheet has the formatted values; a legacy .xls too; a DOCX writes
   none; Retry on the same doc leaves ONE row.
5. **Web:** `SheetGrid.tsx` (vault/, owner vault.md): per sheet a BRAND §3 caps label with the sheet
   name, `<div class="markdown-table-scroll"><table>` reusing the MarkdownDocument markup + globals.css
   rules (tinted `<th scope=col>` first row, `--rule` hairlines), and honesty lines in words: "Showing
   the first 200 of 1,240 rows — download the original for the rest", "3 more sheets not shown". No
   colour as meaning, no amber, no new dependency. `PreviewModal`: one `useQuery(api.vault.vaultDocSheets)`
   when `displayMime` is a spreadsheet type (xlsx/xlsm/xls/xlsb/ods — the closed list lives beside
   `binaryMediaKind`, NOT inside it, so `previewState.test.ts:103` keeps holding) and the `ready-text`
   branch renders `SheetGrid` when the row exists, else the existing `<pre>`. One test: `sheetGrid.test.ts`
   renders two sheets to static markup and asserts the caps label, the `<th scope="col">`, and both
   honesty lines; a source scan pins that `vaultDocSheets` is queried only for the spreadsheet list.
6. **vault.md:** the invariant block (separate table + why; caps; cascade; the honesty lines; the
   read-budget reason) and `Last verified` bump.

## Not in scope

CSV (decoded client-side as text, never a workbook).
