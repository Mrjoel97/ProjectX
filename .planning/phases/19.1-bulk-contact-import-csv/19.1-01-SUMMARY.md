# Phase 19.1 Plan 01: The Pure CSV Import Brain Summary

RFC-4180 CSV parsing, header auto-mapping and fill-empty-only within-file dedup as pure TS in
`@pikar/core`, with rejections carrying the physical file line and the consent attestation as a
versioned constant — 20 new tests, no Convex, no DOM, no new dependency.

## What Was Built

**`packages/core/src/contactImport.ts`** (205 lines) — the whole import brain:

- `parseCsv(text): CsvRecord[]` — one character-at-a-time loop. Handles quoted fields, commas and
  newlines inside quotes, a doubled quote as one escaped quote, a leading BOM, and CRLF or LF. Each
  record carries the **physical file line** it starts on: newlines consumed inside a quoted field
  are counted, so a two-line quoted field costs two lines and record indexes and file lines diverge
  exactly the way the user's spreadsheet shows.
- `IMPORT_ROW_MAX` (1000), `IMPORT_BATCH_ROWS` (100), `IMPORT_MATCH_CHUNK` (500) — single-sourced so
  client and server cannot drift. The row cap carries the required `ponytail:` comment naming the
  ceiling (one browser tab's memory) and the upgrade path (a server-side chunked job), and records
  why that path is deliberately not built.
- `IMPORT_ATTESTATION` — byte-identical to the design spec sentence, asserted against an inline
  literal in the test rather than against itself.
- `detectMapping(header): ColumnMapping` — literal alias table over headers stripped to lower-case
  alphanumerics, so `E-Mail`, `e mail` and `EMail` all resolve. `first` and `last` both land on
  `name` because the mapping is arrays of column indexes, not one index per field — no special case.
- `mapRows(records, mapping)` — skips the header record, throws `IMPORT_NO_EMAIL_COLUMN` then
  `IMPORT_TOO_MANY_ROWS` in that order, then per row: joins mapped columns, normalizes the address,
  rejects blank and structurally invalid addresses by physical line, and collapses duplicates.

**Two reuses, not re-derivations.** Identity comes from `normalizeAddress` and validity from
`isValidEmail`, both imported. This is what makes "the import cannot disagree with the send path
about who a row is or whether the address is real" true by construction.

## Key Decisions

**In-quote CRLF normalizes to LF.** The plan required "LF-only and CRLF files parse identically".
Without this, a multi-line quoted field would produce `"Multi\r\nLine"` in a Windows-saved file and
`"Multi\nLine"` in a Unix-saved one — the same file, two different contact values.

**`sawQuote` distinguishes blank from quoted-empty.** The blank-line drop is "one empty field and
nothing else"; a lone `""` on a line is a real record. Three lines of state, and it is the correct
edge-case behaviour rather than the smaller one.

**Rejection reasons are user-facing sentences, not codes** ("no email address in this row", "not a
usable email address"). The named `Error` strings are reserved for the two whole-file refusals,
which the panel must branch on.

## Mutation Evidence

Both load-bearing guards were broken, observed red, and restored — the phase-19 lesson that a test
which still passes when the feature breaks is a defect.

| Guard | Mutation | Observed failure |
| --- | --- | --- |
| In-quote physical line counting (`if (c === "\n") line++`) | deleted | `AssertionError: expected [ 1, 2, 3 ] to deeply equal [ 1, 2, 4 ]` |
| Fill-empty-only (`if (value && !row[field])` → `if (value)`) | weakened to always-overwrite | `AssertionError: expected [ { email: 'bob@x.com', …(2) } ] to deeply equal [ { email: 'bob@x.com', …(2) } ]` (name overwritten with the staler `Robert Smythe`) |

The dedup test asserts **both** directions — the blank company filled from row 2 AND the name from
row 1 preserved. Asserting only the fill is the half-test that let "don't erase" pass for "fill
empty only" on the backend.
