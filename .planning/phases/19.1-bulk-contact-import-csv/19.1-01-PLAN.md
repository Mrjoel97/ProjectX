```ts
/** One parsed record and the PHYSICAL file line it starts on (1-based, header included).
 *  Physical, not record index: a quoted newline makes the two diverge and the file line is what
```

Hand-rolled RFC-4180, one character-at-a-time loop, ~60 lines. NOT a dependency (locked). It must
handle: quoted fields, commas inside quotes, newlines inside quotes, a doubled quote as one escaped
quote, a leading BOM, and CRLF or LF. Track the physical line as you consume newlines — including
the ones inside a quoted field — so `line` is the record's FIRST physical line.

Then the three size constants, each single-sourced here so client and server cannot drift:

```ts
/** The whole-file ceiling. A larger file is refused outright, naming this number.
 *  ponytail: a hard cap instead of a job queue. The ceiling is one browser tab's memory and one
 *  user's patience; the upgrade path when someone brings 50k rows is a server-side chunked job with
 *  a reservation row and a resumable cursor — deliberately NOT built, because upsert-by-address +
 *  fill-empty-only makes re-running the whole file a complete recovery strategy at this size. */
export const IMPORT_ROW_MAX = 1_000;
/** Rows per `importContacts` call. Not a Convex limit — every limit would permit all 1,000 in one
 *  call. The reasons are retry blast radius, progress granularity and a shorter OCC window. */
export const IMPORT_BATCH_ROWS = 100;
/** Addresses per `matchExisting` call. Same reasoning. */
export const IMPORT_MATCH_CHUNK = 500;

/** The attestation the user ticks, stored VERBATIM on every contact it covers. It is the evidence,

 *  Changing it applies to FUTURE imports only. */
```

<task type="auto" tdd="true">
  <name>Task 2: detectMapping, mapRows, dedup and rejection</name>
  <files>packages/core/src/contactImport.ts, packages/core/src/contactImport.test.ts</files>
  <behavior>
    - `detectMapping(["E-Mail","Full Name","Organization","Job Title","Phone"])` maps all five fields
    - `detectMapping(["First","Last","email address"])` maps `name` to BOTH name columns, joined by a space
    - A header with no recognizable email column yields `email: []`; `mapRows` then throws `IMPORT_NO_EMAIL_COLUMN`
    - Unmapped columns are dropped and never appear on an `ImportRow`
    - A row whose email is blank → rejected, reason names a missing address, `line` is the physical line
    - A row whose email fails `isValidEmail` → rejected, reason names an unusable address
    - Two rows with `Bob@X.com ` and `bob@x.com` collapse to ONE row; a field blank in the first and
      set in the second is filled, and a field set in the first is NOT overwritten by the second
    - Every returned `email` is already `normalizeAddress`-d
    - More than `IMPORT_ROW_MAX` data records → throws `IMPORT_TOO_MANY_ROWS`
  </behavior>
  <action>
Extend `contactImport.ts`:

```ts
export type ImportField = "email" | "name" | "company" | "phone" | "title";
/** Column indexes per field. An ARRAY so `first`+`last` needs no special case: the values are
 *  trimmed and joined with a single space. Empty array = unmapped. Every field is overridable from
 *  the preview by handing `mapRows` a different mapping. */
export type ColumnMapping = Record<ImportField, number[]>;
export type ImportRow = { email: string; name?: string; company?: string; phone?: string; title?: string };
export type RejectedRow = { line: number; reason: string };

export function detectMapping(header: string[]): ColumnMapping;
export function mapRows(records: CsvRecord[], mapping: ColumnMapping): { rows: ImportRow[]; rejected: RejectedRow[] };
```

`detectMapping`: lower-case + trim + strip non-alphanumerics from each header cell, then match a
literal alias table — `email`/`e-mail`/`email address`; `name`/`full name` (and `first`/`first name`
+ `last`/`last name`, which BOTH land in `name`); `company`/`organization`/`organisation`;
`phone`/`phone number`/`mobile`; `title`/`job title`. First match wins per column; a column matching
nothing is dropped.

`mapRows` takes the records INCLUDING the header record and skips record 0. Order of refusals:
1. `mapping.email.length === 0` → `throw new Error("IMPORT_NO_EMAIL_COLUMN")`
2. data records > `IMPORT_ROW_MAX` → `throw new Error("IMPORT_TOO_MANY_ROWS")`
Then per record: build the field values (join mapped columns with a space, trim, drop empties),
`normalizeAddress` the email; empty → rejected `"no email address in this row"`; failing
`isValidEmail` → rejected `"not a usable email address"`. Both carry `record.line`.

Dedup by normalized address as you go, under the SAME fill-empty-only rule the write path uses: the
first non-blank value for a field wins, later rows fill only what is still empty. A duplicate does
NOT produce a second `ImportRow` and is NOT a rejection.

Extend `contactImport.test.ts` with every behaviour above. The dedup test must assert BOTH
directions (filled where empty, preserved where set) — asserting only the fill is the half-test that
let "don't erase" pass for "fill empty only" on the backend.
