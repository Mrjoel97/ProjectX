  <action>
Extend the shared helper — ONE writer, a flag, not a second implementation (CLAUDE.md §8 rung 2,
playbook invariant 13):

```ts
export async function upsertContactRow(
  ctx: MutationCtx,
  tenantId: string,
  args: {
    email: string;
    name?: string;
    company?: string;
    phone?: string;
    title?: string;
    origin: ContactOrigin;
    /** Import semantics: a value may FILL an empty field and may never overwrite a non-empty one.
     *  Default `false` keeps today's rule — "a blank name must not ERASE a name on record", where a
     *  non-blank one still overwrites — so hand-add and the agent applier are byte-identical to
     *  before this phase. */
    fillEmptyOnly?: boolean;
    /** Written ONLY when the row carries no consent at all. An import must never downgrade a
     *  per-person `asserted-by-user` record to a batch attestation — the same principle as
     *  fill-empty-only, applied to the field where it matters most. */
    consent?: { source: ConsentSource; wording: string; context?: string };
  },
): Promise<{ id: Id<"contacts">; created: boolean; filled: number }>
```

Rules:
- Keep the existing trust boundary (`CONTACT_EMAIL_REQUIRED`) unchanged and first.
- Trim every incoming field; treat blank-after-trim as absent.
- INSERT path: write whatever fields are present, `origin`, and the consent block if given.
  `created: true`, `filled: 0`.
- UPDATE path: for each of the four mappable fields (`name`, `company`, `phone`, `title`) compute a
  patch entry only when the incoming value is non-blank AND (`fillEmptyOnly === false` OR the stored
  field is empty). `filled` = the number of the FOUR MAPPABLE FIELDS this call actually changed —
  consent is not counted (locked: the preview counts are defined over the four mappable fields only;
  counting a consent write would make `unchanged` structurally always 0 and the preview a lie).
- Consent on the update path: write the four consent columns ONLY when `existing.consentAt === undefined`. Never patch consent otherwise, in either direction.
- `origin` is NOT patched on update — provenance is set once, on creation.
- **Skip the `db.patch` entirely when nothing would change** (no fields, no consent). Otherwise an
  `unchanged` row still moves `updatedAt` and the count is a lie in the DB even when it is right on
  the wire.
- Do NOT copy the `?? "asserted-by-user"` fallback into any of this.

Update the three call sites for the new return shape (`(await upsertContactRow(...)).id`). Keep
`upsertContact`'s public return type `Promise<Id<"contacts">>` exactly as it is — the mutation's
contract does not change. Update the helper's doc comment to state the flag and invariant 13.

Do not commit yet — this plan commits once, in task 3.
