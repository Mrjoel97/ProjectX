## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | vitest (core, backend, web) + Playwright (browser) |
| **Config file** | per-package `vitest.config.ts`; `apps/web/playwright.config.ts` |
| **Quick run command** | `pnpm --filter @pikar/core test` (~15s — the parser lives here) |
| **Full suite command** | `pnpm test` (turbo, 9 tasks) then `pnpm typecheck` |
| **Browser command** | `npx playwright test e2e/pipeline-uat.spec.ts --no-deps --workers=1` (~4 min) |
| **Estimated runtime** | quick ~15s · full ~6 min · browser ~4 min |

**Two harness facts that invalidate naive commands:**
- `pnpm --filter <pkg> test -- <name>` **does NOT filter** anywhere in this repo — it runs the
  whole package suite. Do not write a per-task command that relies on it. The working forms are
  `pnpm --filter @pikar/core test contactImport` (no `--`) and, for the backend,
  `cd packages/backend && npx vitest run convex/contacts.test.ts`.
- The backend vitest fork crashes (`vaultDigest.test.ts` failures + `Cannot set properties of
  undefined (setting 'exit')`) when aggregate/retrier components are registered for tests that
  write no audit row. Use `harness({ audit: true })` / `withFanoutOnly()` / per-test
  `convexTest`. A red backend suite after adding tests is yours, not pre-existing — re-run once
  before believing it (the suite also flakes under memory pressure).

a delta, never an absolute.

## Anti-Vacuity Requirements

This phase inherits five findings of green-but-meaningless tests from Phase 19. Each rule below
exists because a specific test passed while the thing it named was broken.

1. **Assert on stored state, not on the reply.** Fill-empty-only, consent non-downgrade and the
   counts must be asserted by reading the contact rows back — a mutation's return value can agree
   with itself while the write is wrong. *(19.1-03 T2, 19.1-04 T2, 19.1-07 T1 step 9.)*
2. **Every new guard is mutation-proven:** break it, observe red, record the exact failing text,
   revert. A guard never observed failing is not proven. *(19.1-02 T3, 19.1-03 T3, 19.1-04 T3,
   19.1-05 T2, 19.1-06 T3 — 13 proofs in total.)*
3. **The browser step is a REQUIREMENT, not a nicety.** Phase 19 shipped a capability that unit
   tests, SMOKE tests and a paid eval gate all certified while it was unreachable from the
   product, because each supplied context the browser never provides. An import feature has the
   identical shape: a `tenantMutation` passing every backend test can still be unreachable
   because the button is not wired. *(19.1-07 T1 — a whole plan, not a bullet.)*
4. **The union walk is evidence, not faith in `tsc`.** Research found 19 sites, of which **3 are
   silent**: `upsertContact`'s hand-maintained arg validator (`contacts.ts:240`), `ORIGINS` in
   `core/src/contacts.ts:126` (structurally decoupled from `CrmContactOrigin`), and
   `PipelineView.tsx:279-283`. Each silent site needs a test that goes red when its case is
   missing. *(19.1-02 T2 — one test each; 19.1-02 T3 mutation-proves all three.)*
5. **`pipelineTiles`' bound must be proven by a test that fails on the old behaviour** — an
   assertion that merely reads a number would pass on the confidently-wrong integer that
   motivated the fix. *(19.1-05 T1 — seeds `SCAN_LIMIT + 1` rows and asserts `partial === "row-cap"`, a field the old code does not return.)*
