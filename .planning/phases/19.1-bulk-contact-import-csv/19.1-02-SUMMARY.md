# Phase 19.1 Plan 02: The Two Union Widenings Summary

`contacts.origin` gains `imported` and `consentSource` gains `imported-attested` — with all 19
consuming sites accounted for in a single commit: 5 widened, 3 deliberately narrowed-and-pinned by
red-able tests, and the Pipeline consent chip finally rendering the source the schema was preserving
for nobody.

## What Was Built

**`schema.ts` — the source of both unions.** `origin` gains `v.literal("imported")`; `consentSource`
gains `v.literal("imported-attested")`; and `company` / `phone` / `title` arrive as
`v.optional(v.string())` — three and no more. Each carries the comment the next reader needs:
widening a union and adding optional fields are **no-migration** changes, while **narrowing either
later would need one**, because a row at rest carrying the dropped literal would fail validation on
read. The three new columns carry the CLAUDE.md §4 content-plane warning that `consentWording`
already carried. No `npx convex codegen` was needed — a schema-only change derives generically.

**`contacts.ts` — the mirrors, deduplicated.** `ContactOrigin` gains `"imported"`. More importantly,
one `export type ConsentSource` now replaces **two independent inline literal pairs** that
`ConsentRecord` and `PipelineContactRow.consent` were each carrying. Those two were the same union
written twice, in a file where nothing forced them to agree; now the pair exists once and tsc binds
it to the schema at the `listContacts` assignment.

**`PipelineView.tsx` — the site tsc cannot see.** Two changes:

- `ORIGIN_LABELS` gains its `imported` entry **and** the compile-time bind that never existed:
  `as const satisfies Record<ContactRow["origin"], string>`. Before this, widening the schema left
  the map silently short and `ORIGIN_LABELS[row.origin]` resolved to `undefined` inside a JSX index
  expression. The RED run below shows exactly that: `<span style="…"></span>` — a **blank chip**, no
  error, nothing to notice.
- The Consent cell renders `row.consent.source`: `Consented {date} · imported` for a batch
  attestation, unchanged for an asserted one. Owner decision 2026-08-10. `chip` / `quietChip` are
  untouched — teal stays a fill and there is no amber (BRAND §2/§6).

## The Nineteen Sites

| Class | Count | What happened |
| --- | --- | --- |
| Widened (source) | 2 | `schema.ts` `contacts.origin`, `contacts.consentSource` |
| Widened (tsc-forced) | 3 | `ContactOrigin`, `ConsentRecord.source`, `PipelineContactRow.consent.source` — the last two collapsed into one `ConsentSource` |
| Deliberately NOT widened | 3 | `upsertContact` args, `core` `CrmContactOrigin`, `core` `ORIGINS` — each now pinned by a test |
| Silent UI registration | 1 | `ORIGIN_LABELS` + the consent chip |
| Verified unaffected | ~10 | `llm.ts:2584` and `contacts.ts:200` hardcode `"mailbox-resolved"`; `assertConsent` hardcodes `"asserted-by-user"`; ~30 narrow literal fixtures across six test files stay valid under a wider union |

The three NOT-widened sites are the point of the plan. Each is a place where the union is
re-declared in a form structurally decoupled from the schema — a hand-maintained `v.union` arg
validator, a second hand-typed literal union, and a `readonly string[]` that never mentions its own
type. Widening the schema does not touch any of them, and **tsc says nothing either way**. The
reasons they stay narrow are policy, not oversight: the hand-add form must not be able to claim
imported provenance, and human-only import is LOCKED so the agent may not stage one.

## Mutation Evidence

Every one of the three silent-site guards was broken, observed red, and reverted. A guard never
observed failing is not proven — 19-06 and 19-11 both turned on this.

Guards 1 and 2 were already green before the plan touched them — the widening does not reach them,
which is exactly why they needed proving rather than trusting. Guard 3 was genuinely RED first: the
initial test run failed 3/170 with the origin chip rendering **empty**, the predicted silent failure.

The consent test asserts **both** renders and that they DIFFER. Asserting only that the imported
chip contains "imported" would still pass if the suffix were appended to every chip — the same
half-test class that let "don't erase" pass for "fill empty only" on the backend.

## Deviations from Plan

### 1. [Plan-internal] One commit, no per-task TDD commits — the plan's own objective

- **Found during:** Task 2 (`tdd="true"`)
- **Issue:** Task 2 is marked TDD (which the executor protocol commits as RED then GREEN), but the
  plan's objective, task 3 and success criteria all require the entire union walk in **ONE commit**,
  with a stated reason: a partially-registered union is worse than none.
- **Resolution:** Followed the plan, not the protocol default. TDD discipline was kept in full —
  tests written first, RED observed and recorded (3 failures, blank origin chip), then GREEN — but
  no intermediate commits were taken. This is the opposite call from 19.1-01, and deliberately so:
  there the single-commit instruction was incidental, here it *is* the plan. Splitting task 1 from
  task 2 would have produced a commit in which an imported contact renders a blank origin cell.

### 2. [Rule 3 — Blocking] The playbook's HOOK ARTIFACT entry was deleted, not merely superseded

- **Found during:** Task 3
- **Issue:** `contacts-crm.md` opened with a `Last verified` entry the concurrent finance lane filed
  when the §9 Stop hook fired on watched paths it had not authored — naming `contacts.ts`,
  `contacts.test.ts`, `schema.ts`, `PipelineView.tsx`, `pipelineView.test.ts` and
  `core/contacts.test.ts` as uncommitted-and-unreviewed. Those are exactly this plan's six code
  files.
- **Fix:** Deleted it and put the real 19.1-02 attestation in its place, which is what the artifact's
  own text asked for ("supersede and delete this entry"). Leaving it would have left a permanent
  "nothing here is verified" banner above an entry that verifies precisely those files.

### 3. Baseline was 0, not the expected 2

- The plan warned `packages/backend/convex/cash.ts` might carry 2 pre-existing `TS2739` from the
  finance lane. Measured baseline was **0 errors, exit 0** — the finance lane had already landed its
  fix. Delta after the widening is therefore 0 against 0, a stricter check than planned.
