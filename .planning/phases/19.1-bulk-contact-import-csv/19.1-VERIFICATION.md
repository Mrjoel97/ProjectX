### Gap 1 -- CLOSED: the done screen now counts every rejected row

**What changed:** the done screen's markup was extracted into a new exported `ImportDone`
component taking `serverRejected` and `browserRejected` as two separate props, summed inside the
component (`{serverRejected + browserRejected}`), rather than the call site picking one number.
Rationale recorded in the code: the done screen previously lived inside the hooks-holding
`ImportPanel` and was unrenderable by this repo's DOM-free test harness, so the only available
check before this fix would have been a source scan (mechanism coverage, not behaviour coverage) --
extracting the pure sub-component is what makes a render-level test possible at all.

**Independently confirmed, adversarially, in this session:**
- Read the current `ImportPanel.tsx` directly: `ImportDone` sums `serverRejected + browserRejected`
  (line ~349); the call site passes `serverRejected={result.rejected.length}` and
  `browserRejected={mapped.rejected.length}` (lines ~596-600) -- matches the commit's own
  description exactly, nothing more, nothing less.
- Re-ran `pipelineView.test.ts` independently: **30/30 passed** (was 27; +3 new tests for this
  fix), matching the claimed count.
- **Mutation-tested it myself, not trusted from the commit message.** Reverted the sum to
  `{serverRejected}` only (the pre-fix behaviour) and re-ran the suite: the new test
  `"the done screen counts EVERY rejected row, including the ones the browser dropped"` went
  genuinely red (`expected ... to contain '<strong>1</strong> rejected'`, actual rendered `0`).
  Restored the file via the backed-up original and confirmed `git diff` was empty (clean revert)
  before continuing.
- The preview and the done screen now agree for the same file: preview computes `mapped.rejected.length`
  (client-dropped rows) and `matchExisting`-derived counts; the done screen now reports
  `result.rejected.length + mapped.rejected.length` for the identical run -- the same two
  quantities the preview always had, just summed where the user reads them again.

## Label-binding test debt — RESOLVED

> **Reconciled 2026-08-16:** the final `921cc5d` changeset anchored both `ImportPreview` counts and
> `PipelineTiles` values to their labels and added swap-regression assertions. The adversarial
> discovery narrative below is retained as the reason for those tests; its "unfixed" conclusion is
> historical, not current.

The commit's own gap-1 fix caught and documented one vacuous assertion
(`toContain(">1<")`, satisfied by the wrong fixture value) and rewrote it to anchor each number to
its label. Asked to check whether any OTHER assertion in the file shares that weakness, I
adversarially tested the two nearest analogues by mutating the source and re-running the suite:

1. **`ImportPreview`'s "the four preview counts render as themselves, including a real 0"**
   (`pipelineView.test.ts` ~356-363). Asserts `[">3<", ">2<", ">0<", ">1<"]` are each present
   *somewhere* in the document, and separately that the words "new"/"enriched"/"unchanged"/"rejected"
   are each present *somewhere*, but never binds a specific number to its specific label.
   **Confirmed exploitable:** I swapped `counts.enriched` and `counts.rejected` in `ImportPreview`'s
   JSX (`ImportPanel.tsx`) -- i.e. reproduced, in the sibling screen, the *exact class* of bug this
   commit just fixed on the done screen -- and re-ran the suite: **still 30/30 green.** Reverted and
   confirmed `git diff` empty.
2. **`PipelineTiles`' "real counts render as themselves and each tile is separately addressable"**
   (~96-113) and its row-cap sibling (~115-138). Same bare-`>N<`-anywhere-in-the-document pattern.
   **Confirmed exploitable:** I swapped which backend key ("needingAttention" vs "followUpsDue") the
   first two tiles in the `TILES` array read from -- i.e. a tile-mislabelling bug where "Contacts
   needing attention" would show the follow-ups-due count and vice-versa -- and re-ran the suite:
   **still 30/30 green.** Reverted and confirmed `git diff` empty.

Both were genuine, adversarially-confirmed gaps in test *coverage*, not confirmed defects in the
shipped code. They are now closed by label-anchored assertions and explicit swap regressions in
`pipelineView.test.ts`.
