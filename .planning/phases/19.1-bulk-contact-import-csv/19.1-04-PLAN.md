  args: {

      phone: v.optional(v.string()),

Handler, in order:
1. `rows.length > IMPORT_BATCH_ROWS` → `IMPORT_BATCH_TOO_LARGE`. The client batches; the boundary
   enforces. Comment the REAL reason for 100 (retry blast radius, progress granularity, OCC window)
   and note explicitly that every Convex limit would permit the whole 1,000-row file in one call.
2. `attestation.wording.trim() === ""` → `CONSENT_WORDING_REQUIRED` (the `assertConsent` rule: a
   consent record with no wording is a defaulted consent wearing a timestamp).
3. Per row: `normalizeAddress` then `isValidEmail` — **re-validated, not trusted**, the
   `parseCrmOperations` discipline. A failure is a `rejected` entry, never a throw: one bad row must
   not discard the 99 good ones in the same transaction.
4. Otherwise `upsertContactRow(ctx, ctx.tenantId, { ...row, origin: "imported", fillEmptyOnly: true,
   consent: { source: "imported-attested", wording: attestation.wording, context: attestation.context } })`
   and classify from its reply: `created` → created; `filled > 0` → enriched; else unchanged.
5. **Write NO audit row.** Decision, recorded in the doc comment: `assertConsent` writes none either,
   and this module's audit surface is exactly one event (`contact.unsuppressed`) with a key-set
   EQUALITY test over it. CLAUDE.md §4 says what an audit payload may carry, not that every write
   must have one — and the strongest available guarantee that the wording never becomes a payload is
   that the path emits no payload at all. The §4 test in task 3 asserts that as a ROW COUNT, not as
   a substring.

Doc comment on the return type: the counts are defined over the four mappable fields ONLY; a contact
that gained a consent record but no field values counts as `unchanged`, because counting the consent
write would make `unchanged` structurally always 0 and the preview a lie.

Add the isolation test to the BETA-05 block and `"importContacts"` to `COVERED` in sorted position.
