# Phase 03.4 Plan 04: Phase Close — E2E + smoke distinct-body + playbook (CKPT-03) Summary

Closed the automated half of Phase 3.4: the per-recipient personalization feature is now proven
end to end offline (the `cockpit-personalize` E2E) and on the live delivery plane (the `smoke:fanout`
distinct-body assertion — the INVERSE of 3.3's shared-attachment fan-out), and the cockpit playbook
records the three personalization invariants with `Last verified` bumped to 03.4-04. The sole
remaining proof is the CKPT-03 human-verify — a real 2-inbox distinct-wording send — which is
**PENDING** (it needs human OAuth consent + real inboxes; it cannot be automated).

## What was built

- **cockpit-personalize.spec.ts (NEW)**: mirrors `cockpit-attachment.spec.ts` over the offline
  `SMOKE::agent::` grammar. Drives `add=alice@example.com,bob@example.com` -> `subject=Q3 sync` ->
  `body=SMOKE::route=direct_llm:: the shared body…` -> `mode=individual` ->
  `personalize=1:SMOKE::route=direct_llm:: make Alice's note warmer…` -> `propose`, sequencing turns
  on the composer clearing (never asserting agent prose). Asserts the PLAN card's **PER-RECIPIENT
  BODY** section shows alice as **tailored** and bob as **shared body** — two DISTINCT bodies BEFORE
  the single Approve (the two tags co-existing is the plan-row-derived distinctness proof; the
  section renders only when a recipient is tailored). Asserts NOTHING is sent before Approve (no
  REPORT, exactly one Approve), then Approve -> REPORT fills per-recipient (offline settles at
  `awaiting_reauth` — the harness user has a stale token by design). The personalize intent carries
  the `SMOKE::route` sentinel so the tailored draft stays deterministic offline AND differs from the
  shared body (a different `safeText` hashes differently -> a different `Smoke draft for <hash>`).
  Playwright-discovered + type-loads; the live green run is deferred to verify-work.
- **smoke.ts — `seedFanout` optional `recipientBodies` arg**: append-only. When present, each row's
  `draft` is that recipient's DISTINCT tailored body and the SUBJECT (`goal`) is SHARED (the `#i`
  disambiguator is dropped; the `SMOKE::fail` sentinel still prefixes the fail row's goal). Absent ->
  the historic single-shared-body seeding is byte-for-byte unchanged. Length-mismatch guards added.
- **smokeAssert.ts — `assertFanoutBodiesDistinct`**: the mirror-inverse of
  `assertFanoutAttachmentShared`. Reads the `requests` rows for the cids and asserts every `draft` is
  unique (no two recipients share a body) AND every subject is identical (one shared subject, after
  stripping the delivery-only `SMOKE::fail ` prefix). This is the SC2 distinct-body proof.
- **run-smoke-fanout.mjs**: generates N distinct `TAILORED-SECRET-<i>-<uuid8>` body needles, passes
  them as `recipientBodies` to `seedFanout`, calls `assertFanoutBodiesDistinct` after the seed
  (alongside `assertFanoutAttachmentShared`), and adds EVERY distinct body needle to the `needles`
  fed to `assertNoRawPiiFanout` — so each tailored body is proven ABSENT from any audit/deadLetters/
  telemetry row (§4, Pitfall 5). The forced-fail isolation / write-once / reached-all assertions are
  intact.
- **cockpit.md (§9 phase close)**: `Last verified` -> 03.4-04. Added three personalization
  invariants — **Per-recipient wording rides the existing per-recipient spine** (tailored body in
  `plans.recipientBodies`, content-plane only never audited; `executePlan` seeds `recipientBodies
  [recipient] ?? body`, delivery spine UNCHANGED — the INVERSE of the shared-attachment fan-out);
  **Personalization requires individual mode** (`proposePlan` refuses a group plan carrying any
  tailoring; the skill teaches SUGGEST-then-confirm + individual mode); **Guardrail parity is by
  construction** (`personalizeRecipient` reuses `draftBody`'s exact `scanText`->`draftCockpit` path;
  per-recipient `correlationId` already isolates audit/telemetry — no new audit event). Updated
  Key-files (executePlan seed override, `PlanRecipientBodies` card, `personalizeRecipient` tool,
  `patchPlan recipientBodies`), the Tests list, the How-to-verify Playwright + smoke lines, and added
  the CKPT-03 Manual-only human-verify row.

## Deviations from Plan

None — plan executed exactly as written. Two implementation choices the plan left to build time:
(1) the shared-subject compare strips the delivery-only `SMOKE::fail ` sentinel (it is gmail.send

render `Smoke draft for <hash>`, so exact-text distinctness is brittle). Both preserve the plan's
intent (distinct bodies, shared subject, shown pre-Approve).
