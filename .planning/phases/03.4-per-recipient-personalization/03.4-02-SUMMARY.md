# Phase 03.4 Plan 02: personalizeRecipient Tool + Group Gate Summary

Added the governed `personalizeRecipient({ index, instructions })` tool — the whole feature's engine for CKPT-03. It tailors ONE recipient's wording by 1-based `#index` (address resolved server-side, §2-D), mirroring `draftBody` VERBATIM (`scanText` fail-closed → `draftCockpit` → patch) so PII redaction + cost `preCall`/`recordSpend` parity is FREE by construction (SC2), but writes the tailored body into `recipientBodies[address]` (a merge-spread) instead of the shared `body`. Plus a `proposePlan` group-mode refusal gate, `buildAgentContext` personalization surfacing, a SMOKE offline driver, and the `cockpit-agent` skill's Personalization section.

## What was built

- **llm.ts — `personalizeRecipient` tool** (in `buildCockpitTools`, next to `draftBody`): resolves `recipients[index-1]` server-side (out-of-range → refuse with NO write), scans `instructions` fail-closed, calls `draftCockpit` (OMITTING `greetingName` — Pitfall 4), and patches `recipientBodies` with the merged map `{...existing, [address]: draft.body}` via `patchPlan`. The shared `body` is untouched; the return is a `#index` LABEL only (never the address/body, §2-D/§4).
- **llm.ts — `buildAgentContext` surfacing**: widened the param with `recipientBodies?`; each recipient line now ends `— personalized` (when `recipientBodies[addr]` exists) or `— shared body`. The address is used ONLY to look up the flag — never emitted. Both call sites already pass the whole `plan` row, so no call-site edit was needed.
- **llm.ts — `proposePlan` group gate**: after the attachment gates and before `proposeEmailPlan`, refuses when `Object.keys(recipientBodies).length > 0 && mode === "group"`, telling the agent to switch to individual. Facts read from the ROW.
- **llm.ts — SMOKE op**: `AgentSmokeOp` gains `{ kind: "personalize"; index; instructions }`; `parseAgentSmoke` splits `personalize=<i>:<intent>` on the FIRST colon (mirrors `regenerate`); `runAgentSmokeOp` routes it to the tool. Grammar comment updated.
- **cockpitTools.test.ts** (+7): patches `recipientBodies` not `body`; out-of-range index bounces without a write; merge preserves prior overrides; `buildAgentContext` address-free surfacing (direct import); group-refusal / individual-proceeds / group-no-personalization-unaffected.
- **llmRedaction.test.ts** (+2 static scans): `personalizeRecipient` scans BEFORE `draftCockpit` (redact-then-draft); `recipientBodies` never appears in any audit/deadLetters/telemetry payload or insert across llm.ts/cockpit.ts/plans.ts (Pitfall 5, §4).
- **cockpit-agent.md + cockpitAgent.ts** (5-file mirror): added "## Personalization" (SUGGEST-then-confirm, reason by `#index`, individual-mode requirement); regenerated the derived `cockpitAgentSkillBody` byte-identically (JSON.stringify of the LF-normalized `.md`). `seedSkills` publish-on-change ships v-next automatically; the drift `test.each` row stays green (name const + seed row untouched).
- **cockpit.md + skill-registry.md** (§9): `Last verified` → 03.4-02; cockpit.md notes the `personalizeRecipient` tool + group gate in the tool-boundary invariant and plans.ts key-files line; skill-registry.md notes the Personalization skill section.

- **Per-recipient greeting** (Pitfall 4): the tailored draft omits `greetingName`, so a personalized body has no auto "Hi <name>," — the instruction must carry any greeting. A per-recipient greeting map is the documented upgrade path if Wave 4's human-verify demands it.

Wave 3's `executePlan` seed must use the same raw `recipient` value (`recipientBodies[recipient] ?? body`, RESEARCH Pattern 2) to stay aligned; if mixed-case addresses ever need normalizing, normalize at BOTH the personalize write and the seed read together.
