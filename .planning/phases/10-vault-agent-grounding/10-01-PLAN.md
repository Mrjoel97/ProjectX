<objective>
Give the retrieval engine a hydrated path that returns real chunk TEXT + doc TITLES (parallel to
docIds), so Plan 02's `searchVault` tool has actual content to fence into the agent loop and titles
to surface on the source card. Today `vaultGround` returns `{ docIds, context }` where `context` is
an identity placeholder (`context: [...docIds]`, marked ponytail in `packages/vault/src/fusion.ts`).

Approach (locked by research — do NOT redesign retrieval): expose an `internalAction`
`vaultGroundHydrated` that Plan 02's identity-less `runCockpitAgent` can call as
`internal.vaultGround.vaultGroundHydrated`. It takes `tenantId` as an EXPLICIT arg (the codebase
convention — mirror `internal.gmail.search` / `internal.llm.digestInbox`, which never read auth),
because the cockpit tool loop and the test/eval harnesses carry no live identity. To reuse retrieval
with zero duplicated logic AND keep `vaultGround`'s public signature + existing tests byte-for-byte
unchanged, extract `vaultGround`'s handler body into a plain shared helper `runVaultGround(ctx,
tenantId, query)`; the existing public `vaultGround` tenantAction calls it with `ctx.tenantId`, and
the new `vaultGroundHydrated` internalAction calls it with its explicit `tenantId` arg, then hydrates
titles via `ownedDocsMeta` and text via `getDoc`. Ride the existing `SMOKE::` seam for deterministic
offline tests.

Purpose: unblock the S1 grounding chain — the vault becomes readable mid-conversation with content,
not just ids, AND callable from the identity-less tool loop.
Output: `vaultGroundHydrated` internalAction returning `{ docIds, titles, chunks }`, a shared
`runVaultGround` helper, extended engine tests, and an updated vault playbook.
</objective>
