  <name>Pure briefing module (bucketing + selection + digest join)</name>
  <files>packages/core/src/briefing.ts, packages/core/src/briefing.test.ts</files>
  <behavior>
    Types (exported):
    - `InboxMessageMeta = { id: string; from: string; subject: string; snippet: string; internalDate: number; isUnread?: boolean }`
    - `DigestItem = { index: number; gist: string; category: string; needsReply: boolean; deadline?: string }` (what the toolless digest call returns — index-keyed, NO sender/ts fields: the model never owns identity or time)
    - `BriefingItem = { bucket: "today" | "yesterday" | "thisWeek"; sender: string; ts: number; gist: string; category: string; needsReply: boolean; deadline?: string; isUnread?: boolean }`
    - Constants: `BRIEFING_BODY_CAP = 25`, `BODY_TRUNCATE_CHARS = 2000`.

    Functions:
    - `dayKey(ms, tz)`: `Intl.DateTimeFormat("en-CA", { timeZone: tz, year: "numeric", month: "2-digit", day: "2-digit" }).format(ms)` → "YYYY-MM-DD".
    - `bucket(msgTsMs, nowMs, tz)`: returns "today" when dayKey(msg)===dayKey(now); "yesterday" when it equals yesterday's key; "thisWeek" when msgTsMs >= nowMs - 7*86400000 (and not today/yesterday); otherwise null (drop — outside window). Future-dated msg (clock skew) → "today". DST-PROOF yesterday derivation: parse today's dayKey into Y/M/D ints, `new Date(Date.UTC(y, m-1, d) - 86400000)` and read Y-M-D back in UTC (UTC has no DST; handles month/year rollover for free) — NOT dayKey(now - 86400000).
    - `selectForDigest(messages, cap = BRIEFING_BODY_CAP)`: sort by internalDate desc, slice cap. Pure, does not mutate input.
    - `joinDigest(selected: InboxMessageMeta[], items: DigestItem[], nowMs, tz)`: map each DigestItem by index onto selected[index] → BriefingItem with bucket/sender/ts from the MESSAGE (code-owned), gist/category/needsReply/deadline from the digest. Out-of-range or duplicate index → dropped (the model cannot invent a message). Messages bucketing to null are dropped.

    Test cases (write FIRST — RED commit, then GREEN):
    - Fixed clock nowMs, tz "Asia/Tokyo" (east) and "America/Los_Angeles" (west): a message 1h ago = today; a message just before local midnight = yesterday even when it is "today" in UTC (and vice versa west).
    - Yesterday across a month boundary (e.g. now = 1st of month local) — rollover correct.
    - 6-days-ago = thisWeek; 8-days-ago = dropped; future ts = today.
    - selectForDigest: 30 messages → 25 newest, order newest-first.
    - joinDigest: out-of-range index dropped; sender/ts always from message meta even if the digest item is weird.
  </behavior>
