# Golden deployment preflight — one-run safety note

This note records the narrow correction made after the 2026-09-19 configuration attempt was
consumed by malformed environment bytes. It grants no provider, deployment, spend, or retry
authority and records no successful live evidence.

The deployment now exposes `guardrails:goldenProviderReadiness`, a read-only query that returns
only closed readiness enums and one aggregate boolean. It never returns or logs a credential,
length, prefix, suffix, or hash. Both provider keys must be nonblank and contain no whitespace or
control characters. The recorded billing posture must be exactly:

- `GOLDEN_OPENROUTER_BILLING=standard`
- `GOLDEN_TAVILY_BILLING=free`
- `GOLDEN_TAVILY_CREDIT_USD=0`

For a self-hosted local evidence instance, the installed Convex CLI refuses a
simultaneous `CONVEX_DEPLOYMENT` and `CONVEX_SELF_HOSTED_URL`/admin key. Use a
process-scoped `PIKAR_GOLDEN_LOCAL_INSTANCE=<exact /instance_name>` declaration
with the self-hosted URL/admin key and **no** `CONVEX_DEPLOYMENT`. The guard
requires a loopback URL and consistent explicit `CONVEX_URL`; the operator must
separately match `/instance_name` and current functions before preflight. This
route is only a named local diagnostic/qualification target, not a hosted or
production substitute. The 2026-09-28 disposable check reached the readiness
function and initially refused missing keys without a budget or provider call.
After the existing workspace credentials and the three billing attestations were
set on that exact disposable instance, the closed readiness query returned
`ready: true` and the standalone `--preflight` passed its 57-fixture offline
self-check and provider-readiness gate. No budget was opened or provider called.
The isolated runner then exited 0 and removed its owned temporary root.

On PowerShell, piping a secret to `convex env set NAME` appended a line ending;
the readiness query correctly reported `invalid_format`. For this local check,
the operator passed the existing `.env` value through redirected process stdin
with `.Write(value)` (no newline), without placing it in command arguments,
output, a temporary file, or the application's deployment. This establishes
byte-clean local configuration only; it does not establish external key validity,
provider billing status, a golden corpus result, or Wave 1 qualification.

After synchronizing the current functions to the named non-production deployment, run the free
standalone check:

```powershell
pnpm --filter @pikar/backend eval:golden -- --preflight
```

`--preflight` cannot be combined with run flags. It performs the offline self-check and exactly one
read-only Convex readiness query, then exits before corpus loading, budget creation, fixture seeds,
provider calls, evidence writes, or cleanup. A refusal prints only safe reason codes such as
`openrouter_key_invalid_format`; it never echoes the rejected value.

Only after that command passes, and only under a still-valid explicit one-run authorization, is the
full shared gate command eligible to be invoked:

```powershell
pnpm --filter @pikar/backend eval:golden -- --skill cockpit-agent@26 --skill inbox-digest@2 --no-retry
```

The full runner repeats the same readiness query before it loads the corpus or opens
`guardrails:openEvalBudget`. Preflight success is readiness only: it is not a corpus attempt, live
observation, evidence row, gate pass, or permission to retry. Evaluator revision
`2026-09-11.budgeted-evaluator.b860a1fb68954482be8ecf9520d02766eeee347fec8b876e0db0dfb8974b0cca`
retires evidence written by the previous evaluator implementation.
