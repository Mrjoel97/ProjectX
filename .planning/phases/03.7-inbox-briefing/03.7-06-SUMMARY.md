**Action-first ordering, newsletter noise-collapse, and code-owned-counts lede composition moved into pure, tested `@pikar/core` `briefing.ts` — the Gap 1 "intelligent report, not a receipt" transform, as the typed contract for the backend synthesis (07) and reshaped card (08).**

## Accomplishments
- `composeLede(items, listedCount, synopsis?)` — lede leads with CODE-OWNED counts (`{total} messages, {needsYou} need you`) welded to the model's qualitative synopsis clause; a fabricated number in the synopsis (a "99") can never become the count the lede states (Gap 1.1, ADR-004); empty/blank/absent synopsis degrades to a counts-only lede with no dangling separator (never throws on a pre-delta row).
- `collapseNoise(items)` — `newsletter` rows collapse into ONE `collapsedCount` so 12 automated notifications never render as 12 rows (Gap 1.3); conservative on both edges (`other` stays surfaced; a needs-you row is never collapsed even if mis-categorized `newsletter`).
- `buildBriefingView(briefing)` — needs-you (needsReply||deadline) is a SEPARATE top block, never interleaved chronologically (Gap 1.2); the de-noised remainder groups into `timeSections` in fixed [today, yesterday, thisWeek] order, empty buckets skipped — proving time grouping survives as the SECONDARY axis (locked constraint).
- `DigestBatch { items, synopsis }` type exported for plan 07's `digestInbox` return.

## Decisions Made
- Counts are read from `listedCount` + `items.filter(needsReply||deadline)`, structurally never from the synopsis — the ADR-004 code-owns-facts / model-owns-prose boundary applied to the lede.
- `collapseNoise` collapses only `category === "newsletter" && !needsReply && !deadline`; `other` is deliberately NOT hidden (conservative — the toolless digest already declines to classify uncertain mail as newsletter).
- `index.ts` barrel left unchanged — it already does `export * from "./briefing"`, so the new symbols re-export automatically (ponytail: the laziest re-export that works).
