# Phase 20.2 — The Scene Timeline

Replace the uniform fixed-block reel with a variable-duration scene timeline that hits an
**exact** target length of 15, 30 or 60 seconds, mixes four visual sources, and places narration
on one master audio track instead of centring it inside per-block windows.

---

## 0. Why this phase exists — the reel is currently unreachable

The render chain is whole. `packages/core` render/storyboard/assembly/captions tests are
**159/159 green**, `apps/web/app/api/media/render/route.ts` is intact, and
`mediaComplete.maybeStartRender` → `renderReel` → sandbox → `assemble_final.sh` is wired end to
end. Nothing was deleted.

What is broken is a **contract collision between the specialist and the money gate**:

| Where | What it says |
|---|---|
| `packages/contracts/skills/media-director.md:82` | The worked example the specialist copies emits a `SCREEN REC` block. |
| `packages/contracts/skills/media-director.md:87-89` | Teaches the closed set `AI`, `SCREEN REC`, `TEXT`, `VIDEO` as all legal. |
| `packages/core/src/storyboard.ts:109-121` | `PAID["SCREEN REC"] = false`, `PAID.TEXT = false`. |
| `packages/backend/convex/media.ts:228` | `if (!isPaidBlock(block)) return { ok: false, reason: "unrenderable_block" }` — refuses the **whole deck**. |

An unpaid block gets no video line, so nothing ever writes its `blockNN.mp4`, and
`assemble_final.sh` discovers inputs **by index** and hard-errors on the first missing clip. The
refusal is correct and deliberate. The defect is that the specialist is taught to write decks
that trip it.

Because the proposal stage is free, this fails silently: the user gets a plan card that looks
fine and only discovers the reel cannot be made when they click Generate.

`media.ts:224-227` already names the repair in a `ponytail:` comment — *a `drawtext` branch for a
clipless index; the font is already baked into the sandbox snapshot from 20-17*. **Step 1 of the
requested order and step 4 are therefore the same work**, and this plan treats them as one.

### The second, quieter blocker

`Clip seconds: 4` (`media-director.md:90`) with `SPEECH_SLACK_S = 1.4` forces every narration line
into **31–56 characters** and every voice take into **2.6–4.0 s of measured speech**. That is a
near-impossible band for natural narration, it is enforced twice (parse time and again by
`assemble_final.sh`), and there is no notion of total reel length at all — the reel is however
long `blocks × 4` happens to be. Steps 2, 3 and 6 remove this band rather than tune it.

## 2. The new contract

### 2.1 Target duration (step 2)

```ts
export const TARGET_DURATIONS = [15, 30, 60] as const;
export type TargetDuration = (typeof TARGET_DURATIONS)[number];
```

Declared once in the deck header (`Target duration: 30`), stored on the plan row, carried into the
assembler as `--target-seconds`, and **asserted on the output** in place of today's
`N × CLIP` arithmetic. A deck whose scene durations do not sum to it is a parse failure
(`duration_mismatch`), refused before a cent moves — same placement rule as today's narration band.

### 2.2 The Scene (step 3)

`Block` becomes `Scene`, and the uniform-length assumption goes with it:

```ts
export type VisualKind =
  | "generated_video"   // paid — Sora, on the provider's duration grid
  | "animated_image"    // paid — one still + ffmpeg pan/zoom, any duration
  | "uploaded_video"    // free — tenant asset from the vault, trimmed
  | "text_card";        // free — drawtext, any duration

export type Scene = {
  index: number;
  startMs: number;      // running sum of prior durationMs — NOT index * clipSeconds
  durationMs: number;
  visual: VisualKind;
  asset?: { source: "vault"; docId: string };  // uploaded_video only
  description: string;
  narration: string;    // may be "" — see 2.4
  overlay?: string;
  prompt: string;
};
```

Three refusals from `storyboard.ts` change:

- `mixed_durations` — **deleted**. Disagreeing durations are now the point.
- `narration_too_long` / `narration_too_short` — **re-scoped**. The band is no longer per scene
  (see 2.4); it becomes one whole-reel check against `targetDurationSeconds`.
- `unknown_shot_type` — retained, over `VisualKind` instead of `ShotType`.

**Migration of the old closed set:** `AI` → `generated_video`, `VIDEO` → `generated_video`,
`TEXT` → `text_card`, `SCREEN REC` → `uploaded_video`. Accepted by the parser for one version so
already-proposed decks still read, and not taught by the new skill body.

### 2.3 The provider grid is a real constraint — name it, don't hide it

Sora returns 4, 8 or 12 second clips. **A `generated_video` scene's `durationMs` must land on that
grid.** Variable duration is delivered by the other three kinds, which are frame-exact at any
length. This is not a limitation to paper over — it is the reason the cheap kinds exist:

| Kind | Cost per 4 s | Duration freedom |
|---|---|---|
| `generated_video` | ~$0.40 | 4 / 8 / 12 s only |
| `animated_image` | ~$0.04 | any |
| `uploaded_video` | $0 | any |
| `text_card` | $0 | any |

A 30-second reel built as 3 generated clips + 4 animated stills + 1 card costs roughly **$1.36**
against **$3.00** for eight generated clips. The pan/zoom path is a 10× cost lever, not a
fallback.

### 2.4 Narration moves to a master timeline (step 6)

Today each take is level-matched, `adelay`-padded and mixed **inside its own block**, then the
blocks are concatenated. That is why speech must fit `[clip - 1.4, clip]` seconds — the window is
the mixing unit.

New shape:

1. Level-match each take individually (**keep** the existing per-input
   `loudnorm=I=-19:TP=-1.5:LRA=11` — it is what removes the "narrator quiet, character loud"
   spread, and it is cheap).
2. Concatenate the **video** scenes into one silent-or-diegetic track first.
3. Place each take on one master timeline at its scene's absolute `startMs` via `adelay`, `amix`
   all of them plus the diegetic bed **once**.
4. One two-pass **linear** loudnorm at −16 LUFS over the result (unchanged — linear is what
   preserves the voice/SFX ratio).

What this unlocks: a line may run past its scene boundary, so narration is written for the *reel*
and not for a 56-character cell. What it costs: the per-window guarantees below have to be
re-expressed rather than dropped.

### 2.5 The guarantees that must survive

`assemble_final.sh` encodes seven guarantees, each recording a failure that actually happened.
None may be quietly lost:

| Guarantee | Under the scene timeline |
|---|---|
| Fixed length, never shortened to fit audio | Assert against `--target-seconds`, tolerance tightened **1.0 s → 0.5 s** (we now control every duration) |
| No time-stretch, ever (no `atempo`) | **Unchanged.** An overrunning line is still a hard error → rewrite upstream |
| Clip shorter than its window is a hard error | Per **scene**, against that scene's own `durationMs` |
| Speech-centred via `silencedetect` | Only for scenes that own a take; a take spanning scenes anchors at its **first** scene's start |
| Narration in every window | Re-expressed: assert narration over the **narrated span**, not every scene. A deliberately silent card must not fail the reel — but a scene that *declares* narration and carries none still must |
| Level law (voice 1.0, SFX ≤ 0.20, linear −16 LUFS) | **Unchanged** |
| `assembly.json` sidecar written last | **Unchanged** shape-wise, generalised fields (§2.6) |

> The fifth row is the one to get wrong. Today's assert scans the centre 60 % of every window.
> With optional-narration scenes that check becomes vacuous if simply relaxed — it must key off
> the **declared** narration, or it stops catching the "silent second half" failure it exists for.

### 2.6 Sidecar and captions (step 8)

`packages/core/src/assembly.ts` — `parseAssemblySidecar` is the publish gate; a reel whose sidecar
fails it is never published, and `renderReel.ts:419` re-validates from the bytes that landed in our
own storage. Field changes:

```
block_count      -> scene_count
clip_seconds     -> (removed; per-scene duration_s)
                 +  target_duration_s
blocks[]         -> scenes[] { index, start_s, duration_s, visual,
                               lead_silence_s, speech_abs_s, speech_dur_s,
                               overrun, internal_pauses, freeze_head, freeze_tail }
```

The validator must **reject the old shape outright**, not tolerate both. A sidecar is proof of a
governed render; a validator that accepts two shapes proves neither.

`packages/core/src/captions.ts` already rebases per block:
`absolute_t = speech_abs_s + (word_t - lead_silence_s)`. The arithmetic is unchanged — it reads
`speech_abs_s` off the sidecar and never recomputes `i × CLIP`. Generalising it is mostly renaming,
**plus** one real change: a take spanning two scenes produces caption lines that cross a scene
boundary, so `buildCaptionLines`' per-block grouping must group by **take**, not by scene.

## 6. Risks, ranked

1. **The narration assert going vacuous.** Optional-narration scenes make the "narration in every
   window" gate trivially passable if relaxed rather than re-expressed. This repo has a named
   defect class for exactly this (`green-tests-over-broken-capability`, five vacuous-test findings
   in one phase). *Mitigation: the Wave 4 test must be observed RED with the assert removed, and
   the check keys off declared narration, not scene count.*
2. **`zoompan` jitter.** Naive `zoompan` on a still is visibly steppy. *Mitigation: upscale ×4,
   zoompan at an explicit `fps=`, scale back down; commit one rendered fixture frame-hash so a
   regression is detectable offline.*
3. **Two copies of the assembler drifting.** `assemble_final.sh` and `assembleScript.ts` must stay
   byte-identical. *Mitigation: regenerate the mirror from the shell file in the same commit,
   never hand-edit; the drift test already exists.*
4. **The skill body and the parser drifting.** The parser reads prose the specialist writes. *The
   existing round-trip test (20-03 feeds the body's own worked example back through the parser)
   must be updated in Wave 8, not skipped.*
5. **Sidecar shape change orphaning published reels.** Any plan row with a v1 sidecar becomes
   uncaptionable if the validator hard-rejects the old shape. *Mitigation: check the count of
   `plans` with `sidecarStorageId` set before Wave 5; if non-zero, decide explicitly — re-render
   or accept the loss. Do not silently support both shapes.*
6. **This branch is 232 commits behind `origin/main`** and carries extensive uncommitted work.
   `origin/main` (`d7ca017`) holds the media permissions/routing fixes from PRs #9/#10.
   *Mitigation: reconcile with `origin/main` before Wave 1, or this phase lands on a stale base and
   repeats the 2026-08-14 production rollback.*
