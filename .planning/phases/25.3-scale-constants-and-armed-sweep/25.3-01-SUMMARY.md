# 25.3-01 — Scale constants and bounded maintenance jobs

**The four diffs (all `packages/backend/convex`):**
1. `guardrails.ts` + `lib/env.ts`: the three deployment-wide ceilings read `process.env.DEPLOYMENT_{,MEDIA_,INGEST_}BUDGET_CENTS` at module load through `envCents(raw, fallback)`; a positive integer replaces the compiled $50 / $100 / $250 per day, anything else keeps the fallback (never zero). Three `feature`-tier manifest rows. The rate-limiter windows, the Finance rails view and the ingest refusal all read the same value. Sharding the three deployment counters is deferred with the ceiling named (`ponytail:` comment): ~10k users honest unsharded; a sharded fixed window is approximate.
2. `proactiveReview.ts`: `runWeekly` (cron target, name unchanged) kicks `enumerateWeeklyReview`, a `@convex-dev/migrations` batch walk over `users` (one row per tenant). Per user: one indexed `by_tenant_kind` `.first()`, one `deploymentSpendCents` check (a spent day schedules nothing instead of 10k refusals and 10k "failed" cards), then `reviewOne` at a random point in the next 30 minutes. The bare catch now logs the error's class with the tenantId. The old code collected every `business_profile` document with its text in one mutation and `runAfter(0)`'d every tenant.
3. `gmailAuth.ts`: `flagExpiringTokens` (cron target, name unchanged) kicks `scanExpiringTokens`, a batch walk over `gmailTokens`; an expiring grant raises ONE unread `gmail_reconnect` notice (dedupe via `by_tenant_read`, bounded take); a read one re-arms it.
4. `worm.ts`: `exportAudit` loops pages (10k, `pageSize` arg for tests) until a short page or an 8-minute budget; each page is its own Object-Lock object and cursor advance. A backlog drains in one run.
4b. `vaultIngest.ts` / `audit.ts`: `retryStuckIngests` and `backfillAuditCounts` keep their names and become batch jobs (`retryStuckIngestsBatch`, 20 rows; `reinsertAuditCounts`, 200 rows). `retryStuckIngests`'s unused `olderThanMs` argument is gone.
