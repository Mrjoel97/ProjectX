# Phase 37.1 Research — Closure Programme Integration and Wave 0 Baseline

**Researched:** 2026-09-19
**Method:** four parallel read-only audits plus a GSD cross-phase integration check; Graphify was used
before targeted source reads; no paid or live-provider action was performed.

## Planning question

What must be true before the owner-adopted Waves 1-8 can execute quickly in parallel without losing
the repository's existing GSD, Ponytail, Graphify, verification, and release disciplines?

## Findings

### 1. Authority is split

- The merged audit makes Wave 0 authoritative.
- ROADMAP and STATE previously pointed to Phase 23; STATE has now been moved to Phase 37.1, but the
  untracked `.planning/GSD-ROUTING.json` still points to `23 -> 30 -> 25`.
- Native GSD helpers infer Phase 01 or Phase 28 because they count files rather than semantic evidence.
- Phase 37.1 must leave one route and make any derivative route mechanically agree with it.

### 2. File counts do not equal completion

- Twenty-seven PLAN files have no canonical SUMMARY.
- Auxiliary FIX/TAIL summaries inflate aggregate counts; Phase 29 is the clearest example.
- Several matching summaries say `partial`, `in-progress`, `awaiting_live_seed`, or equivalent, yet
  native progress treats them as complete.
- Open phases frequently lack VERIFICATION; several nominally complete phases still say
  `human_needed` or contain live consequences routed nowhere.
- A closure ledger must name the evidence layer, successor wave, objective closure test, and owner.

### 3. Core implementation is broad; closure debt is concentrated

- Onboarding/profile, Gmail/inbox, CRM, the defined Phase 31 artifact funnel, and manual routines are
  substantially complete and need exact-release regression rather than rebuilding.
- Blueprint acceptance, Outlook, calendar, Drive/vault, documents, media, content batches,
  agent-authored skills, revenue connectors, provider activation, recurrence, and beta qualification
  remain partial, parked, live-unobserved, or external-gated.
- Phase 47 has research/ADR material but no product recurrence runtime.

### 4. Websites, landing pages, and online shops are genuinely missing product domains

- `documentGen.ts` renders one escaped self-contained HTML file; it is not a site model, editor,
  preview, publisher, host, version history, or rollback system.
- Phase 31 funnels are tracked bearer redirects to stored artifacts. They are not hosted landing pages
  and have no anonymous form/abuse/conversion lifecycle.
- Pikar billing charges tenants for Pikar subscriptions. Tenant Stripe/PayPal connectors are
  read-only. Neither is tenant merchant commerce.
- No site/page/product/inventory/cart/order schema exists.
- The merged audit admits these capabilities, but REQUIREMENTS and ROADMAP do not yet assign stable
  IDs or owning implementation phases.

### 5. Evidence is strong but the current baseline is not release-green

- Local re-drive: 22 free gates, 11 operator regressions, planning tests/check, lint over 1,040 files,
  12 workspace typechecks, and 4,431 backend tests are green.
- Focused HTML/funnel/contact/billing/provider tests add 345 green tests for reusable primitives and
  intentional negative boundaries.
- Remote `main` CI failed after all 4,431 backend tests passed because Vitest reported an unhandled
  worker `ReferenceError: process is not defined`; deployment correctly skipped.
- Local HEAD is ahead of remote and unqualified by GitHub CI. The latest verified production release
  remains `07350fc` with its recorded CI/deploy receipts.
- `pnpm gate` is not the canonical release gate; it omits lint, free gates, operator checks, planning,
  playbook freshness, browser/live evidence, and release receipts.
- SkillOpt is not operational in CI because required runtime configuration is absent.

### 6. Existing disciplines should be tightened, not replaced

- Graphify is query-first navigation and must be refreshed once after concurrent source edits settle;
  its nonblocking hook and dirty output mean it is not release evidence.
- Ponytail is a documented design/review discipline in this environment, not a standalone executable
  gate. Plans must name the smallest implementation, known ceiling, and upgrade trigger.
- The planning checker already catches structural drift, as demonstrated when the new Phase 37.1
  heading lacked a progress row. It should gain narrowly scoped semantic checks rather than a new
  planning service.

## Recommended plan decomposition

1. **Authority and milestone audit:** freeze exact local/remote/production identities; reconcile
   ROADMAP, STATE, routing, Phase 32, and the formal v2.0 gap audit.
2. **Requirement and phase ownership:** mint stable SITE/LAND/SHOP requirement families and map all
   open requirements/semantic partials to Waves 1-8 and concrete GSD owners.
3. **Plan-level closure ledger:** add evidence-layer, entry/exit, stop-condition, and objective-test
   fields for every admitted workflow; no silent deferral.
4. **Planning-checker hardening:** canonical summary counting, semantic partial detection, verification
   state, and authority agreement, with focused tests and Ponytail ceilings.
5. **Wave 1 handoff:** create current-code delta plans with non-overlapping ownership and validation,
   then allow parallel execution.

## Validation Architecture

Phase 37.1 is validated as a planning-control change:

- Fast feedback after each task: `node --test scripts/check-planning.test.mjs`, then
  `'{}' | node scripts/check-planning.mjs --exit-code`, followed by `git diff --check`.
- Any checker code change also runs `node scripts/check-free-gates.mjs --self-test` and the focused
  tests added for the new semantic rules.
- At phase close, run the repository's current offline integration gate: typecheck, lint, free gates,
  tests, operator regressions, planning checks, playbook freshness, build, and diff check.
- Graphify update plus Convex edge fixup happens once after concurrent edits settle, not per task.
- Manual review confirms every open requirement and newly admitted capability has exactly one owner,
  wave, evidence classification, objective closure test, and no contradiction among the merged audit,
  ROADMAP, STATE, REQUIREMENTS, routing, and phase plans.
- This phase cannot certify production or providers. Remote CI/deploy/browser/live evidence remains a
  later release gate and is explicitly recorded as open.

## Planning risks

- Concurrent edits to ROADMAP/STATE/REQUIREMENTS can overwrite user work; assign one integration owner
  and keep parallel workers on disjoint phase/checker files.
- Automatically rewriting historical summaries would destroy evidence. Add derived checks and delta
  plans instead.
- A generic “website generator” plan would collapse distinct runtimes. Keep site, landing conversion,
  recipe/eval, and merchant commerce boundaries explicit.
- Treating provider/legal blockers as reasons to omit technical work would recreate parked workflows;
  technical plans must end with exact Wave 7 re-entry tests.
