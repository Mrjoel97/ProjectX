# Step 0 — restore revision-tied evidence integrity

This record exists because the 2026-09-26 checkpoints in `37.1-WAVE-MAP.md`, `ROADMAP.md` and
`STATE.md` described a qualified Phase 49 aggregate that could not be reproduced. It is a
repository/local repair. **It certifies no external, provider, founder or production fact, and it
does not advance any wave exit gate.**

## What was actually wrong

Two gates were red in the very tree those checkpoints described as green:

| Command | Recorded state | Observed 2026-09-27 |

Root cause: `HEAD` (`dd6ffca`) was **103 commits ahead of `origin/main`** and never pushed, so CI

56 Phase 49 `ARTIFACT_INPUTS` entries were dirty, 42 of them never committed at all.** Evidence
that cannot be tied to an exact revision is a named programme stop condition
(`37.1-WAVE-MAP.md:20-21`).

## Repair 1 — the recipe implementation pin never matched its source

`run-web-recipe-evals.mjs --self-check` failed with
`evaluator implementation changed; retire evidence and review revision`.

Reading the assertion correctly matters, and it is the opposite of what it first appears:
`actual` is the pin **declared** in `packages/contracts/src/skill.ts` and `expected` is the digest
**computed** from the ten bound implementation files. `49-VERIFICATION.md:20` records that the
2026-09-26 checkpoint moved the pin from `1243d1d4…` to `c55234e909e0…` and that the self-check
then passed. It did not, and could not have: every one of the ten implementation files has an mtime
at or before `2026-09-24 05:59`, while the pin was written into `skill.ts` at `2026-09-26 19:08`.
The recorded value was never the digest of the source it was filed against.

Evidence was regenerated before the constant was touched, using the sanctioned read path:

- `node packages/backend/scripts/run-web-recipe-evals.mjs --print-implementation-hash`
- the exact three-family corpus `convex/webRecipeEvals.test.ts` passed **10/10** independently,
  including mutation controls and a runtime recomputation of the core fixture digest
- `verify-design-knowledge-provenance.mjs` reported three immutable MIT sources
- the digest is a fixed point: `normalizedSource()` replaces the pin field with `<self-hash>`, so
  the pin's own value cannot change the digest it is compared against

## Repair 2 — the aggregate's test-count matcher could not read a colourised summary

With Repair 1 landed the aggregate still failed three planes that had exited `0` with every test
passing (core 33/33, backend 345/345, web 13/13). `exactTestCount()` matched
``Test Files\s+N passed \(N\)`` against raw stdout, but vitest writes its summary into a pipe
wrapped in ANSI escapes:

```
ESC[2m Test Files ESC[22m ESC[1mESC[32m6 passed ESC[39mESC[22mESC[90m (6)ESC[39m
```

So a fully green plane was reported `FAIL exit=0`. This is the exact hazard
`.github/workflows/ci.yml:68-70` warns about — a gate that sits red for a non-reason stops being
read, taking the real failures with it.

`exactTestCount()` now strips the escapes before matching and **keeps the exact count
requirement**. Four self-test controls were added so the stripper is proven rather than assumed:
the plain form must match, the real colourised form must now match, a wrong count must not match,
and a colourised partial/skipped summary must not satisfy the count. The escape is built from a
character code rather than written into the pattern, because
`lint/suspicious/noControlCharactersInRegex` rejects a literal control escape.

## Repair 3 — lint was red, so CI could never have been green

`pnpm gate:lint` (exactly what `ci.yml:62` runs) failed with **102 errors** across 70 files:
almost entirely `format` and `organizeImports`, plus two genuine findings.

- `ApprovalsView.tsx` used an array index in a React key. `betaJourney.history` is a redacted
  projection with no `_id`, so identity is now composed from the row's own governed references
  (`auditId ?? approvalId ?? planId ?? requestId`). Two rows tying on every field now surface as a
  duplicate-key warning instead of being masked by position.
- The `noControlCharactersInRegex` finding was in Repair 2's own new code and was fixed there.

`pnpm format` (`biome check --write .`) then settled 73 files. This is mechanical, but it moved
bytes, which invalidated four identity systems in sequence. Each was regenerated through its own
declared writer and re-verified, and the cascade is recorded here rather than left implicit:

| Identity | Regenerated via | Verified by |
| --- | --- | --- |
| native vertical corpus pin | `vertical-eval-corpus.mjs --write` | `--check` → 6 lanes, 40 cases |
| design-knowledge module + manifest | `compile-design-knowledge.mjs` (no `--check`) | `--check` + provenance; bundle `d818e4d9…` matches `49-VERIFICATION.md:30` |
| golden `AGENT_EVAL_SUITE` revision | `--write-suite-manifest`, then the revision bump the tool names | `--self-check` → 57 fixtures, 12 gated skills |
| recipe implementation pin | `--print-implementation-hash` | recomputed after writing: **converged** at `66e37c1d6908…` |

**The order matters, and getting it wrong looks exactly like a loop.** `skill.ts` carries both the
golden suite revision and the recipe implementation pin, and the recipe digest also covers
`designKnowledge.generated.ts`. So the generators must settle *first* and the recipe pin must be
written *last*; repinning the recipe before regenerating design knowledge yields a computed value
that is stale the moment design knowledge is rewritten. Settled order:

```
pnpm format                                   # mechanical; must be a no-op afterwards
compile-design-knowledge.mjs                  # generated module + manifest
vertical-eval-corpus.mjs --write              # generated corpus module
run-eval-golden.mjs --write-suite-manifest    # then bump AGENT_EVAL_SUITE as the tool names
run-web-recipe-evals.mjs --print-implementation-hash   # write this value last
check-phase49-qualification.mjs --manifest    # record, then run the aggregate
```

Repair 4 below is what makes that order sufficient. Without it the first and second steps undo each
other forever, so the sequence alone will not converge.

**Consequence, stated plainly:** the golden evaluator revision moved from
`…e8423177c66c…` to `…32f2d3443debc…`. Per the comment above `AGENT_EVAL_SUITE`, bumping the
revision *is* the act that retires older evidence, so the 2026-09-25 preflight record keyed to
`e8423177` at `STATE.md:36` is **retired** and needs re-establishing before any paid golden
attempt. The recipe pin is a confirmed fixed point but likewise carries a new value from the old
one.

## Repair 4 — a generator/biome tug-of-war that made the digest un-settleable

With the three repairs above green, the aggregate still refused to certify: the Phase 49 digest
alternated between two values and the recipe gate flip-flopped. This was not an ordering mistake on
my part, and it is a pre-existing defect. Measured directly:

```
STEP 0                    recipe=cc505082…  generated=D85F5736
STEP 1 after compile      recipe=66e37c1d…  generated=0807B31D
STEP 2 after format       recipe=cc505082…  generated=D85F5736
STEP 3 after compile      recipe=66e37c1d…  generated=0807B31D
STEP 4 after format       recipe=cc505082…  generated=D85F5736
```

`scripts/compile-design-knowledge.mjs` writes `packages/core/src/designKnowledge.generated.ts`
with quoted object keys and expanded arrays; biome wants unquoted keys and collapsed arrays. Each
rewrote the other's output forever. Because the recipe implementation digest covers that generated
module, the recipe pin, the free-gate sweep and the Phase 49 aggregate digest could **never** all be
green at once — the two recorded digests in this file's history are the two phases of that cycle.

**Fix:** byte-exactness *is* this file's contract — `compilerSha256` is the hash of the compiler
itself and `--check` demands a deterministic recompile — so a formatter must not own those bytes.
`biome.json` already excludes generated and vendored paths (`!**/_generated`, the assembly
fixtures); `packages/core/src/designKnowledge.generated.ts` is now excluded the same way. Biome
checks 1143 files instead of 1144. `verticalEvalCorpus.ts` is generator-owned too but already
emits biome-clean output, so it was left alone rather than excluded unnecessarily.

After this, compile → format → compile → format is a genuine no-op and every identity is a fixed
point.

## Two more defects found while making the suite deterministic

Neither is in the original five, and neither is a formatting artifact.

- **`connectorCredentials.test.ts` had a TIME-DEPENDENT leak check.** It asserted
  `expect(JSON.stringify(status)).not.toContain("503")` — grepping the whole serialized connector row
  for the provider status code. That row includes `connectedAt`, an epoch-millis timestamp, so the
  assertion passed or failed **on the digits of the current clock**: a `connectedAt` of `1790503470595`
  contains the sequence 5-0-3 and reddened a green gate. A leak check that fires on the wall clock is
  worse than none, because it trains you to ignore it. The intent is unchanged and still enforced —
  the property is named directly and the substring check is scoped to the `revocation` projection,
  which carries no timestamp. Found only because the suite was re-run at a different moment.
- **A SECOND generator/formatter oscillation, on the compiler's own manifest.**
  `third_party/design-knowledge/manifest.json` had the same defect as Repair 4: the compiler writes
  it in a form `biome check --write` rewrites, so `compilerSha256`/`compiledBundleHash` could never
  satisfy both `--check` and `biome ci`. Now excluded on the same rationale — the file is
  generator-owned and its integrity hashes are the contract. Biome checks 1142 files, not 1144.

Neither exclusion relaxes coverage: both files remain fully enforced by `compile-design-knowledge.mjs
--check`, the provenance verifier, and the aggregate's own provenance and compiler planes. Coverage
moved to the tool that can actually enforce it.

The authoring-probe fix retires two further evaluator identities, since `llm.ts` and
`lib/evalBudgetModel.ts` are members of both the golden and the native-vertical evaluator
inventories: golden `32f2d3443debc…` → `a8f2127b60b4e3c…`, and native vertical `6387a7959eb1…` →
