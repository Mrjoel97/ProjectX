# Phase 37.1: Closure Programme Integration and Wave 0 Baseline - Context

**Gathered:** 2026-09-19
**Status:** Ready for planning
**Source:** Owner direction plus the owner-adopted closure programme in the merged audit

<domain>
## Phase Boundary

Make Waves 0-8 operational inside the repository's existing GSD, evidence, Ponytail, Graphify,
playbook, testing, and release systems. Reconcile planning truth, classify every remaining workflow
at the correct evidence layer, mint traceable requirements and owning phases for business websites,
campaign landing pages, and tenant online shops, strengthen planning checks where the current helper
miscounts semantic partials, and leave executable Wave 1 handoffs.

This is a planning-control and evidence-baseline phase. It must not implement product features,
perform paid/live provider actions, reuse expired authorization, activate candidates, arm WORM,
start recurrence, or convert missing evidence into completion.
</domain>

<decisions>
## Implementation Decisions

### Existing operating system is locked
- The merged audit is the standing programme reference until Wave 8 closes.
- ROADMAP, STATE, REQUIREMENTS, phase plans, summaries, verifications, validations, playbooks, ADRs,
  and release evidence remain the execution records; no parallel planning system may be introduced.
- GSD remains the plan/execute/verify mechanism. Ponytail remains the minimal-code and explicit-
  ceiling discipline. Graphify remains the query-first code map and must be refreshed after source
  changes through the existing update/fixup path.

### Truth vocabulary is locked
- Report implemented, offline-tested, deployed, live-observed, owner-accepted, and externally
  enabled separately.
- A matching PLAN/SUMMARY filename is not completion when the summary or verification is partial,
  awaiting live evidence, human-needed, parked, blocked, or superseded.
- Historical records remain honest. Delta plans supersede stale criteria explicitly; they do not
  rewrite old evidence as if it happened.

### Closure order is locked
- Wave 0 reconciles authority and creates the executable ledger before parallel product edits.
- Wave 1 closes foundation and evidence debt; later waves follow the dependencies and exit gates in
  the merged audit.
- Phase 23 resumes in Wave 4, not as the immediate route. Its prior bounded authorization expired
  and cannot be reused.
- External legal/provider activation is Wave 7. Repository-controlled technical readiness may be
  planned earlier, but external approval is never simulated.

### Newly admitted beta scope is locked
- Multi-page business websites, campaign landing pages, public forms/lead capture/analytics, and
  tenant online shops are planned beta capabilities.
- Existing self-contained HTML, tracked file funnels, Pikar subscription billing, and read-only
  tenant payment connectors are reusable primitives, not completed versions of those capabilities.
- Pikar billing and tenant merchant commerce must remain separate identities, credentials, tables,
  events, money flows, ledgers, and operational controls.

### Parallel execution contract is locked
- Independent delta plans may execute concurrently only after shared contracts and file ownership
  are explicit.
- Every plan must name affected files, dependencies, objective tests, founder-facing acceptance,
  evidence outputs, and stop conditions.
- Shared-tree agents must not revert unrelated work and must reconcile concurrent edits.

### Claude's Discretion
- Exact names and numbering of new requirement IDs and closure phases, provided traceability is
  stable and the SITE/LAND/SHOP boundaries remain distinct.
- Whether the routing JSON is retired or retained as a generated, validated derivative; it may not
  remain an independent authority.
- Mechanical implementation details of the planning checker, provided it remains small, local, and
  fail-closed under the Ponytail discipline.
</decisions>

  lifecycle. Existing relevant primitives have 345 focused passing tests.

  missing; the row was added and `node scripts/check-planning.mjs --exit-code` returned green.
</specifics>
