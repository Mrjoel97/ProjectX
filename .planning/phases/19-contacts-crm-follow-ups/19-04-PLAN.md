<objective>
The phase's ONLY public unauthenticated route: a signed unsubscribe link that opens an inert
landing page and suppresses only on an explicit POST.

Purpose: A bare GET would be fired by corporate mail scanners and link prefetchers, silently
unsubscribing people who never clicked. The confirm button is what stops the feature firing
itself. The route lives on `convex/http.ts`, NOT `apps/web` — `apps/web/middleware.ts` is
default-deny (`isPublic` = `/`, `/privacy`, `/terms`, `/signin`, `/signup`) and a public page there
means a security-sensitive matcher edit plus a second bearer-secret hop back into Convex to write
the suppression. The Convex site origin is untouched by that middleware, which is why the fal
webhook works at all.

Output: two `httpAction` routes, their tests, and playbook bumps.
</objective>

```ts
http.route({
  // `pathPrefix`, not a glob: Convex's router has no `*` syntax, so `path: "/fal/callback/*"`
  // would match nothing at all.
  pathPrefix: "/fal/callback/",
  method: "POST",
  handler: httpAction(async (ctx, req) => {
    const segment = new URL(req.url).pathname.split("/").pop() ?? "";
    const dot = segment.lastIndexOf(".");          // gmailAuth.verifyState's idiom, verbatim
    if (dot <= 0) return unauthorized();
    const job = await ctx.runQuery(internal.mediaComplete.resolveJob, {
      raw: segment.slice(0, dot), digest: segment.slice(dot + 1),
    });
    if (!job) return unauthorized();
```

    `new Response("not found", { status: 404 })`. On success return `200 text/html` with a

    No JS. No external asset. No tracking pixel.

    **POST** — verify, then `ctx.runMutation(internal.contacts.suppressFromUnsubscribe, { raw,
    digest })`, then return `200 text/html` confirming, naming every address suppressed (group
    mode decodes to more than one). A replayed link idempotently re-suppresses and shows the same
    confirmation — that idempotency IS the abuse mitigation. Do NOT add a rate limiter: a valid
    segment requires the deployment secret, brute-forcing an HMAC-SHA-256 digest is infeasible, and
    a per-address ceiling is meaningless when the operation is idempotent. Write that reasoning as
    the comment (`@convex-dev/rate-limiter` is already a pinned component if it ever becomes
    necessary).

    Style both pages with inline `style="..."` using hex values copied from `globals.css` /
    BRAND §2 — an httpAction cannot import `globals.css`. Add the ceiling note:
