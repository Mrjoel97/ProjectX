Locked gap-closure decisions:

1. `calendar_event` remains CREATE. Add one new `calendar_manage` type; do not repurpose the shipped
   type and do not add one type per provider.
2. `CalendarManageOperation = "update" | "delete"`. User words move/reschedule map to update;
   cancel/remove map to delete. Do not call provider cancellation-message endpoints: they can email
   attendees outside the plan/audit/DLQ spine.
3. Management is limited to Pikar-created, attendee-free events recorded in `calendarEvents`.
   Arbitrary mailbox event discovery and attendee-bearing meetings remain refused.
4. `calendarProvider` is optional on old create plans and defaults to Google. Old Phase-17 rows need
   no schema migration and the existing Google path keeps its meaning.
</context>
