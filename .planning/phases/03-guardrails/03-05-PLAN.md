<interfaces>
From plan 03-04 (the behavior under test):
- Sentinel grammar: `SMOKE::route=<route>::[cache=1::][fail=primary::]` — `cache=1` routes THROUGH preCall + the action cache (uncached action returns a fixed draft + audits `llm.called`); `fail=primary` throws a TimeoutError inside the try so the real classifier routes to the fallback branch (fixed fallback draft + `llm.fallback` audit). Default sentinel bypasses preCall/cache entirely.
- `llm.called` / `llm.fallback` audit rows: `correlationId = safeTextHash`, payload `{ model, skillVersion, stage: "route" | "draft" }` — count DRAFT-stage rows only (route rows share the hash).
- Blocked terminal: request.status "blocked", audit `guardrail.blocked` payload `{ requestId, reason }`, telemetry reviewOutcome "blocked". Wrappers propagate preCall governed stops as `{ blocked: reason }`; the pipeline routes them to this same terminal — mid-flight and pre-flight stops are indistinguishable at the terminal.
- `request.redacted` audit: payload `{ requestId, piiCounts, safeTextHash }`.

From guardrails.ts: `rateLimiter` (names "submitRequest" token bucket capacity 5, "dailySpendCents" fixed window 500/24h), `setKillSwitch({ on })`, `recordSpend({ costUsd })`.
RateLimiter also exposes `reset(ctx, name, { key? })` — use it for cleanup so a drained window never poisons later smoke runs (Pitfall 5).

From smokeRun.mjs: `must(fn, args)` (single banner-judged `npx convex run`), `pollPass(fn, args)` (poll until no failure banner). NEVER trust convex CLI exit codes on Windows/Node24. Dev deployment must be running `convex dev` (not --once).
