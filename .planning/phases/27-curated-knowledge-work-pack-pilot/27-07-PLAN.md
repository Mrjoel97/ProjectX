<scope_corrections>
Applied 2026-08-23 from `27-READINESS.md`. Binding on the executor — this plan was over-scoped as
written and several of its paths do not exist.

1. **DO NOT BUILD A RUNTIME.** `runSpecialistTurn` (`llm.ts:4633`) ALREADY IS the `(skill body,
   tool-set)` seam: it takes `{ tenantId, planId, skillName, toolNames, prompt, skillVersions }`,
   loads the §5 registry body itself (fail-closed on `NO_ACTIVE_SKILL` / `NO_SUCH_SKILL_VERSION`),
   and `runAgentLoop` (`llm.ts:4230`) already filters the built tool record to the exact `toolNames`
   (verified at `llm.ts:4351-4353`, `Object.fromEntries(... .filter(([n]) => toolNames.includes(n)))`,
   with `=== undefined` deliberately used so an EMPTY allow-list yields an EMPTY record).
   Task 1 is therefore a **~40-line binding**: pack id → `{ skillName, toolNames, prompt, planId }`,
   plus the `traced()` wrapper and the refusal guards. It is NOT a second agent loop. The file was
   renamed `workflowPackRuntime.ts` → **`workflowPackBinding.ts`** for exactly this reason: a file
   called "runtime" invites an executor to write one.

2. **Allow-listed packs are LEAF AGENTS (owner decision, 2026-08-23).** Passing `toolNames` is NOT
   side-effect-free. `llm.ts:4337` `grantDispatch: toolNames === undefined` and `llm.ts:4342`
   `grantSkillAuthoring: toolNames === undefined` — an allow-list structurally withholds specialist
   dispatch and skill authoring, by construction, and the comment at 4338-4341 says reading
   `toolNames.includes(...)` there would be a defect. So: **Campaign Plan PRODUCES A PLAN; it does
   not orchestrate research/content/media.** State the leaf-agent property in the binding's header
   and assert it in the test. Do not try to re-grant dispatch.

3. **`planId: Id<"plans">` is REQUIRED by `runSpecialistTurn`.** Analysis-only packs still need a
   plan row. Reuse the thread's existing row via `plans.byThread` (`plans.ts:1013`, a `tenantQuery`);
   mint one with `internal.plans.insertPlan` (`plans.ts:62`, args `{ tenantId, threadId }`) when the
   thread has none. It starts at `status: "collecting"` with no `kind`, which is exactly right for an
   analysis-only run: nothing arms, nothing delivers. **Do NOT widen `ACTION_TYPES`**
   (`packages/core/src/actionType.ts:8`) — it is a closed, email-shaped set with an exhaustive switch
   in `llm.ts:1119` and a runtime walk in `cockpitTools.test.ts:1245`; adding a member for a pack
   would drag the whole delivery arm table into this phase.

4. **`traced()` is mandatory on the new entry point.** Wrap the pack turn in
   `traced({ agentName: …, workflowName: …, workflowRunId: …, sessionId: … }, () => …)` from
   `convex/lib/foglamp.ts:92` — the `llm.ts:5307` cockpit-turn call is the shape to copy. Without it
   the pack lane is the single model path with no Foglamp span, and nothing in the suite would fail.

5. **Hallucinated modules — `convex/artifacts.ts` never existed.** It is removed from
   `files_modified`. The real seams, all of which this plan READS rather than creates:
   - bounded artifact reads → `content.ts` (`listArtifacts:257`, `summary:315`, `artifactById:347`,
     all `tenantQuery`);
   - created documents → `llm.ts createDocument:3715` → `internal.vault.insertCreatedDoc`
     (`llm.ts:3840`);
   - inbox → `llm.ts listInbox:3377` / `briefInbox:3417`, plus `gmail.ts` and `briefings.ts`.
   Do not create a second artifact store (27-RESEARCH's Don't-Hand-Roll list forbids it).

6. **The event recorder is 27-03's, renamed.** There is no `convex/workflowPackEvents.ts` — that is
   the TABLE name (27-02's `schema.ts` deliverable). The recorder module is
   `convex/workflowPackEventLog.ts` and 27-03 owns its closed event vocabulary. This plan supplies
   the **call sites**. The bounded read projection lands in a new `convex/workflowPackOutcomes.ts`
   (the pure metric definitions are 27-03's `packages/core/src/workflowPackMetrics.ts` — do not
   duplicate them here). If a call site needs an event kind the vocabulary lacks, add it in
   `workflowPackEventLog.ts` beside the existing ones; do not open a parallel plane.

7. **No cost or latency event kinds.** Same rule as 27-03: `spendEvents` owns cost, `telemetry` /
   `agentSteps` own latency. The projection READS them by `correlationId`. A duplicate cost number
   that can disagree with the billing plane is worse than no number.

8. **Merge-collision risk.** `llm.ts` and `dispatch.ts` both changed on 2026-08-23 (commit
   `63ca792`, Foglamp tracing). Rebase before editing and re-read the line numbers cited above —
   they are from the post-`63ca792` tree. Prefer leaving `llm.ts` **byte-unchanged** (the
   `dispatch.ts:301` precedent: the whole specialist lane was built without touching it); it stays in
   `files_modified` only in case the binding forces a signature widening.

9. **Playbooks (CLAUDE.md §9, Stop-hook enforced).** `cockpit.ts` and `llm.ts` are both watched by
   `docs/playbooks/cockpit.md` — update it and bump its `Last verified` line in this plan's commit.
   The two new `convex/workflowPack*` files sit under the prefix 27-02 registers against
   `docs/playbooks/workflow-packs.md`; update that too. If 27-02 did not register the prefixes in
   `docs/playbooks/watch.json`, register them here.
