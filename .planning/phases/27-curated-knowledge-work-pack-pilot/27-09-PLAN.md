<replan_required>
**THIS PLAN REQUIRES A RE-PLAN BEFORE EXECUTION.** The 2026-08-23 readiness audit
(`27-READINESS.md`, "Needs re-planning rather than execution: 27-09 only") found its route paths,
component directory, e2e location, rollback story and candidate-preview mechanism all wrong or
unsupported. The mechanical rot is corrected below (paths, verify commands, files_modified,
playbooks) so an executor is not misled — but four decisions are still open and MUST be settled by
a planner with the owner before Task 1 starts:

1. **Owner candidate preview does not exist today.** `skillVersions` is threaded only INSIDE
   `llm.ts` (declared on `runAgentLoop` at :4240; also 1576 / 4643 / 4710). `cockpit.ts:99
   sendCockpitMessage` takes only `{ threadId, text, clientContext }` and
   `useSendCockpitMessage.ts:35` passes only `{ threadId, text, clientContext }`. Nothing in the
   browser can pin a version, so a "candidate preview" in the UI silently loads the **ACTIVE** row
   and the owner gate reviews a lie. This is the recorded *clock-plane-dead-in-production* class:
   a cockpit param not threaded through BOTH `runAgentLoop` and the web caller refuses live while
   every unit/SMOKE/eval gate stays green. `cockpit.ts`, `llm.ts` and `useSendCockpitMessage.ts`
   are now in `files_modified` for exactly this. Decide: thread an owner-only `skillVersions`
   through `sendCockpitMessage` -> `runCockpitAgent` -> `runAgentLoop`, or cut the preview and
   have the owner review eval transcripts instead. Do not leave it implied.
2. **Which rollback is being drilled.** Rollback-to-**prior-version** is supported by the registry
   today. Rollback-to-**dark** is not: `skills.ts` has exactly one active-patch site (:367, with
   :644/:678 the seed/candidate paths) and **no owner-facing deactivate**. The only dark path is
   `archiveSkill` (:765, an `internalMutation`) via `npx convex run`.
3. **`npx convex run` signs the browser out.** Measured 2026-08-14 and documented in
   `apps/web/e2e/README.md`: one `convex run` against the local deployment kills the saved
   `storageState`, and the next navigation lands on `/signin`. So either (a) sequence **all**
   browser evidence BEFORE any `convex run`-driven rollback drill, or (b) add a proper
   owner-facing deactivate mutation to `skills.ts` (already in `files_modified`, so in scope — but
   it is new registry surface and needs its own test + `skill-registry.md` update). Pick one; (a)
   is free.
4. **Six packs or three.** The audit recommends cutting the pilot to three (eval cost is the
   phase's only real spend). Owner decision A (2026-08-23) keeps all six, with unreachable
   capabilities classified MISSING and carried by the honest-partial-state contract. This plan is
   written for six; if the pilot is cut upstream, Task 3's per-pack loop shrinks with it.

Also settled by owner decision (do not re-litigate): packs are **leaf agents**. A tool allow-list
structurally disables specialist dispatch (`llm.ts:4337` `grantDispatch: toolNames === undefined`,
`:4342` `grantSkillAuthoring`). This UI must not imply a pack orchestrates other agents.
</replan_required>
