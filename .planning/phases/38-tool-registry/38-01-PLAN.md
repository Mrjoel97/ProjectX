# 38-01 — One tool context, one grant derivation, one validator (scope A)

**Source:** `38-RESEARCH.md` (measured 2026-09-06) and the three owner decisions of the same day: scope A
(context + grants object; tool bodies stay where they are) · keep ADR-007's agent-side name lists and add
tool-side grant predicates · the mock model provider stays out.

**Execution shape (owner: "ultracode, not more than 5 agents"):** one workflow, five agents — snapshot test
and `grantsFor` in parallel → the refactor → a gates agent and an adversarial reviewer in parallel. Docs,
planning corpus, commit and deploy stay with the main session.

## Tasks

1. **Snapshot first** — `toolRegistrySnapshot.test.ts` records the tool KEY SET per caller class as hard
   literals against the OLD positional signature (bare shim · continue turn · Gmail off · executive with and
   without lineage · each specialist route · each workflow pack · the revenue eval seam · the two SMOKE
   paths), every build through ONE local helper. Green before the refactor starts; a changed literal is a
   behaviour change and is refused.
2. **`grantsFor` in `packages/core`** — `ToolGrants` (eight booleans), `NO_GRANTS` (what a bare caller gets
   today), `isRevenueToolGrant` (the identity check, moved), `grantsFor(input)` — the ONE derivation of the
   three `toolNames === undefined` copies. Table test, mutation-checked by hand.
3. **Refactor** — `buildCockpitTools(toolCtx: ToolContext, grants: ToolGrants = NO_GRANTS)`; every spread
   reads `grants.x`; lineage rides `ToolContext`; `runAgentLoop` calls `grantsFor` then builds; the SMOKE
   path grants `dispatch` alone on the direct-video route; `__invokeCockpitTool` builds bare;
   `TOOL_CONTEXT_ARGS` (the pins every door must accept) spread into `runCockpitAgent.args` and
   `dispatchArgs` with a source-scan test; 16 test call sites migrated; static-scan anchors re-pointed where
   code moved, never loosened.
4. **Verify** — core suite, backend both shards, web suite, repo typecheck, lint at `--diagnostic-level=error`;
   an adversarial reviewer derives the before/after key set for twelve caller classes by hand and tries to
   find a specialist that can name its way into an executive capability.
5. **Docs** — `agent-runtime.md` (the "adding a tool" checklist step 2 changes shape), `cockpit.md`
   Last-verified block, `watch.json` registers the new files; ROADMAP/STATE per the Phase 37 hook.
6. **Live** — one cockpit turn with a send time (the clock hop), one `SMOKE::agent::` op, one dispatched
   specialist, on the local deployment — the clock-plane lesson: only a browser turn sees all four hops.
