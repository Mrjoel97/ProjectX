# Phase 15.2 Plan 02: Universal Format Coverage (Pure Layer) Summary

`extractOfficeText` now takes the bytes and nothing else — it unzips once and dispatches on the
marker ENTRY it finds, which covers DOCX/DOCM, XLSX/**XLSM**, PPTX/PPTM, ODT/ODS/ODP and EPUB by
construction — plus a new dep-free `rawText.ts` that recovers RTF, HTML/XML and legacy OLE2
DOC/PPT text with **zero new dependencies**.

## What was built

**`packages/vault/src/officeText.ts` — one fewer parameter, three more formats.** The three
`*_MIME` constants are deleted. The dispatcher is:

```
word/document.xml      → docxText   (DOCX / DOCM)
xl/workbook.xml        → xlsxText   (XLSX / XLSM  ← the owner's stuck file)
ppt/presentation.xml   → pptxText   (PPTX / PPTM)
mimetype ~ application/vnd.oasis.opendocument.*  → odfText  (ODT / ODS / ODP)
META-INF/container.xml → epubText   (EPUB)
otherwise              → throw office_parse_failed: unrecognized zip
```

OOXML markers are checked FIRST, and an archive carrying both a `word/document.xml` and an ODF
`mimetype` entry resolves deterministically to DOCX — pinned by a test, because "whichever branch
happens to be written first" is not a contract. The error message names the **zip**, not a mime
type, since there is no longer a mime type to name.

The two new walkers are the point of the ladder's rung 2: `odfText` reuses `rawRunsOf` and
`markupText`, `epubText` reuses `markupText` — **no second XML walker was written**. `runsOf` split
into `rawRunsOf` (undecoded) + `runsOf` (decoded) so the ODF walker can pass raw `<text:p>` runs
through `markupText` (which strips inner `<text:span>` markup and then decodes) without decoding
entities twice. `odfText` is ONE function for three formats: split on `</table:table-row>` and
tab-join, else on `</draw:page>`, else join `<text:p>` runs — chosen from what `content.xml`
contains, never from the declared `mimetype`.

**`packages/vault/src/rawText.ts` (new, ~200 lines, dep-free, barrel-safe).** Four exports:

- `decodeEntities` — MOVED here from `officeText.ts`, which now imports it. One decoder, three
  callers.
- `markupText(html)` — script/style/comment **bodies** removed BEFORE the generic tag strip (strip
  tags first and you inline the script source as document text), block tags become newlines, then
  entities decode, then whitespace collapses. Attribute values never surface as text.
- `rtfText(bytes)` — a brace-DEPTH scanner, not a regex, because `{\*\...}` ignorable destinations
  nest and a regex cannot balance braces; flattening them would emit generator/font/colour tables
  as prose. Handles `\par`/`\line`/`\sect`/`\page` as breaks, `\'hh` hex escapes through CP1252,
  escaped `\{ \} \\` literals, and skips control words with their numeric argument and one
  delimiter space. Throws `raw_parse_failed: not rtf` on non-RTF input.
- `oleText(bytes, kind)` — the dependency-free half of SC#3. Maximal printable runs in CP1252 AND
  UTF-16LE, merged in **byte-offset order** (deterministic and roughly document-ordered), minimum
  run length 4, a 13-name stop-list matched on the **whole run** (a substring rule would delete any
  sentence containing the word "Data"), consecutive duplicates dropped. **Throws rather than
  returning `""`.**

`TextDecoder("windows-1252")` is constructed **lazily inside the decode helper**, never at module
scope. That is not style: `rawText.ts` is on the `@pikar/vault` barrel, and that constructor throws
`RangeError` on a runtime built without full ICU — a module-scope throw would take down every
module that touches the barrel, whereas a throw inside `rtfText`/`oleText` is one honest `failed`
document.

**1. [Rule 3 - Blocking] `markupText` had to land in Task 1, not Task 2.**

- **Issue:** The plan's Task 1 action requires `epubText` to "strip tags and decode entities via the

  barrel exports and the rest of `rawText.test.ts`. Both halves are still TDD (RED committed
  separately from GREEN); only the file's arrival moved one task earlier.
- **Files:** `packages/vault/src/rawText.ts`, `packages/vault/src/rawText.test.ts`
- **Commits:** `2ed7447` (RED), `0abaf21` (GREEN)

**2. [Rule 1 - Dead branch] The plan's `\x05`-strip before stop-list comparison was NOT implemented.**
- **Found during:** Task 2
- **Issue:** The plan says to "compare after stripping a leading `\x05`". But `0x05` is not a
  printable byte under either scanner, so a run can never *begin* with it — the
  `\x05SummaryInformation` stream surfaces as the bare `SummaryInformation` and matches the
  stop-list exactly. Writing the strip would have added a branch that can never be taken (the
  15.1-04 `?? "lean"` lesson).
- **Fix:** Omitted, with the reason recorded as a source comment on `OLE_STREAM_NAMES` and as a
  playbook invariant. The plan's *test* is honoured literally — the fixture carries the `\x05`
  prefixes and asserts the bare names are absent from the output.
- **Files:** `packages/vault/src/rawText.ts`

**3. [Rule 1 - Dead branch] `docxText`'s `missing word/document.xml` guard deleted.**
- **Found during:** Task 1
- **Issue:** Under entry dispatch, `docxText` is only reached when that entry exists, so the guard
  became unreachable. It also let `docxText` keep taking the whole entry map for one lookup.
- **Fix:** `docxText(doc: Uint8Array)` now takes the entry the dispatcher already narrowed. Same
  treatment for `odfText(content: Uint8Array)`, except that its `missing content.xml` throw is REAL
  (the ODF branch is gated on the `mimetype` entry, which does not guarantee `content.xml`) and so
  moved up into the dispatcher, where it is still reachable and is pinned by a test.
- **Files:** `packages/vault/src/officeText.ts`

### Choices inside the plan's latitude (not deviations)

- **`oleText`'s second parameter is named `_kind` and is unused.** The sweep is format-agnostic and
  the stop-list is the union of both formats' stream names, so branching on `kind` would either be a
  no-op or would make the DOC path leak PowerPoint stream names (and vice versa). The parameter
  stays in the signature because the caller has it and the upgrade path (`word-extractor` / SheetJS)
  needs it; the `ponytail:` block says so verbatim.
- **`rtfText` also throws `raw_parse_failed: no text recovered` on an empty result.** The plan only
  mandates this for `oleText`, but a `{\rtf1}` yielding `""` produces the same `ready`-with-0-chars
  outcome the phase exists to remove. One line, same reasoning.
- **`markupText` maps block-level tags to newlines** rather than replacing every tag with a space.
  Required by the plan's own `<p>Hi</p><p>There</p>` → newline-separated case, which a
  space-for-every-tag rule cannot satisfy.
- **`collapse()` is shared** by `markupText` and `rtfText`; the whitespace rule has one home.

### Tooling note worth carrying forward

**Bash heredocs in this environment HALVE backslashes, even quoted (`<<'EOF'`).** Appending
`rawText.ts`'s RTF scanner and its test block that way silently turned `/\\([a-zA-Z]+)/y` into
`/\([a-zA-Z]+)/y` and `"{\\rtf"` into `"{\rtf"` (i.e. `{` + CR). It surfaced as an esbuild
`Unexpected ")" in regular expression`, but the test-file damage would NOT have surfaced — a
template literal containing `\r` is a valid string. Both files were rewritten with the Write tool.
Separately, the Write tool JSON-decodes its content, so `\x05` in a source string literal lands as
a literal control character; the three occurrences were converted back to visible escape sequences
and verified by char-code dump. **Do not use heredocs for backslash-bearing source in this repo.**
