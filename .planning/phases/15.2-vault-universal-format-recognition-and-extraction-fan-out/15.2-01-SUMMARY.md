# Phase 15.2 Plan 01: Pure Recognition Layer Summary

Content-first format recognition (`sniffContainer` / `ole2Kind` / `resolveRail`) plus a scheduling
decision that is total by type — the `kind === null → schedule nothing` branch that stranded the
owner's `.xlsm` is now impossible to express.

## What was built

**`packages/vault/src/sniff.ts` (new, 189 lines, dep-free, V8-safe).** Three exports:

- `sniffContainer(bytes)` — an offset-0 prefix table (zip ×3 variants, OLE2, RTF, PNG, JPEG, GIF),
  then a bounded `%PDF` search over the first 1024 bytes (leading junk before `%PDF` is legal and
  occurs in the wild; the window keeps a text file that merely *mentions* `%PDF` out), then a UTF-8
  text heuristic — `TextDecoder("utf-8", { fatal: true })` with `stream: true` so a multi-byte char
  straddling the 4 KiB window edge is not misread as binary, BOM stripped before counting, ≥95%
  printable required. Empty input is `"binary"`, never a throw.
- `ole2Kind(bytes)` — gated on the OLE2 header, then a UTF-16LE needle scan over the first 8 KiB for
  `WordDocument` / `PowerPoint Document` / `Workbook` / `Book`, with `Workbook` checked before the
  BIFF5 `Book` (a suffix of it). This is what tells a MIME-less `.xls` from a MIME-less `.doc`.
- `resolveRail(bytes, mimeType, filename?)` — the sniffed container is an **override ahead of** the
  MIME/extension checks; `extractionKindFor` survives as the fallback behind it (rung 2: the MIME
  table already exists, so it is reused rather than restated).

**`schedulingRailFor` in `extractKind.ts` — three lines, and the comment is longer than the code on
purpose.** `SchedulingRail = "transcribe" | "extract"`. Media rides `vaultTranscribe` by MIME exactly
as before; everything else rides `vaultExtract`, including formats no allow-list recognises. That is
the whole fix: `ctx.storage.get` is action-only, so a magic-byte sniff physically cannot run at a
scheduling site — rather than teaching three mutations to guess, we schedule permissively and let
the one place that can read bytes decide, where `fail("unsupported_format")` already existed and was
until now unreachable.

**Lane V contract** written into `.planning/PARALLELIZATION.md` *before* any code landed, and the
Phase 15.2 playbook container opened in `docs/playbooks/vault.md`.

## Deviations from Plan

**None — the plan executed as written.** Every interface it named was where it said it would be
(`extractionKindFor`'s signature, `packages/vault`'s `"./*"` subpath export, the `watch.json`
`packages/vault/` mapping). Two implementation details are worth recording as *choices inside* the
plan's latitude, not deviations:

- **`TextDecoder` is used with `stream: true`.** The plan specified `{ fatal: true }` over
  `subarray(0, 4096)`. Taken literally, a multi-byte character straddling byte 4096 throws and the
  file is reported binary — a real false negative for any non-ASCII document over 4 KiB.
  `stream: true` holds back an incomplete trailing sequence, which is the standard-library answer
  (rung 3) rather than a hand-rolled trailing-byte trim. Pinned by its own test.
- **`ole2Kind` gates on the OLE2 header** before scanning. The plan only required "non-OLE2 bytes →
  unknown, never throw"; the header gate is one line and makes the function honest when called
  standalone, not merely when `resolveRail` has already vetted the container.
