# Phase 15.2 Plan 03: Permissive Scheduling + In-Action Rail Dispatch Summary

The first plan of this phase to touch `convex/`: scheduling became permissive at ONE shared
decision point, the magic-byte sniff became the dispatcher inside the only runtime that can read
bytes, `fail("unsupported_format")` became REACHABLE after existing unreachable since 03.8-02, and
every non-terminal status now has exactly one governor.

## What was built

**`vault.scheduleExtraction` — the chokepoint (the `vaultIngest.startIngest` precedent).** Three
callers route through it: `vaultUpload`, `vaultSweep.sweepPendingExtraction` and
`vaultSweep.retryExtraction`. All three previously carried their own copy of
`extractionKindFor(...) === null → schedule nothing`; all three copies are gone. The helper asks
`schedulingRailFor` (which is total by type) and then arms `internal.vaultSweep.watchdogStalled` at
`+EXTRACTION_WATCHDOG_MS`. Referencing `internal.vaultSweep.*` from `vault.ts` while `vaultSweep.ts`
imports `scheduleExtraction` from `vault.ts` is not a module cycle — `internal.*` is codegen.

**`vaultSweep.watchdogStalled` — the never-silent backstop.** Flips ONLY a doc still at
`pending_extraction`/`extracting`, through `internal.vault.markFailed`, with reason
`extraction_stalled`. `processing` is deliberately excluded: `onIngestComplete` has owned it since
the 2026-07-20 stranding fix, and two governors on one status is a flip war. It never overwrites an
existing `failureReason`, so a watchdog firing after an honest `unsupported_format` changes nothing.

**The in-action rail dispatch.** `resolveRail(bytes, meta.mimeType, meta.title)` after
`ctx.storage.get` replaced `extractionKindFor`, and the branch table widened from
pdf/image/office/else to pdf, image, zip, legacy_doc, legacy_ppt, legacy_xls, rtf, markup, text and
an honest terminal refusal. `legacy_xls` refuses with `unsupported_legacy_spreadsheet` on purpose:
a printable-run sweep over BIFF recovers the column headers and silently loses every number, which
fails PLAUSIBLY — the shape this phase exists to remove. A sniffed image with a wrong or empty MIME
is now sent with a real `mediaType`, or SC#1 would "work" right up to the point the model call was
silently malformed. A new guard fails an extraction that recovered zero characters.

## Deviations from Plan

### Auto-fixed

**1. [Rule 3 - Blocking] `watchdogStalled` had to land in Task 1, not Task 2.**
- **Found during:** Task 1
- **Issue:** Task 1's `scheduleExtraction` references `internal.vaultSweep.watchdogStalled`, and
  Task 1's own gate is `pnpm --filter @pikar/backend typecheck`. The generated API is typed from
  the real module exports, so Task 1 cannot typecheck while its callee lives one task away.
- **Fix:** the `watchdogStalled` mutation landed in Task 1; Task 2 supplied its tests and the
  scheduling tests, non-vacuity proven by mutation checks 1-3 rather than by a RED-first commit.
- **Files:** `packages/backend/convex/vaultSweep.ts`
- **Commit:** `a390f95`

**2. [Rule 1 - Bug] A THIRD test asserted the defect as a requirement, in a file the plan did not name.**
- **Found during:** final verification
- **Issue:** `vault.test.ts` carried *"an unrecognized binary (zip) stays pending_extraction,
  nothing scheduled"* — the same `kind === null` branch that stranded the `.xlsm`, written down as
  a requirement. The plan named only the two in `vaultSweep.test.ts`. Left alone it would have gone
  red on `main` and read as a regression in the fix.
- **Fix:** inverted to assert the upload IS scheduled. The row still stays `pending_extraction`
  (the action flips it) — that half of the original assertion was correct and is unchanged.
- **Files:** `packages/backend/convex/vault.test.ts`
- **Commit:** `c44c5cd`

**3. [Rule 1 - Bug] My own watchdog-delta assertion was a 1 ms flake.**
- **Found during:** final verification (it had already produced one phantom red mid-run)
- **Issue:** `scheduleExtraction`'s two `runAfter` calls read `Date.now()` independently, so the
  gap is `EXTRACTION_WATCHDOG_MS` plus however many milliseconds elapsed between them. Observed
  900001 vs 900000. An exact equality here is a test that fails on a slow machine.
- **Fix:** a window (`>= WATCHDOG` and `< WATCHDOG + 1000`), which still fails mutation #3.
- **Files:** `packages/backend/convex/vaultSweep.test.ts`
- **Commit:** `c44c5cd`

**4. [Rule 1 - Bug] Two existing fixtures were content-LIES that content-first recognition exposed.**
- **Found during:** Task 3
- **Issue:** the image test's fixture was the JS string `"\x89PNG not a sentinel"`, and a Blob
  encodes `U+0089` as UTF-8 `0xC2 0x89` — so those bytes are decodable text, not a PNG, and they
  honestly resolved to the `text` rail. Separately, printable `SMOKE::extract::` bytes sniff as
  `text`, so the audit `kind` on those rows changed from `"image"` to `"text"`.
- **Fix:** the PNG fixture now carries real PNG magic as a `Uint8Array`; the two SMOKE audit
  assertions were relabelled to the honest rail. Neither was suppressed or loosened — the sniff was
  right and the fixtures were wrong. (The `"PK\x03\x04 not a real docx"` fixture, by contrast, was
  already real ZIP magic — the control bytes are simply invisible when the file is read.)
- **Files:** `packages/backend/convex/vaultExtract.test.ts`
- **Commit:** `fa564c4`

### Choices inside the plan's latitude (not deviations)

- **The ZIP fixtures use a ~35-line STORE-method writer, not `fflate`'s `zipSync`.** The plan said
  to build fixtures with `zipSync`, but `fflate` is a dependency of `@pikar/vault` ONLY — the
  arrangement that keeps it out of the V8 Convex bundle — so it does not resolve from
  `@pikar/backend` (verified with a throwaway probe test). Adding a devDependency to build three
  fixtures is a lockfile change to save thirty lines, and a lockfile change in a tree with two
  other lanes merging is a coordination event. Marked with a `ponytail:` comment naming the
  upgrade path.
- **One prose mention of `extractionKindFor` survives in `vault.ts`** — the comment that explains
  the shape being deleted and why it stranded the `.xlsm`. The plan's `grep -c "extractionKindFor"`
  → 0 was a proxy for "no call site"; `grep -c "extractionKindFor("` across `convex/*.ts` is 0
  except for the static scan's own needle in `vaultExtract.test.ts`. Deleting the sentence would
  delete the record of the root cause.
- **The `sniffContainer` import is used only inside the image branch**, exactly as specified, to
  recover a mediaType when the declared MIME is empty or wrong. That fallback is NOT observable
  offline (the hosted call fails closed at `getActiveSkill` before the mediaType matters), so it is
  covered by construction and by the source, not by an assertion.
