```typescript
export function extractOfficeText(bytes: Uint8Array): { text: string } {
  let entries: Record<string, Uint8Array>;
  try {
    entries = unzipSync(bytes);
  } catch {
    throw new Error("office_parse_failed: not a zip");
  }
  if (entries["word/document.xml"]) return { text: docxText(entries) };
  if (entries["xl/workbook.xml"]) return { text: xlsxText(entries) };
  if (entries["ppt/presentation.xml"]) return { text: pptxText(entries) };
  const odf = entries["mimetype"] && strFromU8(entries["mimetype"]).trim();
  if (odf?.startsWith("application/vnd.oasis.opendocument.")) return { text: odfText(entries) };
  if (entries["META-INF/container.xml"]) return { text: epubText(entries) };
  throw new Error("office_parse_failed: unrecognized zip");
}
```

Write `rawText.test.ts` FIRST. Dep-free, no fixtures on disk — the OLE2 buffer is **synthesized
in-test** (RESEARCH §6, the locked convention).

`rtfText(bytes)`:
- `{\rtf1\ansi\deff0 Hello world}` → `"Hello world"`.
- `{\rtf1 A\par B}` → `"A"` and `"B"` on separate lines (`\par` is a break, not deleted text).
- `{\rtf1 {\*\generator Riched20}Real text}` → `"Real text"` — the `{\*\…}` destination group and
  everything inside it is dropped, not flattened.
- `{\rtf1 caf\'e9}` → `"café"` (hex escape unescaped).
- Escaped literals `\{`, `\}`, `\\` survive as `{`, `}`, `\`.
- Nested groups `{\rtf1 {\b bold} plain}` → both `"bold"` and `"plain"` present.
- Non-RTF bytes → throws `raw_parse_failed: not rtf`.

`markupText(html)` (takes a **string**, since both the EPUB walker and the markup rail already
have decoded text):
- `<p>Hi</p><p>There</p>` → `"Hi"` and `"There"`, newline-separated.
- `<script>alert(1)</script><p>Safe</p>` → contains `"Safe"`, does **not** contain `"alert"`.
- `<style>.a{color:red}</style><p>Safe</p>` → does not contain `"color:red"`.
- `<!-- secret --><p>Safe</p>` → does not contain `"secret"`.
- `&amp;` / `&#65;` / `&#x41;` decode.
- Attribute values are NOT emitted as text (`<img alt="x" src="y">` yields neither `"y"` nor a
  tag fragment).
- Runs of whitespace collapse; the result has no leading/trailing whitespace.

`oleText(bytes, kind)` where `kind` is `"doc" | "ppt"`:
- Synthesize an OLE2 buffer: the 8-byte signature `D0 CF 11 E0 A1 B1 1A E1`, some padding, a
  UTF-16LE stream-name region containing `"WordDocument"`, then a CP1252 run
  `"The quarterly report is attached."`, then some `0x00`-heavy binary padding →
  `oleText(bytes, "doc")` contains the sentence.
- A UTF-16LE body run (`"Board minutes 2026"` encoded UTF-16LE) is recovered too — both encodings
  in one file are both found.
- **Noise stop-list:** the same buffer with `"Root Entry"`, `"WordDocument"`, `"1Table"`,
  `"Data"`, `"\x05SummaryInformation"`, `"\x05DocumentSummaryInformation"`, `"ObjectPool"`,
  `"CompObj"` present → NONE of those strings appear in the output, while the real sentence does.
  (This is the test that stops the sweep from emitting the file's own plumbing as document text.)
- **Minimum run length:** a 3-character printable island between binary is dropped; a
  4-character one is kept.
- PPT: a buffer containing `"PowerPoint Document"` plus a CP1252 run `"Slide one heading"` and a
  UTF-16LE run `"Slide two heading"` → `oleText(bytes, "ppt")` contains both, and does not
  contain `"PowerPoint Document"` or `"Current User"` or `"Pictures"`.
- A buffer with no printable runs at all → throws `raw_parse_failed: no text recovered`.
  **Failing honestly beats returning `""`**, which downstream would store as a `ready` document
  with 0 chars — the exact silent-plausible failure this phase exists to remove.
- Determinism: two calls on the same bytes give byte-identical output.
  </behavior>

```typescript

export function markupText(html: string): string;
```

- `rtfText`: decode as latin1/CP1252-ish via `TextDecoder("windows-1252")` (natively available;
  do not hand-roll a code-page table). Then, in order: drop `{\*\…}` destination groups by
  scanning brace depth (a regex cannot balance braces — write the ~12-line depth scanner, it is
  the boring correct choice); replace `\par`/`\line`/`\sect` with `\n`; unescape `\'hh` hex;
  unescape `\{ \} \\`; strip remaining `\word` control words and their optional numeric argument
  and one following space; drop bare `{`/`}`; collapse whitespace runs. Throw
  `raw_parse_failed: not rtf` if the input does not start `{\rtf`.
- `markupText`: remove `<script …>…</script>`, `<style …>…</style>` and `<!-- … -->` **bodies
  first** (order matters — strip tags first and you inline the script source as text), then strip
  remaining tags, then `decodeEntities`. `decodeEntities` already exists in `officeText.ts` —
  **move it to `rawText.ts` and have `officeText.ts` import it from there.** One entity decoder,
  two callers; do not copy it. (`officeText.ts` importing from `rawText.ts` is safe: `rawText.ts`
  is dep-free, so it adds nothing to what the subpath already pulls.)
- `oleText`: scan for printable runs in BOTH encodings and concatenate.
  - CP1252 run: a maximal span of bytes in `0x20-0x7E` plus `0x09/0x0A/0x0D` and the printable
    CP1252 high range, length ≥ 4.
  - UTF-16LE run: a maximal span of `(printable byte, 0x00)` pairs, length ≥ 4 characters.
  - Emit runs in **byte-offset order** (that is what makes it deterministic and roughly
    document-ordered — Word 97 body text is largely contiguous).
  - Apply the stop-list **exactly**: drop any run that equals, or after trimming equals, one of
    `Root Entry`, `WordDocument`, `1Table`, `0Table`, `Data`, `SummaryInformation`,
    `DocumentSummaryInformation`, `PowerPoint Document`, `Current User`, `Pictures`,
    `ObjectPool`, `CompObj`, `MsoDataStore`. Compare after stripping a leading `\x05` (the
    `SummaryInformation` streams carry it — RESEARCH §6). Match on the whole run, not a substring:
    a substring match would delete a sentence that happens to contain the word "Data".
  - Dedupe consecutive identical runs (OLE2 repeats names), join with `\n`.
  - Throw `raw_parse_failed: no text recovered` when nothing survives.
  - **Required `ponytail:` block** naming the ceiling verbatim from RESEARCH §6: this is a
    printable-run sweep, deliberately imperfect — no field codes, no table structure, no reading
    order guarantee. A downstream LLM structures the text; we are not round-tripping the file.
    Upgrade path: `word-extractor` for DOC, SheetJS for PPT/XLS, if fidelity complaints surface.

Barrel: export `rtfText`, `markupText`, `oleText` from `packages/vault/src/index.ts`. `oleText`
