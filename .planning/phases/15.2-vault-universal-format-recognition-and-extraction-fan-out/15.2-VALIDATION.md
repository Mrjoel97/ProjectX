## Manual-Only Verifications

Three of the seven success criteria **cannot** be closed offline. This is not a gap to be
engineered away — it is a property of the subsystem, and the playbook records two consecutive
incidents (Pitfall 9, then the 480 s timeout) where a green offline suite sat on a production path
that could never execute.

| Behaviour | Criterion | Why manual | Test instructions |
|-----------|-----------|------------|-------------------|
| SheetJS resolves real named exports inside the deployed Convex bundle | SC#3 | Node/vitest recover CJS named exports via `cjs-module-lexer`, so a broken import shape looks **fine offline** and fails only when deployed (Pitfall 9, verbatim precedent) | Upload a legacy `.xls` to the live deployment; assert the row reaches `ready` **and that numeric cell values appear in `text`** — headers alone means the parser silently degraded |
| Scanned-PDF output is VERBATIM, not a summary | SC#5 | Offline tests prove batch *shape* (count, order, reassembly) but cannot prove the model transcribed rather than digested — that needs a real model on a real scan | Re-extract the known 12-slide deck currently at 2,161 chars. Assert `textChars` is **materially higher** and the text contains slide-level detail, not "Here's a breakdown…" |
| The owner's stuck `.xlsm` recovers | SC#7 **(PHASE GATE)** | Live-only by definition — the row exists only on the deployment | From `packages/backend`: `npx convex run vaultSweep:runSweep`. Assert the `.xlsm` row (`application/vnd.ms-excel.sheet.macroEnabled.12`, 803,281 bytes, created 2026-07-26T21:33) reaches `status: ready` with **non-zero `textChars`** and no `failureReason` |

**Offline green does NOT close this phase.** The gate is the deployed run.
