## The spike — and why the control is the real result

**Run before the parser existed**, so a failure would have cost a dependency revert, not a wasted
module. Rebuilt with Convex's exact node-action flags, read out of
`convex/dist/esm/bundler/debugBundle.js` (`innerEsbuild`) and the `platform: "node"` call site in
`cli/lib/config.js` — `format:"esm"`, `conditions:["convex","module"]`, `splitting:true`,
`treeShaking`, `minifyIdentifiers`, `keepNames`; no `convex.json`, so no external-package
allow-list. esbuild 0.27.0.

| Probe | Chunks | Namespace keys | Result |
| --- | --- | --- | --- |
| SheetJS **STATIC** import | 1 | **19** — `CFB, SSF, default, parse_xlscfb, parse_zip, read, readFile, readFileSync, set_cptable, set_fs, stream, utils, write, …` | `read` = `function`, `utils.sheet_to_csv` = `function` |
| SheetJS **dynamic** `await import()` | 3 | **19** — also survives | passes |
| **CONTROL: `pdf-lib` dynamic** | 3 | **1** — `default` only | `PDFDocument` = **`undefined`** |

**The control is the point.** Without it, "SheetJS was fine" and "my probe cannot detect a collapse"
produce identical output. The known-broken case still collapsed under the identical harness, so the
SheetJS result is a measurement rather than a reassurance.

### Pitfall 9's predictor was WRONG, and is now corrected

The plan assumed SheetJS was "a CJS-first package of the same generation and shape" as `pdf-lib`.
**It is not.** The manifest is the whole story:

| Package | `main` | `exports` map | ESM build |
| --- | --- | --- | --- |
| `pdf-lib` | `cjs/index.js` | **NONE** | none |
| `xlsx` 0.20.3 | `xlsx.js` | **YES** — `"import": "./xlsx.mjs"` | **yes** |

So SheetJS is the **`unpdf` case**, and it survives *both* import forms. **The discriminator is the
package manifest, not the import form.** That rule is worth more to this repo than the SheetJS
result, so it was promoted **out of the phase narrative** into `## Invariants — what must never
break` and `## Dependencies & blast radius`, where someone adding a dependency will actually meet
it. A rule only a SUMMARY reader finds is not a rule.

The static import was kept regardless: it is the shape that was actually proven, it costs nothing,
and a version bump could drop the ESM build without a single test going red.

## The hazard the plan did not predict

**SheetJS's `read()` falls back to a DSV/plain-text guesser for unrecognised bytes.** Measured: 64
bytes of noise come back as a workbook holding **one cell of mojibake** — *non-empty*, so it clears
`empty_extraction` and lands as a `ready` document. That is a plausible failure, the exact shape
this phase exists to delete, and it would have shipped.

Fixed at the trust boundary by reusing what already exists (rung 2): `sniffContainer` — dep-free,
already on the barrel — gates on `ole2`/`zip` magic so the fallback can never fire.

## Shape of the code

- **`xlsText` is subpath-only** (`@pikar/vault/xlsText`) — the `officeText` rule, for ~1 MB instead
  of a few KB. The barrel's NOTE now states the rule where someone would otherwise add the export.
- **The success signal is `okSheets`, a COUNT** (the 15.2-06 `okPages` rule). The `Sheet N` header
  is emitted **only for a sheet that yielded content** — so this is deliberately **not** a third
  instance of the `Slide N`/`Sheet N` false-ready family.
- Throws `xls_parse_failed: <reason>` — our string, never SheetJS's (§4). Never returns `""`.
- `sheet_to_csv({ FS: "\t" })` over a hand-rolled cell walk (rung 5), matching `xlsxText`'s house
  style so the model sees one convention for all spreadsheets.

- **Found during:** Task 3 (RED)
- **Issue:** the convex-test fixture must be SheetJS-written (VALIDATION's locked convention: no

  **Nothing in production imports `xlsx` from `@pikar/backend`.**
- **Commit:** `13f53a7`

**2. [Rule 1 - Bug] My own static scan matched the banned form inside a COMMENT.**
- **Found during:** Task 2 (GREEN)
- **Issue:** `xlsText.ts`'s header deliberately spells out `await import("xlsx")` so the next reader
  knows exactly what is forbidden — and the naive scan matched that prose and went red on a correct
  file.
- **Fix:** the scan strips line comments and asserts against **code**. Mutation-checked afterwards
  to confirm the lock still locks.
- **Commit:** `2a4a8da`

**3. [Rule 1 - Bug] A test assertion of mine was an aspiration, not the observed routing.**
- **Found during:** Task 3 (GREEN)
- **Issue:** I asserted a truncated `.xls` fails with `xls_parse_failed`. It fails with
  `unsupported_format` — halving the file removes the CFB directory sector, so `ole2Kind` cannot
  find `Workbook` and the dispatcher refuses one rail before `xlsText` is called.
- **Fix:** assertion corrected to the observed behaviour with the reason recorded in a comment
  ("do not fix this to the reason that reads better"), and 15.2-03's synthetic OLE2 fixture
  repurposed to cover the parser's own `xls_parse_failed` ending. Both endings now pinned.
- **Commit:** `9bb73a9`
