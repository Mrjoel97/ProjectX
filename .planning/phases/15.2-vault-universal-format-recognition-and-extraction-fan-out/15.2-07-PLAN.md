on a deployment before believing it works.**

generation and shape. Assume the same hazard until a deployed run says otherwise.

**Dependency, LOCKED (owner-approved 2026-07-27):**
- Pinned tarball from `https://cdn.sheetjs.com/` — the vendor's official channel.
- **NOT** npm `xlsx@0.18.5`, the last registry publish: CVE-2023-30533 (prototype pollution) and
  CVE-2024-22363 (ReDoS). This code parses untrusted uploads, so the registry version is not an
  option to "just try first".
- Pinned **EXACTLY**, no `^` (CLAUDE.md §6, doubly so for a non-registry dependency).
- Behind its **own subpath module** so ~1 MB enters only the one node action that needs it. The
  precedent and the reason: `officeText.ts` is subpath-only specifically to keep `fflate`
  structurally out of the V8 bundle (`packages/vault/src/index.ts` says so, and
  `vaultExtract.ts:24-25` is the import shape).
- **Considered and REJECTED:** consolidating all spreadsheet handling onto SheetJS and deleting the
  fflate XLSX path. It removes code but adds ~1 MB to a deliberately lean bundle, and the fflate
  path is shipped and tested. Do not revisit.

**Why a text sweep is NOT an option for BIFF** (this is what makes SheetJS load-bearing rather than
a nicety): numbers in a BIFF workbook are stored as binary doubles, so a printable-run sweep
recovers the column headers and silently loses **every value**. That fails PLAUSIBLY — a `ready`
document whose numbers are simply absent — which is worse than failing, and is the exact shape this
phase exists to delete. `oleText` (shipped in 15.2-02) must NOT be pointed at `.xls`.

**The bundling hazard, verbatim from the playbook (Pitfall 9, 2026-07-26):**
> `pdf-lib` ships `main: cjs/index.js` with **no `exports` map**; Convex bundles node actions with
> esbuild `platform: "node", format: "esm", splitting: true`; across a **dynamic-import chunk
> boundary** esbuild cannot synthesise a CJS module's named exports, so the namespace carried only
> `default` and `{ PDFDocument }` destructured to `undefined`. Node/vitest recover CJS named
> exports via `cjs-module-lexer`, so the dynamic import looked fine **offline** and died only when
> deployed.

The diagnosis method the playbook records, and which this plan must reuse: rebuild a probe with
**Convex's exact esbuild flags, read out of `convex/dist/esm/bundler/debugBundle.js`**, and inspect
the resulting namespace's keys.

**Where the branch goes:** `vaultExtract.ts`'s `"legacy_xls"` rail, which 15.2-03 landed as
`await fail("unsupported_legacy_spreadsheet")`. `resolveRail` already routes an OLE2 workbook there
from its own stream names (`ole2Kind` → `"xls"`), with no MIME type required.

**The existing static-scan precedent to mirror:** `vaultExtract.test.ts`'s
`describe("dispatcher source contract")` block, specifically
`test("pdf-lib is a STATIC import — a dynamic import() collapses to { default } in the Convex bundle")`.
