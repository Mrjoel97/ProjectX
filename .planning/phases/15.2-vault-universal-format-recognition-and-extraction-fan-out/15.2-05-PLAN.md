**There is no `textChars` field.** The phase docs say "non-zero `textChars`"; the schema stores

**Environment gotchas that have each cost a session before** — treat as preconditions, not advice:
- The Convex CLI must be invoked from `packages/backend`. Anywhere else it will not find the
  deployment.
- `npx convex dev` alone does **not** seed the skills registry. `pnpm dev` does. The ingest
  workflow's graph-extract step loads `graph-extractor` from the registry and **fails closed**
  (`NO_ACTIVE_SKILL`) when unseeded — which would land the row at `failed` for a reason that has
  nothing to do with this phase. Seed first, or misread the gate.
- A network blip can destabilise `convex dev` into a retry storm that surfaces as
  `InternalServerError` at $0 spend. If that happens: kill every convex process, start ONE clean
  `convex dev`, confirm it is stable, then retry. Do not interpret a retry storm as a phase failure.
- `UV_HANDLE_CLOSING` assertion noise from the Node process is benign.

**The `.xlsm` needs no model call.** It rides the `zip` rail → `extractOfficeText` → the ingest
seam. Expected spend for the recovery itself is $0 (the ingest workflow's embed + graph-extract
steps do cost a little). So a `daily_budget_exhausted` failure here would point at the budget rail,
not at extraction.
