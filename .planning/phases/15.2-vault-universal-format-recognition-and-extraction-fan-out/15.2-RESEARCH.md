## 2. ★ CENTRAL FINDING — the sniff cannot live at the scheduling gate

**This changes the plan shape from what the spec implies. Read this before partitioning waves.**

Magic-byte sniffing needs **bytes**. In Convex, `ctx.storage.get()` (which returns a Blob) is
**action-only** — queries and mutations get `getUrl`/`getMetadata` only. But all three scheduling
decisions happen where bytes are unreachable:

| Site | Runtime | Can read bytes? |
|---|---|---|
| `vault.ts:166` `vaultUpload` | `tenantMutation` | **No** |
| `vaultSweep.ts:34` `sweepPendingExtraction` | migration (mutation ctx) | **No** |
| `vaultSweep.ts:62` `retryExtraction` | `tenantMutation` | **No** |
| `vaultExtract.ts:180` `extractDoc` | `internalAction` | **Yes** (`:174`) |

So `sniffContainer(bytes)` **cannot** replace `extractionKindFor` at the gate. The fix must
**invert the scheduling logic** instead:

```
TODAY:     unknown kind  →  don't schedule       →  silent eternal pending
INSTEAD:   unknown kind  →  schedule extractDoc  →  action sniffs bytes  →  extract OR honest fail
```

This is both simpler and lazier than adding a sniff at three sites: the three `kind === null`
guards collapse into "schedule anyway", and `extractDoc`'s already-existing
`fail("unsupported_format")` at `:200` becomes **reachable** — which is why that line exists but
has never fired for the owner's `.xlsm`.

**Route caveat:** `extractionKindFor` returning `"transcribe"` selects `transcribeDoc` rather than
`extractDoc` (`vault.ts:170`). A permissive default must route to `extractDoc`, and the in-action
sniff must recognise audio/video containers and hand off (or fail honestly) rather than treating
them as documents. A `video/*` MIME still routes by MIME as today — only the **null** case changes.

**Client-side sniffing is NOT the answer.** `Dropzone.tsx` holds the real `File` and could sniff
before upload, but that is untrusted client input at a trust boundary (CLAUDE.md: "not lazy about
input validation at trust boundaries"). Client-side sniffing is acceptable only as a *fast
pre-upload error message*, mirroring how the size caps are already duplicated at
`Dropzone.tsx:26-27` — never as the authority.

## 3. The silent-skip blast radius is THREE sites, not one

The `kind === null` skip is duplicated. Fixing only the upload path leaves two live:

| Site | Current behaviour | Consequence |
|---|---|---|
| `vault.ts:167` | `if (kind !== null)` schedule; else nothing. Comment: *"Unrecognized formats stay storage-only"* | The owner's `.xlsm` — silent eternal pending |
| `vaultSweep.ts:35` | `if (kind === null) return;` | **The recovery sweep skips it too** — `runSweep` today would NOT rescue the stuck row |
| `vaultSweep.ts:63` | `if (kind === null) return { ok: false };` | **The user's Retry button silently no-ops.** Worst of the three: the user takes an action and nothing observable happens |

This is the CLAUDE.md §8 root-cause rule in miniature — one shared decision, three callers, and
patching only the reported path leaves the siblings broken. The planner should fix the *decision*
(a shared helper or an inverted default) rather than three call sites independently.

## 4. Magic-byte signatures

| Container | Signature | Notes |
|---|---|---|
| PDF | `25 50 44 46` (`%PDF`) | **Scan the first ~1 KiB** — leading junk before `%PDF` is legal and occurs in the wild |
| ZIP | `50 4B 03 04`; also `50 4B 05 06` (empty), `50 4B 07 08` (spanned) | All OOXML/ODF/EPUB are ZIPs |
| OLE2 / CFB | `D0 CF 11 E0 A1 B1 1A E1` | Legacy `.doc`/`.xls`/`.ppt`, and `.msg` |
| RTF | `7B 5C 72 74 66` (`{\rtf`) | |
| PNG / JPEG / GIF | `89 50 4E 47`, `FF D8 FF`, `47 49 46 38` | Existing `image/*` MIME path already works; sniff is confirmation only |
| text | valid UTF-8, ≥95% printable in first 4 KiB | Must tolerate a UTF-8 BOM (`EF BB BF`) |

**ZIP second-stage discrimination** (do this from entry names, per CONTEXT.md's locked decision):

| Marker entry | Format |
|---|---|
| `word/document.xml` | DOCX / **DOCM** |
| `xl/workbook.xml` | XLSX / **XLSM** ← the owner's file |
| `ppt/presentation.xml` | PPTX / PPTM |
| `mimetype` (first entry, stored uncompressed) = `application/vnd.oasis.opendocument.*` | ODT / ODS / ODP |
| `META-INF/container.xml` | EPUB |

**fflate note:** `unzipSync(bytes)` decompresses **everything** into memory. `officeText.ts:88`
already does this. For discrimination we only need the *entry list*, so a cheap path exists —
`fflate` exposes `unzipSync(bytes, { filter })` to decompress selectively while still enumerating.
Worth using: at the 100 MiB cap (200 MiB in Phase 2) a full decompress of a large workbook is the
memory pressure the playbook already flags under *Large-doc extraction memory/time*.

> `.xlsm` is a **ZIP**, structurally identical to `.xlsx`. It needs **no new parser** — only
> routing. That is why this defect is a one-line-class bug wearing a large costume.

## 5. ★ SheetJS — HIGHEST RISK, must be a SPIKE not an assumption

**OPEN — not resolved by this research.** The planner MUST schedule this as an explicit spike task
with a deployed verification, not fold it into an implementation task.

Why it is the riskiest item in the phase: **Pitfall 9** (`vaultExtract.ts:112-119`, playbook
2026-07-26) burned this exact subsystem eleven days ago. `pdf-lib` ships `main: cjs/index.js` with
**no `exports` map**; Convex bundles node actions with esbuild `platform: "node", format: "esm",
splitting: true`; across a **dynamic-import chunk boundary** esbuild cannot synthesise a CJS
module's named exports, so the namespace carried only `default` and `{ PDFDocument }` destructured
to `undefined`. Critically:

> Node/vitest recover CJS named exports via `cjs-module-lexer`, so the dynamic import looked fine
> **offline** and died only when deployed. The test suite passed against a production path that
> could never run.

SheetJS is a CJS-first package of exactly the same generation and shape. The planner must assume it
has the same hazard until a deployed run proves otherwise.

**Spike acceptance criteria:**
1. Declare the pinned CDN tarball in the pnpm workspace and confirm it resolves offline.
2. Import it **statically** at module top level (the shape that works for `pdf-lib`/`llm.ts`).
3. Reproduce the bundle offline using **Convex's exact esbuild flags**, read out of
   `convex/dist/esm/bundler/debugBundle.js` — the method the playbook records for the pdf-lib
   diagnosis — and assert the namespace carries real named exports, not just `default`.
4. Add a static scan to the test file asserting *no dynamic import of the parser and a static one
   present*, mirroring the existing `pdf-lib is a STATIC import` scan in `vaultExtract.test.ts`.
5. **Prove it on the deployment.** Offline green is explicitly not evidence here.

**Bundle-size caveat:** SheetJS is ~1 MB. It must sit behind its own subpath module (the
`@pikar/vault/officeText` precedent) so it enters only the one node action that needs it. If the
spike shows the bundle cannot carry it, the documented fallback is to fail `.xls` honestly with a
"convert to .xlsx" remedy — which the never-silent guarantee (§3) already handles gracefully. **The
phase does not collapse if the spike fails**; only criterion 3 narrows. Plan it so the spike can
fail without blocking the other six criteria.

## 6. Legacy OLE2 text sweep (DOC / PPT)

No dependency needed — Word and PowerPoint store body text as text.

- **Word 97-2003:** body text lives in the `WordDocument` stream, largely contiguous, CP1252 or
  UTF-16LE.
- **PowerPoint 97-2003:** text sits in `TextBytesAtom` (CP1252) / `TextCharsAtom` (UTF-16LE) records.
- **Approach:** scan for printable runs in both encodings, minimum run length ~4, concatenate.
- **Noise stop-list needed** for OLE2 structural names that will otherwise appear in output:
  `Root Entry`, `WordDocument`, `1Table`, `Data`, `SummaryInformation`,
  `DocumentSummaryInformation` (note the `\x05` prefix on the last two), `PowerPoint Document`,
  `Current User`, `Pictures`, `ObjectPool`, `CompObj`.
- **Fidelity bar:** deliberately imperfect. A downstream LLM structures the text; we are not
  round-tripping the file. Mark with a `ponytail:` comment naming the ceiling and the upgrade path
  (`word-extractor` / SheetJS) if fidelity complaints surface.
- **Fixture:** synthesize the OLE2 header + a stream containing known text in-test. No binary
  fixture in the repo (the Lane-2 precedent, `officeText.test.ts`, builds every fixture with
  `zipSync`/`strToU8`).

## 7. Per-page PDF fan-out

Current hosted path, `vaultExtract.ts:134-148`:
1. `getDocumentProxy(bytes.slice())` — **the `.slice()` is load-bearing.** pdf.js *detaches* the
   buffer it is handed; passing the original leaves the later `slicePdfToPageCap` reading a zeroed
   buffer. Already caught once offline (`:136-137`). Preserve this on every new path that touches
   bytes twice.
2. Garbage-text-layer heuristic: `nonSpaceChars / totalPages >= MIN_CHARS_PER_PAGE` (25).
3. Hosted fallback: `slicePdfToPageCap` (pdf-lib `copyPages`, `:121-128`) → **one** `generateText`
   call with the whole PDF as one file part → the summarisation defect.

**The change:** `slicePdfToPageCap` already proves `copyPages` works; emitting N one-page documents
is the same call in a loop. Then batch. `extractHosted` (`:85-105`) is already a standalone helper
taking `(ctx, bytes, mimeType)` — it can be called per page with **no signature change**, which is
the cheapest possible fan-out.

- **Bounded concurrency** ~6, sequential across batches. `Promise.all` per batch.
- **Ordered reassembly** by page index — do not rely on completion order.
- **Cost:** `extractHosted:100-103` already prices and records spend *per call*, so per-page spend
  accumulates correctly with no new accounting. Verify the guardrails daily-budget interaction:
  50 pages = 50 `recordSpend` calls where there was 1.
- **Budget:** ~10 s/page × 50 pages ÷ 6 = 9 batches ≈ 90 s, inside the 480 s `CALL_TIMEOUT_MS`
  (`:65`) and Convex's 10-minute node-action limit.
- **`CALL_TIMEOUT_MS` is per-call**, so each page gets its own 480 s — the *action* ceiling becomes
  the binding constraint, not the call timeout. Flag for the planner: a per-page timeout well below
  480 s (say 60 s) is now appropriate, since one stuck page must not consume the whole action.
- **§5 satisfied by reuse:** `ATTACHMENT_EXTRACTOR_SKILL` (`:15`, `:90-92`) is already loaded from
  the registry and its contract is written for a single page. No new skill row, no prompt change.

## 8. The watchdog — follow the existing pattern

Two precedents to mirror rather than invent:

- **`vaultIngest.onIngestComplete`** (`vaultIngest.ts:56-76`) — the `processing` guarantee. Flips
  only a doc *still* in `processing` (idempotent; a racing success is untouched).
- **`vaultIngest.retryStuckIngests`** (`:85-102`) — an `internalMutation` with an `olderThanMs`
  cutoff and a **full table scan**, carrying an explicit `ponytail:` comment that there is no
  `by_status` index and that this is fine for an occasional ops sweep.

The new watchdog is the same shape for `pending_extraction` / `extracting`, threshold 15 min
(CONTEXT.md). Reuse the `vaultSweep.ts` migration idiom (`migrations.define` + `migrations.runner`,
`:26-47`) so it is resumable and batched.

**OPEN — needs a decision the planner should make explicit:** there is **no cron registration**
visible in `vaultSweep.ts`; `runSweep` is an operator one-shot (`npx convex run vaultSweep:runSweep`,
`:17-18`). A watchdog that only runs when an operator types a command is not a watchdog. The planner
must either (a) register a cron entry, or (b) scope it honestly as operator-triggered and say so in
the playbook. **(a) is the intent of success criterion 4** — "no document ever parks silently" is
not achieved by a manual command.
