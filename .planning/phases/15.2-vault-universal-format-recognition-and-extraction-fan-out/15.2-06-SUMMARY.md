# Phase 15.2 Plan 06: Per-Page Fan-Out Summary

**The 12-page scanned deck that returned 2,161 characters of "here's a breakdown" now returns 7,868
characters of the deck's own words, `Page 1` through `Page 12`, for 13¢ — with the
`attachment-extractor` prompt byte-unchanged. The prompt was always right; the input was wrong.**

## Performance

- **Duration:** ~55 min (including the live run and one blocking checkpoint)
- **Tasks:** 4 (one a blocking human-verify gate)
- **Files modified:** 6 (1 created)

## What changed

`extractPdf`'s hosted fallback used to be two lines: slice the PDF to the page cap, send the whole
thing as **one** file part. The `attachment-extractor` skill's contract is written for *a single
image or document (PDF page…)* — so a 12-page deck asked it to do something its prompt never
promised, and it did the reasonable thing: it digested.

Now:

```
pdfPages(bytes, 50) → N one-page PDFs from ONE loaded source
fanOutPages(N, i => extractHosted(ctx, pages[i], "application/pdf"), {6, 60s, 7min})
okPages === 0 → throw → extractDoc's existing catch → markFailed
```

`extractHosted`'s **signature is unchanged** and reused per page. **No new skill row, no prompt
change** — CLAUDE.md §5 is satisfied by reuse, which is the whole reason this fix is cheap.

| Constant | Value | Why |
| --- | --- | --- |
| `PAGE_BATCH_SIZE` | 6 | Also the **OCC-contention width**: each page is its own `recordSpend` write against ONE keyless `dailySpendCents` window |
| `PAGE_TIMEOUT_MS` | 60 s | `CALL_TIMEOUT_MS` (480 s) is **per call** and was tuned for one whole-document call; under fan-out one stuck page would eat the 10-min action ceiling |
| `FANOUT_BUDGET_MS` | 420 s | Whole-fan-out budget under Convex's 10-min node-action limit |
| `VAULT_EXTRACT_PAGE_CAP` | 50 | Unchanged, still binding — `pdfPages` applies it |

## Deviations from Plan

### Auto-fixed

**1. [Rule 3 - Blocking] `const { text, okPages }` collided with `extractPdf`'s existing `text`.**
- **Found during:** Task 2 GREEN
- **Issue:** the plan's literal wiring snippet destructures `text`, but `extractPdf` already binds
  `const { totalPages, text } = await extractText(...)` in the same scope. esbuild refused the whole
  module (`The symbol "text" has already been declared`), taking **all 32 tests** red — a transform
  failure, not a logic failure.
- **Fix:** `const { text: transcribed, okPages }`. One rename, no behaviour change.
- **Commit:** `a461765`

**2. [Rule 1 - Bug] An existing test asserted the OLD failure string and would have gone red on `main`.**
- **Found during:** Task 2
- **Issue:** *"a no-text-layer scan trips the garbage heuristic and routes HOSTED"* asserted
  `failureReason` matches `/NO_ACTIVE_SKILL/`. Under the fan-out, `fanOutPages` absorbs each page's
  throw into a marker (§4 — the reason must never carry an SDK string), so the reason is now our own
  `hosted_extract_failed`. Left alone this reads as a regression in the fix.
- **Fix:** the test was **inverted, not deleted** — it now asserts the branch was still taken, that
  the row is TERMINAL `failed`, and that it is not left at `pending_extraction`/`extracting`. The
  comment says why the string changed.
- **Commit:** `b911206`
