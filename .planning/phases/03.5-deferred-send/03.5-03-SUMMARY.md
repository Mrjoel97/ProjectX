# Phase 3.5 Plan 03: Deferred Send — executePlan Scheduler Branch Summary

**The load-bearing structural change: `executePlan` now SCHEDULES (never starts) when the plan carries a future `sendAt` — extracting the SOLE `workflow.start(deliverApprovedPlan)` into `startFanout` so both the immediate approve path and the `startScheduledDelivery` callback share one call site — plus `cancelScheduledPlan` (CAS + refs-only audit), the `setPlanSendTime` picker writer, and the PLAN-card date picker / ScheduledCard / Canceled surface. "Approve once" becomes "approve once, fires at the requested moment, cancellable until then."**

## Accomplishments
- **`startFanout` extraction (SC3 invariant):** the `workflow.start(deliverApprovedPlan)` + status→delivering block moved into a module-level `startFanout(ctx, {planId, tenantId, requestIds, correlationIds, planCid})` — the SOLE real `workflow.start(` in `cockpit.ts`, now shared by BOTH the immediate approve path and the scheduled callback (no second call site added).
- **`executePlan` scheduled branch:** after the UNCHANGED seed loop (requests rows frozen AT APPROVE), a future `plan.sendAt` → `ctx.scheduler.runAt(sendAt, internal.cockpit.startScheduledDelivery, args)` + status `scheduled` + stored `scheduledFunctionId`, returning `{ok:true, scheduled:true}` (nothing sends before fire, SC3); `sendAt` unset OR ≤ now → immediate `startFanout` (byte-identical to today).
- **`startScheduledDelivery` internalMutation:** at the requested moment fires the SAME frozen fan-out — a dead token at fire inherits `awaiting_reauth`/DLQ/telemetry FOR FREE (SC4).
- **`cancelScheduledPlan` tenantMutation:** CAS-guarded on `status==='scheduled'` (a non-scheduled plan returns `{alreadyResolved:true}` — the guard that keeps `ctx.scheduler.cancel` from throwing on an already-fired id), then `scheduler.cancel` → status `canceled` → ONE refs-only `plan.canceled` audit (`payload {planId}` ONLY, insert-only §3/§4); idempotent + tenant-guarded.
- **`plans.setPlanSendTime` tenantMutation:** the PLAN-card date picker's tenant-guarded writer — `patch {sendAt}`, undefined CLEARS the field → immediate.
- **`cards.tsx` surface (SC2):** the PLAN card gained a native `<input type="datetime-local">` bound to `plan.sendAt` (epoch↔local wall-clock via the browser tz — no hand-rolled tz math) + a "Send immediately" clear + the resolved ABSOLUTE time/tz shown before the single Approve; `ScheduledCard` ("Scheduled for <abs, tz>" + Cancel), `CanceledCard`, and `CardList` dispatch (`scheduled`→ScheduledCard, `canceled`→CanceledCard, DraftCard suppressed under both).
- **Offline fake-timer scheduler tests:** arm→fire, cancel-before-fire (refs-only audit + nothing sent + double-cancel no-op + cross-tenant refused), immediate-path-unchanged, `setPlanSendTime` tenant-guard — via `vi.useFakeTimers()` + `t.finishInProgressScheduledFunctions()`.

## Decisions Made
- **`startFanout` is a plain module-level helper (not a Convex fn):** a mutation ctx works identically whether it comes from the tenantMutation (`executePlan`) or the internalMutation (`startScheduledDelivery`), so one helper keeps the `workflow.start` call site literal and singular. Typed with the generated `MutationCtx` (the tenant wrapper's ctx is structurally assignable to it).
- **Cancel audit correlationId = `plan.correlationId ?? String(planId)`:** a scheduled plan has no pipeline `correlationId` yet (set only on the delivering transition), so the planId string is the stable ref for the `plan.canceled` row — and carries no PII.
- **`withDelivery()` registers `auditCounts`:** the cancel path writes a real audit row and the SOLE audit-insert surface counts the aggregate, so the component must be registered for the in-test insert to run (the same relative-import pattern `cockpitTools.test.ts` uses).
