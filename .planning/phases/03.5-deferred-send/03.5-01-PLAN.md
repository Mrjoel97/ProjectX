  <files>packages/core/src/emailIntent.ts, packages/core/src/emailIntent.test.ts</files>
  <behavior>
    parseSendTime(text: string, nowMs: number, ianaTz: string): SendTimeParse where
      SendTimeParse = { kind: "resolved"; epochMs: number } | { kind: "ambiguous" } | { kind: "past" } | { kind: "none" }
    - "" / whitespace / a message with no time expression → { kind: "none" }  (SC1 immediate default)
    - "tomorrow 9am" (relative to nowMs+tz) → resolved epoch, > nowMs
    - "in 2 hours" → resolved epoch ≈ nowMs + 7_200_000 (tz-independent offset)
    - "Monday" / "Monday 9am" → next Monday at that time (or 09:00 default), resolved, > nowMs
    - "4pm" → today at 16:00 in ianaTz if still future, else tomorrow 16:00 (a concrete am/pm anchor is NOT ambiguous)
    - "4am" with NO day and NO am/pm-vs-day disambiguation the grammar can't anchor → { kind: "ambiguous" } (RE-ASK, never guess — locked bound 3)
    - a concrete time that resolves to <= nowMs (+ a small epsilon) → { kind: "past" } (RE-ASK)
  </behavior>
  <action>
    Append to packages/core/src/emailIntent.ts a pure, deterministic parser (RESEARCH Pattern 5).
    - Add the SendTimeParse union type + `export function parseSendTime(text, nowMs, ianaTz)`.
    - PURE: never call Date.now / new Date() without an explicit ms — the caller injects nowMs and
      ianaTz. Compute wall-clock in the given IANA zone using Intl.DateTimeFormat with timeZone set
      (format the parts of nowMs in ianaTz to get "now" in the user's local wall clock, build the
      target wall clock, then convert back to epoch ms). Do NOT add a dependency (ponytail rung 6/7 —
      a ~60-line reducer over the small grammar, per RESEARCH "Don't Hand-Roll": no chrono-node).
    - Grammar (slice 1, minimal): relative "in N hours"/"in N minutes"; "today"/"tomorrow" +
      optional "at Ham"/"H:MMpm"; a bare "Ham"/"Hpm" (concrete am/pm → today-or-next-occurrence);
      weekday names ("Monday".."Sunday") + optional time (default 09:00). A bare hour with no am/pm
      and no day anchor → ambiguous. Anything unrecognized → none.
    - Resolved-in-the-past (<= nowMs + a small epsilon, e.g. 60_000) → past.
    - Colocate the tests in emailIntent.test.ts covering EVERY behavior case above (the VALIDATION
      Wave-0 gap). Use a FIXED nowMs + a fixed ianaTz (e.g. "America/New_York") so cases are
      deterministic; assert epoch values by reconstructing the expected wall clock, not magic numbers.
  </action>
