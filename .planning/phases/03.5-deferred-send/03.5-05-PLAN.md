<objective>
Turn the terminal `canceled` state into an opt-in re-schedule: a canceled plan can be given a new
future send time and re-approved, transitioning `canceled → proposed → scheduled` — re-arming the
same governed fan-out via the EXISTING `executePlan` scheduled branch, with content re-frozen at
re-approve. Doing nothing keeps `canceled` terminal.

Purpose: SCHD-01 refinement (the CONTEXT `<deferred>` "re-scheduling a canceled plan" item). The
halt-control promise stays intact — reschedule is an explicit user action, the re-armed plan is
cancellable again, and a past reschedule re-asks (never silently sends). Reuses `setPlanSendTime`
+ the single `workflow.start`/`scheduler.runAt` call site (grep-verified invariant, Plan 03).
Output: `reschedulePlan` mutation + orphan cleanup + the CanceledCard reschedule surface + tests.
</objective>
