# Phase 03.5 Plan 05: Reschedule a Canceled Send Summary

`reschedulePlan` turns the terminal `canceled` state into an opt-in re-arm: a new future time + re-approve routes `canceled → proposed → scheduled` through the EXISTING `executePlan` scheduled branch (content re-frozen at re-approve), with a past/absent time re-asking instead of silently sending.

## What was built

**Task 1 — `reschedulePlan` mutation (cockpit.ts, `bfdbdfa`)**
A `tenantMutation` mirroring `cancelScheduledPlan`'s shape: tenant-guard (throw "plan not found"), CAS on `status === "canceled"` (else `{ok:true, alreadyResolved:true}` — idempotent, canceled stays terminal on a no-op), a future-`sendAt` guard that returns `{ok:false, reason:"needs_future_time"}` and writes NOTHING on an absent/past time, deletion of the plan's orphaned `requests` rows (`by_plan` — all never-fanned-out "approved" orphans from the first arm, so `reportForPlan` stays honest), a flip to `"proposed"`, and ONE refs-only `plan.rescheduled` audit (`{planId}` only). It does NOT arm the scheduler — the re-approve re-seeds + re-arms via the existing `executePlan` branch (no new `workflow.start`/`scheduler.runAt` call site). Explicit return-type union dodges TS7022.

Four cockpit.test.ts cases (reuse `withDelivery()`/`seedSchedulable`/`listScheduled` + fake timers): reschedule happy path (arm → cancel → set new future time → reschedule asserts proposed + zero orphan rows + refs-only audit → re-approve asserts scheduled + exactly the recipient count of FRESH rows + a scheduler row → advance/finish asserts delivering), the re-ask (past sendAt → `needs_future_time`, status stays canceled, orphans not deleted, no audit), idempotent (proposed plan → `alreadyResolved`), and the tenant guard.

**Task 2 — CanceledCard reschedule surface (cards.tsx, `03034ef`)**
`CanceledCard` now takes `{plan, threadId}` (CardList dispatch updated) and renders a `datetime-local` picker (reusing `toLocalInputValue`/`formatAbsolute` + `setPlanSendTime` — one source of truth, `plan.sendAt`) plus a busy-guarded Reschedule button, disabled unless a future time is set. Its handler calls `reschedulePlan` then, on `ok`, `executePlan`; a `needs_future_time` result surfaces an inline `role="alert"` re-ask ("Pick a future time to reschedule.") and does NOT send. On success the row flips proposed→scheduled and the card re-renders as `ScheduledCard` (Cancel available again) — no extra client state. The playbook (`cockpit.md`) gained the canceled-terminal-unless-rescheduled invariant and a `Last verified: 03.5-05` bump in the same commit (§9, cards.tsx watch-protected).
