## Decisions Made
- **Reach the ScheduledCard via the datetime picker, not the NL `sendTime=` op.** `SMOKE_NOW_MS` is pinned to `2020-01-01 12:00 UTC`, so `sendTime=in 2 hours` resolves to a 2020 instant; `executePlan` compares `sendAt` to the REAL `Date.now()` (2026) → treats it as past → immediate branch (no ScheduledCard, offline OR live). The NL op still runs first to prove the fast path resolves a concrete absolute time into the picker before Approve (and satisfies the `contains: "sendTime="` artifact); the PLAN-card `datetime-local` picker (`setPlanSendTime`, which has NO NL past-guard — it is the confirm source-of-truth) then sets a real-future `2035` time so Approve actually schedules. Without this, the spec would assert a ScheduledCard that never appears.

## Deviations from Plan
- **[Rule 3 — Blocking] The scheduled-flow assertion cannot be driven by `sendTime=in 2 hours` alone.** The plan's Task 1 action reads "drive `sendTime=in 2 hours` → … Approve → ScheduledCard". The pinned 2020 SMOKE clock makes that resolved instant real-past, so Approve would take the immediate branch and render a REPORT, never a ScheduledCard — on both the offline `--list` load AND the deferred live verify-work run. Resolved by adding a real-future datetime-picker fill between the resolved-time assertion and Approve (the plan itself sanctions "or use the PLAN-card picker"). No production code changed; the spec is faithful to the SCHD-01 intent (resolved-abs-time-before-Approve → schedule → cancel, nothing sent). Documented as a Decision above.
