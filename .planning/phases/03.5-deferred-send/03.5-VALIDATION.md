# Phase 3.5 — Validation Strategy

> Deferred send composes onto the plan/approve/execute spine. SC1: optional NL time slot (absent → immediate). SC2: absolute time shown pre-Approve, ambiguous → re-ask. SC3: Approve SCHEDULES (not starts) — nothing sent before fire, single `workflow.start` call site intact, audit/telemetry/DLQ reused. SC4: cancellable-until-fire (audited); dead token at fire → `awaiting_reauth`.
> Load-bearing capability: testing Convex scheduled functions OFFLINE via vitest fake timers + `t.finishInProgressScheduledFunctions()`.

## Convex scheduled-function testing (offline, the pivotal capability)

convex-test drives the scheduler with vitest fake timers:
1. `vi.useFakeTimers()` before building the instance.
2. `executePlan` with a future `sendAt` → assert `status === "scheduled"`, `scheduledFunctionId` set, a `_scheduled_functions` system row exists, and **no `requests` row past `approved`** (SC3: scheduled, not started).
3. `vi.advanceTimersByTime(...)` + `await t.finishInProgressScheduledFunctions()` → `startScheduledDelivery` runs → `status === "delivering"` (reuse `withDelivery()`).
4. Cancel-before-fire: `cancelScheduledPlan` → `status === "canceled"`, scheduled system row gone, refs-only `plan.canceled` audit row; then advance timers + finish → assert **nothing sent**.
