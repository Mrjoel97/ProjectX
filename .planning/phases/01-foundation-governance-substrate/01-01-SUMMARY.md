## Decisions Made
- **TypeScript 7 dropped `baseUrl`/non-relative `paths`.** Removed them from all tsconfigs and rely on pnpm workspace symlinks + package `exports` for `@pikar/*` resolution — cleaner and works for both Convex esbuild and Next.
- **Local Convex dev deployment for codegen.** `npx convex dev --once --configure new --dev-deployment local --project pikar-ai` created a deployment non-interactively (already logged in), pushed the schema, installed all 5 components, and generated `_generated/` — no interactive cloud project setup and no auth gate.
- **Source-export resolution proven in schema.ts**, so no internal `tsc` build step for `packages/*` was needed (Open Question 3 resolved in favor of source-export).

## User Setup Required

A Convex dev deployment is required for codegen. On this machine it was created automatically (already logged in) as a **local** deployment. For a fresh clone / cloud deployment:
- Run `npx convex login` then `npx convex dev` in `packages/backend` (writes `CONVEX_DEPLOYMENT` to `.env.local` and `NEXT_PUBLIC_CONVEX_URL` to `apps/web/.env.local`).
- Set server secrets via `npx convex env set` (never Vercel); Vercel holds only `NEXT_PUBLIC_CONVEX_URL` + `CONVEX_DEPLOY_KEY`.
