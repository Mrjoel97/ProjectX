    feeds the model; raw addresses stay out.

    Add `export function buildCockpitTools(ctx, tenantId, planId)` returning the AI-SDK `tool()`
    set (import `tool` from `ai`). Each tool's `execute` reads the plan row via
    `ctx.runQuery(api.plans.byThread, ...)` as needed and calls the matching primitive:
    - `resolveContacts({ name })`: `internal.gmail.search` → on `{ok:false}` call `notify`
      (gmail_reconnect) and return a structured error string for the agent to ask; on ok,
      `rankCandidates` → `internal.plans.writeCandidates`; return a refs-only summary
      (counts/labels, NO addresses) so the model learns matches exist and the ResolutionCard
      renders (the human picks the chip → existing `resolveRecipients`).
    - `addRecipients({ addresses })` / `removeRecipient({ index })` / `setRecipients({ addresses })`:
      call `applyRecipientEdit` against the plan's current `recipients`; on a bounce, return the
      rejected tokens to the agent (re-ask) and do NOT patch; on ok, `patchPlan({ recipients })`.
      `removeRecipient` resolves the 1-based index → the address is substituted server-side
      (the model only ever knew `#index`).
    - `setSubject({ subject })` → `patchPlan({ subject })`; `setMode({ mode })` → `patchPlan({ mode })`.
    - `draftBody({ intent })`: `scanText(intent)` (fail-closed throw if `!ok`) →
      `internal.llm.draftCockpit({ tenantId, safeText, safeTextHash: contentHash(safeText), greetingName })`

      MUST precede the draftCockpit call (GRDL-01/02).

      row's recipients/mode/subject/body (structural facts from the row, never model args).
    Annotate explicit return types on the exported function + any new runQuery/runAction results
    (guidelines §96 — keep llm.ts out of the circular-inference cliff). Do NOT add a second
