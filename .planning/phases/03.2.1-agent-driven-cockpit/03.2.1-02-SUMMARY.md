## Accomplishments
- `buildRecipientView` projects recipients into `{ index, label }` rows where the label is the display name or a neutral `#<index> (no name)` placeholder — never the address. This is the §2-D enforcement point the Plan 03 recipient tool relies on: a raw email cannot reach the model's reasoning surface.
- `applyRecipientEdit` add/remove/set reducer: invalid addresses bounce into `rejected` and never enter recipients (the trust boundary); add/set dedupe case-insensitively via the existing `dedupeAppend`; remove resolves a 1-based index and bounces out-of-range as `#<index>` rather than silently no-op'ing into a send.
- Reused the ONE shared `isValidEmail` regex (no second validator) and the existing `dedupeAppend` helper — the shortest correct diff.
- 100%-sampled (Nyquist truth #2) coverage: every recipient verb plus the no-`@` view invariant has an explicit test. 32 emailIntent tests / 59 core suite green; typecheck + biome clean.
