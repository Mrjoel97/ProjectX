## Decisions Made
- **resolveRecipients has no advance/draft tail.** The pick folds recipients + greetingName + wipes candidates; the next user turn drives the agent. This keeps it a thin fold and avoids re-implementing the deleted FSM's advance logic.
- **index.ts untouched.** `@pikar/core` re-exports emailIntent via `export *`, so removing symbols from the module drops them from the barrel automatically — no named-export edit needed (ponytail: no diff where none is required).
- **The E2E asserts card state, not prose.** The agent's replies vary; the plan-row-derived cards are stable. Turns are sequenced on the composer clearing (a prose-free send-complete anchor) to avoid a second-thread race before the threadId lifts.
