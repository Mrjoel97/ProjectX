## Decisions Made
- Sweep tests use the migration's documented one-off mode (`{cursor: null, oneBatchOnly: true}`) — one batch runs synchronously with zero component machinery; component registered anyway per plan instruction
- Card Retry rendered as a sibling absolutely-positioned button in a relative wrapper — nested interactive content inside the card `<button>` would be invalid HTML and break keyboard order; existing e2e card selectors stay intact
- E2E sentinel bytes are chained (`SMOKE::extract::SMOKE::graph::…`) so the extracted "text" is itself the ingest sentinel — the full post-seam walk (embed bypass, deterministic graph, ready) runs offline once Lanes 1/4 merge
- Ready status + deterministic entity chips serve as the "searchable" proof in the E2E (same evidence the existing paste test uses; the UI cannot know a docId to drive the `SMOKE::<docId>` search grammar, and hybrid retrieval quality remains the live smoke:vault gate's job)
