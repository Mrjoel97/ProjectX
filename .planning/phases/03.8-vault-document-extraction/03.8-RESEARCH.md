# Phase 3.8: Vault Document Extraction - Research

**Researched:** 2026-07-18
**Domain:** Document text extraction (PDF/DOCX/XLSX/PPTX/images/videos) in Convex actions, feeding the existing `vaultIngestText` seam
**Confidence:** HIGH (nearly everything verified in-repo or against official docs/npm; the two MEDIUM items are flagged)

## Summary

The phase is smaller than it looks because every hard part already exists in-repo: the seam
(`vault.ts vaultIngestText` docId path), the hosted OCR engine (`intake.ts extractVisual` —
already sends `application/pdf` file parts to gpt-4o-mini in production), the governance triad
(`guardrails.preCall`/`recordSpend`, verified call shapes below), the durable-retry pattern
(`vaultIngest.ts`), and a proven resumable batch mechanism for the sweep (`@convex-dev/migrations`,
installed and exercised since Phase 2). What's genuinely new is (a) a PDF text-layer parser,
(b) a pure-TS Office flatten, and (c) the Wave-0 contract stubs.

Two findings materially change the Wave-0 plan and MUST be honored: **(1) `vaultDocuments.status`
is a CLOSED union** in `schema.ts` (verified, line 443) — adding `extracting` is a required schema
edit, not an open string. **(2) `vaultIngestText` is a public `tenantMutation` that throws
UNAUTHENTICATED without a user identity** (verified in `lib/functions.ts requireTenant`) — a
scheduler-invoked extraction action **cannot call it**. Wave 0 must add an internal seam variant
(`internal.vault.ingestExtractedText({docId, tenantId, text})`, ~10 lines mirroring the existing
docId path) or every lane is blocked at integration.

**Primary recommendation:** Two tiny pinned deps total — `unpdf@1.6.2` (PDF text layer, Lane 1)
and `fflate@0.8.3` + a regex XML text-walk (all three Office formats, Lane 2, one approach).
Everything else is reuse: `extractVisual`'s shape for hosted OCR, the `attachment-extractor` skill
as-is (no new skill row, no skills.ts edit), `migrations` for the sweep, `pdf-lib` (already
installed) for PDF fixtures and page-slicing. Video (Lane 4, scope override 2026-07-18) adds
ZERO deps: the intake `transcribeAudio` pattern's endpoint accepts mp4/webm/mpeg containers
directly, and the vault's 8 MiB cap sits under the API's 25 MB limit.

### Pattern 1: The dispatcher action (Lane 1, mirrors intake.ts structurally)

`vaultExtract.ts` is `"use node"` and holds ONLY actions (intake.ts precedent — a second
`"use node"` module is fine as long as it never imports `llm.ts` internals and handlers carry
explicit `Promise<...>` return types, per the 02-06/§96 circular-inference mitigation).

```typescript
// convex/vaultExtract.ts — shape (Lane 1)
"use node";
export const extractDoc = internalAction({
  args: { vaultDocId: v.id("vaultDocuments"), tenantId: v.string() },
  handler: async (ctx, { vaultDocId, tenantId }): Promise<null> => {
    // 1. Governed gate BEFORE any work (verified shape, vaultIngest.ts:29):
    const gate: { ok: true } | { ok: false; reason: "kill_switch" | "daily_budget_exhausted" } =
      await ctx.runMutation(internal.guardrails.preCall, {});
    if (!gate.ok) { await ctx.runMutation(internal.vault.markFailed, { vaultDocId, reason: gate.reason }); return null; }

    // 2. Flip the visible pill (markExtracting is a Wave-0 internal mutation — "use node" files can't hold mutations)
    await ctx.runMutation(internal.vault.markExtracting, { vaultDocId });

    // 3. Load bytes from storage (NOT via args — node-action args cap at 5 MiB; vault cap is 8 MiB)
    const blob = await ctx.storage.get(storageId);  // storageId via internal.vault.getDoc-style read
    const bytes = new Uint8Array(await blob.arrayBuffer());

    // 4. SMOKE:: sniff FIRST (decodeUtf8 prefix — intake.ts:63/89 pattern), then dispatch:
    //    pdf    → text layer (unpdf) → garbage heuristic → hosted fallback
    //    image  → hosted (extractVisual shape verbatim)
    //    office → extractOfficeText (pure TS, no model, no spend)

    // 5. scanText FAIL-CLOSED on extracted output → on Err: markFailed + ONE refs-only audit row
    //    (intake.ts:182–194 ordering verbatim: audit "vault.extraction_failed" carries
    //    { vaultDocId, kind, reason } — never text)

    // 6. Refs/counts-only success audit: { vaultDocId, kind, path: "text_layer"|"hosted"|"office",
    //    piiCounts, charCount, truncated } — mirror intake.ts:201–207.

    // 7. THE SEAM — internal variant (public vaultIngestText throws UNAUTHENTICATED here):
    await ctx.runMutation(internal.vault.ingestExtractedText, { docId: vaultDocId, tenantId, text, truncated });
    return null;
  },
});
```

**Retry/durability:** schedule `extractDoc` via `ctx.scheduler.runAfter(0, ...)` from the
`vaultUpload` hook. For transient-failure absorption the laziest correct option is the
action-retrier-free one already proven in-repo: the model call itself carries `maxRetries: 1`
(SDK-level, intake.ts:99), and a thrown action marks nothing — so wrap the body in try/catch and
`markFailed` with a refs-only reason on any throw. A full `@convex-dev/workflow` per extraction
(like `vaultIngest.ts`) is the upgrade path if per-step durable retry proves necessary; for a
single-step extract it's ceremony. `ponytail:` comment the ceiling.

### Pattern 2: PDF text-layer-first with garbage heuristic (Lane 1)

```typescript
// Source: github.com/unjs/unpdf README (v1.6.2)
import { extractText, getDocumentProxy } from "unpdf";

const pdf = await getDocumentProxy(bytes);
const { totalPages, text } = await extractText(pdf, { mergePages: false }); // string[] per page
const joined = text.join("\n\n");
// Garbage/no-text-layer heuristic: scans yield ~0 chars/page; real text layers yield hundreds.
const MIN_CHARS_PER_PAGE = 25; // const, tuned generously low — false "garbage" just costs one model call
const hasTextLayer = joined.replace(/\s/g, "").length / Math.max(totalPages, 1) >= MIN_CHARS_PER_PAGE;
if (hasTextLayer) return { text: joined, path: "text_layer", costUsd: 0 };
// else: hosted fallback — slice to page cap with pdf-lib if totalPages > VAULT_EXTRACT_PAGE_CAP,
// then send the (possibly sliced) PDF bytes as a file part, extractVisual-style.
```

Chars-per-page is the standard heuristic (used by most RAG ingestion pipelines); also treat a
high replacement-char (`�`) ratio as garbage if observed. Threshold is a named const —
Claude's-discretion value, start at 25.

### Pattern 3: One XML text-walk for all three Office formats (Lane 2)

All three are zip+XML with text in known elements. One `fflate.unzipSync` + one
`collectXmlText(xml, tagName)` helper (regex `matchAll` + 5-entity decode) covers everything —
**no XML parser dep**. Deterministic flatten is the locked fidelity bar, so lossy-but-boring
regex extraction is correct here, not a shortcut.

| Format | Zip entries | Text element | Structure notes |
|--------|-------------|--------------|-----------------|
| DOCX | `word/document.xml` | `<w:t>` runs | newline per `</w:p>` (paragraph); tab per `<w:tab/>` if trivial |
| XLSX | `xl/sharedStrings.xml` + `xl/worksheets/sheet*.xml` | `<t>` (shared strings); `<v>` in `<c>` cells | cells with `t="s"` index into sharedStrings; others are literal values; emit rows as tab-joined lines, sheets in numeric order with a `Sheet N` header |
| PPTX | `ppt/slides/slide*.xml` | `<a:t>` runs | sort slide files numerically (`slide2` < `slide10` — numeric, not lexicographic); `Slide N` header per slide |

```typescript
// packages/vault/src/officeText.ts — core helper shape (Lane 2)
import { unzipSync } from "fflate";
const decodeEntities = (s: string) =>
  s.replace(/&(amp|lt|gt|quot|apos|#x?[0-9a-fA-F]+);/g, (_, e) => /* 5 named + numeric */);
const runsOf = (xml: string, tag: string): string[] =>
  [...xml.matchAll(new RegExp(`<${tag}(?:\\s[^>]*)?>([\\s\\S]*?)</${tag}>`, "g"))]
    .map((m) => decodeEntities(m[1]));
export function extractOfficeText(bytes: Uint8Array, mimeType: string): { text: string } { /* dispatch on mime */ }
```

Malformed/corrupt file → throw a typed error; the dispatcher catches → `markFailed("office_parse_failed")`.
Zero model calls, zero spend, runs anywhere (pure TS — testable with plain vitest in `packages/vault`).

### Pattern 4: Sweep as a migration + retry mutation (Lane 3)

`@convex-dev/migrations` is installed, proven (`migrations.ts` + `run-smoke-migration.mjs`
precedent), resumable, batched — and OPSG-06 explicitly mandates it over ad-hoc backfills.
`vaultSweep.ts` imports the existing `migrations` instance (defining a migration in a sibling
file is supported — the runner references by function name):

```typescript
// convex/vaultSweep.ts (Lane 3) — default runtime
import { migrations } from "./migrations";
export const sweepPendingExtraction = migrations.define({
  table: "vaultDocuments",
  migrateOne: async (ctx, doc) => {
    if (doc.status !== "pending_extraction" || !doc.storageId) return;
    const kind = extractionKindFor(doc.mimeType);
    if (kind === null) return; // unrecognized formats stay storage-only
    await ctx.scheduler.runAfter(0,
      kind === "transcribe" ? internal.vaultTranscribe.transcribeDoc : internal.vaultExtract.extractDoc,
      { vaultDocId: doc._id, tenantId: doc.tenantId });
  },
});
// Operator one-shot: npx convex run vaultSweep:runSweep  (migrations.runner precedent)

export const retryExtraction = tenantMutation({
  args: { vaultDocId: v.id("vaultDocuments") },
  handler: async (ctx, { vaultDocId }) => { /* owner-guard; status "failed"|"pending_extraction" only;
    schedule by kind (same two-line dispatch); return refs only */ },
});
```

Governance: each scheduled `extractDoc` starts with `preCall` (kill switch + `dailySpendCents`
budget window), so a large backlog self-throttles to the daily budget and the kill switch stops
the sweep mid-flight — no separate sweep rate-limit config needed. `ponytail:` comment the
ceiling (default batch size 100; a genuinely huge backlog would burst-schedule — per-batch
`runAfter` stagger is the upgrade path; beta backlog is expected to be tiny).

### Anti-Patterns to Avoid

- **Calling the public `vaultIngestText` from the extraction action** — throws UNAUTHENTICATED
  (no identity in scheduler-invoked actions). Use the Wave-0 internal seam variant.
- **Writing embeddings/graph rows from the extraction path** — the seam is sacred; extraction
  produces text and calls the seam, the existing `vaultIngest.ts` workflow does the rest.
- **Passing file bytes as action args** — node-action args cap at 5 MiB; vault files go to 8 MiB.
  Always `ctx.storage.get` inside the action (intake.ts precedent).
- **Importing `llm.ts` internals from the new `"use node"` module** — re-triggers the TS
  circular-inference cliff (intake.ts:12–16 warning). Duplicate the 1-line model resolver if needed.
- **Editing `packages/contracts/skills/attachment-extractor.md`** — republishing mints a new
  version for the *intake* path too; if the prompt ever needs vault-specific changes, seed a
  separate `vault-extractor` skill instead (see below).
- **Trusting client-declared sizes for caps** — enforce on the real loaded bytes (intake.ts:147).

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| PDF text-layer parsing | content-stream/CMap decoder | `unpdf@1.6.2` | Font encodings, compression filters, CID fonts — a career, not a task |
| ZIP container reading | central-directory parser over `node:zlib` | `fflate@0.8.3` | Node stdlib inflates streams but does NOT read the ZIP container format; the CD parser is ~150 fragile lines |
| Scanned-page OCR | anything local | hosted gpt-4o-mini file call (existing engine) | Already in production for intake PDFs/images; governed, priced, skill-prompted |
| Video audio-track demux | ffmpeg sidecar | direct container upload to the transcription API | mp4/webm/mpeg accepted natively; 8 MiB vault cap < 25 MB API cap (see Lane 4) |
| Resumable batch sweep | cursor bookkeeping table | `@convex-dev/migrations` | Installed, proven, resumable, OPSG-06-mandated |
| PDF page slicing (oversize scans) | manual object surgery | `pdf-lib.copyPages` (installed) | Exact fit; already pinned |
| OOXML *full* fidelity parsing | a real XML/OOXML object model | regex text-walk | The locked bar is deterministic FLATTEN — text runs only; a DOM buys nothing v1 uses |

**Key insight:** the phase's model-call half is already built (intake), and its parse half is two
tiny, boring, pinned libraries plus ~100 lines of walk code. Any design bigger than that is
smuggled complexity.

## Common Pitfalls

### Pitfall 1: unpdf's pdf.js 5.x needs `Promise.withResolvers` — Convex node actions default to Node 20
**What goes wrong:** unpdf 1.6.2 bundles pdf.js 5.6.205, which uses `Promise.withResolvers`
(Node ≥ 22). Convex `"use node"` actions run **Node 20 by default** (verified: docs.convex.dev/functions/runtimes;
configurable to 20/22/24 via `convex.json` `node.nodeVersion` — no `convex.json` exists in this
repo today). Local dev machines run Node 24, so **local tests pass while the deployed action
crashes** — the nastiest kind of failure.
**How to avoid:** three-line polyfill at the top of `vaultExtract.ts` before any unpdf import
usage (`if (!Promise.withResolvers) Promise.withResolvers = ...`) — contained, no deployment-wide
runtime change, no re-verification of `llm.ts`/`intake.ts` under a new Node. Alternative: create
`packages/backend/convex.json` with `{"node": {"nodeVersion": "22"}}` (cleaner long-term, wider
blast radius mid-phase). **Either way, Lane 1's live smoke on its own dev deployment MUST include
one real PDF text-layer extraction** — that is the only place this bug can surface.
**Warning signs:** `Promise.withResolvers is not a function` in the deployed action log only.

### Pitfall 2: The closed status union
**What goes wrong:** a lane assumes `status` is an open string (the CONTEXT flagged this as
unverified) and writes `"extracting"` → schema validation rejects the patch at runtime.
**How to avoid:** Wave 0 adds `v.literal("extracting")` to the `vaultDocuments.status` union
(schema.ts:443–448) plus `extractionTruncated: v.optional(v.boolean())` in the same append-only
edit. No migration needed (additive union member + optional field).

### Pitfall 3: The seam's identity wall (blocks Lanes 1, 3, and 4 at integration)
**What goes wrong:** `vaultIngestText` = `tenantMutation` → `requireTenant` throws
UNAUTHENTICATED for scheduler/internal callers (verified `lib/functions.ts:22–26`).
**How to avoid:** Wave 0 adds `internal.vault.ingestExtractedText({docId, tenantId, text, truncated})`
— an `internalMutation` mirroring the existing docId path (patch text/hash/size/status:"processing"
+ `workflow.start(internal.vaultIngest.ingestDoc)`, vault.ts:54–65) with an explicit tenant-match
guard exactly like `getDoc`/`markReady`/`markFailed` already do. ~12 lines.

### Pitfall 4: pnpm-lock.yaml is a shared singleton nobody listed
**What goes wrong:** Lane 1 adds `unpdf` to backend, Lane 2 adds `fflate` to vault — both edit
the ROOT `pnpm-lock.yaml` → guaranteed merge conflict in a generated file.
**How to avoid:** **Wave 0 installs both deps** and commits package.jsons + lockfile once.
Lanes then never touch a package.json or the lockfile. (Lane 4 needs no dep — nothing changes.)

### Pitfall 5: `watch.json` entries are prefixes — new files aren't covered by existing ones
**What goes wrong:** `vaultExtract.ts` is NOT covered by the existing `"packages/backend/convex/vault.ts"`
entry (exact-file prefix ≠ `vault*` glob); the Stop hook blocks the lane's first commit-turn.
**How to avoid:** Wave 0 appends to `vault.md`'s watch list: `convex/vaultExtract.ts`,
`convex/vaultExtract.test.ts`, `convex/vaultTranscribe.ts`, `convex/vaultTranscribe.test.ts`,
`convex/vaultSweep.ts`, `convex/vaultSweep.test.ts` (and updates the `vault.md` playbook itself
in the same commit, §9). `packages/vault/` and `apps/web/.../dashboard/vault/` are already
watched prefixes (verified).

### Pitfall 6: Convex 1 MiB document size limit vs extracted text
**What goes wrong:** an 8 MiB text-heavy PDF extracts to multi-MiB text; patching it onto
`vaultDocuments.text` exceeds Convex's ~1 MiB per-document cap → the seam call itself throws.
**How to avoid:** the per-doc char cap (locked decision anyway) must sit BELOW the doc limit:
recommend `VAULT_EXTRACT_CHAR_CAP = 400_000` chars (~400 KB, comfortable headroom beside the
row's other fields) applied to ALL paths (text-layer, hosted, office, transcript) before the seam
call, with `truncated: true` when it bites. Units: **chars** for the stored-text cap (universal),
**pages** for the hosted-PDF input cap (`VAULT_EXTRACT_PAGE_CAP = 50`, comfortably under
OpenAI's 100-page PDF-input limit; vault's 8 MiB is already under the 32 MB file-input limit).

### Pitfall 7: OOXML gotchas that break naive walks
**What goes wrong:** XLSX numbers look like garbage (they're fine — only `t="s"` cells index
sharedStrings); PPTX slides ordered lexicographically put slide10 before slide2; XML entities
(`&amp;`) leak into extracted text; `<w:t xml:space="preserve">` has attributes so `<w:t>` literal
matching misses runs.
**How to avoid:** the Pattern-3 details: attribute-tolerant tag regex, numeric slide sort,
entity decode, sharedStrings indirection. Lane 2's tests must cover each (they're cheap —
fixtures are built in-test).

### Pitfall 8: `pdf-lib` does not extract text
**What goes wrong:** rung-5 reflex ("already installed!") reaches for pdf-lib for the text layer.
It has no text-extraction API at all (creation/modification only).
**How to avoid:** pdf-lib's roles this phase are fixtures + page slicing, nothing else.

### 2. Video containers direct to the endpoint — yes, no ffmpeg

Verified against the OpenAI speech-to-text guide: accepted input types are **mp3, mp4, mpeg,
mpga, m4a, wav, webm** — the endpoint demuxes the audio track from **mp4/webm/mpeg video
containers natively**. `mov`/QuickTime is **NOT accepted**. File limit is **25 MB**.

**Cap math resolves cleanly:** `VAULT_FILE_CAP_BYTES = 8 MiB` (verified,
`packages/vault/src/constants.ts`) < 25 MB — **every video that can enter the vault fits the
API**, so no oversize-video path exists at all; the existing upload cap already rejects bigger
files at `vaultUpload`. The honest-failure behavior is therefore only for **unsupported
containers**: a `video/quicktime` (or other non-mp4/webm/mpeg `video/*`) doc goes
`markFailed("unsupported_video_container")` — failed badge + visible reason in the panel, Retry
affordance present but honest (matches the truncation-honesty decision; a silent forever-pending
row is exactly the gap this phase closes). 8 MiB of compressed video is short (~1–4 min typical),
so no duration-cap handling v1 — `ponytail:` ceiling comment; chunking is the upgrade path if a
duration limit ever surfaces.

Transcript output flows the standard spine: scanText fail-closed gate → refs/counts audit
(`vault.extraction_failed` / `vault.extracted` with `kind: "video"`, `durationSeconds`,
`charCount` — counts only) → `VAULT_EXTRACT_CHAR_CAP` truncation → `ingestExtractedText` seam.
`categoryFor` already routes `video/*` → the `videos` category tab (verified categories.ts:33) —
the "Videos" tab populates for free.
