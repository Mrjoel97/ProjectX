## The human-verify uncovered a page-crash root cause (not the trace)

The user's first verification attempt reported the cockpit looking "stuck" — the message stayed in
the input, the send button stayed green, no steps showed. Investigated live in the user's browser +
against the live deployment. Findings:

- **The activity trace itself works** — observed rendering live: `LATEST TRACE / Briefed your inbox
  · 43.6s / · 21.0s`, with real `agentSteps` rows (durations, phase transitions) in the deployment.
- **Root cause of "stuck": the whole WorkspacePage was CRASHING.** `api.cockpit.listThreads` (the
  past-chats menu) breached Convex's 1-second query limit under memory pressure, and a throwing
  `useQuery` throws *inside* the component — killing the entire page ("This page couldn't load",
  reproduced). A dead page cannot clear an input, recolor a button, or render steps: one crash
  produced every symptom the user described.
- **Environmental trigger:** the machine (7.9 GB total) was at **0.4 GB free** — the Next dev
  server's ~2.4 GB heap leak (a known ~45-min V8 ceiling crash, exit 134) plus Convex plus Chrome.
  A starved local backend blows the 1s budget (CLI calls to the same component query measured
  13–14 s). Killing the leaked dev process freed 0.4 → 3.1 GB immediately.
