## Decisions & findings

**The emitter is ~20 lines and touches no tool.** `ai@7` emits the events natively; the whole
backend of the phase is two options on the one `generateText({...})` call plus ~12 lines per driver.
`cockpitTools.test.ts` stayed 35/35, confirming no tool wrapper gained a side effect.

**`ctx.runMutation` is not a style choice — and it is the feature.** Actions cannot write
(`guidelines.md:266`), so it is the only option. It is also the mechanism: an action is not a
transaction, so each `runMutation` COMMITS and pushes to live `useQuery` subscribers *while the
action is still running*. That non-transactionality is what makes the trace live.

**The `finally` is load-bearing and will look redundant to the next reader.** In today's code the
driver's `catch` swallows, so a `finish` after the try/catch would also run on all three exits. It
is a `finally` anyway because the governed stop is an early `return` inside `runCockpitAgent` (DATA,
not a throw) and the construct must survive someone later removing or narrowing the `catch`. A
comment says exactly this, because the next session will want to "simplify" it.

**`SMOKE_OP_TOOL` genuinely de-duplicates rather than adding a second copy.** The plan asked for a
`smokeOpToolName(op)` helper "rather than duplicating the switch". A bare helper would still have
been a second copy of the mapping. Instead `runAgentSmokeOp`'s switch now READS the record for its
tool name (each case keeps only its input shape, its actual job), so the emitter and the invoke
cannot drift — and the `Record<AgentSmokeOp["kind"], StepTool>` type makes a new SMOKE op fail to
compile until it names its tool.

**The thinking row is `phase: "done"` even when the loop threw** — per the plan's explicit spec.
The turn ended (terminal is what matters) and the driver already surfaces the failure as a chat
message; `error` is reserved for tool-level failures, which is what Plan 03 will render.

**`StepTool` is derived from the schema, not retyped** — `Doc<"agentSteps">["tool"]`, mirroring
`agentSteps.ts`'s `TOOL` validator derivation. A hand-copied literal list would drift, and a drifted
literal means a silently swallowed insert.

**A throwing tool needed a real throw, not a mocked one.** Most cockpit tools return conversational
strings on failure rather than throwing (`briefInbox`/`listInbox` → `mailboxUnavailable`; a bad
index → a refusal string), and invalid tool input is rejected by the SDK *before* the callbacks
fire. The reliable offline throw is `readPlan()` on a deleted plan row (`proposePlan`'s first
statement) — deterministic, zero network.

## Deviations from plan

None to the plan's intent. Three notes, each recorded above rather than silently applied:
1. **Scan B mutation-checked three times** instead of once (short-circuiting made one insufficient).
2. **`SMOKE_OP_TOOL` is a Record read by the switch**, not a standalone `smokeOpToolName(op)`
   function — same intent, genuinely single-source instead of a second copy.
3. **"A zero-tool turn leaves exactly ONE terminal thinking row"** is asserted by the governed-stop
   and thrown-failure tests (both are zero-tool turns, both assert `toHaveLength(1)`) rather than by
   a third test. A zero-tool turn with a live model cannot be driven offline through
   `sendCockpitMessage`, which takes no model arg — a separate test would have been identical.

## Honesty notes

- **The fallback test proves less than its name suggests, and says so.** With the existing
  `failPrimary` shim the primary throws at its FIRST `doGenerate`, so it never reaches a tool call
  and has no rows of its own. The test pins that the re-entered run still emits and that the second
  attempt's rows are not suppressed; true both-attempts coexistence rests on `record` being
  insert-only (covered by `agentSteps.test.ts`). Making the primary call a tool *then* fail would
  need a new shim arg — not built.
- `cockpitDraft.test.ts` went red once during a mid-run scan (5042ms) and passes in the full sweep —
  the documented parallel-load flake, not a regression.
- **Not verified live.** Everything here is offline (mock model + SMOKE). The live cockpit
  emission is 03.9-04's human-verify.
