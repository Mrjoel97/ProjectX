## The gate's own substring defect — how a green gate was caught lying

**This is the plan's most transferable finding, not a footnote.**

Task 1's checker matched symbols with `String.includes`. `--self-check` passed on all 91 symbols, because its only mutation was **deletion** — and deletion is invisible to a substring matcher's blind spot.

The gate was then observed against the *real* working tree: two exported symbols were renamed in place (`listPacks` → `listPacksRENAMED` in `workflowPackDiscovery.ts`; `pipelineTiles` → `pipelineTilesRENAMED` in `contacts.ts`).

**The gate stayed GREEN.** `listPacks` is still a substring of `listPacksRENAMED`. A gate that survives the exact rename it exists to catch is a gate that reads green forever.

Fixed with `containsSymbol` (identifier-boundary aware whole-symbol matching), and `--self-check` was extended with **suffix-rename and prefix-rename mutations** alongside deletion. Re-run: `p19-pipeline-view` and `p27-discovery` both went red, each naming the exact missing symbol, exit 1. Files restored, `git diff --stat` empty.

The generalizable rule: **mutation testing only proves what it mutates.** A deletion-only mutation suite cannot see a matcher that is too permissive. This sits directly alongside the repo's existing "mutation-test the assumption, not the guard" finding — here the untested assumption was inside the test harness itself.

## The one row that no code checked

`p25-production-posture` is green **because a person said so.** It is not a `files` row and never can be. Three facts it needs are not facts about this repository:

1. **Production secret SOURCE** — `lib/env.ts` reports names only, never a value or a length (deliberately), so it cannot see which values a hosted deployment holds or how they got there.
2. **Redirect-URI OWNERSHIP** — `isDurableOrigin()` rejects `localhost`, plain `http`, `.local` and preview hosts, but nothing in the repo can know whether the URI is registered under an org-owned or a personal OAuth client.
3. **Hosted FAIL-CLOSED behaviour** — `requireEnv` / `requireEnvMedia` throw *in source*; whether the deployed build actually refuses rather than serving a left-on fixture seam is an observation, not a source fact.

**The owner attested `pass` on 2026-08-27**, claiming exactly those three (verbatim, reproduced in the readiness doc). Recorded under an explicit heading stating that no code verified any of it — this repo has a recorded defect class where supplied figures get laundered into "observed" facts, and the posture row exists precisely to stop that laundering here.

**Standing caveat, carried into the doc's Result table:** the bookkeeping still disagrees with the attestation's implied history. Phase 25 plans **25-11**, **25-12** and **25-13** — deploy the production bundle, automated production qualification, final live acceptance — have **no `SUMMARY.md` on disk**. Those are exactly where production secret/OAuth posture would have been exercised. The owner did not attest that they ran. If a production connector grant misbehaves in Phase 28, this row is the first thing to revisit. Reversing it needs one edit: set the block value to `block` and the gate re-blocks every dependent plan on the next run.

## Three inventory consequences every Phase 28 plan must respect

Each contradicts something a 2026-08-05 planner could reasonably have assumed:

- **There is no second CRM.** `packages/backend/convex/contacts.ts` is the only person/consent/suppression/follow-up store. REVN-04 attaches provider references to it; it does not create opportunities, deal stages or monetary pipeline values. `contacts.test.ts` asserts this structurally under `PIPE-01: no second CRM data plane leaked an opportunity concept into the substrate`.
- **A pack with a tool allow-list is a LEAF agent.** `runAgentLoop` sets `grantDispatch: toolNames === undefined`, so a revenue pack carrying a static grant structurally cannot dispatch a specialist. Compose in the Executive Agent, not inside a pack.
- **There is no sixth tenant event plane.** `workflowPackEvents` + `packages/core/src/workflowPackMetrics.ts` is the pack telemetry contract; cost/latency are read from `spendEvents`/`telemetry` rather than re-emitted. REVN telemetry extends these.

Plus two that bear directly on the revenue lane:

- **Suppression is checked twice and both sites read `suppressions` only** — `cockpit.executePlan` (per-recipient, before the group join, refusing `all_recipients_suppressed`) and `gmail.prepareGovernedMessage` (at the wire). REVN-06 reminder drafts terminate at these; do not add a third check.
- **Missing credentials throw; they do not degrade.** `requireEnv` / `requireEnvMedia` are the idiom a connector adapter must copy. A connector falling back to a development default is the one thing `p25-no-dev-fallback` exists to forbid.

## Decisions Made

- **Posture is a separate, blocking-by-default row rather than a code check with a lenient heuristic.** Making it auto-pass would defeat the whole point; `undecided` (including a typo or an absent doc) is blocking.
- **Whole-symbol matching over substring matching**, forced by the observed failure rather than by review.
- **Rename mutations added to `--self-check` permanently**, so this class cannot regress silently.
- **Inventory generated, not retyped** — a hand-maintained second copy goes stale and then gets believed.
- **The attestation is recorded as testimony, in its own heading, with the three claims verbatim** — not folded into the machine-verified evidence.
