## The reply invariants (recorded in cockpit.md)
1. **Recipient by message-ref, no panel** — `replyToMessage` sets the recipient from the original sender by ref (`recipients=[fromAddr]` + display-name label); the loop sees `#1: <name>`, never the address.
2. **Toolless original-body ingestion** — the untrusted original body reaches an LLM only in the toolless `draftReply`; never a tool return or an audit payload (mutation-checked static scans); injection is described-not-actuated (`24-reply-injection` eval PASS).
3. **Single-arm fan-out unchanged** — a reply rides the same `executePlan → startFanout → deliverApprovedPlan → gmail.send` spine; zero sends before Approve, refs-only audit.
4. **Threading fields optional-on-read** — the four fields are `v.optional`; a non-reply plan carries none and every seam no-ops; `resetPlan` clears them (Pitfall 6).
