## Recorded values (the plan's `<output>` asked for these explicitly)

### The `converse` contract — plan 07's page is written against exactly this

```ts
converse({
  slots: {
    oneLineDescription?: string,
    headcount?: number,
    paidStaff?: number,
    revenueStage?: "pre-revenue" | "early-revenue" | "steady-revenue",
    funding?: "bootstrapped" | "seeking" | "funded",
    yearsOperating?: number,
  },
  userMessage: string,
  history?: { role: string; text: string }[],   // bounded to the last 10 in the prompt
}) : Promise<{
  reply: string;              // what the user reads
  slots: OnboardingSlots;     // provided-over-stored merge of what this turn learned
  missing: SlotName[];        // missingSlots(slots), in REQUIRED_SLOTS order
  nextSlot: SlotName | null;  // missing[0] — null once nothing is left
  done: boolean;              // canComplete(slots) — NEVER read off the model
}>
```

`ConverseResult` is exported from `convex/onboarding.ts`. The five fact validators are derived from
`schema.tables.tenantProfiles.validator.fields`, so they cannot drift from the table; only
`oneLineDescription` is hand-written (it lives on the vault doc, not the row).

**It is a `tenantAction`. It writes NOTHING** — no row on any table, no audit, no telemetry, no
dead letter. The caller owns the transcript and the draft; the facts land through
`api.tenantProfile.saveFacts` and the narrative through `commitProfile`.

### The `SMOKE::onboard::` grammar, verbatim

```
SMOKE::onboard::<slot>=<value>,<slot>=<value>|reply=<text>
```

Both halves optional — `SMOKE::onboard::` alone is a turn that learns nothing and replies `""`.
Unknown slot names are dropped silently; off-union values are refused at the merge (the sentinel
stands in for a MODEL, so it must not be able to smuggle a value the real path would refuse).
Content-free and PII-free, mirroring `SMOKE::profile::`. Worked example:

```ts
await asTenant(t).action(api.onboarding.converse, {
  slots: { oneLineDescription: "A neighborhood coffee roaster." },
  userMessage: "SMOKE::onboard::headcount=4,funding=bootstrapped|reply=Four of you, got it.",
});
// → { reply: "Four of you, got it.",
//     slots: { oneLineDescription: "…", headcount: 4, funding: "bootstrapped" },
//     missing: ["paidStaff", "revenueStage", "yearsOperating"],
//     nextSlot: "paidStaff", done: false }
```

## Decisions Made

- **The merge's admission test IS the completion predicate.** `admits(slot, value)` is
  `!missingSlots({[slot]: value}).includes(slot)` — reuse (ponytail rung 2), not a second copy of
  the presence rules. The payoff is structural: `converse` cannot return a slot that is populated on
  plan 07's page yet still counted as missing by the gate, and it inherits both properties that
  matter for free — `0` is an ANSWER, and an off-union enum is refused rather than coerced. A test
  pins the drop ("admits nothing it would then report as missing").
- **`nextSlot` is `SlotName | null`, not `undefined`.** The plan wrote `missingSlots(slots)[0]`; a
  bare `undefined` field is ambiguous across the Convex serialization boundary (Convex omits it) and
  reads as "not computed" rather than "nothing left". `?? null` is one character and an unambiguous
  contract for the page. Asserted by `expect(complete.nextSlot).toBeNull()`.
- **`SLOT_SHAPE` carries a one-clause DEFINITION per slot, not question text.** "a number —
  everyone working on the business, paid or not, founders included" is the slot's meaning (it is
  lifted from `TierFacts`' own doc comments), and it is code-owned for the same reason `TASK_LINE`
  is: it is a FACT about the contract, not wording. Without it `paidStaff` is ambiguous and the
  model would guess, which is the defect this plan closes. The two enums list their literals because
  the model must choose from the closed union (Q7) — and the BODY deliberately does not repeat them,
  so the union has exactly one home.
- **The prompt is composed BEFORE the SMOKE short-circuit.** Wasted work offline, but it means the
  whole composition path runs in the offline suite: a throw in `turnPrompt` fails a test rather than
  waiting for a paid call. Same instinct as loading the skill first.
- **`converse` returns `slots` as the merged set, not a delta.** The caller round-trips it back in
  on the next turn, so a delta would put the accumulation in the UI — and the completion gate would
  then be reading a number the page computed. One accumulator, on the server, per turn.
- **The body does not name the tier or the presets.** The conversation collects FACTS; `deriveTier`
  turns them into a tier and `saveFacts` writes it. A body that mentioned "solopreneur" would invite
  exactly the classification this phase removed.
