# Phase 15.1 Plan 04: The Rubric Follows the Table Summary

**The evaluation engine picks its rubric from the `tenantProfiles` row instead of from a string
matched out of markdown — so a `business_profile` doc with a garbage `Persona` line can no longer
silently reclassify a tenant, and a new tier literal is now a compile error rather than a silent
fall-through to `lean`.**

Both authority tests were run against the unmodified engine BEFORE any implementation, and both
failed with the exact value the plan predicted:

```

  → AssertionError: expected 'lean' to be 'swot'   // Object.is equality
× the TABLE moves the pick: the same markdown at tier `startup` picks bmc
```

`"lean"` is `deserializeProfile`'s `"solopreneur"` fallback resolving through the old

behaviour this plan must NOT change.

## Decisions Made

- **The trailing `?? "lean"` was dropped, not kept "for safety".** With `TIER_FRAMEWORK` bound
  `satisfies Record<Tier, Framework>` and the index narrowed to a `Tier` by `?? "solopreneur"`, the
  lookup is total — the `??` would be a branch that can never be taken, i.e. an assertion that can
  never fail. The mutation-check proves the payoff: with the fallback gone, a missing map entry
  fails at the INDEX SITE too (`TS7053`), not just at the map.
- **`enterprise` → `swot`.** It is operator-granted (D6) and never derived, so there is no evidence
  a fourth rubric is wanted; an SME-shaped rubric is the honest default and the map stays total.
- **The `- **Persona:**` block survives with all four `fillVault` calls.** They are CONTENT fills
  (name / niche / avatar / offers) and the block is also the profile-doc DETECTOR. Only the
  authority was removed — deleting the block would have silently dropped the user's own identity
  fields out of every grounded evaluation.
- **`deserializeProfile`'s fallback is untouched.** Design §4.2 is explicit that it "stops being a
  silent reclassification risk once nothing authoritative depends on it"; this plan is what makes
  that sentence true. Changing the fallback instead would have left the real reader in place.
- **The test file kept its untyped convex-test instance.** Plans 02 and 03 both had to switch to
  `TestConvex<typeof schema>` because they queried a user index inside `t.run`. These tests only
  INSERT into `tenantProfiles`, so the 15-04 SystemIndexes wall is never reached — retyping the
  whole 688-line file would have been a large diff proving nothing. Confirmed by `tsc` staying at
  exactly 55.
- **The fixture is built by `.replace()` on the real serializer output, with a non-vacuity guard.**
  `expect(MALFORMED_PERSONA_DOC).toContain("- **Persona:** wizard")` plus
  `.not.toContain("solopreneur")` — if `serializeProfile`'s format ever drifts, the replace silently
  no-ops and all four tier tests would pass for the wrong reason.
- **`frameworkFor` asserts an EMPTY scheduler queue before returning.** `runEvaluation` is the
  read-only shape and must queue nothing; asserting it (rather than assuming it) is what keeps this
  file free of the 15-04 hidden `OPENAI_API_KEY` dependency, and it would catch a future change that
  made the evaluate path schedule work.
