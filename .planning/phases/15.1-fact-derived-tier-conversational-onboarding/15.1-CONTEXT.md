<domain>
## Phase Boundary

The business tier stops being something a user can assign themselves and becomes a fact-derived,
auditable property of the tenant — because tier now selects agent voice and how specialists are
briefed, making a self-writable tier a behavioral control rather than a preference.

**In scope:** the tier write path (`deriveTier` as sole writer), the indexed tenant-profile table
with `tierSource`/`derivedAt`, fact-asking conversational onboarding, the truthful audit row, tier
reaching the agent's voice and the specialist's prompt, and the legacy backfill.

**Out of scope:** forking the dispatch router (Phase 15 shipped it tier-agnostic on purpose —
tier plugs in as a layer over it, never a fork).
</domain>

### Owner decisions on the research's open questions (2026-07-26)

**Q1 — Conversational onboarding loop: `generateObject` slot-filler. LOCKED.**
Each user turn is one `generateObject` call returning `{ reply, slotUpdates }`. **Code owns the
state machine and picks the next question; the model owns only the wording.** ~80 lines in
`onboarding.ts`. **Zero edits to `llm.ts`, zero `schema.ts` change, no new `agentSteps.tool`
literal.** This is the ponytail-ladder answer — `extractProfile` already proves the pattern ~100
lines away in the same file — and §5 is satisfied identically (`getActiveSkill` + `system:
skill.body`).
*Rejected:* generalizing `runAgentLoop` (highest blast radius on the repo's hottest file, for a
phase whose real job is the write path) and minting a throwaway plan row (`plans.byThread` is
`.unique()` — a synthetic row breaks every workspace reader).
*Required:* a `ponytail:` comment naming the ceiling — "no activity trace, no shared cost rail;
upgrade to `runAgentLoop` if onboarding ever needs real tools."

**Q2 — SC#5 means tier shapes the specialist's PROMPT, not an offer set. LOCKED.**
`diagnose()` emits exactly one prescription, so the design doc §8's "filters and orders which
specialists are offered" describes a candidate set that does not exist today. Ship the perceivable
half: tier + agent name + behavior preset ride into `runSpecialistTurn`'s prompt, so a solopreneur's
`money-model-designer` never proposes hiring — directly delivering §8.1's "a solopreneur does not
receive advice premised on delegation."
*Deferred with an ADR:* widening `diagnose()` to emit secondary candidates so `leverageRank` finally
sorts a real array. That changes the diagnosis contract and `cards.tsx` rendering — a second phase's
blast radius.
**A verifier must not read SC#5 as "the offer set is filtered" or "the rubric pick changes."**

**Q3 — `financialsPresent` keeps overriding the framework pick.**
`evaluations.ts:291-295` giving any financially-grounded tenant `growth-os` is correct and stays.
The tier's effect lands on voice / framing / specialist prompt instead, which is unconditional. Say
this explicitly in the plan so a verifier does not read SC#5 as "the rubric must change."

**Q4 — Enterprise (D6) is operator-granted via an `internalMutation`.**
`requireOwner` (GOVN-01) does not land until Phase 22 and is a recorded open blocker. Ship
`tierSource: "admin"` as a representable value plus an `internalMutation` with **no public API
surface** (the `actOnGapInternal` precedent), invoked by an operator via `npx convex run`. No
`tenantMutation`, no UI, no route. `deriveTier`'s return type structurally excludes `enterprise`, so
D6 holds by construction regardless of who can call the grant.
**Do NOT add a fourth tenant-callable pseudo-admin function** — that deepens the Phase-22 blocker.

**Q5 — `apps/web` is UNFROZEN for 15.1.**
The `PARALLELIZATION.md` freeze was scoped to Phase 15, which is complete and verified. Lane C's
Phase 14 touches the voice surface, not profile/onboarding. Still required: `watch.json`
registration for any new watched path (§9) and reading `docs/design/BRAND.md` before either page
change (§10).

**Q6 — `onboarding-agent` is UNGATED.**
Matches `business-profile`, the nearest precedent — also an onboarding skill, also ungated. Gating
adds an eval-corpus obligation this phase has no budget for, and Phase 15's eval gate is already
unpaid. Record the decision in the playbook.

**Q7 — `revenueStage` and `funding` are closed `v.union` literals**, mirrored by TS unions in
`@pikar/core`, so `deriveTier` is total and its branch table exhaustively testable. A free string
here would reintroduce string-matching — the exact defect class this phase exists to close.
`headcount` / `paidStaff` / `yearsOperating` are numbers.

<specifics>
## Specific Ideas

- `deriveTier` is pure-TS in `@pikar/core` (CLAUDE.md §1) and the ONLY writer of the tier.
- The two design-§11-mandated regressions must be named individually in verification, because the
  design doc says they are the two that will otherwise silently rot:
  1. **SC#1b** — the *mutation* refuses a caller-supplied tier ("the page-level check only proves
     the widget is gone; this one proves the control is gone")
  2. **SC#4** — the audit row on an edit path is truthful (no hardcoded `personaConfirmed: true`)
- Audit payloads carry refs / hashes / ids / counts only — **no fact values** (§4).
- Phase 11's pure `decideConfirm` returning literal `{ needsConfirm: true }`, and "enterprise is not
  an emittable Persona", must not regress.
</specifics>
