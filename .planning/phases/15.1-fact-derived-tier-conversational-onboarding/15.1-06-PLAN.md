<objective>
Replace guessing the persona from prose with ASKING the determining facts. One `generateObject` call
per user turn returns `{ reply, slotUpdates }`; **the code owns the state machine and picks the next
question, the model owns only the wording.**

Purpose: defect 1a. Design §6's non-negotiable is *"it simply cannot COMPLETE with a required slot
empty"* — and that guarantee must not live in the prompt, because a prompt that says "always ask about
headcount" is a model-temperature guarantee, which is the defect itself.
Output: an `onboarding-agent` registry skill and a `converse` action. The refusal that makes the
guarantee true already shipped in plan 03 (`commitProfile`'s slot gate, SC#3b).
</objective>

```ts
export const extractProfile = tenantAction({
  args: { intakeText: v.string() },
  handler: async (ctx, { intakeText }): Promise<ProfileInput> => {
    const skill: { body: string; version: number } =
      await ctx.runQuery(internal.skills.getActiveSkill, { name: BUSINESS_PROFILE_SKILL });  // fails CLOSED
    if (intakeText.startsWith(SMOKE_PROFILE_PREFIX)) return smokeProfileFixture(intakeText);
    const { object } = await generateObject({
      model: resolveModel(DEFAULT_MODEL), schema: profileSchema, system: skill.body, prompt: intakeText,
      abortSignal: AbortSignal.timeout(CALL_TIMEOUT_MS), maxRetries: 1,
    });
    return object;
  },
});
```
Note the ordering: the skill loads FIRST, **before** the SMOKE short-circuit, so the fail-closed load is
exercised even on the offline path. Keep that ordering.

cliff) STRICT-mode shape to copy: `additionalProperties: false` and every property also listed in
`required`.

`SMOKE_PROFILE_PREFIX = "SMOKE::profile::"` (`:96`) — the offline determinism seam. Content-free
sentinel, no PII.
