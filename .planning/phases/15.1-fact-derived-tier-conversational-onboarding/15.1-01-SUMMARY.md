## Accomplishments

- **`deriveTier` is total by construction and proven so at runtime.** Two guarded returns plus an
  unconditional fallthrough over closed unions; a 135-case cross-product sweep
  (`REVENUE_STAGES × FUNDING_STATES × [0,1,2] paidStaff × [0,1,2,3,9] headcount`) asserts every
  result is a `PERSONAS` member and never `enterprise`. The sweep is **non-vacuous**: it enumerates
  from the exported unions, so adding a literal widens it automatically.
- **D6 is a compiler property.** `DerivedTier` (= `Persona`, 3 members) vs `TIERS` (4, `enterprise`
  included). The `@ts-expect-error` bind in the test file is load-bearing and was mutation-checked.
- **The completion gate treats `0` as an answer.** `missingSlots` tests numeric slots for
  *finiteness*, string slots for a non-empty trim, enum slots for *membership*. A truthiness check
  would have made the design §6 conversation uncompletable for exactly the user the phase is about
  (a solo founder answering `paidStaff: 0`).
- **`tenantProfiles` landed with zero codegen.** `Doc<"tenantProfiles">` resolves offline because
  `dataModel.d.ts` derives from `../schema.js`; proven non-vacuously (renaming the table to a
  nonexistent one produces `TS2344: does not satisfy the constraint 'TableNames'`).
- **Plan 02 is un-blockable by the Stop hook** — `convex/tenantProfile.ts` and its test are already
  registered under `onboarding.md` in `watch.json`.
- **ADR-009 closes an interpretation hole** that would otherwise have made SC#5 look unimplemented.

## Decisions Made

- **`index.ts` was left untouched.** The plan's Task 1 item 7 said "match whatever style that file
  already uses" — the style is `export * from "./businessProfile"`, so the new surface is already
  re-exported and an explicit named re-export would be redundant duplication. `deriveTier` is
  importable from `@pikar/core` today (the plan's `key_links` intent is satisfied; the literal
  `pattern: "deriveTier"` string does not appear in `index.ts` and does not need to).
- **`sanitizeAgentName` uses `/\p{C}/gu`** rather than an explicit `[ -]` class.
  Same coverage for Cc, no `biome-ignore` suppression needed (biome's recommended
  `noControlCharactersInRegex` would have flagged the escape class), and it additionally strips Cf —
  zero-width and bidi-override characters, which are a display-name spoofing surface. U+2028/U+2029
  are Zl/Zp rather than Cf and are handled by the `\s+` collapse; both cases are asserted.
- **Trim runs AFTER the 40-char slice** so a cut landing mid-whitespace cannot leave a dangling
  separator (asserted with a `"b"×39 + " tail"` input).
- **`tenantProfiles` was appended at the END of `schema.ts`** under its own
  `── Phase-15.1 tier control plane ──` header. The file is phase-ordered, so this is "near the other
  tenant-scoped control-plane tables" in the sense the file actually organizes itself.

## Issues Encountered

- **A source file briefly contained literal control bytes.** While authoring the test file the
  intended escape sequences ` ` / `` / `\n` / `\r` were emitted as LITERAL U+0000, U+0007,
  U+2028 and U+2029 characters, which made the file binary to ripgrep and broke exact-match editing.
  Resolved by rewriting the affected `describe` block programmatically with real escapes plus a guard
  that rejects any stray control / line-separator character in the whole file before writing. Nothing
  about the tests' meaning changed.
- **The backend FULL suite is flaky on this worktree** (6-7 failures, a *different* set each run, all
  of the form `Component "<rateLimiter|auditCounts>" is not registered`). Every affected file passes
  in ISOLATION; the sole genuine red is the documented `audit.test.ts` `auditCounts` row. This plan
