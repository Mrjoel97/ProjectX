# Phase 15.1 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.
> Derived from `15.1-RESEARCH.md` § Validation Architecture. Read that section for the reasoning
> behind each row.

**Environment constraint, material to every row below:** this worktree
(`.worktrees/lane-a-dispatch`) has **no live `CONVEX_DEPLOYMENT`**. Offline gates work
(`convex-test` + vitest, `tsc --noEmit`, `scripts/check-playbooks.mjs`). Anything needing a live
backend or a real model call does not. The backfill migration in particular **cannot be run for
real** here — only exercised through `convex-test`'s in-memory DB; the operator `migrations.runner`
invocation is a live-deployment step deferred to integration on `main`.

| Property | Value |
|----------|-------|

| **Estimated runtime** | ~30s per affected file; full suite ~3-4 min |

**Pre-existing reds that are NOT regressions** — confirm before blaming a change:

- `convex/audit.test.ts` — the `auditCounts` row (documented since Phase 2)
- ~55 backend `tsc --noEmit` errors, **all in test files**
- `@pikar/audit` has no `tsconfig.json` → use `npx turbo run typecheck --continue`;
  **8/10 is the baseline**, not 10/10

## Sampling Rate

- **After every task commit:** the single affected test file (`< 30s`)
- **After every plan wave:** `npx turbo run test --continue` **and**
  `npx turbo run typecheck --continue` (8/10 baseline) **and** `node scripts/check-playbooks.mjs`
- **Before `/gsd:verify-work`:** full suite at baseline-or-better, plus the two design-§11-mandated
  regressions (SC#1b mutation refusal, SC#4 truthful audit) named individually — the design doc
  says these are the two that will otherwise silently rot
- **Max feedback latency:** 30 seconds
