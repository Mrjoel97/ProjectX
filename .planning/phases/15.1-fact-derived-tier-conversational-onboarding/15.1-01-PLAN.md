Content, in the template's sections:

- **Context.** Design §8.2 presumes a candidate set. It does not exist: `runEvaluation` computes
  `const ranked = leverageRank([diagnose(scorecard)])` (`evaluations.ts:324-325`) — `diagnose()`
  (`packages/core/src/growth/diagnose.ts:32-179`) is a top-down gate cascade that RETURNS at the first
  failing gate, so `leverageRank` sorts a single-element array and `gaps` holds at most one route.
  A tier filter over a set of one can only REJECT, and a rejected route lands the user on the
  deterministic `buildMemo` fallback (`evaluations.ts:683-719`) — i.e. "solopreneurs get a template
  instead of a specialist", a downgrade wearing tailoring's clothes.
- **Decision.** Ship the perceivable half: the tier, the agent name and the behavior-preset directive
  ride into `runSpecialistTurn`'s PROMPT (plan 05), so a solopreneur's `money-model-designer` never
  proposes hiring — directly delivering §8.1's *"a solopreneur does not receive advice premised on
  delegation"*. The offer SET is unchanged and the dispatch router is NOT forked
  (`PARALLELIZATION.md`'s constraint on Lane A; `SPECIALISTS` stays a pure readonly record).
- **Consequences.** SC#5 is satisfied by prompt-shaping. **A verifier must not read SC#5 as "the offer
  set is filtered" or "the rubric pick changes."** Q3 stands: `financialsPresent` keeps overriding the
  framework pick (`evaluations.ts:291-295`), correctly — financials mean a growth-os diagnosis is
  possible; the tier's effect lands on voice/framing instead, which is unconditional.

  finally sorts a real array. That changes the diagnosis contract, the `evaluations.gaps` array shape,
