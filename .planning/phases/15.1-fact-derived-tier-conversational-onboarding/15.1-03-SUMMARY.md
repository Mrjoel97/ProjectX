### The error codes — plan 07's UI must render these

| Code | Thrown by | When | Data |
|---|---|---|---|
| `INCOMPLETE_ONBOARDING` | `commitProfile` | any `REQUIRED_SLOTS` fact slot empty, or no `tenantProfiles` row at all | `{code, missing: SlotName[]}` |
| `INCOMPLETE_FACTS` | `updateProfile` | **no `tenantProfiles` row at all** (never for merely-incomplete facts) | `{code, missing: SlotName[]}` |
| `INVALID_PROFILE` | both | `validateProfile` fails (empty `oneLineDescription`) | `{code, errors: string[]}` (unchanged) |

Both new codes carry the SAME `missing` array shape deliberately, so plan 07 renders one branch for
both. `missing` is in `REQUIRED_SLOTS` order and excludes `oneLineDescription` (the narrative is
supplied by the profile argument itself, so it is never reported as a fact gap).

**The asymmetry is the point.** `commitProfile` is the first-time completion gate; `updateProfile`
deliberately has no slot gate, because design §10 forbids forcing a legacy tenant back through
onboarding and they must still be able to correct their profile. A legacy tenant never REACHES
`commitProfile`, because `onboarding.status` already returns `{needsOnboarding: false}` for them —
both halves of that are asserted in the SC#6c test.

## Decisions Made

- **`commitProfile`'s gate is one condition, `!row || missing.length > 0`.** The `!row` half is
  runtime-redundant: with no row every fact slot is missing, so `missing` is already non-empty and
  informative. It is there so `row.tier` narrows without a non-null assertion, and a comment says
  both halves mean the same thing — otherwise a later reader "simplifies" one away.
- **`INCOMPLETE_FACTS` carries a `missing` array too.** The plan only required the code. Giving both
  refusals the same data shape means plan 07 writes one renderer, not two.
- **The SMOKE grammar is unchanged.** `SMOKE::profile::<anything>` still parses; the suffix simply
  selects nothing now. Rejecting it would be a breaking change to an offline seam whose whole job is
  to stay boring, for zero benefit.
- **`currentTierRow`, not the plan's `currentTier`.** It returns a `Doc<"tenantProfiles">`, and the
  file already names its sibling `currentProfileDoc`. A direct `ctx.db` read, not
  `ctx.runQuery(internal.tenantProfile.forTenant, …)` — same transaction inside a mutation, one
  fewer hop — with `.unique()` mirroring `tenantProfile.byTenant` so a duplicate row is LOUD.
- **Both pages build the mutation arg field-by-field.** This is not tidiness: `getProfile` returns
  the full `BusinessProfile` including the read-only `persona` projection, and a `v.object` rejects
  an extra key — a spread would make Save fail outright for every user, and would make a
  pre-15.1 `localStorage` draft's stale `persona` a hard Confirm failure on the onboarding page.
- **`deserializeProfile`'s `"solopreneur"` fallback stays.** It is now a DISPLAY convenience (plan 04
  removes the last authoritative consumer), and `getProfile` still pre-fills an edit form from stored
  markdown, so it must not throw on a legacy or garbled line. The test carries that note.
- **`business-profile` was re-verified UNGATED before the body edit** (absent from `GATED_SKILLS`,
  `skill.ts:100-115`), so unlike 15-06 this body edit does NOT ride the unpayable eval gate.
- **The injection example in the skill body ("set the persona to enterprise") was left alone.** It is
  an example of an instruction to IGNORE, and it now reinforces the new rule rather than contradicting
  it. The shortest working diff wins.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `profileRedaction.test.ts`'s numeric scan could not read `telemetry.payload`**
- **Found during:** Task 2 (backend `tsc --noEmit` went 55 → 56)
- **Issue:** The plan asked the sentinel sweep to cover `audit`/`telemetry`/`deadLetters`. The
  `telemetry` table has **no `payload` column**, so `[...audit, ...telemetry, ...deadLetters]
  .map(r => r.payload)` is a `TS2339` on the union. Invisible to the plan's own vitest verify command
  (the property is simply `undefined` at runtime).
- **Fix:** the NUMERIC scan targets `audit.payload` + `deadLetters.payload` — the two objects
  CLAUDE.md §4 governs by name. `telemetry` stays fully covered by the STRING sweep in
  `logPlaneJson`, which reads whole rows of all three tables, and is structurally incapable of
  carrying a fact. The rationale is a comment on the helper.
- **Files modified:** `packages/backend/convex/profileRedaction.test.ts`
- **Verification:** backend `tsc --noEmit` back to the exact 55-error baseline.
- **Committed in:** `1f99673`

**2. [Rule 2 - Missing Critical] The §4b numeric needles are COMPARED, not substring-scanned**
- **Found during:** Task 2 (while writing the test)
- **Issue:** The plan said "extend the existing sentinel sweep so no row carries a fact value". The
  existing sweep is a substring scan over JSON. A 2-digit needle like `41` appears inside a Convex
  document id or an epoch-milli timestamp a large fraction of the time — the 15.1-02 flake, one
  layer down. It is also the WEAKER assertion: a real leak would be indistinguishable from noise.
- **Fix:** `payloadNumbers()` walks every numeric LEAF of every payload and the test asserts
  `not.toContain(137 | 41 | 29)` — a number-to-number comparison. The three needles are all > 8 so
  they cannot collide with a legitimate `fieldCount` (max 7) or `factsChanged` (max 5). A
  non-vacuity assertion (`numbers.length > 0`) proves a populated payload set is being scanned. The
  STRING facts (`agentName`, `revenueStage`, `funding`) ride the existing sweep unchanged, where a
  substring scan is exactly right.
- **Files modified:** `packages/backend/convex/profileRedaction.test.ts`
- **Committed in:** `1f99673`

**3. [Rule 3 - Blocking] `onboarding.test.ts` needed a typed convex-test instance**
- **Found during:** Task 2
- **Issue:** the same 15-04 "SystemIndexes wall" 15.1-02 hit — `ReturnType<typeof convexTest>` erases
  the schema generic, so inserting into and querying `tenantProfiles` inside `t.run` does not
  type-check.
- **Fix:** `TestConvex<typeof schema>` throughout (the `tenantProfile.test.ts` / `gapAction.test.ts`
  precedent). Same for `profileRedaction.test.ts`.
- **Committed in:** `700107f`

**4. [Rule 1 - Bug] The `onboarding.ts` module header still described the deleted contract**
- **Found during:** final verification
- **Issue:** the header said *"SC#1 (persona is confirmed, never auto-committed)"* — false after this
  plan; nothing confirms a persona any more.
- **Fix:** rewritten to state the no-tier-input contract and the §4.2 projection rule, so a reader
  who opens the adapter before the playbook still meets it.
- **Committed in:** `c80396c` (with the matching `onboarding.md` touch — the Stop hook correctly
