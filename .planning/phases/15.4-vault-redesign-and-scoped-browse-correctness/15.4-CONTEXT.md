# Phase 15.4: Vault Redesign and Scoped Browse Correctness - Context

**Gathered:** 2026-08-04
**Status:** Ready for planning
**Source:** PRD Express Path (`docs/superpowers/plans/2026-08-04-pending-pages-vault-integration-plan.md`)

<domain>
## Phase Boundary

Implement only the Knowledge Vault slice of the approved pending-pages integration map. Apply the Nord Edge visual system to `/dashboard/vault` and connect every rendered state to the existing vault/folder backend. Fix the known folder-search scope defect. Preserve, rather than replace, the richer controls already shipped by Phases 5, 15.2 and 15.3.

This phase does not implement Approvals, Finance, Content, Reports, Sales Pipeline, or Command Center v2. Those remain in Phase 26 and retain the dependency gates recorded in the source plan.

</domain>

<decisions>
## Implementation Decisions

### Source of Truth
- The HTML mockup defines composition and visual direction; repository behavior and backend contracts override any mock annotation that implies unavailable data or reduced functionality.
- Reuse the current route and component architecture. Do not build a parallel mock-only page or duplicate the vault data plane.
- Use the existing Convex tenant wrappers and bounded query conventions. No raw builders, unbounded list reads, or client-side trust boundaries.

### Root Browse
- Keep the real `VaultStats`, category tabs, search, upload dialog, folder upload, Google Drive import, folder cards, document cards, stale digest banners, processing/error states, and pagination/load-more behavior.
- Restyle these into the approved Nord Edge hierarchy: warm canvas, compact header/actions, restrained cards, category rail, responsive grid and accessible focus/hover states.
- Do not display the mockup's exact category counts. Existing bounded aggregate counters may continue where already truthful; no new count claim ships without a bounded counter contract.

### Folder Browse
- Opening a folder keeps breadcrumb navigation, folder metadata, digest/synthesis status, rebuild action, file listing and existing drill-in behavior.
- Search inside a folder must be server-scoped by `folderId` (plus tenant and any selected category/type). Client-only filtering of an unscoped result set is not acceptable.
- Root search remains tenant-scoped and category-aware. Pagination cursors and result ordering must remain deterministic across both scopes.
- Partial ingest, failed files, stale digests and unsupported content must be visible; the redesign must not turn these into a generic empty state.

### Preview
- Keep the current richer preview controls: metadata/identity correction, extracted-content view, citations/provenance, download where supported, and delete confirmation.
- Match the mockup's preview composition without hiding governed controls or reducing the document state model.
- Long extracted content, absent preview media, processing documents, failed extraction and unsupported formats each require an explicit state.

### Empty and Error States
- Distinguish true empty vault, empty category, empty folder, no search results, loading, query failure, partial ingest, and stale synthesis.
- Empty-state calls to action must open the real upload/folder-import paths; decorative buttons or dead links are prohibited.
- Errors must be visible, retryable where the backend supports retry, and must not be silently represented as zero results.

### Visual System
- Translate the mock's colors, radii, shadows, type and spacing into shared semantic tokens in the existing design system. Avoid page-local hardcoded hex values.
- Preserve global `.pane-canvas` and `.clay-card` behavior used by other routes unless a cross-route visual regression pass proves a safe shared change. Prefer Vault-scoped composition classes/tokens when necessary.
- Responsive behavior must cover narrow mobile, tablet and desktop widths; interaction states must be keyboard accessible and respect reduced motion.

### Verification
- Add backend tests that prove tenant isolation and folder-scoped search, including a mutation test that fails if the `folderId` predicate is removed.
- Add component tests for root, folder, preview, empty, loading, failure, partial-ingest and stale-digest states and for every retained action.
- Run backend tests, web typecheck/build, and browser UAT against the actual route. A static render of the mockup is not acceptance evidence.
- Browser UAT must exercise upload entry, folder open/search, document preview, metadata correction, download/delete where available, digest rebuild and empty/no-results recovery.

### Release
- Keep the existing route; avoid a second permanent URL. If implementation risk requires gating, use a temporary owner-only flag and remove it after UAT.
- Do not migrate or rewrite stored vault documents for a visual redesign. Any query/index change must be backward-compatible with existing documents and folder rows.
- Record UI and backend failures with existing observability seams; never include extracted document text or user filenames in free-form telemetry/audit payloads.

### Claude's Discretion
- Exact component boundaries, CSS class names, token names and test file placement, provided they follow current repository conventions.
- Whether folder-scoped search extends the existing query or adds a narrowly named bounded read model, based on the smallest safe blast radius.
- Minor spacing and breakpoint tuning needed to reconcile the static mock with real dynamic content.

</decisions>
