# Phase 15.4: Vault Redesign and Scoped Browse Correctness - Research

**Researched:** 2026-08-04
**Requirement:** VALT-16
**Confidence:** High for the contract and file boundaries; browser pixel tuning remains UAT-driven.

## Executive Finding

The Vault is not a blank frontend. The route already has the complete functional surface needed by the approved design: root/category browse, bounded stats, single-file upload, folder upload, Google Drive import, folder drill-in, synthesis/rebuild state, document preview, extracted text, entity citations, metadata correction, download and delete. The safe implementation is a presentation refactor over those contracts plus one narrow backend correction: `vaultSearch` must accept and enforce `folderId` exactly as `listVaultDocs` already does.

No schema migration is required. Exact category counts must remain absent because `vaultStats` is intentionally a bounded-window projection and the category tabs have no maintained counter contract.

### Backend Read Plane

- `readVaultPage(ctx, tenantId, folderId?)` is the single bounded reader. It selects `by_tenant_folder` for folder drill-in and `by_tenant` at the root, stops at row/byte ceilings, and never exposes the full partition.
- `listVaultDocs({ category?, folderId? })` already enforces tenant and folder scope server-side and projects metadata without `text`.
- `vaultStats()` derives counts/storage from the same bounded root window and returns `capped`. It is intentionally not an exact aggregate.
- `vaultDocText({ vaultDocId })`, `vaultDownloadUrl({ vaultDocId })`, and `docEntities({ vaultDocId })` are tenant-checked on-demand detail contracts.
- Folder reads/actions live in `vaultFolders.ts`; the UI must preserve folder status, digest freshness, retry/rebuild, cancellation and Drive-import semantics.

### Search Gap

`vaultSearch` currently accepts `{ query, category? }`, calls tenant-namespaced hybrid RAG search, resolves candidates through `internal.vault.ownedDocsMeta`, removes sealed folder members, and post-filters by category. It does not accept `folderId`, so an open folder can display hits from elsewhere in the tenant's Vault.

The correction belongs server-side:

1. Add optional `folderId` to the public action arguments and return path.
2. Carry `folderId` on the metadata projection used to resolve candidates, or add a dedicated narrow resolver that returns it.
3. Validate the folder belongs to the tenant or make a foreign/missing ID return no results without creating an ownership oracle.
4. Filter visible results by both category and folder before returning them.
5. Pass `folderId` from `DocGrid` only in folder context.
6. Keep sealed-member filtering unchanged.

A schema/index change is unnecessary because hybrid search returns at most eight candidate IDs; resolving those IDs and comparing `folderId` is bounded.

## Design-to-Behavior Mapping

### Root Browse

- Nord Edge header and action cluster wrap the existing upload/folder/Drive commands.
- Category navigation stays driven by the fixed category vocabulary and does not show fabricated badge counts.
- Folder cards and document cards remain separate semantic types; status badges reflect real ingestion/synthesis states.
- Search uses `vaultSearch` and must expose loading, zero results and action errors independently from the normal browse query.

### Inside Folder

- Breadcrumb and folder title/status are sourced from the existing folder view.
- Folder digest/rebuild, manifest failures and stale state remain above the member grid.
- Member browse uses `listVaultDocs({ folderId })`; member search uses `vaultSearch({ folderId })` after the contract widening.
- A folder with no members, a folder still ingesting, and a folder whose members all failed are distinct states.

### Preview

- The preview shell may change, but its queries remain lazy/on demand.
- Preserve extracted text, document identity/type correction, entity/citation display, download capability and guarded delete.
- Explicitly render processing, failed, unsupported/no-preview and long-text states.

### Empty and Failure States

- True empty Vault: show upload/folder/Drive entry actions.
- Empty category: offer category reset and upload.
- Empty folder: preserve folder context and import/upload affordance.
- No search results: clear/reset search without suggesting the Vault itself is empty.
- Query/action failure: visible retry/error copy; never coerce to `[]` in the component.
- Partial ingest/stale digest: retain existing warning/rebuild surfaces.

## File and Plan Boundaries

### Backend Contract Plan

Own only `packages/backend/convex/vault.ts` and focused Vault tests. Avoid `schema.ts` because no index is needed and it currently has unrelated active edits. Add mutation-resistant assertions proving removal of the folder predicate leaks another same-tenant folder, and preserve cross-tenant/sealed filtering.

### UI State/Composition Plan

Own the Vault route/components and any new Vault-local pure state helpers/tests. Preserve current handlers and query activation conditions while reshaping markup. Prefer pure view-model helpers for state matrices that can be tested under the existing Node Vitest environment instead of installing a DOM stack solely for this phase.

### Styling and Browser Plan

Own semantic additions to `globals.css` plus Vault component class usage. Use scoped selectors/tokens to avoid cross-route blast radius. Verify responsive layouts and all real controls through the existing Playwright/browser path.

## Blast Radius and Pitfalls

- `vaultSearch` is also a public surface with smoke tests; widening must remain backward-compatible by making `folderId` optional.
- `ownedDocsMeta` is shared with grounding and has index-parallel assumptions. Changing its result shape is safe only if existing fields/order remain unchanged; a dedicated folder-aware resolver may have smaller risk.
- Do not move `text` back into list/search results. It was deliberately split into `vaultDocText` to stay below Convex read limits.
- Do not replace bounded stats with `.collect()` or infer exact category counts from the bounded page.
- Do not alter global `.pane-canvas` or `.clay-card` colors without checking Workspace, Approvals-era cards and other dashboards.
- Do not weaken folder sealing: ingesting folder members must remain absent from search/grounding until completion.
- Search/action race: stale responses from a prior folder/query must not paint over the current folder. Query keys and effect cleanup must include `folderId`.
- Modals must restore focus, close on Escape, label controls, and prevent destructive actions from firing without confirmation.
- Telemetry/audit may contain IDs/counts/status only; never introduce extracted text or filenames in free-form payloads.
- Existing unrelated edits are present in Media, plans, schema and LLM files. This phase must not rewrite or revert them.

### Required Automated Cases

1. Same tenant, folders A and B, search candidates contain both: `folderId=A` returns A only.
2. Foreign/missing folder ID returns no cross-scope results and does not reveal ownership.
3. Category + folder intersection is enforced.
4. Sealed ingesting members remain excluded after adding folder scope.
5. Omitting `folderId` retains existing root search behavior.
6. Pure UI state tests cover root empty, category empty, folder empty, no results, loading, query error, partial ingest and stale digest.
7. Handler/contract tests prove upload, folder upload, Drive import, preview, correction, download, delete and rebuild remain represented/reachable.

### Mutation Checks

- Remove the folder comparison from search: the cross-folder test must fail.
- Remove tenant resolution: isolation test must fail.
- Coerce search error to empty: UI state test must fail.
- Add category counts from the bounded list: contract/static assertion must fail.

### Manual Browser UAT

- At desktop, tablet and mobile widths: root browse, category switch/search, folder open/search, document preview and empty/no-results recovery.
- Exercise the real upload, folder upload and Drive browser entry points.
- Exercise identity correction, citation display, download/delete when supported, and digest rebuild.
- Confirm keyboard focus order, Escape/focus restoration, reduced-motion behavior and no horizontal overflow.
- Capture before/after screenshots against `docs/design/mockups/vault-redesign.html`, but accept only behavior connected to live queries/actions.

## Recommended Plan Shape

1. Backend folder-scoped search contract and tests.
2. Pure UI state model plus Nord Edge root/folder composition while retaining handlers.
3. Preview/empty/failure polish and semantic token layer.
4. Full automated gates and browser checkpoint/UAT.
