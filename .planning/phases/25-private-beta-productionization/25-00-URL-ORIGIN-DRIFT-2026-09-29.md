# Phase 25 user-shareable URL origin drift — 2026-09-29

**Status:** planning-only material-drift finding at source SHA `2089ce5`. This is not an exhaustive URL census, Plan 25-00 release, deploy proof, or invitation to send links. Do not treat ADR-022's accepted durable-origin *policy* as proof of any hosted origin.

Phase 25's current roadmap criterion requires **every user-shareable app/API/HTTP URL and OAuth/unsubscribe origin** to be durable and verified before mandatory live sends. Plan 25-10's Task 3 intended generated user-shareable URLs to derive from named durable `SITE_URL`/`CONVEX_SITE_URL`, but the existing implementation and tests do not establish that universal claim:

| Surface | Current source | Evidence limit / gap |
|---|---|---|
| Beta invite copied by owner | `apps/web/app/(app)/admin/AdminView.tsx:130-138` builds `/signup?invite=` from `window.location.origin`, then writes it to the clipboard. Its fallback displays only the relative path at lines 202/248. | A preview-host admin session can copy an ephemeral host even if configured production `SITE_URL` passes `envCheck`. `apps/web/e2e/admin.spec.ts:84` tests only button visibility; it does not click or assert clipboard/origin. No production invite has been sent by this recheck. |
| Marketing funnel links | `packages/backend/convex/funnels.ts:42-55,89-126` validates `CONVEX_SITE_URL` as HTTPS `*.convex.site` before minting `/f/` links; `MarketingView.tsx:275-288` displays/copies returned URLs. | Source construction is anchored to the backend setting, but hosted DNS/TLS/current deployed value and the client copy surface remain separate evidence. |
| Public web-project host | `packages/backend/convex/webProjects.ts:141-147,238` derives `publicHost` from `CONVEX_SITE_URL` but returns `pikar-platform` when missing/invalid. | Must classify whether this fallback can reach a published user-facing URL or is only a dark/internal identity; a search hit alone does not prove exposure. |
| Unsubscribe footer | `packages/backend/convex/contacts.ts:727-734` constructs `/unsubscribe/{token}` from `CONVEX_SITE_URL` and refuses a missing origin. | Source path exists; actual hosted origin, route reachability, and a received email link remain unobserved here. |
| OAuth sign-in callbacks | Installed `@convex-dev/auth` uses `CONVEX_SITE_URL` by default and accepts `CUSTOM_AUTH_SITE_URL` as a library-level override in `dist/server/oauth/convexAuth.js` and `dist/server/implementation/signIn.js`. | The app's `ENV_MANIFEST`, origin readiness check, and backend source scanner do not classify this override. Whether it is configured is unverified. Its origin must be reconciled before claiming every auth callback derives from the named durable origin. |
| Public legal/metadata host | `apps/web/app/legal.ts:3` and `apps/web/app/layout.tsx:31` use `https://pikar-ai.com`, while the production app setting is described as `https://www.pikar-ai.com` in ADR-022. | Static host may be acceptable if redirect/DNS is durable, but that is a hosted observation, not something the source constants prove. It must be classified rather than silently treated as the configured app origin. |

The scan was targeted (`window.location.origin`, `navigator.clipboard.writeText`, `CONVEX_SITE_URL`, `SITE_URL`, public URL/link sites). It is **not** a complete enumeration of every `href`, attachment capability, download URL, provider-hosted invoice, web project, or HTTP route. The full Plan 25-00 Task 2 census and an exact-SHA repository/hosted origin gate are still required. Material drift has been returned to `$gsd-plan-phase 25` for plan-only reconciliation; no Phase 25 application source, provider, or deployment work is authorized by this note.
