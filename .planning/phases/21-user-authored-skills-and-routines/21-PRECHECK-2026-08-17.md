## Root cause: `tenantSkillIds` is threaded through dispatch but NOT through `runCockpitAgent`

Every case died before the model on the same Convex arg-validation error:

```
ArgumentValidationError: Object contains extra field `tenantSkillIds` that is not in the validator.
```

- `packages/backend/scripts/run-eval-golden.mjs:686` builds `tenantSkillIds` and
  `:2751` attaches it to the turn args. Correct.
- `packages/backend/convex/llm.ts:4215` declares `tenantSkillIds?: Record<string, Id<"tenantSkills">>`
  on the internal loop's TS type, and `:4265`/`:4282` read it to resolve the tenant pin. Correct.
- **`packages/backend/convex/llm.ts:4614-4646` — `runCockpitAgent`'s `args` validator lists
  `skillVersions` and does NOT list `tenantSkillIds`.** In Convex the `args` validator is the runtime
  contract; an extra field is rejected *before* the handler runs. The eval runner calls
  `llm:runCockpitAgent` directly, so it is stopped at the door.

**This is not a stale deployment.** The validator quoted in the error is byte-identical to the local
source. The argument was never added to this entry point.

### Why nothing caught it, which is the more useful finding

`d2374bf` ("feat(21-03): thread exact tenant candidate ids through scheduled dispatch") threaded the
pin through **scheduled dispatch** and proved it there — `dispatch.test.ts:2358-2427` pins a
candidate, asserts the pinned body wins, and even carries a named mutation *"drop `tenantSkillIds`
at one handoff"*. That test is real and it is green.

It is green because it goes through **dispatch**. The eval runner goes through **`runCockpitAgent`**.
The commit's own title says "scheduled dispatch" — one of the two callers. Nothing in the suite calls
`runCockpitAgent` with `tenantSkillIds`, so the missing validator field was invisible:

- **2030 backend tests green** — they reach the loop by paths that bypass this validator.
- **`--self-check` PASSED** — `run-eval-golden.mjs:2298` asserts the merge produces
  `{skillVersions:{}, tenantSkillIds:{}}` **offline**. It proves the runner *composes* the argument;
  it can never prove the server *accepts* it.
- **21-06's browser gate passed** — it drove the authoring UI, not the eval's live pin.

Same shape as the clock-plane defect: a parameter threaded through one caller and not the other,
green everywhere that isn't the live path.

## The fix, scoped

Four lines in `packages/backend/convex/llm.ts`, no new mechanism:

1. `args`: add `tenantSkillIds: v.optional(v.record(v.string(), v.id("tenantSkills")))` beside
   `skillVersions` (`~:4626`) — same internal-only justification, it is an `internalAction`.
2. destructure it in the handler (`~:4656`).
3. forward it into the loop at **both** call sites — `~:4730` and `~:4857`. `:4857`'s existing
   comment ("the loop builds its OWN tools — the drafter pin must ride there too") is precisely the
   hazard that produced this bug.

**And a regression test that fails for the right reason:** the existing coverage proves the mechanism
through dispatch. What is missing is a test that calls `runCockpitAgent` *through its validator* with
`tenantSkillIds` present. Without that, re-adding the field and deleting it again would stay green.
