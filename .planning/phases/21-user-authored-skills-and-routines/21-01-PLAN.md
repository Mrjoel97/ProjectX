<task type="auto" tdd="true">
  <name>Task 2: Add tenant skill-overlay and pinned-prompt schema</name>
  <files>packages/backend/convex/schema.ts</files>
  <action>
Add `tenantSkills` without modifying the existing `skills` definition. Required fields:

```text
tenantId, name, version, body, authoredBody,
status: active|candidate|archived|rolled_back,
author: system|user, authorUserId?,
basedOnScope: global|tenant, basedOnName, basedOnVersion,
basedOnGlobalSkillId?, basedOnTenantSkillId?,
rollbackEligible, evidence?, createdAt
```

`body`, `authoredBody`, name/version/author/base lineage are immutable after insert; later code may
patch only status, evidence, and the code-owned `rollbackEligible` transition when a row genuinely
becomes active. A server-created initial baseline uses `author: system`, empty `authoredBody`,
`status: archived`, and `rollbackEligible: true`; a user candidate uses `author: user`, a real
`authorUserId`, `status: candidate`, and `rollbackEligible: false`.

Add indexes named for all their fields:

```text
by_tenant_name_status  [tenantId,name,status]
by_tenant_name_version [tenantId,name,version]
by_tenant_createdAt    [tenantId,createdAt]
by_status_createdAt    [status,createdAt]
```

Add `savedPrompts` with `tenantId,text,title,textHash,createdAt` and indexes
`by_tenant_createdAt [tenantId,createdAt]` and `by_tenant_textHash [tenantId,textHash]`.
Do not add a `routines` table, trigger/schedule fields, execution history, next-run time, cron, graph,
or arrays that can grow without bound.
  </action>
  <verify><automated>pnpm --filter @pikar/backend typecheck</automated></verify>
  <done>The additive schema isolates tenant customizations and inert prompts without disturbing the
  global registry or introducing an automation engine.</done>
</task>
