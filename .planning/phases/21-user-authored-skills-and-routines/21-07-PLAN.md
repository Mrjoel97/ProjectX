**THE COMPARATOR — one script, called, never re-inlined.**

```powershell
$H = '.planning/phases/21-user-authored-skills-and-routines/21-LIVE-HANDOFF.json'
$live = npx convex run --json ... # or: eval:golden -- --inspect-tenant-skill <id> ... --json > live.json
node packages/backend/scripts/compare-refs.mjs --expected $H --actual live.json --label pre-live `
  --pair deploymentUrlHash=deploymentHash `
  --pair candidate=candidate --pair rollbackBaseline=rollbackBaseline `
  --pair effectiveBefore=currentEffective --pair globalBefore=globalCurrent `
  --pair foreignBefore=foreignCurrent `
  --allow-extra rollbackBaseline.scope
```

Why each piece, because the previous cut of this plan got all of this wrong:

- **`--pair deploymentUrlHash=deploymentHash`.** The handoff records `deploymentUrlHash`; the
  inspector emits `deploymentHash` (`run-eval-golden.mjs:3266`). The old verify compared
  `$h.deploymentUrlHash` to `$live.deploymentUrlHash` — always `$null` — so it threw
  `'deployment mismatch'` on a HEALTHY deployment, and the plan's next instruction was "do not
  refresh the handoff; diagnose/replan". Naming the rename is the fix; hiding it is how it recurred.
- **`--pair`, not a whole-document compare.** The inspector adds `expectations`, `mismatches` and
  `foreignCollision` at the root. Those are the inspector's verdict, not state, and comparing them
  to a handoff that never recorded them is meaningless.
- **`--allow-extra rollbackBaseline.scope`.** `baselineRefs` (`convex/skills.ts:1123`) writes
  `scope: "tenant"` as a HARDCODED LITERAL — never read from the row, so it cannot vary and cannot
  drift. 21-06's writer simply did not record it. Verified, then allow-listed BY PATH. It is the
  only one; anything else live-only and non-null is a real failure.
- **`candidate.lineage.basedOnTenantSkillId` needs no flag.** It is live-only and `null`, and a
  live-only null passes by rule (the live shape declares a field this row has no value for — this
  candidate descends from a GLOBAL row).
- **Never `ConvertTo-Json -Compress` equality.** Key ORDER differs (the inspector alphabetises, the
  handoff does not) and the key SET differs, so identical data compares unequal. Sorting keys first
  would fix the ordering half and leave the rename half — which is exactly how one broken idiom
  became three copies. `compare-refs` walks the tree and never builds a string.

Run `node packages/backend/scripts/compare-refs.mjs --self-check` before trusting it (14 assertions,
$0, includes the two defects above as regression cases).

`--only` cannot record evidence and is forbidden in a gate run. A prior approval does not authorize
