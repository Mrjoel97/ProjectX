<objective>
Build the intake trust boundary: an authenticated, validated submit that either
starts the pipeline workflow or rejects with an auditable "Request Rejected —
Validation Failed" outcome and an in-app notification (INTK-01, INTK-04) — plus the
tenant-scoped reactive queries the UI reads.

real mail to a stranger) structurally impossible by validating an explicit `To:`
field at the boundary, and put the five INTK-04 rejection checks in pure, testable
domain logic (CLAUDE.md §1) ahead of the un-testable workflow.start.

Output: `validateSubmit` (pure + tested), `requests.ts`, `notifications.ts`.
</objective>
