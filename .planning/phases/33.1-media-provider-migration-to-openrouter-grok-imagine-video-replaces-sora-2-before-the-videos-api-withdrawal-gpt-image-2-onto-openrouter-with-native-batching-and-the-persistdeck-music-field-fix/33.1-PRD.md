## Locked decisions

### L1. Video → `x-ai/grok-imagine-video` via OpenRouter

**This reverses ADR-026 and requires a superseding ADR-027.** ADR-026 (Accepted 2026-08-27) picked
`veo-3.1-lite`, and its decisive argument was *"introduces NO new data-transfer counterparty"* —
the owner already holds a GCP credential and ADR-016 admitted Google in principle.

**The owner was shown that argument explicitly and chose Grok anyway.** xAI becomes a new
data-transfer counterparty for customer scene prompts. That is accepted knowingly, and ADR-027 must
say so in those words rather than omitting the cost.

What the reversal buys, and why it was judged worth a new counterparty:

| | `grok-imagine-video` | `veo-3.1-lite` (ADR-026) | `sora-2` (today) |
|---|---|---|---|
| Durations | **1–15, any integer** | 4, 6, 8 | 4, 8, 12 |
| 720p | $0.07/s | $0.05/s w/audio · $0.03 w/o | $0.10/s |
| 480p | $0.05/s | not offered | not offered |
| 9:16 | yes | yes | yes |
| Native audio | none | yes | — |

The duration grid is the reason. `1–15 any integer` **retires the `illegal_generated_duration`
failure class outright** — the second of the two defects the owner hit live — where Veo's `4/6/8`
merely narrows it (5s and 7s scenes still refuse). Grok has no native audio, which suits a pipeline
that generates TTS narration separately and muxes it in `assemble_final.sh`.

Cost moves **down** from Sora ($0.07/s vs $0.10/s at 720p), so `MEDIA_JOB_CAP_USD` stays `3.50` and
ADR-016's never-landed raise to `7.50` stays unlanded.

### L2. Images → `openai/gpt-image-2`, same model, moved onto OpenRouter

ADR-024's **image half** is explicitly untouched by ADR-026 and remains valid — only `/v1/videos` is
being withdrawn. Keeping `gpt-image-2` is the standing decision, not inertia. What changes is the
transport and the key.

Verified on OpenRouter's endpoint for this model: `aspect_ratio` includes `9:16`;
`quality` ∈ `{auto,low,medium,high}`; **`n`: range 1–10**.

`x-ai/grok-imagine-image-2.0` was **rejected**: `n: {min: 1, max: 1}` — no batch — and $0.04/image
against gpt-image-2's ~$0.01. Batch is an explicit owner requirement; a single-vendor story does not
outrank it.

### L3. Both media planes go through OpenRouter

One transport, one funded key. OpenRouter is already an approved counterparty for all text traffic
since `845f4b1`, so it is not a new relationship — unlike xAI, which is (see L1).

### L4. Seedance is refused by construction, not by taste

`bytedance/seedance-*` is the cheapest published per-second rate on OpenRouter's collections page
($0.01345/s) and is **unusable here**. Its live SKU is `{"video_tokens": "0.0000035"}` — billed per
video token, configuration-dependent, not pre-computable before a request exists.
`packages/cost/src/media.ts` rule 1 refuses any such unit by construction, because the whole-job
reservation must be priced *before* any provider request. This session and ADR-026 reached this
conclusion independently.

## Verified API contracts

Confirmed by direct calls to OpenRouter on 2026-08-30, plus the published docs.

### Video — `POST https://openrouter.ai/api/v1/videos` (asynchronous)

```
Request  { model, prompt, duration?, resolution?, aspect_ratio?, size?,
           frame_images?, generate_audio?, seed?, callback_url? }
202      { id, polling_url, status: "pending" }
Poll     GET {polling_url}  ->  { id, status: pending|in_progress|completed|failed,
                                  unsigned_urls: [...], usage: { cost } }
Download unsigned_urls[0]   or  GET /api/v1/videos/{id}/content?index=0
```

**This is structurally the same shape `pollOpenAiVideoTask` (`media.ts:1603`) already implements** —
submit returns a ticket, a scheduled poller re-runs on `runAfter(10_000)` until a terminal state,
then content bytes are fetched. It is a sibling adapter, not new machinery. Precedent for a second
video adapter already sits in the file: `pollWanTask` (`media.ts:1467`) is the previous provider's
poller, retained.

### Images — `POST https://openrouter.ai/api/v1/images` (synchronous)

```
Request  { model, prompt, n?, aspect_ratio?, size?, quality?, output_format?, seed? }
200      { created, data: [ { b64_json, media_type } ], usage: { ..., cost } }
```

**`data[0].b64_json` is byte-identical to what `submitLine` already parses** (`media.ts:1042`). The
image change is close to a URL-and-key swap. Note `size` is accepted as explicit pixels, and
`aspect_ratio` is what this model's endpoint advertises — pin one deliberately, do not send both.

## Scope

### In scope

1. **The `music` fix** — widen `persistDeck`'s `artDirection` validator, plus a `dispatch.test.ts`
   fixture that carries a `Music:` line so the parser→mutation seam is covered for the first time.
2. **Images onto OpenRouter** — route, key, model id, request-shape change, price row re-derived
   from a real `usage.cost` rather than carried over.
3. **Video onto OpenRouter** — submit/poll/download adapter, `MEDIA_VIDEO_PRICING` and
   `MEDIA_VIDEO_SECONDS` rows, `MEDIA_DEFAULT_VIDEO` repin, `GENERATED_CLIP_SECONDS` widened to
   `1..15`, `succession.replacementWiredUp` set true only once the submit path and price row are
   both landed.
4. **ADR-027**, superseding ADR-026's video half. ADRs are immutable (CLAUDE.md §9) — supersede,
   never edit.
5. **`media-director.md` grid rule** — the body teaches `4, 8 or 12` at lines 172-175 and 290-291.
   It is a **gated skill row** (§5): changing it needs a recorded passing eval run, not a code edit.
6. **Playbook updates** — `docs/playbooks/media.md` in the same phase (CLAUDE.md §9), `Last verified`
   bumped.

### Out of scope — deliberately, and each for a stated reason

- **Image/video batch UX** (`proposeImage` count, N-variant plan rows). `n: 1..10` makes the
  *provider* side free, but `plans` is `.unique()` on `(tenantId, threadId)` — one plan row per
  thread — so N results is a data-model decision, not a transport one. It gets its own phase.
- **The clarifying-question gate** before `MEDIA_TASK_LINE`. Product design, not migration.
- **The media-director model pin** (`DEFAULT_MODEL = or/openai/gpt-4o-mini`, $0.003/run, wrote
  off-grid durations in every variation of every observed run). A wider grid absorbs most of it;
  repinning is a separate change with its own eval cost.
- Anything touching the **stills decision** beyond transport — ADR-024's image half stands.

## Constraints that bind every plan here

- **Cost rule 1** — every price table entry must be keyed on a unit computable *before* the request.
  This is what refuses Seedance; it applies to whatever else is proposed.
- **CLAUDE.md §4** — audit payloads carry refs, hashes, ids and counts only. Provider error *codes*,
  never provider prose, never a prompt, never a narration line.
- **CLAUDE.md §5** — no hardcoded prompts; `skills.test.ts` refuses any inline string over 200 chars
  in `convex/`. Assemble from short pieces, as the existing refusal bodies do.
- **No paid call without the human Approve gate.** The specialist grant is `SPECIALIST_TOOLS =
  ["searchVault"]` by identity. Paid calls fire only from `cockpit.ts`'s `EXTERNAL_TARGETS.media`
  after approval. Do not add a media tool to a dispatch to make testing easier.
- **`MEDIA_JOB_CAP_USD` stays `3.50`.** A successor needing a bigger cap than the model it replaces
  is a worse outcome wearing a migration's clothes.
- **TDD** — RED observed per test against a deliberate stub before each implementation, per the
  standard this repo holds elsewhere.
