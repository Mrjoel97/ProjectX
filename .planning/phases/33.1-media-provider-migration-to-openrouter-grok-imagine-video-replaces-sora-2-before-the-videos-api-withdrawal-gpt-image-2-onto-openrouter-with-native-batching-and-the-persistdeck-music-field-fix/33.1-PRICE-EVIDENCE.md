## Image — `openai/gpt-image-2` via `POST https://openrouter.ai/api/v1/images`

**Two calls, 2026-08-30. Total spend $0.008610.** Identical prompt (27 prompt tokens) and
`quality: "low"`, `n: 1`, `output_format: "png"`. The only difference is how geometry was requested.

| Geometry parameter | Returned dims | Ratio | `image_tokens` | `usage.cost` |
|---|---|---|---|---|
| `aspect_ratio: "9:16"` | **864 × 1536** | 0.5625 (true 9:16) | 120 | **$0.003735** |
| `size: "1024x1536"` | **1024 × 1536** | 0.6667 (2:3) | 158 | **$0.004875** |

Full `usage` from the `size` call:

```json
{"prompt_tokens": 27, "completion_tokens": 158, "total_tokens": 185, "cost": 0.004875,
 "cost_details": {"upstream_inference_prompt_cost": 0.000135,
                  "upstream_inference_completions_cost": 0.004740},
 "completion_tokens_details": {"image_tokens": 158}}
```

### What this settles

1. **`data[0]` carries exactly `{ b64_json, media_type }`** — `media_type: "image/png"`. This is
   byte-identical to what `submitLine` (`media.ts:1042`) already parses. No response-shape change.
2. **`size` IS honoured** — the endpoint's `supported_parameters` advertises `aspect_ratio` and not
   `size`, but explicit `WIDTHxHEIGHT` works and returns exactly those pixels.
3. **The two parameters are NOT interchangeable.** They produce different geometry, different token
   counts and different prices. Sending both would be a guess about precedence; send one.

### Decision: keep `size: "1024x1536"`

The migration changes the **transport**, not the picture. `MEDIA_DEFAULT_IMAGE` is
`{width: 1024, height: 1536}` today, `size` reproduces it exactly, and the assembler's geometry
handling stays untouched. A cheaper, differently-shaped image is an improvement, and improvements
do not ride in on a migration.

### Deferred, with the evidence already in hand

**Stills are 2:3 but reels are 9:16.** `MEDIA_DEFAULT_IMAGE` is 1024×1536 (0.6667) while the reel is
1080×1920 (0.5625), so every generated still is currently reshaped by the assembler to fit a frame
it was never composed for. `aspect_ratio: "9:16"` returns 864×1536 — the reel's true ratio — and
costs **23% less** ($0.003735 vs $0.004875, because 120 image tokens beat 158).

So the better-composed option is also the cheaper one. That is a real finding and it is **not** this
phase's to spend: it changes what every generated still looks like. Own phase, and this file is the
evidence it starts from.

### The price row

Measured floor is `$0.004875` at a 27-token prompt. `image_tokens: 158` is fixed for
`(1024x1536, low)`; only the prompt varies, at `$0.000005/token`.

Real scene prompts are longer than the probe's. The bodies observed on 2026-08-30 ran ~150–200
characters (≈40–55 tokens, ≈$0.00028). A reservation must never under-estimate, so the constant
carries a prompt allowance the way the existing one says it does:

```
MEDIA_IMAGE_PRICING["openai/gpt-image-2"] = 0.006
```

= `$0.004740` fixed image cost + `$0.00126` allowance, i.e. headroom for a ~250-token prompt.
**Down from `$0.01`**, which was a guess made without a measurement and is 2× the real cost. The
number is now derived from a recorded call rather than from caution.

## Video — `x-ai/grok-imagine-video` via `POST https://openrouter.ai/api/v1/videos`

**One submit + nine polls + one content fetch, 2026-08-30. Spend `usage.cost` = $0.490000.**

### The request that was accepted

```json
{"model":"x-ai/grok-imagine-video","prompt":"a lighthouse at dusk, slow push in",
 "duration":7,"resolution":"720p","aspect_ratio":"9:16"}
```

`HTTP 202` with `{"id":"VNpaxAbAfAomXJ…","polling_url":"…","status":"pending"}`.

### The five things this settles

**1. `duration: 7` SUCCEEDS.** A non-multiple-of-four length is the entire reason ADR-027 accepted
a new counterparty, and it was, until this call, an unverified reading of a docs table. It now has a
finished 7-second MP4 behind it. The phase's premise holds.

**2. The accepted field names are `duration` / `resolution` / `aspect_ratio`** — not Sora's
`seconds` / `size`. All three of the price table's keyed dimensions (`model`, `resolution`, and the
seconds, spelled `duration`) reach the request, so `buildSubmitBody`'s doc-comment promise stays
literally true. `aspect_ratio: "9:16"` was accepted alongside `resolution` — unlike the images
endpoint, where `size` and `aspect_ratio` are alternatives.

**3. The terminal status vocabulary is narrower than Sora's.** Nine polls at 10-second intervals
returned `pending` eight times, then `completed`. **No `queued` and no `in_progress` were ever
observed** — where Sora emits four states, this endpoint emitted two. The adapter therefore treats
*anything that is not `completed` and not `failed`* as non-terminal, rather than enumerating an
in-progress allow-list: an unlisted transient state must reschedule, never land a failure.
Completion took ~90 s for a 7 s clip, comfortably inside the 180-attempt (30-minute) budget.

**4. We construct both URLs; we follow neither. And `unsigned_urls` is a misnomer.**

| What was fetched | Result |
|---|---|
| `GET /api/v1/videos/{id}` — **our construction** | `200`, full status body |
| `polling_url` from the 202 | byte-identical to the line above |
| `GET /api/v1/videos/{id}/content?index=0` — **our construction**, our bearer | `200`, `video/mp4`, **4 471 786 bytes**, magic `ftypisom` |
| `unsigned_urls[0]` fetched **without** the bearer | **`401`** |

`unsigned_urls[0]` is on `openrouter.ai` at `/api/v1/videos/<id>/content` with a query string, and
it **requires our Authorization header anyway**. So it is not a pre-signed asset link, and the
plan's assumption that it was one is corrected here.

This resolves the trust boundary the clean way rather than the guarded way: **no provider-supplied
URL enters the system at all.** There is no `polling_url` on the scheduler args and no host check on
a returned link, because there is no returned link to check. A host check is a guard on a foreign
value; not accepting the foreign value is strictly stronger, and it is available here for free.

**5. `usage.cost` = `$0.49` against `7 × $0.07 = $0.49` predicted — exact, to the cent.**

The `MEDIA_VIDEO_PRICING["x-ai/grok-imagine-video"]["720p"] = 0.07` row plan 33.1-04 landed is
confirmed against an invoice, not against a docs page. The reservation does not sit below the charge,
so plan 05 Task 3's stop condition is not triggered and the flag may flip. `is_byok: false` confirms
the charge is OpenRouter's own, on the funded key.

### Not recorded here, deliberately

No `unsigned_urls` value, no prompt beyond the eleven harmless words above, no key, no video bytes.
The id appears truncated to a 14-character prefix. Per CLAUDE.md §4 this file carries refs, counts
and prices only.
