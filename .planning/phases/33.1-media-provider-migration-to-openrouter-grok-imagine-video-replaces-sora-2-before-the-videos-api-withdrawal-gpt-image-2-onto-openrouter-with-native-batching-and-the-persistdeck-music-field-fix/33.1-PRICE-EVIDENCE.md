## Image — `openai/gpt-image-2` via `POST https://openrouter.ai/api/v1/images`

**Two calls, 2026-08-30. Total spend $0.008610.** Identical prompt (27 prompt tokens) and
`quality: "low"`, `n: 1`, `output_format: "png"`. The only difference is how geometry was requested.

| Geometry parameter | Returned dims | Ratio | `image_tokens` | `usage.cost` |
|---|---|---|---|---|
| `aspect_ratio: "9:16"` | **864 × 1536** | 0.5625 (true 9:16) | 120 | **$0.003735** |
| `size: "1024x1536"` | **1024 × 1536** | 0.6667 (2:3) | 158 | **$0.004875** |

Full `usage` from the `size` call:

```json
{"prompt_tokens": 27, "completion_tokens": 158, "total_tokens": 185, "cost": 0.004875,
 "cost_details": {"upstream_inference_prompt_cost": 0.000135,
                  "upstream_inference_completions_cost": 0.004740},
 "completion_tokens_details": {"image_tokens": 158}}
```

### What this settles

1. **`data[0]` carries exactly `{ b64_json, media_type }`** — `media_type: "image/png"`. This is
   byte-identical to what `submitLine` (`media.ts:1042`) already parses. No response-shape change.
2. **`size` IS honoured** — the endpoint's `supported_parameters` advertises `aspect_ratio` and not
   `size`, but explicit `WIDTHxHEIGHT` works and returns exactly those pixels.
3. **The two parameters are NOT interchangeable.** They produce different geometry, different token
   counts and different prices. Sending both would be a guess about precedence; send one.

### Decision: keep `size: "1024x1536"`

The migration changes the **transport**, not the picture. `MEDIA_DEFAULT_IMAGE` is
`{width: 1024, height: 1536}` today, `size` reproduces it exactly, and the assembler's geometry
handling stays untouched. A cheaper, differently-shaped image is an improvement, and improvements
do not ride in on a migration.

### Deferred, with the evidence already in hand

**Stills are 2:3 but reels are 9:16.** `MEDIA_DEFAULT_IMAGE` is 1024×1536 (0.6667) while the reel is
1080×1920 (0.5625), so every generated still is currently reshaped by the assembler to fit a frame
it was never composed for. `aspect_ratio: "9:16"` returns 864×1536 — the reel's true ratio — and
costs **23% less** ($0.003735 vs $0.004875, because 120 image tokens beat 158).

So the better-composed option is also the cheaper one. That is a real finding and it is **not** this
phase's to spend: it changes what every generated still looks like. Own phase, and this file is the
evidence it starts from.

### The price row

Measured floor is `$0.004875` at a 27-token prompt. `image_tokens: 158` is fixed for
`(1024x1536, low)`; only the prompt varies, at `$0.000005/token`.

Real scene prompts are longer than the probe's. The bodies observed on 2026-08-30 ran ~150–200
characters (≈40–55 tokens, ≈$0.00028). A reservation must never under-estimate, so the constant
carries a prompt allowance the way the existing one says it does:

```
MEDIA_IMAGE_PRICING["openai/gpt-image-2"] = 0.006
```

= `$0.004740` fixed image cost + `$0.00126` allowance, i.e. headroom for a ~250-token prompt.
**Down from `$0.01`**, which was a guess made without a measurement and is 2× the real cost. The
number is now derived from a recorded call rather than from caution.
