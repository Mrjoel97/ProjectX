<domain>
## Phase Boundary

**Delivers:** every media generation in this product runs through OpenRouter on a funded key, and a
storyboard that parses is a storyboard that persists.

Three things, bound by one deadline:

1. `plans.persistDeck` accepts the `music` field its own parser emits and its own schema stores.
   Today it does not, and every deck carrying a `Music:` line is discarded at the write boundary
   after the memo has already landed.
2. Still images move from `api.openai.com` to OpenRouter, same `gpt-image-2` model.
3. Video moves from the `sora-2` / `/v1/videos` path — **withdrawn 2026-09-24** — to
   `x-ai/grok-imagine-video` on OpenRouter's async video API.

**Does NOT deliver:** batch UX, the clarifying-question gate, or a media-director model repin. Each
is named in the PRD's out-of-scope section with the reason it was excluded.

**Two dates bind this phase.** The cost suite goes RED on **2026-09-10**
(`packages/cost/src/media.test.ts:299`, `RUNWAY_DAYS = 14`). The endpoint dies **2026-09-24**.
Neither is negotiable and neither may be silenced by moving a constant.

<decisions>
## Implementation Decisions

### Models — locked by the owner on 2026-08-30

- **Video: `x-ai/grok-imagine-video` via OpenRouter.** Not `veo-3.1-lite`. This reverses ADR-026.
- **Images: `openai/gpt-image-2` via OpenRouter.** Same model as today; only the door changes.
- **Both planes go through OpenRouter.** One transport, one funded key.
- **`x-ai/grok-imagine-image-2.0` is rejected** — `n: {min:1,max:1}`, no batch, and 4x the price.
- **Seedance is refused by construction** — billed per video token, not pre-computable before a
  reservation exists. Cost rule 1, not taste.

### The ADR obligation — non-negotiable

- **ADR-027 must be written**, superseding ADR-026's video half. ADRs are immutable (CLAUDE.md §9):
  supersede, never edit.
- It **must state the counterparty cost in plain words**: ADR-026 chose Veo precisely because it
  added no new data-transfer counterparty, and this reverses that. xAI becomes a new recipient of
  customer scene prompts. The owner accepted this knowingly, in exchange for the `1–15` duration
  grid. An ADR that omits the cost is a worse record than no ADR.
- ADR-024's **image half stands** and is not superseded. Only the transport changes.

### Constants that move

- `MEDIA_VIDEO_PRICING` — add `"x-ai/grok-imagine-video": { "480p": 0.05, "720p": 0.07 }`
- `MEDIA_VIDEO_SECONDS` — add `1..15`
- `MEDIA_DEFAULT_VIDEO` — repin off `sora-2`
- `GENERATED_CLIP_SECONDS` (`packages/core/src/storyboard.ts:545`) — `[4,8,12]` → `1..15`
- `MEDIA_IMAGE_PRICING` — `gpt-image-2` re-derived from a **real** `usage.cost`, not carried over.
  The existing `$0.01` is self-described as "conservative"; OpenRouter bills this model per output
  token, so the constant must be measured once, not assumed.
- `MEDIA_JOB_CAP_USD` **stays 3.50.** Grok at $0.07/s is cheaper than the Sora it replaces.
- `wan2.5-*` rows stay — historical-only, so old rows remain priceable. Not a fallback.

### Constants that must NOT move

- `RUNWAY_DAYS` — it measures a real deadline. Set `succession.replacementWiredUp = true` only once
  the submit path AND the price row are both landed. A decision is not a migration.

### The skill body

- `media-director.md` teaches the `4, 8 or 12` grid at lines 172-175 and 290-291, and the worked
  example's decks are built on it. It is a **gated skill row** (§5) — a body change needs a recorded
  passing eval run, not a code edit. Plan the eval cycle explicitly; do not treat it as a text edit.

### Claude's Discretion

- Adapter shape: whether the OpenRouter video poller is a new `internalAction` beside
  `pollOpenAiVideoTask` or a parameterised generalisation of it. `pollWanTask` is precedent for a
  retained sibling.
- Whether `MEDIA_IMAGE_PRICING`/`MEDIA_VIDEO_PRICING` keys carry an `or/` route prefix the way
  `@pikar/cost`'s text models do, or stay bare. Follow whichever keeps the audit/pricing key honest
  about which billing path was used.
- Wave decomposition and plan count.
- Whether the dead `/v1/videos` code is deleted or left env-gated. Note the standing rule that
  Microsoft code is env-gated rather than deleted — decide deliberately and record the reason.
</decisions>

<specifics>
## Specific Ideas

### The failure being fixed is proven, not theorised

An isolated convex-test already demonstrates it: baseline art direction persists; the same object
plus `music: "upbeat"` throws `Validator error: Expected one of null, object`. The live audit log
for 2026-08-30 shows two media runs with `subagent.completed` and **no `media.deck_*` terminal at
all**, and the exact failing body was re-run through the real parsers, returning `kind: "two"` with
both decks OK. Reproduce this as the RED test before fixing.

### Test coverage is the actual root cause, and the plan should say so

`storyboard.test.ts` has 14 `Music` fixtures. `dispatch.test.ts` has **zero**. The parser is well
covered; the seam it writes across has never been exercised with music. A fix without a
`dispatch.test.ts` fixture carrying a `Music:` line leaves the hole open for the next field.

### The adapters are siblings, not new machinery

OpenRouter's video flow (`202` → `polling_url` → poll → `unsigned_urls[0]`) is structurally what
`pollOpenAiVideoTask` (`media.ts:1603`) already does with `runAfter(10_000)`. OpenRouter's image
response is `data[0].b64_json` — **already parsed byte-identically** by `submitLine`
(`media.ts:1042`). Reuse the shapes; do not invent a second rail.

### Two request-shape details that will bite

- gpt-image-2's OpenRouter endpoint advertises `aspect_ratio` (9:16 available), not `size`. Today
  `buildSubmitBody` sends `size: "1024x1536"`. Pin one deliberately; do not send both and hope.
- The video submit is JSON on OpenRouter. Today it is `FormData` (multipart) for OpenAI.

### Everything the money boundary already refuses must keep refusing

`buildSubmitBody`'s doc comment is the contract: every dimension the price table keys on is set from
the same spec object `chooseMediaBatch` consumed, and the `never` arm makes that mechanical. A new
priced dimension gets added in the SAME commit as its table entry.
</specifics>

<deferred>
## Deferred Ideas

- **Batch image/video production** (`proposeImage` count, N-variant plans). `n: 1..10` makes the
  provider side free, but `plans` is `.unique()` on `(tenantId, threadId)` — one plan row per thread
  — so N results is a data-model decision. Own phase.
- **The clarifying-question gate** before `MEDIA_TASK_LINE`, which today says "Do not ask questions"
  for a recorded reason (2026-08-18: without it, the same brief produced a deck on one run and prose
  on another). Product design.
- **Repinning `media-director`** off `DEFAULT_MODEL` (`or/openai/gpt-4o-mini`, $0.003/run, wrote
  off-grid durations in every variation of every observed run). The wider grid absorbs most of it.
- **`resetPlan` does not clear `altShots` / `altTargetDurationSeconds` / `lostVariation` /
  `deckAdjustments`** — carried over from phase 33's `deferred-items.md`. Adjacent, not this phase.
</deferred>
