## 6. The `regenerateBlock` re-test — the audit's refutation expired, and the finding is REAL

The audit refuted *"`regenerateBlock`'s partial buy routes around the cap"* on the only ground then
available: the cap did not exist. Re-tested against the landed cap, **the hole was real**:

```
scene 0 bought alone: expected { …(3) } to deeply equal { ok: false, … }
```

A 12 + 12 + 6 deck (24 generated seconds) was refused as a whole reel and then **reserved
successfully one scene at a time**. `reserveSceneJobInner` narrows `lines` to the chosen scene and
builds the batch specs FROM `lines`, so each partial buy carried only 12 seconds; `regenerateBlock`
requires no prior batch, so the entire deck was purchasable in instalments and would then render.

**Closed** by measuring the ceiling over the WHOLE deck's generated scenes in
`reserveSceneJobInner` — which is the rule that function already documents for every other refusal
("every refusal a full buy would raise, a partial buy raises too; only the LINES are narrowed").
Placed AFTER the scene loop, deliberately: every length above the grid is also above the ceiling, so
checking the ceiling first would make `illegal_duration` unreachable for a generated scene and
report "too much video" about a clip that cannot be bought at any price. Both are free refusals.

Two tests ship with it: the over-ceiling deck refuses on all four routes (whole reel + each scene
alone) with zero rows and zero cents, and a legal deck's partial buy still succeeds — without the
second, the fix would read as "partial buys are refused".

This was a **Rule 2 deviation** (a money guard with a bypass), taken without asking because
`33.1-CONTEXT.md` states the position outright: *"a cap with a documented bypass is not a cap"*.
