**One deliberate deviation from the plan's suggested mechanics, and it is a deviation from HOW, not
from WHAT.** The plan said to move `requireEnvMedia` *inside* the branches. Doing that would have
moved the credential read *below* the `MEDIA_PROVIDER_FIXTURE` short-circuit and silently retired an
existing invariant with its own test — *"fixture mode remains free but still requires configured
credentials"*. That test would have stayed green (it drives the video spec) while the property it
names stopped holding for images: an offline run would no longer catch the misconfiguration it exists
to catch. The one-line selector keeps the read above the short-circuit and satisfies every behaviour
the plan asked for, including the one it gave as the reason — an image submit with `OPENAI_API_KEY`
unset now succeeds, asserted.

`packages/backend/convex/lib/env.ts`

  is untouched.
- The comment records that the 2026-08-24 note's promise — *"it drops back to `feature` the moment

## 9. What I could NOT verify, stated rather than implied

1. **Nothing was exercised against a live provider.** Per the execution brief, no network call was
   made. Every assertion in this plan is against a stubbed `fetch`. That an OpenRouter image request
   *actually succeeds from this codebase* rests entirely on the orchestrator's Task 1 probe, which
   sent `buildSubmitBody`'s body verbatim — the same body a test now pins byte-for-byte. **The first
   real proof will be the first live generation.**
2. **Whether OpenRouter returns an `x-request-id` header is unknown.** `33.1-PRICE-EVIDENCE.md` does
   not record it, so I did not claim it either way. The `openrouter-${uuid}` fallback is therefore
   load-bearing rather than decorative, and both the code comment and the test say so. If a live run
   shows the header is present, the fallback stops mattering; if it is absent, `requestId` is a
   locally-minted id and any reconciliation that assumed a provider-side id needs re-reading.
3. **`33.1-PRICE-EVIDENCE.md` was deliberately left unmodified.** Task 3 asked for the raw
   measurement and the rounded constant to be on the record there; both already are (`$0.004875` /
   `= 0.006`), written by Task 1. Editing an evidence file after the fact to restate a number it
   already carries is how evidence stops being evidence. It appears in `files_modified` for this plan
   because Task 1 created it, and Task 1's commit is where it was touched.
4. **`.planning/STATE.md` and `.planning/ROADMAP.md` were NOT updated by this executor.** This lane
   is a separate worktree, another lane is actively committing in the main tree, and those two files
   are shared — advancing a plan counter from here would have conflicted with the orchestrator's own
