  <name>Task 1: billingApi.ts — the single outbound transport, keyed by construction</name>
  <files>packages/backend/convex/billingApi.ts, packages/backend/convex/billingApi.test.ts</files>
  <behavior>
    Write these RED first, all against a stubbed global `fetch` that captures the Request:
    - `stripePost("/v1/checkout/sessions", params, { idempotencyKey })` sends
      `Authorization: Bearer <key>`, `Content-Type: application/x-www-form-urlencoded`,
      `Stripe-Version: <STRIPE_API_VERSION>` and `Idempotency-Key: <idempotencyKey>`
    - The body is `application/x-www-form-urlencoded`, never JSON — Stripe's API is form-encoded
    - `stripePost` called WITHOUT an idempotency key is a TYPE error and, at runtime, throws. The key
      is a required parameter, not an option. Assert the throw.
    - The SAME inputs produce the SAME key and therefore the same body — replaying a key with
      different parameters is an error at Stripe, so the key must be derived from the same inputs
      that build the body. Assert key-and-body determinism together in one test.
    - `stripeGet` sends no `Idempotency-Key` (Stripe honours it on POST only)
    - `BILLING_STRIPE_SECRET_KEY` unset → throws naming the variable, and `fetch` is NEVER called.
      No development fallback (`p25-no-dev-fallback`).
    - A Stripe 4xx returns a structured failure carrying the Stripe `error.code` and `request-id`
      ONLY — assert that no `error.message` prose and no response body text survives into the
      returned value or into anything loggable (CLAUDE.md §4: refs, ids and counts only)
    - A network throw is surfaced as a failure, never swallowed into a success
  </behavior>
  <action>
Create `packages/backend/convex/billingApi.ts` — the ONE place this repo talks outward to Stripe.
Plain `fetch` against `STRIPE_API_BASE`, exactly as every other provider in this repo is called.
Do **not** add the `stripe` npm package: it is not installed, CLAUDE.md §8 rung 5 says do not add a
dependency for what a few lines cover, and it would drag a bundle into the Convex runtime.

Signature shape:
```ts
export async function stripePost(
  path: string,
  params: Record<string, string>,
  opts: { idempotencyKey: string },   // REQUIRED — not optional, not defaulted
): Promise<Result<unknown, StripeFailure>>;
export async function stripeGet(path: string, query?: Record<string, string>): Promise<Result<unknown, StripeFailure>>;
```

Read the secret through a **literal** `process.env.BILLING_STRIPE_SECRET_KEY` — `env.test.ts` scans
source for literals and a computed key is invisible to it.

Pin `Stripe-Version: STRIPE_API_VERSION` on every request. Without it a Dashboard-side default
change reshapes payloads underneath us; the invoice tax field is `total_tax_amounts` before Basil
and `total_taxes` from `2025-03-31.basil` onward.

Write the idempotency-key contract as a comment on `stripePost`: **the Stripe key is a same-day belt
only.** Stripe prunes keys after ~24h and then generates a new request, so a retry more than a day
later mints a second object. The durable guard is always our own claim row (plan 07's
`billingPeriods`); this header never replaces it.

This module is an action-runtime module (it does `fetch`). It must NOT be `"use node"` — nothing
here needs Node APIs, and a `"use node"` module may hold only actions.
