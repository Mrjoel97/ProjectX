**A signature-verified `POST /billing/stripe/webhook` on hand-rolled Web Crypto (no `stripe` dependency), with two-key structural idempotency inside one Convex `internalMutation` — proven offline at $0 against a fabricated `whsec_` secret, and 12 non-deletion mutations observed RED then restored.**

## Accomplishments

- **The route is un-forgeable.** Secret + header presence → raw body read ONCE → HMAC-SHA-256 over `` `${t}.${raw}` `` compared constant-time against **every** `v1` → only then `JSON.parse`. A tampered body, a wrong secret, a stale or future `t`, a `v0`-only header, a malformed header, an absent secret, non-JSON and a missing `event.id` all return **400 with zero rows**.
- **The route is un-double-appliable.** `receiveAndApply` reads `by_event`, then `by_object_type`, then inserts and runs the effect switch **in one transaction**. Convex has no unique index; OCC re-runs the loser of a race, which finds the row on its second pass. Two duplicate shapes are handled separately, because `event.id` alone is not a complete dedupe (Stripe's own guidance).
- **`packages/billing` exists as a pure package** — `parseStripeSignature`, `timingSafeEqualHex`, `SIGNATURE_TOLERANCE_S`, `HANDLED_EVENT_TYPES`, `classifyEvent`. No `ctx`, no `fetch`, no Convex import, and **no new external dependency**.
- **Everything is offline at $0.** No live Stripe key, no Dashboard work, no network. The test computes the HMAC itself rather than calling the function under test.
- **Two pre-existing red gates were found and fixed** (see Deviations) — one of them a drift tripwire that had been failing since 28-03.

## Decisions Made

See `key-decisions` in the frontmatter. The load-bearing one:

**`receiveAndApply` returns a three-value `outcome`, not a boolean.** The plan's `{ inserted: boolean }` would have made the duplicate-by-object branch **unobservable**: while the effect switch is empty, `status` is `ignored` on every path, so no assertion over the stored rows can tell that branch from the ordinary one. A mutation that swapped the `by_object_type` index columns confirmed it — under the row-count-only test it survived. With `outcome`, that mutation fails **exactly one** test.

## Issues Encountered

- **A crashed mutation run poisoned the battery.** The first mutation harness died on a Windows cp1252 decode error *after* applying M7, leaving `stripe-sig` on disk. The second run then snapshotted the already-mutated file as its "original" and restored to it after every mutation, so all eight mutations reported the same nine failures and the post-restore check was red. Caught by reading the actual file rather than trusting the harness. Fixed the encoding, restored the header by hand, re-ran from a verified-green baseline. **The lesson generalises: a mutation harness that dies mid-mutation leaves a mutated tree, and every subsequent result is measured against a broken baseline.**
- `npx convex codegen` needs a running local backend and cannot be run here (see Deviation 3).
