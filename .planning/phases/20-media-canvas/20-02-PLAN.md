  .index("by_batch", ["tenantId", "batchId"]),

**DELIBERATE DEVIATION from research §5.2 — record it in the summary.** Research proposed a stored
`callbackHash` field plus a `by_callback` index. Dropped: the webhook path segment is
`${jobId}.${hmacHex(jobId, FAL_WEBHOOK_SECRET)}` and plan 20-06 resolves the row with
`ctx.db.normalizeId("mediaJobs", raw)` and RE-DERIVES the HMAC — which is exactly what
`gmailAuth.verifyState` already does for the OAuth `state`, in an `httpAction`, in production today.
Storing the digest buys nothing and costs a field plus an index (ponytail rung 2). `normalizeId`
returning `null` for a malformed or foreign-table id is the fail-closed shape.

Comment the schema with the two §4 guarantees that are STRUCTURAL here:
- *"There is no URL field on this table, deliberately. The webhook downloads fal's bytes and stores
  them via `ctx.storage`; the signed fal URL is never persisted anywhere. A signed URL in a row is
  both a content leak and a live credential."*
- *"`promptHash`, not the prompt. The prompt text is content-plane and lives on `plans.shots`."*
- On `verdict`: *"four values, and `none_reported` means the provider reported NOTHING — it is not
  'clean'. Every Wan 2.5 video lands here; the model publishes no per-output moderation field.
  Never render it as a pass."*
