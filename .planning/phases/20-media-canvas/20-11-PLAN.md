  <files>docs/decisions/013-the-render-worker.md</files>
  <action>
**A separate ADR, deliberately.** Ponytail favours fewer files, and this is the exception the rule
names: D8 and D9/D11 are two decisions with two different alternatives-rejected sections, and ADRs are
immutable — a grab-bag ADR cannot be partially superseded later. If the renderer is ever replaced,
ADR-013 is superseded and ADR-012 stands. That is worth one file.

What ADR-013 decides:
1. **Convex cannot encode video.** `assemble_final.sh` needs `ffmpeg`, `ffprobe` and a POSIX shell.
2. **Chosen: Vercel Sandbox** (ephemeral Firecracker microVMs). Zero new vendors, zero always-on cost,
   the bundled bash runs near-verbatim.
   **Rejected, with reasons (D9 already wrote both):**
   - a persistent Fly/Cloud Run worker — a whole new deploy target, secret plane and monthly floor;
     the first infrastructure outside Vercel + Convex;
   - `ffmpeg.wasm` in the browser — the tab must stay open for minutes, it OOMs on multi-block 1080p,
     and decisively **assembly would run client-side where it cannot be audited and the sidecar would
     be self-reported by the browser rather than produced by a trusted runner.**
3. **The runner lives in `apps/web` as a route handler, NOT in Convex (D11)** — and this is the
   ADR's sharpest point. The alternative was `VERCEL_TOKEN` + `VERCEL_TEAM_ID` + `VERCEL_PROJECT_ID`
   as Convex deployment secrets. **A Vercel personal access token is scoped to a TEAM, not to a
   capability:** it can deploy, delete projects and read every project environment variable. That is
   strictly more powerful than anything this codebase holds, and it would falsify ADR-011's cleanest
   property — *"an API key in a deployment secret is the whole auth story"* — which is true of
   `FAL_KEY` precisely because `FAL_KEY` can only generate media. In a route handler OIDC is
   automatic and **no Vercel access token exists anywhere in the system**; plan 20-15 ships a
   repo-wide scan asserting exactly that.
   **The cost, stated:** one HTTP hop, one shared bearer secret, and **the Vercel function's max
   duration replaces Convex's 10-minute action limit as the binding ceiling.** Record the tier and
   the number settled at plan 20-15's checkpoint.
   Record the rejected alternative anyway, because a future reader will re-derive it: a dedicated
   render-only Vercel team holding the token. Lazier by one hop, but three secrets and a team-wide
   credential to avoid one route file.
4. **Two STRUCTURAL invariants, stated as decisions rather than implementation details, so relaxing
   either requires a superseding ADR:**
   - **`persistent: false` on every `Sandbox.create`, and never a `name`.** The SDK default is
     `true`: on stop the filesystem is snapshotted and restored on the next resume, so tenant A's
     clips would survive into the VM that renders tenant B's reel. A cross-tenant data leak created
     by an unset option.
   - **`networkPolicy: "deny-all"`.** With egress denied, tenant clips cannot leave even if the
     script were compromised. It is also why ffmpeg is baked into a snapshot rather than downloaded
     per invocation — the two are mutually exclusive.
5. **The sandbox is a trust boundary in both directions.** No key, no fal URL, no signed storage
   read-URL and no `tenantId` crosses in; nothing that comes back is published without passing
   `validateRenderReturn` and `parseAssemblySidecar`.
6. **The assemble script is CODE, not a `skills` registry row.** §5 governs prompts; a runtime-mutable
   shell script executed in a VM is remote code execution. One sentence, one scan (plan 20-13).
7. **Operational note that is a decision, not trivia:** on the Hobby tier, exhausting the free Sandbox
   allotment **pauses creation for 30 days rather than charging** — the render stage stops working
   mid-month with no invoice to notice. The mitigation is the offline fixture being the default in
   every test. Record the project's actual tier.

Status: Accepted, dated, owner decision.
