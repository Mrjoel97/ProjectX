**Four sections, in order, all produced in ONE turn:**

**1. SCRIPT** — D8 moves `/script` IN, because voiceover has nothing to say without it. A short
narration script for the whole reel, written for the EAR: spoken-language sentences, one idea per
sentence, no bullet syntax, no URLs read aloud. **Target 150–170 words for a 6-block 60-second
reel** — the body must be told the arithmetic (English narration runs ~150 wpm ≈ 2.5 words/second)
so it writes to length rather than being trimmed afterwards.

**2. ART DIRECTION** — koda's fixed 9-field block, emitted verbatim in shape:
`Palette` (3–5 hex colours WITH names — **hex, never vague colour words**), `Mood` (one sentence),
`Lighting` (a specific setup — *"warm golden light from camera left at 45 degrees"*, not *"warm
lighting"*), `Composition`, `Environment`, `Texture`, `Typography`, `References` (2–3 findable
real-world references — photographer, film, campaign), `Do NOT`.

**Creative DNA reads what already exists — do NOT ask for a new store (D6).** The body reads the
grounding spine already injected into the turn (`renderSpine`, `packages/core/src/blueprint.ts`,
per-tenant voice/audience/tier from `businessProfile.ts` + `tenantProfile.ts`) and, for the product's
own visual language, `docs/design/BRAND.md`'s palette and typography rules. Say so in the body.

**3. BLOCK DECK** — koda's table, re-shaped to D8's fixed-length contract. **This section IS the
contract with `parseBlockDeck`:**
```
BLOCK DECK
Clip seconds: 10
---
| # | Type | Description | Narration | Text overlay |
|---|------|-------------|-----------|--------------|
| 1 | VIDEO | [detailed visual description] | [the spoken line for this 10s window] | [if any] |
| 2 | VIDEO | [detailed visual description] | [the spoken line for this 10s window] |          |
```
Rules ported from koda: the first block is the strongest visual; hard cuts only; every block has a
stated purpose or is cut; text overlays bold, ≤3–4 words, **never top-right** (profile zone); screen
recordings ≤20% of total duration.

**Five adaptations that are NOT optional (D8 + delta §5.1):**
- **`Type` is a CLOSED set: `AI`, `SCREEN REC`, `TEXT`, `VIDEO`.** Nothing else.
- **Every block is the SAME length**, declared once as `Clip seconds:` and drawn from **{5, 10}**.
  There is no per-block duration column and no free-rhythm 1.5–2 s shot deck. Our model accepts
  nothing but 5 or 10 seconds, and the assembler's windows are fixed by construction so generation
  and assembly agree without negotiation.
- **Every block has a NARRATION line.** A silent block breaks the assembler's narration-per-window
  assert. If a block genuinely needs no words, the block should not exist.
- **A narration line must be at most 140 characters.** Teach the arithmetic, not just the number:
  *"English speech runs about 15 characters per second, so a 10-second window holds roughly 150
  characters. Write to 140 or fewer. A line that overruns its window is a hard error at render time —
  after the clips have been paid for — so length is a writing constraint, not a formatting
  preference."* This is the delta's highest-value invariant and the body is its PRIMARY enforcement;
  plan 20-01's parser is the backstop.
- **The deck IS a reel.** `Total duration = blocks × clip seconds`. The system assembles these blocks,
  with the narration voiced over them, into ONE finished mp4. Say so.
  **DELETE the old instruction** from `20-RESEARCH.md` §9.2 (*"the deck is a SET OF ASSETS, not a
  reel … the body must not promise a finished video"*). **D8 REVERSES it.** Do not leave both — a body
  that says both is a body that will say the wrong one.
  What the body must still NOT promise: music, a sung track, re-cutting footage the user already has,
  or a deliverable longer than the budget allows.

**4. BLOCK PROMPTS** — koda's `/generate` output, per block: `Prompt` (specific and technical, never
poetic — lighting, camera angle, lens, composition in every one; add *"photograph, ultra realistic,
editorial quality"* for photorealistic blocks), `Negative prompt`, `Settings` (aspect ratio; default
**9:16, 1080×1920**).

**DROP from koda (D6 — their invocation is not ours):** *"Read CLAUDE.md for API keys"*, *"Save
outputs in `visuals/`"*, *"Name files `shot-01.png`"*, `Output: [file path]`. **And drop `Model:`
from the output entirely** — the model is chosen by our price table, and a model-authored model name
is an unpriced-model vector. **Also drop any voice/speed direction** — the TTS voice and sample rate
are pinned in code (`MEDIA_DEFAULT_VOICE`), and a `speed` instruction would be a live violation of
D8's no-time-stretch rule (delta pitfall 15).

**Two things the body MUST say, because tests and D2 depend on them:**
- It has ONE tool, **`searchVault`**, for grounding in the tenant's own corpus — taught explicitly
  with what it is for. (`specialists.test.ts:94-112` asserts every granted tool is TAUGHT in its
  specialist's body and goes RED otherwise.)
- **It proposes; it never generates, never voices and never renders.** Nothing it writes spends money.
  The human clicks Generate on the canvas, or approves the plan. koda's own `/generate` rule agrees:
  *"Never generate without the user's approval — propose prompts first, generate after validation."*
