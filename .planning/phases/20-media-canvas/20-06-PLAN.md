<objective>
The authenticated callback and the landing plane: prove the caller knows a secret we minted for this
job, download the asset bytes inside the webhook, store them under the tenant, and record an
honest moderation verdict and the real cost.

Purpose: two things at once. An unguarded `POST /fal/callback` is a write endpoint that flips job
status, stores attacker-supplied bytes as a tenant's asset and drives spend reconciliation. And a
signed fal URL persisted anywhere is **both a content leak and a live credential** — downloading the
bytes here is what makes CLAUDE.md §4 structural instead of a promise: there is nowhere in the schema
for a fal URL to live.

Output: the route, `mediaComplete.landResult`, and the static scans that pin the audit surface.
</objective>

  <name>Task 1: `POST /fal/callback/*` — fail-closed 401, and nothing security-relevant from the body</name>
  <files>packages/backend/convex/http.ts, packages/backend/convex/media.test.ts</files>
  <behavior>
    - Absent segment, malformed segment, wrong digest, or unset `FAL_WEBHOOK_SECRET` → **401**, and
      the target row is byte-unchanged (assert the row, not just the status code).
    - A path id that does not `normalizeId` to a `mediaJobs` row → 401/404, zero writes.
    - `x-fal-webhook-timestamp` outside ±300 s → rejected.
    - A correct segment for a job already at a terminal status → 200, **no second store and no second
      spend consumption** (idempotent; fal delivery is assumed at-least-once).
    - A correct segment → the bytes are fetched, stored, and `landResult` runs for exactly that row.
    - **The asset-URL extraction is dispatched on the ROW's `kind`, not on the payload's shape.**
      A `video` row reads `payload.video.url`; an `image` row reads `payload.images[0].url`; an
      unhandled kind fails with a code rather than probing the body for whatever it can find.
  </behavior>
  <action>
```ts
http.route({ path: "/fal/callback/*", method: "POST", handler: httpAction(async (ctx, req) => { … }) });
```
The handler, in order:
1. Take the last path segment; `lastIndexOf(".")`; left half = the raw job id, right half = the
   digest. **`gmailAuth.verifyState`'s shape verbatim.**
2. `const secret = process.env.FAL_WEBHOOK_SECRET; if (!secret) return new Response("unauthorized", { status: 401 });`
   — **fail closed when the env is unset**, the `/skillopt/*` rule.
3. Resolve via `ctx.runQuery(internal.mediaComplete.resolveJob, { raw, digest })`, which does
   `normalizeId("mediaJobs", raw)` (null → refuse: a malformed or foreign-table id must never reach
   `ctx.db.get`), re-derives `await hmacHex(raw, secret)` and compares. Return 401 on any mismatch.
   **Everything security-relevant — `tenantId`, `planId`, `kind`, `model`, `estUsd`, `spec` — is read
   from the ROW, never from the payload.** The only things taken from the body are the asset URL to
   fetch and the moderation field, and both are validated.
4. Timestamp guard: `x-fal-webhook-timestamp` within ±300 s, else 401. Three lines, and it kills
   replay of a captured URL+body. Take it.
5. Terminal-status short-circuit: if the row is already `succeeded`/`failed`/`blocked`, return 200
   and do nothing. Idempotency, because fal's retry policy is undocumented.
6. On `status: "ERROR"`: `landResult` with a failure CODE derived from the body — never fal's
   `error` string verbatim (§4, the `reasonCode` idiom).
7. On `status: "OK"`: extract the asset URL **through a small `ASSET_PATH` table keyed by the row's
   `kind`**, not by sniffing the payload:
```ts
// One arm per kind. `tts` is added by plan 20-14, `stt` by plan 20-17 — and until then an unhandled
// kind returns a reasonCode rather than guessing, because "find whatever url is in this body" is a
// third party choosing what we download.
const ASSET_PATH = {
  video: (p) => p?.video?.url,
  image: (p) => p?.images?.[0]?.url,
} as const;
```
   then `fetch` it, `arrayBuffer()`, `ctx.storage.store(new Blob([bytes], { type }))`.
   **Then discard the URL.** It is not passed to `landResult`, not logged, not stored. `httpAction`
   has `ctx.storage`, so no extra hop is needed.
8. `ctx.runMutation(internal.mediaComplete.landResult, { jobId, storageId, bytes: byteLength, mimeType, moderation, actualSpecFromPayload })`.

**The `ponytail:` ceiling comment at the route, verbatim intent:**
> *"HMAC path segment, not Ed25519/JWKS. The segment proves the caller knows a secret we minted for
> THIS job; it does not prove fal sent it. Upgrade path when that matters: verify
> `X-Fal-Webhook-Signature` (Ed25519 over `request_id\nuser_id\ntimestamp\nsha256(body)`) against
> fal's JWKS at `https://rest.fal.ai/.well-known/jwks.json`, cached ≤24 h. FIRST confirm the Convex

> deliberately deferred out of this phase** — and note that a file holding an `http.route` cannot be
> `"use node"`, so `node:crypto` is only reachable via an extra `runAction` hop."*

// Kinds whose spend is a pure function of what WE SUBMITTED, so actual == estimate BY CONSTRUCTION.
