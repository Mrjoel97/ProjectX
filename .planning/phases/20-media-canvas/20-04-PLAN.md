<objective>
The second budget rail, and the transactional batch reservation that is this phase's real money
guard.

Purpose: a per-request $1.00 cap bounds NOTHING when a storyboard is N shots — ten 480p×5 s clips
are ten passing $0.25 requests and one $2.50 day. And the shipped LLM rail's shape (check in
`prepare`, consume in `recordSpend` afterwards) **cannot be copied**: N fal jobs are in flight
concurrently for minutes, so N post-hoc recordings all pass against a window nothing has consumed —
a TOCTOU on money. The fix is one mutation that estimates the whole deck, refuses over the cap,
checks the per-tenant window and consumes it with `reserve: true`, all in the same serializable
transaction.

Output: `mediaSpendCents` + `deploymentMediaSpendCents`, the media kill switch, and
`media.reserveBatch`.
</objective>

Implement the reservation as a **plain exported async function plus a thin `internalMutation`
wrapper**:

```ts
export async function reserveBatchInner(
  ctx: MutationCtx,
  a: { tenantId: string; planId: Id<"plans">; shots: readonly { shotIndex: number; spec: MediaSpec; prompt: string }[] },
): Promise<{ ok: true; batchId: string; estCents: number; shotCount: number }
         | { ok: false; reason: "kill_switch" | "unknown_model" | "over_batch_cap" | "illegal_duration"
                              | "media_daily_exhausted" | "deployment_media_exhausted" }>;

export const reserveBatch = internalMutation({ /* args validators; body = reserveBatchInner */ });
```

**Why a plain function and not only a mutation:** plan 20-07's approve arm runs INSIDE
`executePlan`, which is itself a `tenantMutation` — and a Convex mutation cannot `runMutation`.
Calling `reserveBatchInner` directly keeps the reservation in the SAME transaction as the plan's
`proposed → approved` CAS, which is exactly the property that makes "approve once, reserve once"
true. The `internalMutation` wrapper exists for the canvas path (plan 20-09) and for tests.

The algorithm, in order, and **the order is load-bearing**:
1. `const cfg = await getGuardrailConfig(ctx)` → `if (cfg.killSwitch || cfg.mediaKillSwitch) return { ok:false, reason:"kill_switch" }`.
2. `chooseMediaBatch(shots.map(s => s.spec), MEDIA_BUDGET_USD_PER_REQUEST)` → on Err, return its
   `code` as the reason. FAIL CLOSED — never guess a price.
3. `cents = est.value.estCents` — **the WHOLE deck, one number.**
4. `rateLimiter.check(ctx, "mediaSpendCents", { key: tenantId, count: cents })` → refuse
   `media_daily_exhausted`. **Tenant checked FIRST**, so a tenant that is personally out is told so
   rather than blamed for a global pause (the `prepare` ordering, verbatim).
5. `rateLimiter.check(ctx, "deploymentMediaSpendCents", { count: cents })` → refuse `deployment_media_exhausted`.
6. `rateLimiter.limit(ctx, "mediaSpendCents", { key: tenantId, count: cents, reserve: true })` **and**
   the same for `deploymentMediaSpendCents`. **CONSUME NOW, before any POST exists.**
7. `batchId = crypto.randomUUID()` (server-minted; `crypto.randomUUID()` in a mutation is the shipped
   `cockpit.ts` correlationId idiom). Insert N `mediaJobs` rows at `status: "queued"`, each carrying
   its own `estCents`, `spec`, `model`, `promptHash = await contentHash(prompt)` (`lib/hash.ts`),
   `shotIndex`, `createdAt`/`updatedAt`.
8. Return `{ ok: true, batchId, estCents: cents, shotCount: N }`.

**Steps 4-6 MUST be in the same mutation.** Convex mutations are serializable, so check-then-limit is
atomic and two concurrent storyboards cannot both pass a check against a window neither has consumed.
Splitting them across an action boundary is the defect this whole task exists to prevent — leave a
comment saying so.

**Reserve BEFORE the POST, not after — this is the one place media DIVERGES from the LLM rail.**
`prepare`/`recordSpend` can safely check-then-record-later because LLM calls inside a turn are
serial and an overshoot is cents. Here N jobs are submitted back-to-back and land minutes apart, so
post-hoc recording would let all N fire against a window that had room for one. Comment it with
`20-PROVIDER-EVAL.md` §4's line: *an LLM overshoot is cents, a media overshoot is dollars.*

`ponytail:` comment on the no-refund rule: *"if 3 of 10 shots come back provider_blocked, the
reserved cents stay consumed. Over-reservation is the fail-closed bias, same as
`Math.max(1, Math.ceil(...))`. Refunding turns a rate-limiter window into a ledger; if drift ever
proves material the upgrade path is a real spend table, not a credit call."*

Regenerate-one-shot is a **batch of one** through this identical path. No second rail, no second cap,
no bypass. Say so in the doc comment.
