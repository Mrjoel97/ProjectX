<objective>
Turn D5(b) — *is the price table still the vendor's price?* — from a manual procedure nobody runs
into a scheduled check that fails loudly.

Purpose: `packages/cost/src/media.ts` is a hand-maintained price table. Its `ponytail:` comment says
so and names the upgrade path. The committed fixture test proves the table agrees with
`media.fixtures.json` — i.e. that a table edit did not forget the fixture. **It cannot detect that
fal changed a price**, because both sides of that comparison are ours. The one thing that can is a
GET against fal's catalog API, which is unauthenticated, machine-readable and free, and which the
playbook has documented as runnable since 20-01 while nothing has ever run it.

The same response carries `deprecated` / `removed` / `status`, so this is simultaneously the
detection mechanism for the risk `media.md` calls out by name: `fal-ai/wan-25-preview/*` is a
**preview** endpoint, and preview paths get renamed and retired. A rename turns every generation
into `unknown_model` — the *correct* failure (loud, free, fail-closed) but one that reads to a user
as a broken product, and which we would currently learn about from the user.

Output: one script, one npm script, one weekly workflow, and the proof that the workflow goes red.
</objective>

<!-- Vendor shape as observed 2026-08-02 by 20-01's preflight and re-confirmed in media.md. -->

`GET https://fal.ai/api/models?keywords=<kw>&page=1` — unauthenticated, JSON, `{ items: [...] }`.
Per item, the fields this check reads: `id`, `status`, `deprecated`, `removed`,
`pricingInfoOverride` (a human-readable markdown string), `billingMessage`.

The four keywords that cover the table: `wan-25` · `inworld` · `scribe` · `schnell`.

**Verbatim strings pinned by 20-01 (these are what to diff against, NOT parsed numbers):**

| id | `pricingInfoOverride` |
|---|---|
| `fal-ai/wan-25-preview/text-to-video` | *"Your request will cost \*\*$0.05\*\* per second for \*\*480p\*\*, …"* |
| `fal-ai/inworld-tts` | *"Your request will cost \*\*$0.01\*\* per 1000 character."* |
| `fal-ai/elevenlabs/speech-to-text/scribe-v2` | *"Your request will cost \*\*$0.008 per input audio minutes\*\*. If keyterm is used, you request will cost %30 more."* |
| `fal-ai/flux/schnell` | **ABSENT.** Only `billingMessage: "Images are billed by rounding up to the nearest megapixel."` — recorded `confidence: "MEDIUM"` |

**DIFF THE STRING, DO NOT PARSE THE PRICE.** A regex that extracts `$0.05` and compares numbers
will silently pass a vendor edit that changes the *unit* — "per second" → "per generated second" is
the exact class of change ADR-011 exists to refuse, and it moves no number at all. The fixture
already stores the verbatim string; string equality is both stricter and less code.

**The scribe-v2 keyterm surcharge is part of that string.** We submit `keyterms: []`; if the
surcharge wording changes, the row needs re-pricing to $0.0104/min. That is a drift, not a footnote.

**The `skillopt.yml` precedent, and why task 3 exists:** `STATE.md` records that
`.github/workflows/skillopt.yml` has been **passing vacuously since it was written** — a `|| true`
on its kill-switch step swallows a failed `convex run`, so it logs an empty value and reports green
regardless. A monitoring job nobody has ever seen fail is indistinguishable from no monitoring job.
Do not add a second one.

<task type="auto">
  <name>Task 1: the three-outcome catalog check</name>
  <files>packages/backend/scripts/check-fal-catalog.mjs, packages/backend/package.json</files>
  <action>
A plain Node script — **no new dependency**: `fetch` is global on Node 18+, and the fixture is a
`JSON.parse` of a repo file. Wire it as `"check:fal-catalog": "node ./scripts/check-fal-catalog.mjs"`
in `packages/backend/package.json`.

**THREE outcomes, and the third is the point:**

| exit | meaning | when |
|---|---|---|
| `0` | AGREE | every pinned id found, `status: public`, `deprecated:false`, `removed:false`, and every `pricingInfoOverride` byte-identical to the fixture |
| `1` | DRIFT | any price string differs, any flag flipped, or a pinned id is MISSING from the catalog (the `-preview` retirement) |
| `2` | UNREACHABLE | the fetch failed, timed out, or returned non-JSON / a non-200 |

**Exit 2 must never collapse into 0.** A monitoring check that reports green when it could not
reach the thing it monitors is worse than absent, because it manufactures confidence. It must also
not collapse into 1 — waking someone for a network blip trains them to ignore the alarm that
matters. Print the distinction in the first line of output.

Set `process.exitCode` rather than calling `process.exit()`, so stdout flushes before the process
ends (a truncated diff is the second-most-annoying failure mode of a check like this).

Per-id report, one line each: `OK` / `DRIFT` / `MISSING`, and on drift print BOTH strings — the
fixture's and the vendor's — so the diff in the log IS the patch instruction.

**FLUX schnell is not a special case in the script.** It carries `confidence: "MEDIUM"` and no
price string in the fixture; the rule is general — *an entry with no pinned `pricingInfoOverride` is
checked for FLAGS and PRESENCE only, and its absence of a price string is not a drift.* If the
vendor ever STARTS publishing one, that IS a drift (it is now confirmable, and the MEDIUM
confidence must be resolved). Encode that as the general rule, and it handles schnell for free.

A `--timeout` guard (default ~10s per request, `AbortSignal.timeout`) so the workflow cannot hang.
</action>
