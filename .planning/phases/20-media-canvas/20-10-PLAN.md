<task type="auto">
  <name>Task 2: `MediaCanvas.tsx` — the reel region, the block pipeline, and live status with no ticker</name>
  <files>apps/web/app/(app)/dashboard/workspace/MediaCanvas.tsx</files>
  <action>
A self-querying dumb renderer (the `SourceCard` idiom): `useQuery(api.media.byPlan)` +
`useQuery(api.media.assetUrls)` + `useQuery(api.media.reel)` rather than threading data through props.

**No polling anywhere.** Convex reactivity delivers the webhook's mutation and the render terminal's
patch to an open canvas with no ticker. `ActivityCard:1239` already records the rule: *"Measured
server-side … never a `setInterval`."* If you find yourself writing one, the bug is elsewhere.

Structure, top to bottom:
1. **Art-direction header**, compact: `capsTeal` "ART DIRECTION", then palette swatches (the hexes
   the model authored — these are CONTENT, so they are legitimately inline styles, unlike product
   chrome) with their names, plus mood / lighting / composition as short labelled lines.
2. **`capsTeal` "REEL" — the new top-level artifact.** A BRAND Output card whose body is decided by
   `reel.status`:
   - `pending` → *"Not assembled yet. The reel is built after every block's clip and voice have
     landed."*
   - `rendering` → *"Assembling the reel… (usually 1–3 minutes)"*, inside the `aria-live` region.
   - `rendered` → `<video controls src={reel.url} />` plus the sidecar's gate summary in words:
     *"6 blocks · 60 seconds · every block's narration fits its window."*
   - `failed` → **the reason IN WORDS**, and the sidecar-invalid case gets its own sentence:
     *"The render finished but did not produce a valid assembly record, so it was not published."*
     Never a bare code, never a red dot alone.
   - **When a block has been regenerated or the deck edited since the last render**, the region says
     *"The reel is out of date — the blocks have changed since it was assembled."* Plan 20-09 clears
     the render fields on every such edit, so this state is `pending` with blocks already landed;
     distinguish it by the presence of landed assets and say so.
3. **`capsTeal` "STORYBOARD"**, then one tile per block **in `blockIndex` order**, each showing its
   window (`0:00–0:10`), its `Type`, its description and its narration (`traceText` on both — the
   split handle is user-resizable and a long line must wrap, not overflow).
4. **Each tile is the BRAND Output card** (`BRAND.md:101-102`): titled card, UPPERCASE type badge
   pill (`VIDEO` / `IMAGE` / `SCREEN REC` / `TEXT`), and the rendered artifact once it lands
   (`<img>` / `<video controls>` from `assetUrls`).
   **18-07 COLLISION:** Phase 18-07 plans the same BRAND Output card in `cards.tsx`. If it has
   already landed, IMPORT and reuse it. If not, build it here in a shape 18-07 can reuse, and say so
   in the summary. Do not ship two Output cards.
5. **TWO status rows per tile, not one** — the block is a pipeline. Use the `.trace-line` class:
   - **Clip:** `queued` → "Waiting to start", `submitted` → "Generating… (usually 1–3 minutes)",
     `failed` → the failure code in words, `blocked` → **"Refused by the provider's content check"**.
   - **Voice:** the same four states, worded for audio — `submitted` → "Recording the narration…".
   A block whose voice has landed and whose clip has not must LOOK different from the reverse. Wrap
   the whole status region in `aria-live="polite"` (BRAND §6).
6. **Verdict copy, and this is a compliance statement, not a style choice:**
   - `checker_clear` → "Provider safety check: passed"
   - `checker_flagged` → "Provider safety check: flagged"
   - `provider_blocked` → "Refused by the provider's content check"
   - `none_reported` → **"Not checked — this model reports no safety verdict"**
   Never a green tick for `none_reported`. Every Wan 2.5 video and every voice take lands there, and
   rendering it as a pass makes a compliance claim fal never made. Never colour alone.

`globals.css` tokens only. No component library. No timeline, no transitions, no filters, no layers,
no masking, no music controls, no client-side rendering — D7's ceiling.

**The estimate gate — D7's binding rule, now with four lines.** `useQuery(api.media.jobEstimate)`. The
Generate button is `disabled` until the estimate has resolved, and the panel above it always shows,
in words:
- **the four itemised lines and the total** — *"6 clips $3.00 · voice $0.02 · captions $0.01 ·
  render $0.02 = $3.05"*. One number is not enough: the user must be able to see WHICH line is
  expensive before deciding to cut a block.
- **the model and resolution the clips were priced at** ("Wan 2.5, 480p, 10 s per block"),
- **today's remaining media budget** ("$6.95 of today's $10.00 media budget remains").

When `jobEstimate` returns a `refusal`, the button stays disabled and the copy names the lever:
- `over_job_cap` → *"This reel would cost $6.00, over the $3.50 per-reel limit — remove blocks or
  drop to 480p."*
- `illegal_duration` → *"Every block must be 5 or 10 seconds."*
- `narration_too_long` → *"Block 4's narration is 186 characters — trim it to 140 or fewer, or the
  render will fail."* **With the Edit-narration control right there**, because a refusal whose cure is
  three clicks away is a dead end.
- `unknown_model` → *"This block names a model we can't price, so it won't run."*
Reuse the `approve()` / `busy` / `note` handler shape verbatim for the click.

**The five editor affordances, and NOTHING more (D7's floor AND ceiling):**
1. Edit a block's prompt → `api.media.editBlockPrompt`. Free.
2. **Edit a block's narration → `api.media.editBlockNarration`. Free.** With a **live character count
   against 140**, shown as `137 / 140` and switching to the `--held-text` amber (never `--held`, and
   never colour alone — the count itself is the signal) at the limit. This control is the UI half of
   the pre-payment guard.
3. Regenerate that one block → `api.media.regenerateBlock`. **PAID** — so it shows its own single-block
   itemised estimate and the remaining budget before it is clickable, same rule as the reel button,
   and it must state that regenerating **also re-renders the reel**.
4. Reorder blocks → `api.media.reorderBlocks`. Free.
5. Delete a block → `api.media.deleteBlock`. Free.

Label the free/paid classes visibly. A control that can spend money without showing its estimate
first is the one thing D7 forbids by name. **And every structural edit must warn that it invalidates
the reel** — the mutation already clears it (plan 20-09); the UI must not let that be a surprise.
