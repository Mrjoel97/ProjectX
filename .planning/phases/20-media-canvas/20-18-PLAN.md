`mediaJobs` carries, per PROVIDER LINE (never a render line — the render has no row):
```ts
tenantId · planId · batchId · blockIndex · provider:"fal" · kind:"video"|"image"|"tts"|"stt"
model · spec · promptHash · status:"queued"|"submitted"|"succeeded"|"failed"|"blocked"
estUsd: number            // FRACTIONAL USD, never floored cents (D12a)
actualCents?: number      // written by 20-06 on landing; ABSENT until then
verdict? · assetStorageId? · assetHash? · failureReason? · createdAt · updatedAt
```
Indexes: `by_plan` = `["tenantId","planId"]`, `by_batch` = `["tenantId","batchId"]`.

**THREE THINGS THAT WILL MAKE A NAIVE SUM LIE, and the plan exists to handle all three:**

1. **`sum(estUsd)` over rows is NOT the reserved amount.** The reservation was
   `chooseMediaBatch` over the whole batch **including the `render` line**, floored to cents
   **ONCE**. The render line has no row. So reserved ≠ Σ rows, by construction and by design.
   *Do not add a render row to make the arithmetic tidy* — 20-04 explains why it has none.
2. **A `tts` row's `estUsd` is the DOUBLED estimate.** 20-04 reserves voice at
   `narration.length * 2` so one rewrite round is pre-paid. So `est` will exceed `actual` on tts by
   ~2x **when nothing is wrong**. An output that does not say so reads as a 100% overcharge.
3. **`actualCents` is absent on any row that has not landed** (queued/submitted), and on any row
   that failed. `Σ actualCents` over a period therefore silently under-reports unless the rows
   without one are counted separately.

From 20-06: `actualCents` is `Math.round(row.estUsd * 100)` for a kind in `EXACT_SPEND_KINDS` and
re-priced from the same `@pikar/cost/media` table otherwise. **For the exact kinds the est-vs-actual
comparison is therefore VACUOUS by construction** — the real signal for those is our total vs fal's
dashboard, which is an EXTERNAL comparison this query only supplies one side of. Say so in the
output shape, not only in a comment.

Tenant scoping: `media.ts`'s existing surface is `internalMutation`. These are READS an operator
runs; use `convex/lib/functions.ts`'s wrappers for anything tenant-facing (CLAUDE.md §2), and an
`internalQuery` for the operator/CLI path. 20-09 owns the tenant-facing canvas queries — **do not
duplicate `jobEstimate`/`remainingCents` here.**

  <behavior>
    - An empty period returns every counter at 0 and `unlanded: 0` — never throws, never null.
    - Rows are selected by `createdAt` in `[sinceMs, untilMs)` — half-open, so two adjacent periods
      never double-count a row on the boundary. Assert that directly with a row ON the boundary.
    - `estCents` is `Math.round(Σ estUsd * 100)` over the SELECTED rows. Rounded ONCE, on the total
      (the D12a discipline, at the reader this time).
    - `actualCents` is `Σ actualCents` over rows that HAVE one.
    - **`unlanded` counts rows with no `actualCents`.** A period with 3 landed and 2 queued rows
      reports `unlanded: 2`, and the test asserts the total does NOT include the two.
    - `byKind` breaks both figures down by the four-member `kind`, because a drift in ONE table row
      is invisible in a single total.
    - **`notes.ttsReservedAt2x` is `true` whenever any `tts` row is in range** — the disclosure that
      stops a healthy 2x est/actual ratio reading as an overcharge.
    - A tenant sees ONLY its own rows: seed two tenants, assert the totals are disjoint.
    - The query NEVER writes: assert the rows are byte-identical before and after.
  </behavior>
  <action>
Add to `packages/backend/convex/media.ts`:

```ts
export const spendForPeriod = internalQuery({
  args: { tenantId: v.string(), sinceMs: v.number(), untilMs: v.number() },
  handler: async (ctx, a): Promise<{
    estCents: number; actualCents: number; rowCount: number; unlanded: number;
    byKind: Record<string, { estCents: number; actualCents: number; rowCount: number }>;
    notes: { ttsReservedAt2x: boolean; reservedTotalNotDerivable: true };
  }> => { /* … */ },
});
```

**`reservedTotalNotDerivable: true` is a LITERAL in the return shape, not a comment.** It is the
one-line answer to the question every reader of this output will ask — *why does this not equal what
the rate limiter consumed?* — and putting it in the payload means the CLI output carries its own
caveat. Interfaces note 1 is the reason.

Iterate with the `by_plan` index prefix (`q.eq("tenantId", …)`) and filter on `createdAt` in the
handler. **Never a full-table scan and never a `.collect()` over all tenants** — the index prefix is
the tenant boundary, the same shape `plans.ts` uses.

Keep it a pure fold. No `ctx.db.patch`, no rate-limiter call, no re-pricing: this reader must be
safe to run against production at any time, including while a batch is in flight.

**Payload discipline (CLAUDE.md §4):** counts, cents and the `kind` enum ONLY. Never a `promptHash`
preimage, never a `model` prompt, never a URL. `model` as a table key is a ref and is fine.
