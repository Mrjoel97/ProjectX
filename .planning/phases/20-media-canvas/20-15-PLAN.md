<objective>
The renderer: a Next.js route handler that starts an ephemeral Vercel Sandbox, streams the clips and
voice takes in, runs `assemble_final.sh`, and returns a validated `final.mp4` plus its sidecar — with
no Vercel access token existing anywhere in the system.

Purpose: Convex cannot encode video (D9) and a Convex-hosted runner would need `VERCEL_TOKEN` +
`VERCEL_TEAM_ID` + `VERCEL_PROJECT_ID` — and a Vercel personal access token is scoped to a **team,
not a capability**: it can deploy, delete projects and read every project environment variable. That
is strictly more powerful than anything this codebase holds, and it would falsify ADR-011's cleanest
property (*"an API key in a deployment secret is the whole auth story"*), which is true of `FAL_KEY`
precisely because `FAL_KEY` can only generate media. **D11's answer: put the runner where OIDC is
automatic.** One extra HTTP hop, one shared secret, zero team-scoped credentials.

The sandbox is a **trust boundary in both directions**, and this plan's job is to make that
structural rather than a promise: `deny-all` egress and `persistent: false` are infrastructure
guarantees; the return validation and the sidecar check are code; and both are asserted by tests that
never touch a real VM.

Output: the route, the Convex caller, the pure options builder and validators, the snapshot bake
script, and the offline seam that keeps every test at $0.
</objective>
