<interfaces>
Google's revoke endpoint (verified against developers.google.com/identity/protocols/oauth2, "Token
revocation" — not from memory):

```
POST https://oauth2.googleapis.com/revoke
Content-Type: application/x-www-form-urlencoded
token=<access OR refresh token>          # NO client_id, NO client_secret
```

200 = revoked. 400 + an error code = invalid/already-revoked/malformed. Revocation is NOT
2xx-idempotent, so **200 and 400 are the same end state ("gone at Google")** and only a network
throw / 5xx means "unconfirmed" — the same discipline `calendar.ts`'s `eventIdFor(planId)` already
uses where a 409 duplicate IS success. Post the **refreshToken**: revoking it kills the grant and
every access token derived from it; revoking the accessToken kills one short-lived token and leaves
the user's Google "Third-party access" entry alive, which is the exact bug this plan exists to fix.

Where the code may live is decided by two hard constraints, and the second one is the non-obvious
half:

1. `gmail.ts:1` is `"use node"` (actions only, no `ctx.db`), **and** `llmRedaction.test.ts:159-168`
   statically pins its POST set to exactly `["TOKEN_ENDPOINT", "SEND_ENDPOINT"]` and asserts the
   total `method: "POST"` count matches. A third POST in `gmail.ts` fails by construction.
   **gmail.ts is out.**
2. `gmailAuth.ts:3` is deliberately NOT `"use node"` — and that does not stop it fetching. Convex's
   default (isolate) runtime has `fetch`, proven twice in shipped code: `voiceToken.ts:1-3` ("two
   PLAIN-runtime actions… both are just `fetch`", plus its warning that a second node module
   re-trips the TS circular-inference cliff), and `http.ts:39-49`, an `httpAction` in a non-node
   module POSTing `URLSearchParams` to `https://oauth2.googleapis.com/token` with the identical
   content-type — byte-for-byte the shape revoke needs.

Therefore everything lands in `gmailAuth.ts`. Existing shapes it composes with:

```ts
// lib/functions.ts:74 — the only wrapper that can fetch; injects ctx.tenantId from the identity.
export const tenantAction = customAction(action, customCtx(requireScope));
// lib/functions.ts:50-51 — "There is deliberately no `ownerAction`". None is wanted: this is the
// caller's OWN grant, not an admin control.

// audit.ts:16-25 — the sole insert surface. `ts` is set inside; callers pass:
{ tenantId, correlationId, eventType, actor, payload }
```

`AuditPayload` (`packages/contracts/src/audit.ts:18-32`) admits a flat map of
`AuditRef | AuditHash | number | boolean | null | readonly string[]`, so `{ revoked: boolean,
status: number }` is representable and a nested Google response body structurally is not.
