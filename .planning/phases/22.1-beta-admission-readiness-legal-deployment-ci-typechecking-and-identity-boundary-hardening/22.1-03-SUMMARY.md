Two lint findings had to be fixed to reach that state, and both are recorded because of *how* they

- `6b8c438` — five genuine format violations that a *sampled* CRLF assumption had wrongly dismissed.
  The correct discriminator is per-file: `git ls-files --eol` showing `w/crlf` is local noise,
  `w/lf` is a build breaker. Same rule name, opposite meaning.

## Tasks 2 and 3 — the synthetic three-red proof: DEFERRED

Task 2 is a decision checkpoint requiring explicit owner authorization to push a scratch branch
producing three deliberate red CI runs; Task 3 executes it. **Neither was authorized and neither was
performed.** No scratch branch was created and no deliberate failure was pushed.

**What substitutes for it, partially and honestly:** on 2026-08-16 the gate went red on a *real*
defect and blocked a real release.

| Evidence | Run |
|---|---|
| CI **failure** at the Lint/format stage on `d38f627` | https://github.com/Mrjoel97/ProjectX/actions/runs/31954504792 |
| `deploy-production` **skipped** for that SHA | https://github.com/Mrjoel97/ProjectX/actions/runs/31954555500 |
| CI **green recovery** on `6b8c438` | https://github.com/Mrjoel97/ProjectX/actions/runs/31954922744 |
| `deploy-production` **success** on `1ca7c6f` | https://github.com/Mrjoel97/ProjectX/actions/runs/31956285601 |

That is stronger than a tripwire in one respect — it was a real defect, not a synthetic one — and it
proves the two claims that matter most: the gate is anti-vacuous, and a red gate produces **no
deploy** rather than a half-deploy.

**It is weaker in coverage, and that gap is the honest remainder:** only the Lint/format stage has
been observed red on the remote. The **Typecheck** and **Test** stages have never failed a remote
run, so their remote failure behaviour is still asserted rather than observed. Anyone wanting that
evidence should run the original Task 3 procedure on a scratch branch, with owner authorization.
