# 22.1-02 Summary — per-tenant budget keying, with the ceiling kept

`dailySpendCents` was a KEYLESS fixed window: it capped the **deployment**, not the tenant. One
tenant's agent loop drained everyone else's day, and every other tenant saw governed refusals it
could not explain. `dispatch.ts`'s `ENVELOPE_FRACTION` took its 25% from that same shared pool.
With one owner this was invisible; the moment Phase 25 admits a second user it is a live bug.

## The decision that shaped this plan

Keying the window by `tenantId` — the obvious fix — trades a noisy-neighbour bug for a cost bug:
exposure becomes `N × DAILY_BUDGET_CENTS`, unbounded in N, with the manual all-or-nothing kill
switch as the only global stop. **Owner decision 2026-08-01: keep a deployment ceiling.** So there
are now two rails:

| Rail | Keyed? | Value | Meaning |
|---|---|---|---|
| `dailySpendCents` | **by tenantId** | `DAILY_BUDGET_CENTS` = 500 (≈$5) | what ONE tenant may spend today |
| `deploymentSpendCents` | **deliberately keyless** | `DEPLOYMENT_BUDGET_CENTS` = 5000 (≈$50) | the hard cap across everyone |

`prepare`/`preCall` check both — **tenant first**, so a tenant that is personally out is told so
rather than blamed for a global pause. `recordSpend` consumes both, so neither can be drained
without the other seeing it. `remainingDailyCents` returns `min(tenant, deployment)`, each clamped
to `>= 0` **before** the min: `recordSpend` uses `reserve: true`, so either rail can go negative,
and an unclamped negative ceiling would silently zero every tenant's envelope.

Two refusals now exist and they say different things: `daily_budget_exhausted` ("you are done for
today") and `deployment_budget_exhausted` ("everyone is paused").

## What shipped

- `guardrails.ts` — both windows; `{ key: tenantId }` on every `dailySpendCents` call; `preCall`,
  `recordSpend` and `remainingDailyCents` gained a required `tenantId`; `prepare` needed no new
  arg (it already reads `req.tenantId` off the row).
- **53 threading replacements across 12 modules.** The 15 call sites that already had a
  `tenantId`, plus **six private helpers** that did not and now take one:
  `intake.transcribeAudio`, `intake.extractVisual`, `llm.recordModelSpend`,
  `vaultExtract.extractPdf`, `vaultExtract.extractHosted`, `voiceDoc.modelDocReview`.
  `recordModelSpend` is the shared spend sink — seven call sites route through it, so it was
  threaded **once** there rather than at seven sites (ladder rung 2).
- `pipeline.ts` `BlockReason` + `BLOCK_LABELS`, `failureCopy.ts`, and the 12 hand-repeated
  refusal unions gained the new reason.
- `smoke.ts`'s `drainDailySpend`/`resetDailySpend` take a tenantId and exercise ONE tenant;
  `run-smoke-guardrails.mjs` passes `"smokeBudget"`. Draining the ceiling is deliberately not
  offered — it would block every tenant, which is the blast radius this removed.
- Five playbooks updated (`agent-runtime`, `cockpit`, `vault`, `voice`, `onboarding`).

## Evidence

- **`guardrails.test.ts` +4 tests, 9/9 green**, driving the REAL rate-limiter component. The
  headline one — *tenant A exhausting its day does not refuse tenant B* — is
  **mutation-verified**: dropping `key: tenantId` from `preCall` turns it RED with
  `expected { ok: true } to deeply equal { ok: false, … }`. It also asserts
  `DAILY_BUDGET_CENTS < DEPLOYMENT_BUDGET_CENTS` so the test cannot pass vacuously.
- **Backend 865/866.** The one red, `onboarding.test.ts §4.2`, is **pre-existing and not from this
  plan** — verified by stashing every change in this plan and watching it fail identically. It
  traces to another lane's 17.1-07 work.
- **Typecheck at exactly 150 — the baseline, zero delta.** Web typecheck clean.
- **The type system did the finding.** Making `tenantId` a required arg meant every missed site
  was a compile error, not a silent mis-billing: `tsc` surfaced 10 call sites where a `tenantId`
  looked in scope but was not (four handlers declared it in `args` and never destructured it).
  That is the whole reason the arg is required rather than optional-with-a-default.

## One guard widened, never relaxed

`vaultExtract.test.ts`'s 15.2-06 static scan asserts the hosted branch receives `pages[...]` and
never the sliced whole document. Inserting `tenantId` broke its regex. The regex was **widened for
the new parameter, not loosened** — the per-page fan-out guarantee is unchanged and still fails
closed.

## Consequences worth knowing

Spend now lands on the acting tenant's rail. A long voice session, or a large vault fan-out
extraction, can exhaust **that tenant's** day — where previously it drained everyone's. That is
the intended behaviour, but it means a single heavy user hits their own wall sooner than before.
`DAILY_BUDGET_CENTS` is the one knob.
