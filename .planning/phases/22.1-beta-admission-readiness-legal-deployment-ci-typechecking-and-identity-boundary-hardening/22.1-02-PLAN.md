<objective>
Stop one tenant's spend from refusing every other tenant, without trading a bounded bill for an
unbounded one.

Purpose: `dailySpendCents` is a KEYLESS fixed window (`guardrails.ts:23-28`) — it caps the whole
DEPLOYMENT, not the tenant. `dispatch.ts:41-45`'s `ENVELOPE_FRACTION` takes its 25% from that same
shared pool. With one owner this is invisible. The moment Phase 25 admits a second user, one
tenant's agent loop drains everyone else's day and every other tenant sees governed refusals it
cannot explain. This is a hard blocking prerequisite for Phase 25 multi-user, and it is small.

The naive fix — key the window by tenantId — swaps a noisy-neighbour bug for a cost bug: exposure
becomes N x $5/day, unbounded in N, with the manual all-or-nothing kill switch as the only global
stop. So this plan keeps a second, deliberately keyless deployment ceiling alongside the keyed
window. Owner decision, 2026-08-01.

Output: both windows, both consumed, distinguishable refusals, and a two-tenant test that fails if
the keying regresses.
</objective>
