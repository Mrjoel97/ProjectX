# Phase 3.3 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.
> Derived from `03.3-RESEARCH.md` § Validation Architecture (V1–V10).

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | vitest (unit, `packages/*`) + convex-test (backend) + Playwright (E2E, `apps/web/e2e`) |
| **Config file** | `packages/backend/vitest.config.*`, `packages/core/vitest.config.*`, `apps/web/playwright.config.*` |
| **Quick run command** | `pnpm --filter @pikar/backend test` (or `--filter @pikar/core test` for pure validators) |
| **Full suite command** | `pnpm -r test` + backend `pnpm --filter @pikar/backend smoke:fanout && smoke:guardrails` |
| **Estimated runtime** | ~20–40s unit; smoke scripts ~30–60s each (need live `convex dev`) |

Notes:
- Pure-JS logic (`markdownToPdf`, `buildMime` multipart) → assert-based self-check colocated with the code (ponytail: "one runnable check"), also runnable under vitest.
- Backend Convex paths that hit `audit.log` need the `auto counts` aggregate registered in the test (see 03.2.1-03 — `auditCounts` component registration; a known convex-test 0.0.54 quirk).
- Smoke + E2E run against an already-running `convex dev` (NOT `--once`) + `next dev :3111`.

---

## Sampling Rate

- **After every task commit:** Run the relevant `pnpm --filter <pkg> test` (quick).
- **After every plan wave:** Run `pnpm -r test` + the extended `smoke:fanout` (attachment path).
- **Before `/gsd:verify-work`:** Full suite green + `cockpit-attachment` E2E green + one live human-verify send.
- **Max feedback latency:** ~40s (unit); smoke/E2E on wave close.
