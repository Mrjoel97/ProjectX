## Accomplishments
- `generateAttachment({topic})` — scan (fail-closed §4) → `draftDocument` → `markdownToPdf` → `buildDocFilename` → cap check → `storage.store` → `recordAttachments` (append ref, clear error). Returns a filename/count LABEL only — never a URL/bytes.
- `regenerateAttachment({index, topic})` supersedes in place then `storage.delete`s the OLD id AFTER the new ref persists (O3); `removeAttachment({index})` persists the shortened array then deletes the bytes. Both bounce an out-of-range #index with no side effect.
- Render throw OR over-`PLAN_ATTACHMENT_CAP_BYTES` total → `attachmentError` set, NO ref added (block-on-render-fail, block-on-oversize).
- `proposePlan` refuses when `attachmentError` is set OR the summed attachment size exceeds the cap (defense-in-depth over the tool-level refusal, facts from the ROW).
- `buildAgentContext` now lists attachments by `#index/filename` (address/URL-free).
- `SMOKE::agent::attach=<topic> | regenerate=<i>:<topic> | removeAttachment=<i>` drive the real tools offline with deterministic bytes.
- `cockpit-agent` skill v-bumped (5-file mirror; seedSkills publish-on-change): suggest-then-confirm before attaching, reason about attachments by filename/#index, never claim a send.

## Decisions Made
- `removeAttachment` records the shortened array before deleting bytes (O3-consistent) rather than the plan's literal delete-then-record sketch — avoids a dangling ref if the mutation were to fail; a transient orphan is the lesser evil. (Deviation Rule 1, below.)
- Attachment tools use 1-based `#index` matching `removeRecipient` and the agent's index/label reasoning.
- `buildAgentContext` surfaces attachments so regenerate/remove-by-index work across turns (feature-required, address-free).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] removeAttachment ordering: record-then-delete instead of delete-then-record**
- **Found during:** Task 1 (removeAttachment)
- **Issue:** The plan's remove behavior sketch deletes storage before writing the shortened array; if the mutation failed, the plan would keep a ref to already-deleted bytes (a broken attachment). The regenerate action in the same plan already mandates delete-AFTER-persist (O3).
- **Fix:** removeAttachment persists the shortened array via `recordAttachments`, THEN `storage.delete`s the old id — uniform with regenerate's O3 ordering.
- **Files modified:** packages/backend/convex/llm.ts
- **Verification:** `removeAttachment` test asserts the ref is gone AND `getUrl(oldId)` is null.
- **Committed in:** `3725383`

**2. [Rule 3 - Blocking] Cast Uint8Array → BlobPart for ctx.storage.store**
- **Found during:** Task 1 (renderAndStore)
- **Issue:** `new Blob([bytes])` failed source typecheck — the DOM lib types `Uint8Array<ArrayBufferLike>` too strictly (potentially SharedArrayBuffer-backed) for `BlobPart`.
- **Fix:** `new Blob([bytes as BlobPart], ...)` — valid at runtime; marked with a `ponytail:` comment.
- **Files modified:** packages/backend/convex/llm.ts
- **Verification:** `tsc --noEmit` clean for llm.ts; cockpitTools tests green.
- **Committed in:** `c96d83a`

**3. [Rule 2 - Missing critical] render=fail:: SMOKE hook + buildAgentContext attachment surface**
- **Found during:** Task 1 / Task 3
- **Issue:** (a) block-on-render-fail could not be exercised deterministically offline — `markdownToPdf` sanitizes all input and effectively never throws on content. (b) Without attachments in `buildAgentContext`, the agent cannot regenerate/remove a prior attachment across turns.
- **Fix:** Added a per-request `render=fail::` content sentinel (mirrors the existing `fail=primary::` pattern) to force the render-fail branch; extended `buildAgentContext` to list attachments by `#index/filename` (address/URL-free).
- **Files modified:** packages/backend/convex/llm.ts
- **Verification:** render-fail test asserts `attachmentError` set + no ref; llmRedaction static index/label scan stays green.
- **Committed in:** `3725383` (context + hook), `c96d83a` (SMOKE ops)
