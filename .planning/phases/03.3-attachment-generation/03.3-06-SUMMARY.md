## Deviations from Plan

The three deviations were **gap-closure defects surfaced during the Task 3 human-verify** — live-only issues the offline SMOKE suite could not catch. All were fixed and committed DURING verification and are referenced here (NOT re-committed).

### Auto-fixed Issues

**1. [Rule 1 - Bug] cockpit-agent prompt dropped an explicitly-requested attachment**
- **Found during:** Task 3 (human-verify)
- **Issue:** The agent walked a rigid recipients→subject→body→mode pipeline and dropped an explicitly-asked attachment because the request did not fit the next pipeline slot.
- **Fix:** Reworked the prompt to read the whole message and act on every intent (incl. an explicitly-asked attachment), ask only when genuinely missing, never invent. Shipped via the 5-file skill mirror + `seedSkills` publish-on-change (live-verified active).
- **Files modified:** packages/contracts/skills/cockpit-agent.md, packages/contracts/src/skills/cockpitAgent.ts, docs/playbooks/skill-registry.md
- **Verification:** USER-VERIFIED — the explicitly-asked attachment is now generated.
- **Committed in:** `efdecd3`

**2. [Rule 1 - Bug] Contact resolution substituted an unmatched name**
- **Found during:** Task 3 (human-verify)
- **Issue:** `rankCandidates` fell back to returning ALL correspondents when no contact matched the searched name — silently surfacing a stranger for an unfound "Joel" with no signal the match failed. A wrong recipient on a proposal/deal is a liability.
- **Fix:** `rankCandidates` returns `[]` on no match; `resolveContacts` reports the miss and asks for the address. Core 21/21 green; test flipped in `emailIntent.test.ts`.
- **Files modified:** packages/core/src/emailIntent.ts, packages/core/src/emailIntent.test.ts, packages/backend/convex/llm.ts, docs/playbooks/cockpit.md
- **Verification:** USER-VERIFIED — asking for an absent name now reports "couldn't find them" instead of substituting.
- **Committed in:** `846fa81`

**3. [Rule 2 - Missing Critical] PDF renderer painted raw markdown literals**
- **Found during:** Task 3 (human-verify)
- **Issue:** `markdownToPdf` was a flat line renderer that painted raw `**` and `#` literally — the delivered PDF looked unprofessional with visible stars/hashes.
- **Fix:** Upgraded to a professional layout (accent title block + rule, colored headings with section rules, square-bullet + numbered lists, inline bold via run-aware wrap, GitHub pipe tables); `@pikar/core` `tokenizeMarkdown` extended + new `inlineRuns` strips stray markers; the `document-drafter` skill relaxed to instruct structured sections/bold/bullets/tables. Deterministic — byte-identity held (V1).
- **Files modified:** packages/backend/convex/llm.ts, packages/backend/convex/markdownToPdf.test.ts, packages/core/src/documentGen.ts, packages/core/src/documentGen.test.ts, packages/contracts/skills/document-drafter.md, packages/contracts/src/skills/documentDrafter.ts, docs/playbooks/skill-registry.md, docs/playbooks/cockpit.md
- **Verification:** USER-VERIFIED — the regenerated PDF looks professional, no literal stars/hashes. Tests: core documentGen 16/16, renderer smoke 6/6, skills drift+scan 12/12.
- **Committed in:** `59e740d`
