**Adding a scope does NOT invalidate any stored refresh token.** `include_granted_scopes=true`

statically for Calendar.

<task type="auto">
  <name>Task 3: Enumerate a Drive folder</name>
  <files>packages/backend/convex/vaultDrive.ts</files>
  <action>
A `"use node"` internalAction. **Order is load-bearing:** `getTokens` → `hasScope(…, DRIVE_READONLY_SCOPE)`
→ return `reauth` **before** `freshAccessToken` and before any network call.

`GET /drive/v3/files` with
`q='<ID>' in parents and trashed=false`,
`fields=nextPageToken,files(id,name,mimeType,size,modifiedTime,md5Checksum,shortcutDetails,capabilities/canDownload)`,
`pageSize=1000`, **`supportsAllDrives=true`**, **`includeItemsFromAllDrives=true`**. Loop on
`nextPageToken`. Prefer this projection over per-file `files.get` — N files = 1 request, not N+1.

**⚠ Both shared-drive params on EVERY call.** Omit them and a shared-drive folder returns HTTP 200
with an **empty files array** — the user sees "imported 0 files, folder complete", a lying folder.
Additionally: treat a zero-child result on a folder the user explicitly picked as a **suspicious
outcome worth surfacing**, not a success.

Sub-folders (`application/vnd.google-apps.folder`) recurse breadth-first with an explicit node cap and
a visited-id set — Drive nesting is unbounded and can cycle via shortcuts. Enumeration must survive
the 10-minute action limit: paginate and continue in a scheduled follow-up rather than looping.

Pre-classify into the unreadable bucket **during pre-flight**, so the count the user approves matches
what imports: `capabilities.canDownload === false`; shortcuts not resolvable via
`shortcutDetails.targetId`; `form`/`site`/`map`/`jam`/`script`/`drive-sdk` (no text-bearing export);
and **anything over the per-file byte cap** (CONTEXT §A6 — the cap DOES apply; a 600 MB video would
OOM the ~512 MB action before any cap could refuse it). Enumerate the handled set explicitly and
default everything else to unreadable — never silently skip.
  </action>

Per file: **(1)** found by `(tenantId, driveFileId)` with unchanged `modifiedTime` → UNCHANGED, skip,

**⚠ Do NOT ship Drive dedup on `contentHash` alone.** OOXML is a zip, so docx/xlsx/pptx exports are

re-hash differently and duplicate the entire folder. That is why Docs/Slides export to deterministic
`text/plain` and why `driveFileId + modifiedTime` is the PRIMARY key with `contentHash` as fallback.

and a spurious 403 would otherwise report a readable file as unreadable.

**7-day refresh tokens** (Testing mode) make refresh-two-weeks-later hit `refresh_failed` — present it
as the reconnect flow, not as a Drive error. Copy/routing requirement, not a bug to fix here.
