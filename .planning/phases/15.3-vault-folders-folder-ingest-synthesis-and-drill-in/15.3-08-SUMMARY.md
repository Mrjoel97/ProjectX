# 15.3-08 — document identity classification (VALT-12)

Executed as a **13-agent workflow** (ultracode): 3 read-only recons → foundation (the core union +
the skill row) → 3 implementers on disjoint files → proof → 3 adversarial lenses.

## What shipped

- **`DOC_TYPES` / `DOC_TYPE_LABEL` / `isDocType` in `packages/core`** — not `packages/vault`, because
  `apps/web` already drives a `<select>` off a core union (`ShapePanel`), and a third local
  re-declaration is the exact defect that split produced before. A **two-direction compile bridge**
  makes schema/TS drift a typecheck failure, and the `@ts-expect-error` `_MISSING_ARM` twin pins the
  label table's totality. Both were **mutated in both directions** by the verify pass and genuinely
  fail.
- **`document-classifier`**, deliberately **ungated** — `run-eval-golden.mjs` derives `--skill` from
  `GATED_SKILLS` and no fixture reaches vault ingest, so gating deadlocks the row at v1 on its first
  body edit. The enum literals live in the **output contract**, not guidance prose (guidance is what
  a model drops under length pressure).
- **One workflow step at the single ingest convergence point**, so single-file uploads are classified
  too, with the cost folded into the existing `recordSpend` (a second call would round up a fresh
  cent per document — $3 per 300 documents for $0.10 of real spend).
- **Degrade, never fail.** The try/catch is *inside* `classifyDoc`: a throw at the step boundary
  exhausts the workflow retries and `onIngestComplete` marks the row `failed`, so an unseeded skill
  would have failed **every ingest in the deployment** — and inflated every folder's failure count —
  for a cosmetic label.
- **User-set wins as an ABSENCE.** No branch anywhere writes `docType`/`identityLine` over
  `identityUserSet`, which is what makes `retryExtraction` and `ingestExtractedText` safe to re-run
  on a corrected row. `identityLine` is sanitised at the write boundary because it reaches the folder
  digest and therefore a model prompt.

## The verify pass — three defects after green

**1. `identityLine` was the one field passed raw from the model.** `docType` went through
`isDocType`; `identityLine` went through nothing. `jsonSchema()` is called without a `validate` fn,
so **the SDK does not check the model object at runtime** — the inferred `string` is a promise
TypeScript makes and the provider keeps only usually. A missing or non-string value reached
`applyClassification`'s `v.string()`, which throws inside `step.runMutation` — **outside**
`classifyDoc`'s try/catch — failing the document.

> **The lesson generalises: when you coerce one field out of a model object, coerce every field of
> it. The uncoerced sibling is the one that fails the document.**

**2. The seed guard was per-MOUNT, not per-DOCUMENT.** `PreviewModal` is rendered without a `key`, so
React reused the instance across a document switch and a boolean `identitySeeded` stayed armed — the
form kept document A's identity while displaying document B, and Save would write A onto B. Reachable
without closing the modal: no focus trap, so Shift+Tab reaches a grid card and Enter re-opens with a
different document. Now keyed by `doc._id` **inside the component**, so a future caller cannot
reintroduce it by forgetting a `key`.

**3. A classified-but-still-`processing` row seeded an empty form.** The gate was `ready || failed`,
but `applyClassification` patches while the row is still `processing`. A row that stalls there — what
`vaultSweep` exists to recover — showed empty fields despite having an answer, and Save wrote
`identityLine: ""` with `identityUserSet: true`, blanking and **permanently locking** it.

Also fixed: a `packages/core` typecheck error (`noUncheckedIndexedAccess` on `atom[0]` — mine, from
the 15.3-07 repair), and two §9 gaps the workflow left — `docType.ts` was new code under no playbook
(`watch.json`) and the classifier row landed without its `skill-registry.md` bump.

## The `crypto is not defined` flake is NOT ours

The verify pass reported the backend suite failing ~3 runs in 8 with `ReferenceError: crypto is not
defined` (sometimes `process is not defined`) in `onboarding.test.ts`, correlated with this wave's
61st test file. **That correlation does not hold.** Reproduced with only pre-existing files:

```bash
cd packages/backend && npx vitest run convex/onboarding.test.ts convex/vaultDigest.test.ts
# run 2 of 3 failed with BOTH `crypto is not defined` and `process is not defined`
```

It is a load-dependent `edge-runtime` instability — async work outliving the VM context and executing
against a disposed global scope, so it surfaces in whichever file the worker runs next rather than in
the one that caused it. Adding a test file makes it likelier; it does not create it. Two hypotheses
were tested and are **wrong** (recorded so nobody re-tests them): it is not leaked fake timers
(`vaultClassify.test.ts` pairs `useFakeTimers`/`useRealTimers`), and stubbing `globalThis.process`
does not fix it (the failing global is `crypto`, via `lib/hash.ts`). A real fix means serialising file
execution and roughly doubling a 140 s suite — **an owner call, not a side effect of a feature wave.**

## Notes for the next plan

- **A known coverage gap:** the model-output coercion line is unreachable offline (the `SMOKE::`
  seam short-circuits before `generateObject`), so no test samples it at $0. The guarantee still
  holds by a second, independently proven mechanism — the schema-derived arg validator rejects any
  out-of-union string — so a regression there fails the document rather than writing a bad value.
- **Four skills now carry the identical "ungated because `run-eval-golden.mjs` cannot reach them"
  warning.** That is no longer a per-skill exception; it is a standing limitation of the eval
  harness. A fifth should mean fixing the harness, not writing the warning again.
- `voice/DocPicker.tsx` still renders filenames rather than identities — deliberately out of scope,
  recorded so it reads as a known gap rather than a bug.
- `apps/web` still has no unit-test runner (the 15.3-07 finding). Every observable check for this
  wave's UI had to go in `packages/core/src/vaultSurface.test.ts`.
