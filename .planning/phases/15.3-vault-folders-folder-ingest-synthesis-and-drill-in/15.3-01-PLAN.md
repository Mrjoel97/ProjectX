<task type="auto">
  <name>Task 3: Add the vaultFolders table</name>
  <files>packages/backend/convex/schema.ts</files>
  <action>
A NEW table needs no migration. Place it directly after `vaultDocuments` so a reader meets the
folder immediately after the document it groups.

```typescript
vaultFolders: defineTable({
  tenantId: v.string(),
  name: v.string(),
  source: v.union(v.literal("upload"), v.literal("drive")),
  status: v.union(
    v.literal("reserving"),   // estimate taken, reservation not yet held
    v.literal("ingesting"),   // reserved; members in flight; SEALED
    v.literal("complete"),    // every member terminal; unsealed
    v.literal("refused"),     // over budget — nothing was ingested
  ),
  memberCount: v.number(),    // rows ACTUALLY INSERTED, never files submitted (dedup, RESEARCH §2.9)
  terminalCount: v.number(),
  failedCount: v.number(),
  reservedCents: v.number(),
  spentCents: v.number(),
  reservedAt: v.optional(v.number()),      // window-rollover guard for the refund clamp
  digestDocId: v.optional(v.id("vaultDocuments")),
  digestSourceDocIds: v.optional(v.array(v.string())),
  digestBuiltAt: v.optional(v.number()),
  createdAt: v.number(),
}).index("by_tenant", ["tenantId"]),
```

Write a block comment above it carrying these four facts, because each one is a decision a later
reader will otherwise undo:
1. **There is no `cancelled` status, deliberately.** Cancel DELETES the row (CONTEXT §B13). A
   cancelled folder that merely changed status would keep its members sealed forever, because the
   seal is read through the folder row. Members keep a dangling `folderId` that resolves to nothing
   — every folder read must treat an unresolvable id as "no folder".
2. `memberCount` counts rows inserted, not files picked — hash-dedup returns an existing row and
   starts no workflow, so a folder counting to "files submitted" never completes.
3. `digestDocId`/`digestSourceDocIds`/`digestBuiltAt` are a field-for-field clone of
   `tenantProfiles.blueprintDocId`/`blueprintSourceDocIds` so the 17.1 staleness reader transfers
   unchanged.
4. `reservedAt` exists for the refund clamp: a refund issued after the 24h fixed window rolls
   credits a window that never paid (RESEARCH §1.2 — verified to produce 2900 against a capacity of
   2500).
  </action>
