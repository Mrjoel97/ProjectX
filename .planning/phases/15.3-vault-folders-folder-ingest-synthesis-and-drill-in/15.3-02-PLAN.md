<objective>
Make the vault survive folder scale, and delete the duplicated size caps — **before** anything can
create a 300-document folder.

Why wave 0: `listVaultDocs` and `vaultStats` both `.collect()` the tenant's whole `vaultDocuments`
partition **including every `text` blob** (≤400k chars/row). At 200–400 documents that is 20–160 MB
against a **16 MiB** per-transaction read cap; ~40 max-size rows already exhaust it. **The vault page
hard-fails on the first folder anyone ingests** — so the phase's own acceptance demo cannot render
until this is fixed. This is a pre-existing defect that folder ingest merely triggers, and it is the
same defect class as the `onboarding.status` timeout fixed 2026-08-02.

Output: bounded/projected vault reads, the caps imported from one source, and
`packages/core/src/vaultSurface.test.ts` — the first test that has ever read the vault UI.
</objective>
