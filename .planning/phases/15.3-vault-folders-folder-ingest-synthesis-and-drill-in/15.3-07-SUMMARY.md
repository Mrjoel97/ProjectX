# 15.3-07 — the folder surface (VALT-05/06/08/10/11)

Executed as a **14-agent workflow** (ultracode): 4 read-only recons → one prop/state contract →
4 implementers on disjoint files → `page.tsx` wiring alone → proof → 3 adversarial lenses.

`page.tsx` appears in Tasks 3 **and** 4 of the plan's own `files_modified`, so running those in
parallel would have put two agents in one file. It was carved out to a dedicated wiring agent, which
is only safe if all four implementers agree on prop types *before* they write — hence the design
phase, which produced the contract and no files.

## What shipped

- **`folderEstimate`** — a tenantQuery that consumes nothing and runs `reserveFolderInner`'s refusal
  checks in the same order, so the card cannot promise what the reserve will refuse.
- **`preflightCopy.ts`** — the one writer of the locked sentence. Naming both figures is the
  **default** arm with a three-reason deny-list, so a refusal code added in a later phase names real
  numbers rather than silently going quiet.
- **Folder picking** via a second `webkitdirectory` input (it can only pick directories, so it
  cannot replace the file input), with per-file outcome accumulation. A dropped folder explains
  itself instead of appearing to do nothing.
- **An inline `clay-card` pre-flight, not a modal** — the app has no shared dialog pattern and
  `PreviewModal` ships Esc + scroll-lock but no focus trap, so an inline step inherits no a11y debt.
  READY IN is two terms and **processing dominates transfer** (400 docs at concurrency 6 is tens of
  minutes, not the ~4 to send them).
- **Folder cards in the same grid unit**, a breadcrumb that **replaces** the tabs inside a folder,
  subscription-driven sealed progress (no poll, no second query), and the 17.1 rebuild idiom.
- **Every atom a user would be angry to lose** (`currentFolderId`, `picked`, `phase`) lives in
  `VaultPage`, because `nonce` is `VaultBody`'s remount **key** and a remount destroys state.
- No amber (BRAND §2), no new dependency, no component library.

## The verify pass — four majors after the suite was green and the build passed

> **The unifying cause is infrastructural: `apps/web` has no unit-test runner.** No `test` script,
> no vitest dependency, no config at the app or repo root; `pnpm test` is `turbo run test`, which
> skips a workspace that declares none. **Anything asserted inside `apps/web` is asserted by nobody.**

| # | Defect | Repair |
|---|--------|--------|
| 1 | `preflightCopy.test.ts` **executed nowhere** — worse than no test, because it reads as coverage in a diff | deleted; assertions moved into `vaultSurface.test.ts`, which runs, as its only behavioural import |
| 2 | **Estimate/reserve parity** — the plan's own `<verification>` line — was asserted by nothing; held only by two hand-maintained copies of the same checks | three tests in `vaultFolders.test.ts`, parity checked against the **window**, not just the return value |
| 3 | The Start loop awaited `reserveFolder`/`cancelFolder` **outside any try/catch** in a fire-and-forget handler | `safeCancel` that cannot throw on the refund path, plus a guarded reserve that names the manual exit |
| 4 | Per-file failures were accumulated and then **discarded** on partial success | the panel auto-clears only on a clean run; a partial success holds it open on the `started` arm (previously a dead union member) |

Defect 3's failure mode is the one worth remembering: a slept tab or one transient socket error
after a 20-minute 1.5 GB upload rejected into `void start()`, so `onPhase` never fired again. The
panel froze on "Sending 400 of 400…" forever with Start disabled and Cancel a no-op, while 400
members sat at `pending_extraction` under a folder **no sweep will touch** — `vaultSweep`
deliberately skips `reserving` and there is no folder-level cron. That is the silent parking this
phase abolished, re-introduced in the browser.

Defect 1 is the subtle one. A source scan **cannot** prove "the refusal names both numbers" and must
not pretend to: it checks the template lives in one file, and stays green if someone drops the
remaining-cents interpolation while leaving the words "left today" in place. That exact mutation now
takes four assertions RED.

Smaller fixes: Cancel mirrors its ref into state so it says "Cancelling…" instead of sitting inert
for a whole file; EST. COST renders an em-dash rather than a confident `$0.00` on the two refusal
arms carrying no `estCents`; the dropped-folder message names the control's real label; the
breadcrumb reads "3 added since the last digest"; a search matching no document says so even beside
folder cards (folders are not searched); and the pre-folder empty-state wording is byte-identical
outside a folder.

## Deliberately not fixed

- **The folder Cancel pill's 3.67:1 teal.** 0.72rem bold white on `--teal-600`, below the 4.5:1 that
  applies under 18.66px — but a **byte-identical clone of two already-shipped pills** (Retry,
  Discuss), and BRAND §6 sanctions teal-600 for white-text button fills. Fixing one of three makes
  the surface inconsistent without making it accessible. Needs a surface-wide pass; recorded as a
  known gap in the playbook.
- **`remainingCents` is `min(tenant, deployment)`**, so "you have X left today" can be reporting a
  shared constraint. The refusal *reason* already distinguishes the deployment arms ("for everyone
  today"), and showing the tenant's own untouched allowance while refusing would be worse.
- **`playwright --list` fails from the repo root** (two versions of `@playwright/test`,
  module resolution). Pre-existing, unrelated to this wave; from `apps/web` it reports 25 tests in
  16 files, matching the baseline.

## Notes for the next plan

- **`apps/web` cannot hold a runnable check.** Until it gets a runner, anything that must be
  observable about the web surface belongs in `packages/core/src/vaultSurface.test.ts` (source scan,
  or a behavioural import when the module has no React/Next dependency) or in a backend suite. A
  test file placed under `apps/web` is decoration. Giving `apps/web` a vitest config is a small,
  high-value piece of work that would have caught defect 1 and made defect 4 testable.
- **Parity fixture trap:** a folder whose `memberCount` is still 0 reserves and immediately completes
  (`terminalCount === memberCount` at 0 === 0), settling and **refunding** in the same call — the
  window ends up untouched and a parity assertion passes for the wrong reason. Upload members first.
- The surface scan bans any spelled-out size in the vault route (the 15.3-02 lesson). It caught a
  comment I wrote during this very repair pass — do not re-type a cap, even in prose.
