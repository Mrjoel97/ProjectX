## Sampling Rate

- **After every task commit:** `pnpm --filter @pikar/vault test && pnpm --filter @pikar/core test`
- **After every plan wave:** `pnpm test` + `pnpm typecheck` (several guarantees are COMPILE checks —
  a green vitest run does not sample them)
- **Before `/gsd:verify-work`:** full suite green + `node scripts/check-playbooks.mjs` exits 0
- **Max feedback latency:** 30 s at task level, 5 min at wave level

**Mutation discipline is mandatory in this phase.** Most guarantees here are *absences* (never
half-ingested, never groundable while sealed, never overwritten, never manufactured budget). An
absence cannot be observed on the happy path. Every check listed in RESEARCH.md carries the mutation
that must turn it RED; a check whose stated mutation does not break it is not sampling the guarantee.

## Manual-Only Verifications

| Behavior | Why Manual | Test Instructions |
|---|---|---|
| Cross-window refund behaviour | Requires a real 24-hour boundary; reproducing a window roll inside convex-test means reaching into the component's private `rateLimits` rows | Record as an **operator check** in `docs/playbooks/guardrails.md`. The *clamp* is unit-tested (guarantee 2); the rollover itself is observed live. Do not pretend a test covers it. |
| Real folder throughput | Scheduled-job concurrency is a deployment property (8 on S16 vs 256 on S256 — a 30× swing) that no test can read | One real ~30-file mixed-format folder: record wall-clock time-to-seal, observed peak concurrency, any OCC/`recordSpend` retries in logs, and **whether the pre-flight estimate was within 2× of reality** |
| Classifier real cost | Pricing arithmetic is an estimate, not an observation | Run one classification against a known document; read the recorded `costUsd` before/after |
| Sealed-folder UAT | Subscription behaviour, sealed affordances and digest honesty are only real in a browser | 3-file folder with one deliberately corrupt file: progress counts update with **no page refresh**; stays sealed (no Discuss) until complete; completes with a visible failed count; digest states what it could not read. Then delete one member → stale count + Rebuild emphasis appear **with no model call firing** |
| Drive against a real shared drive | The failure mode is HTTP 200 + empty array; a stub proves the params are sent, not that Google honours them | Import one real shared-drive folder and confirm a non-zero file count |

⚠ The deployment's concurrency class must be confirmed from the Convex dashboard **before** the
pre-flight time estimator is written, or the estimate can be wrong by ~30×.
