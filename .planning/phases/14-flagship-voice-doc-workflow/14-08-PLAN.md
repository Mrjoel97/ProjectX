<objective>
Make the post-call screen the load-bearing surface it was designed to be: run the review, show the
cited findings, and let the user choose — save the memo, or tap a gap and cross the Approve gate.

Purpose: Success Criterion 3, plus the visible half of Success Criterion 2. Phase 6 chose this
surface because it works identically for a clean end AND a dropped call, so a session that drops at
minute 12 still reaches a real outcome. Everything here is reuse: `CardList` already renders cited
findings, the affirmative healthy banner and the wired "Act on this"; `actOnGap` already stages the
proposed memo-plan; `PlanCard` already carries the one Approve button.
Output: one screen, one decision point, no route jump at the flagship flow's most important moment.

**Guardrails.** No new card idiom and no new Approve gate — ONE Approve gate is an architectural
invariant, and `evaluations.ts` / `plans.ts` / `deliverApprovedPlan.ts` get ZERO edits. Do NOT route
the user to `/dashboard/workspace?thread=<synthetic>` as the product path: the synthetic id is not a
Convex Agent thread, so a live composer there would throw on send (Pitfall 7) — rendering `CardList`
in place avoids the whole class. Playbooks are append-only inside your own Phase-14 subsection.
</objective>

export function CardList({ threadId, sending }: { threadId?: string; sending: boolean }) {
  // ActivityCard (only when activity.threadId === threadId) + SourceCard + EvaluationCard + rest()

    if (!threadId) return running ? null : <p style={muted}>No artifacts yet.</p>;

    return <PlanCards plan={plan} threadId={threadId} briefing={briefing} />;

}
