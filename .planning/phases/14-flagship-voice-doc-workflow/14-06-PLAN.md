Extend `ServerEvent` so `response` may carry `output`:
```ts
type FnCallItem = { type?: string; name?: string; call_id?: string; arguments?: string };
type ServerEvent = { type?: string; transcript?: string; delta?: string;
                     response?: { usage?: ...; output?: FnCallItem[] } };
```

Inside the EXISTING `case REALTIME_EVENTS.responseDone:` — after `responseActiveRef.current = false`
and after the usage accumulation, so the ordering guarantees below hold — iterate
`ev.response?.output ?? []` and, for each item whose `type === REALTIME_FUNCTION_CALL.itemType` with
a `call_id`, fire an async relay:

```ts
void (async () => {
  let output: string;
  try {
    const { query } = JSON.parse(item.arguments ?? "{}") as { query?: string };
    const res = await searchDocument({ sessionId: sessionIdRef.current!, query: query ?? "" });
    output = JSON.stringify(res);                       // { passages, found }
  } catch {
    output = JSON.stringify({ passages: [], found: false, error: "unavailable" });
  }
  send({ type: REALTIME_CLIENT_EVENTS.createItem,
         item: { type: REALTIME_FUNCTION_CALL.outputItemType, call_id: item.call_id, output } });
  send({ type: REALTIME_CLIENT_EVENTS.createResponse });
})();
```

Five properties to encode, each with a comment saying why:
- **Trigger from `response.done`, add no new pinned event name** (RESEARCH Pattern 2 / Open
  Question 4). This event is already live-verified in this repo; `response.function_call_arguments.done`
  sits in exactly the MEDIUM-confidence class `realtime.ts` warns about.
- **Always send an output, even on failure** (Pitfall 5). A tool call with no `function_call_output`
  leaves the model waiting and the user hearing silence for the rest of a capped 15 minutes.
- **The `response.create` is legal here** because `responseActiveRef.current` was just cleared in
  this same case — the wrap-up nudge's "conversation already has an active response" 400 does not
  apply.
- **Only the free-text `query` crosses.** The document id is never sent: `searchDocument` reads
  `docRef` off the server session row. Nothing the model says can select a document.
- **No skip guard needed for the no-doc session** — a Phase-6 session declares no tools, so
  `output[]` never contains a `function_call` item; the loop is a no-op. Say so in the comment
  rather than adding a `docId &&` condition that would silently disable a future tool.

Extend the `default:` diagnostic branch to also log unhandled `function_call*` event types
(`ev.type?.includes("function_call")`) — Open Question 4's live-verify instrumentation, filterable
by `"[voice]"`. Keep the existing `ponytail:` remove-at-phase-close note.

Add one assertion to `packages/voice/src/docSession.test.ts` pinning the relay's client-event
vocabulary: `REALTIME_FUNCTION_CALL.outputItemType === "function_call_output"` and
`REALTIME_CLIENT_EVENTS.createItem === "conversation.item.create"` — `apps/web` has no unit runner,
so this is where a silent rename gets caught.
