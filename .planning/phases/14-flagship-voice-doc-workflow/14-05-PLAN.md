<objective>
Turn a finished voice-doc discussion into a persisted, cited findings row: the `vaultLlm.ts`-shaped
producer that reads the transcript plus the document, emits labels only, and lets code weld the
citations, the gap routing and the verdict.

Purpose: Success Criterion 2, in the only place it is testable without a microphone. Because the
row lands in the EXISTING `evaluations` table, everything downstream — per-finding citations, the
affirmative healthy banner, leverage-ranked gaps, "Act on this" → proposed plan → the single
Approve gate — is inherited rather than rebuilt.
Output: `voiceDoc.reviewSession({ sessionId, transcript })` → an `evaluations` row on
`voiceDocThreadId(sessionId)`.

   turn's text starts with it, parse the suffix into a deterministic `RawDocReview` fixture and skip
   the model entirely. Support at minimum three suffixes so the SC-2 tests can drive every verdict:
   `healthy` (findings, no gaps), `gaps` (findings + gaps), `empty` (no findings). Give the `gaps`
   fixture THREE findings: one whose `excerpt` is a verbatim substring of the seeded document text,
   one with `excerpt: null`, and one whose `excerpt` is text that does NOT appear in the document —
   so the carry-through, the absent and the rejected excerpt paths are all covered offline with no
   model call. This is what lets
   `voiceDoc.test.ts` run retrieval → findings → row → `actOnGap` end to end offline.
3. Persona from the registry: `internal.skills.getActiveSkill({ name: DOCUMENT_ANALYST_SKILL })`
   as the `system` prompt (§5, fail-closed). Never a hardcoded prompt.
4. `docReviewSchema = jsonSchema<RawDocReview>({...})` — findings
   `{label, section, confidence, excerpt}`, gaps `{label, reason, proofMetric}`, notEnoughData
   `{section, needs}`. **No citation, verdict, route, playbook or rank key exists in this schema**:
   the model has nothing to get wrong, which is what makes "every finding is cited" structural

   `confidence` with `["high","medium","low"]`. Honour the STRICT-mode rule: every `properties` key
   repeated in `required`, `additionalProperties: false` everywhere.
   **`excerpt` is the ONE deliberate exception to the weld, and it is a LOCKED requirement**

   knows which sentence it was talking about, so the quote text — and ONLY the quote text — comes

   Declare it STRICT-legally as `excerpt: { type: ["string","null"] }` listed in `required` (the
   house rule for optionals: nullable-and-required, normalized after the call), described as "the
   exact sentence or two from the document that supports this finding, copied verbatim; null if you
   cannot quote one".
4b. **Verify the quote is real — cheaply.** Before shaping, drop any `excerpt` that is not actually
   in the report: whitespace-normalize the excerpt and `doc.text` (collapse whitespace runs to a

   excerpt is a valid, non-degraded state. This check is cheap: `doc.text` is already in hand from
   step 1 and it is one `indexOf` over a string already bounded by the 16 MiB document read.
   `ponytail:` accepted ceiling — a substring check cannot tell that a real quote was lifted from a
   different part of the same document than the finding is about, and it rejects a legitimate quote
