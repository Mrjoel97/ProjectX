  <action>
Follow the `packages/backend/scripts/run-smoke-*.mjs` idiom for shape and output style, but this
script needs **no Convex deployment** — it is a direct `generateText` against OpenAI. Keep it that
way (ponytail rung 3: the dependency already installed does it).

Behaviour:
1. Reads `process.env.OPENAI_API_KEY`. Absent ⇒ exit non-zero with the exact recovery line:
   `run from packages/backend: npx convex env get OPENAI_API_KEY`.
2. A CANDIDATE LADDER, probed in order, **stopping at the first PASS** — so a pass on the first
   candidate is exactly ONE call (≈$0.01), which is what D8 budgets. Order (from the research's
   read of OpenAI's own contradictory pages — the first is the one the pricing page implies works
   and is cheapest, the rest are the guide's named list):
   `["gpt-4o-mini", "gpt-4.1-mini", "gpt-4.1"]`. Hard-cap the ladder at 3 calls.
   `gpt-4.1-nano` (today's `CHEAP_MODEL`) is deliberately NOT in the ladder — it appears in
   neither OpenAI page.
3. Per candidate, ONE `generateText` with `openai.tools.webSearch({ searchContextSize: "medium" })`,
   `stopWhen: stepCountIs(4)`, and a prompt whose answer cannot come from model memory (ask for
   something dated — e.g. a figure published in the last 30 days — so an empty `sources` array is a
   real signal, not an artefact of an easy question).
4. Reports, per candidate, in a machine-greppable block:
   - `model` and, as ONE TERMINAL LINE per candidate, `probe: PASS model=<the exact model id>` /
     `probe: FAIL model=<id> <error class + message head>`. **The `model=` suffix on the verdict
     line is load-bearing, not formatting.** The ladder records a `probe: FAIL` block for every
     earlier candidate, so a gate that checks `probe: PASS` and the model id INDEPENDENTLY is
     satisfied when `gpt-4o-mini` FAILED, `gpt-4.1-mini` PASSED, and the constant was pinned to the
     failing one. Printing the id ON the verdict line makes Task 3's gate a mechanical adjacency
     check instead of a coincidence. (It also kills the substring trap: `gpt-4.1` is a substring of
     both `gpt-4.1-mini` and `gpt-4.1-nano`.)
   - `sources: <n>` and every `sourceType:"url"` entry's `url`, each asserted parseable via
     `new URL(u)`
   - `usage: inputTokens/outputTokens` (the search-context tokens ride `inputTokens` — this is the
     number that makes envelope arithmetic real)
   - `steps: res.steps.length` — this retires OQ-3 for free
   - **`toolCalls:` every tool-call part in `res.steps`, printed as
     `{ toolName, providerExecuted }`.** This is load-bearing and easy to skip: we do NOT know
     whether the SDK surfaces a provider-executed call under OUR record key (`webResearch`) or
     under the provider's own name (`web_search`). 16-05's cost counting and every offline mock
     fixture in this phase must match what the provider ACTUALLY emits, or we ship tests that pass
     against a fiction.
   - a one-line `estimated call fee` note using the published $10/1k = $0.01 per call.
5. `--self-check` flag: validates the ladder, the report formatter and the URL parsing against a
   canned fake result object, with **zero network calls and zero spend**. Plain `assert`, no
   framework (the `run-eval-golden.mjs --self-check` precedent).
6. `ponytail:` comment at the top naming the ceiling: one-shot, no retries, no caching — it is a
   decision instrument run once per model-lineup change, not a monitor.
