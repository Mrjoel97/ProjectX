   - `maxSteps?: number` — used as `stopWhen: stepCountIs(args.maxSteps ?? 8)`. Default preserves

     larger, route-specific budget (16-05 sets it); a silently truncated multi-search run
     presented as complete is the failure D10 names.
   - the return type becomes
     `Promise<{ reply: string; costUsd: number; webSearchCalls: number; truncated: boolean;
                sources: readonly { url: string; title: string }[] }>`.
     In THIS plan return `webSearchCalls: 0`, `sources: []` and
     `truncated: res.steps.length >= (args.maxSteps ?? 8) && res.finishReason !== "stop"`.
     `truncated` is real from day one (it is pure arithmetic on the shipped result); the call
     count is wired in 16-05 once the probe has told us what a provider-executed tool call
     actually looks like in `res.steps`.

     already rides `primary`/`fallback`. Do not add a redundant knob.

3. `runSpecialistTurn` (`:1809`) — widen its return to carry `webSearchCalls`, `truncated` **and
   `sources`** through (callers ignore all three today); in THIS plan it forwards the loop's
   placeholder values unchanged.

   produced in `runAgentLoop` and consumed off `DispatchResult`: 16-06 computes
   `sourceCount = r.sources.length`, and that count drives BOTH the fence's zero-source branch and
   16-07's stored insufficient-evidence label — D11's zero-results contract. `governedDispatch`
   sees nothing except `runSpecialistTurn`'s return, so if `sources` does not travel through HERE,
   16-06 either fails to compile or someone quietly defaults it to `[]` — after which every
   research run ships labelled "insufficient evidence". Widen it once, here.
   Add **no** new args: the model pin and the step budget are
   properties of WHICH SPECIALIST is running, so 16-05 derives them from `args.skillName` right
   here, where the models are already resolved. A `models?` / `maxSteps?` arg would be a second
   mechanism for a decision that has exactly one owner — and it would drag `dispatch.ts` into
   model selection for no gain.
