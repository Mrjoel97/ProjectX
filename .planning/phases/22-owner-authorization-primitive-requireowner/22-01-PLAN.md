<objective>
Build the durable identity and owner-authorization substrate before any existing endpoint switches
to it.

Purpose: today the tenant wrappers manually split a provider subject and the three global Phase-8
controls treat any authenticated identity as the owner. This plan replaces the production parser
with the installed Convex Auth adapter, widens the auth user row with an optional owner bit, creates
the sibling owner wrappers, and grants the intended existing user explicitly.

Output: typed tenant/owner wrappers, `owner.viewer`, idempotent audited bootstrap, tests, and a
durable authorization playbook. No optimizer or skill endpoint changes in this plan.
</objective>

    - `bootstrapOwner` rejects a missing id with `NO_SUCH_USER`, changes absent/false to true once,
      returns `{ changed: false }` on repetition, and never changes another user.
    - Exactly one `owner.granted` audit row is inserted on the transition. Its payload key set is
      exactly `owner,userId` and contains no email, name, subject, token, session, or body.

  <action>
In `lib/functions.ts`, export `requireOwner(ctx)` as a sibling of the tenant scope resolver. It must
derive the user id server-side, read that exact `users` row, and accept only
`user?.owner === true`; every other state fails closed with `OWNER_REQUIRED`. Build and export
`ownerQuery` and `ownerMutation` with `customQuery`/`customMutation` + `customCtx(requireOwner)`.
The owner context retains both typed `userId` and compatible string `tenantId`. Do not add an
`ownerAction`: there is no current owner-only action, and actions cannot read the users row
directly.

Create default-runtime `owner.ts`:

- `viewer` is a `tenantQuery`, not an `ownerQuery`, because non-owners need the boolean to decide
  whether to mount presentation. It reads only `ctx.userId` and returns
  `{ isOwner: user?.owner === true }`.
- `bootstrapOwner` is an `internalMutation` taking `v.id("users")`. It rejects a missing row,
  patches `owner: true` only when needed, and returns `{ changed, userId }`.
- On the first grant only, call the existing insert-only `internal.audit.log` choke point with
  event type `owner.granted`, `tenantId: String(userId)`, a deterministic refs-only correlation id,
  an operator actor string, and payload `{ owner: true, userId }`. Repetition writes no second
  event.

Use `convex-test` in `owner.test.ts` for all states above. Negative cases must be anti-vacuous:
insert/read the target user, and assert the audit row count and owner field after the refusal.
Plan 22-02 will exercise the custom owner wrappers through the real protected endpoints; do not add
a public test-only owner function.
