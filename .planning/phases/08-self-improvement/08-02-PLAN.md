  <behavior>
    - submitFeedback({ requestId, rating:"down", comment:"x" }) → inserts ONE feedback row with
      skillName="cockpit-agent" + skillVersion resolved from the request row, rating "down", comment "x".
    - A SECOND submitFeedback on the same requestId with rating:"up" EDITS the same row (no duplicate;
      by_tenant_request stays unique), updates updatedAt.
    - undoFeedback({ requestId }) deletes the row (a mis-tap is fully reversible).
    - A request with no skillVersion (pre-Phase-8 row) → submitFeedback rejects with a clear reason
      (unattributable feedback is not stored — a row with no resolvable version is the Pitfall-1 warning sign).
    - Cross-tenant: submitFeedback on another tenant's requestId → "request not found" (tenant guard).
    - myFeedback({ requestId }) returns the current row (or null) so the UI can render the persisted state.
  </behavior>

      skillVersion, createdAt/updatedAt now).
    - undoFeedback (tenantMutation): delete the row for (tenant, requestId) if present; idempotent.
    - myFeedback (tenantQuery): return the row or null.
