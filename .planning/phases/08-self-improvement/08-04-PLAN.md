  <name>Task 1: buildTrajectoryExport — scrub, score, split (fail-closed)</name>
  <files>packages/backend/convex/skilloptExport.ts, packages/backend/convex/skilloptExport.test.ts</files>
  <behavior>
    - A delivered request with feedback and a body containing "a@b.com" and "555-12-3456" → the output
      item's task_description/conversation contain NO raw email/SSN (only safeText placeholders); counts reflect the redaction.
    - rating "up" → hard:1; rating "down" → hard:0.
    - A trajectory whose goal/body/comment scan returns Err → the whole item is OMITTED (fail-closed: never ship unscrubbed).
    - split key is deterministic: same requestId → same "train"/"valid" every run (hash-based, ~1/5 valid).
    - Only requests that HAVE a feedback row AND a skillVersion are exported (unrated/unattributable are skipped).
  </behavior>
  <action>
    buildTrajectoryExport as an internalQuery (args { skillName?: "cockpit-agent" }):
    - Join feedback rows → their request rows (by requestId). Skip any with no skillVersion.
    - For each: scanText(goal), scanText(deliveredBody = editedBody ?? draft ?? ""), and, if present,
      scanText(comment). If ANY returns Err → `continue` (drop the item). ponytail: fail-closed drop is
      correct over partial redaction — a half-scrubbed export is a leak.
    - Emit ONLY safeText + counts. Build the item to the EXPORT JSON CONTRACT above. Score hard = rating==="up"?1:0.
    - split = deterministic hash of requestId (e.g. a small FNV/`hashString` — reuse an existing hash
      helper if one exists in packages, else a 6-line pure hash) `% 5 === 0 ? "valid" : "train"`.
    - Add the `ponytail:` names-in-prose ceiling comment at the scrub site.
    Test skilloptExport.test.ts: seed a request+feedback with PII in the body/comment; assert the output
    contains no raw PII, hard maps from rating, an Err-scanning trajectory is dropped, split is stable.
  </action>
