# Codebase Concerns

## Risk Posture

- **Critical — local credential spill risk:** `packages/backend/.env.local.bak-before-configure` and `packages/backend/.env.local.bak-pre-repair` are untracked and are not matched by the current rules in `.gitignore`; their names indicate environment backups that may contain secrets. Do not inspect or commit their values. Remove them through a secure/recoverable process and ignore `.env*` backup variants before the next broad Git operation.
- **High — global operator controls lack an owner role:** `packages/backend/convex/optimizerConfig.ts` exposes `setOptimizerEnabled` to any authenticated tenant, while `packages/backend/convex/skills.ts` exposes `activateCandidate` and global candidate bodies through `candidatesForReview`. Authentication is treated as ownership even though these rows are deployment-global. `.planning/STATE.md` explicitly records this as an open Phase-22 `requireOwner` blocker.
- **High — tenant isolation depends on a provider-specific subject parser:** `packages/backend/convex/lib/functions.ts` derives the tenant key from `identity.subject.split("|")[0]` and casts an optional subject to `string`. The checked-in Convex guidance identifies `tokenIdentifier` as the canonical stable identity key. A provider-shape change, missing subject, delimiter collision, or future second issuer could cause denial of service or tenant-key collision at the repository's main isolation boundary.
- **High — the production deployment is intentionally blocked:** `apps/web/app/legal.ts` still contains unresolved legal entity, address, governing-law, venue, and supervisory-authority placeholders and throws when `VERCEL_ENV === "production"`. This is a correct fail-closed behavior, but private-beta production cannot ship until the legal inputs are resolved.
- **High — durable audit retention is configuration-optional:** `packages/backend/convex/worm.ts` logs a skip and returns when `WORM_BUCKET` is absent. The insert-only API in `packages/backend/convex/audit.ts` is not equivalent to the planned immutable/WORM retention plane, so missing bucket credentials silently leave the strongest audit-retention guarantee inactive.

## Security and Privacy

- **High — raw vault content is over-exposed to the browser:** public `listVaultDocs` in `packages/backend/convex/vault.ts` returns complete `vaultDocuments` rows, including stored extracted `text`, when the vault grid generally needs metadata. This expands browser-memory exposure, reactive payload size, and the impact of client-side compromise.
- **Medium — redaction-safe logging is a convention, not an enforcement boundary:** `packages/core/src/logger.ts` accepts arbitrary `Record<string, unknown>` fields and serializes them directly. A future caller can accidentally emit content or PII despite the comment contract; use a narrow safe-field type and/or runtime deny/drop guard.
- **Medium — names in prose are an acknowledged scrubber ceiling:** `packages/backend/convex/skilloptExport.ts` and `.planning/STATE.md` state that `packages/pii/src/scan.ts` handles structured patterns but not personal names embedded in prose. Exporting grounded trajectories remains a privacy risk until this is resolved or prose is excluded.
- **Medium — optimizer write-back accepts loosely validated content:** `/skillopt/writeback` in `packages/backend/convex/http.ts` casts `req.json()` directly and provides no explicit request-size, string-length, finite-number, or schema checks before persisting a global candidate. The bearer token is a strong gate, but malformed or compromised CI input can still create oversized/invalid operational data.
- **Medium — secrets and deployment configuration are read ad hoc:** `packages/backend/convex/http.ts`, `gmail.ts`, `voiceToken.ts`, `vaultRag.ts`, `worm.ts`, and `auth.config.ts` read `process.env` independently, often with empty-string or localhost fallbacks. There is no single startup validation that proves production has coherent issuer, redirect, OAuth, model, WORM, and site settings.
- **Medium — OAuth refresh tokens are crown-jewel rows:** `packages/backend/convex/gmailAuth.ts` stores refresh/access tokens in `gmailTokens`. Tenant-scoped client queries do not return them, which is good, but compromise of the Convex deployment or an unsafe internal function has mailbox-wide impact; document rotation/revocation, least-privilege scopes, and incident response.

## Correctness and Product Gaps

- **High — owner UI is reachable by ordinary authenticated users:** middleware in `apps/web/middleware.ts` only distinguishes public versus authenticated routes; `apps/web/app/(app)/ops/page.tsx` has no separate authorization check. This makes the global-control backend flaw directly reachable rather than merely theoretical.
- **Medium — document-scoped voice search is post-hoc:** `packages/backend/convex/voiceDoc.ts` searches the tenant's whole vault and filters to the selected document afterward. Its own comment notes the selected document's best passage can be absent from global top-K results, producing false “not found” answers for large/mixed vaults.
- **Medium — graph degree can drift upward:** `packages/backend/convex/schema.ts` records that `degree` is incremented per edge insert without deduplication in `packages/backend/convex/vaultGraph.ts`. Re-ingest/re-extraction can therefore distort graph ranking and orphan-GC decisions unless edges are made idempotent or degrees are recomputed.
- **Medium — one-plan-per-thread is a hard ceiling:** `packages/backend/convex/plans.ts` deliberately refuses to stage a second plan row for the same thread. Longer conversations or concurrent requests can block legitimate follow-up work and make recovery depend on reset semantics.
- **Low — browser workspace state is only session-local:** tabs in `apps/web/app/(app)/dashboard/workspace/page.tsx` are not persisted. Reloads lose the user's open-tab arrangement even though server threads remain, increasing confusion around ongoing work.
- **Low — simplified parsers have known fidelity limits:** `packages/core/src/emailIntent.ts` is not a full RFC 5322 address parser; `packages/core/src/documentGen.ts` is a line-oriented markdown tokenizer; and `packages/vault/src/rawText.ts`, `sniff.ts`, and `officeText.ts` intentionally approximate complex formats. Treat extraction/render results as lossy and keep originals downloadable.

## Performance and Scalability

- **High — multiple production reads use unbounded `.collect()`:** examples include vault browsing/stats in `packages/backend/convex/vault.ts`, stalled-ingest recovery in `packages/backend/convex/vaultIngest.ts`, weekly tenant enumeration in `packages/backend/convex/proactiveReview.ts`, Gmail expiry scanning in `packages/backend/convex/gmailAuth.ts`, optimizer eligibility in `packages/backend/convex/optimizerEligibility.ts`, and operational metrics in `packages/backend/convex/opsSignals.ts`. These will eventually hit Convex document/byte transaction limits.
- **High — vault browse reads large blobs twice:** `listVaultDocs` and `vaultStats` in `packages/backend/convex/vault.ts` each scan full tenant document rows; `vaultDocuments` can contain book-sized extracted text. Add metadata-only rows/projections plus aggregate counters, pagination, and category/status indexes.
- **Medium — weekly work is cross-tenant fan-out from one mutation:** `runWeekly` in `packages/backend/convex/proactiveReview.ts` collects every `business_profile` document before scheduling tenants. A dedicated onboarded-tenant marker and batched cursor would avoid a single deployment-wide transaction ceiling.
- **Medium — expiry notifications can duplicate:** `flagExpiringTokens` in `packages/backend/convex/gmailAuth.ts` scans all token rows daily and has no last-notified/dedup field. Tokens in the warning window may create repeated notifications and growing unread rows.
- **Medium — operational metrics scale with event volume:** `packages/backend/convex/opsSignals.ts` collects all telemetry and audit rows in the requested window and all tenant dead letters before in-memory filtering. An authenticated caller can also choose an arbitrarily old `sinceMs`; enforce a maximum window and maintain per-type/day aggregates.
- **Medium — skill history scans grow indefinitely:** candidate selection and write-back in `packages/backend/convex/skills.ts` collect all versions for each gated skill. The registry is append-only by design, so “newest candidate/active/max version” should use purpose-built indexes and bounded reads.
- **Low — large central modules raise change cost:** `packages/backend/convex/llm.ts`, `apps/web/app/(app)/dashboard/workspace/cards.tsx`, `packages/backend/convex/schema.ts`, and `packages/backend/convex/smokeAssert.ts` combine many unrelated behaviors. They are fragile merge/conflict hotspots, especially given the concurrent shared-tree workflow documented in `.planning/STATE.md`.

## Reliability and Observability

- **High — telemetry is incomplete for the primary cockpit lane:** `packages/backend/convex/opsSignals.ts` documents that cockpit rows record `costUsd: 0`, empty decision counts, and zero regenerations. The ops dashboard in `apps/web/app/(app)/ops/page.tsx` therefore cannot report true end-to-end model cost or approval behavior.
- **Medium — external notification delivery has no durable recovery:** `packages/backend/convex/notifyExternal.ts` catches dispatch failures and emits a refs-only warning while leaving only the in-app row. There is no retry schedule, delivery-status row, or dead-letter path for channel failure.
- **Medium — broad catches discard root-cause evidence:** examples include the weekly review catch in `packages/backend/convex/proactiveReview.ts` and client catches throughout `apps/web/app/(app)/dashboard/voice/useVoiceSession.ts`. Privacy-safe static messages are appropriate for users, but operators still need correlation IDs and sanitized failure classes.
- **Medium — generated code is a boot-time dependency:** `packages/backend/convex/_generated/` is ignored, while `@pikar/backend/api` exports from it. `scripts/boot-check.mjs` requires a configured live Convex deployment before codegen, so a clean clone, offline build, or CI runner cannot typecheck without external setup.
- **Medium — deployment readiness has no automated gate:** the repository contains only `.github/workflows/skillopt.yml`, a dormant optimizer workflow. There is no PR workflow running install, formatting/lint, typecheck, unit tests, build, secret scan, or migration/boot verification.
- **Low — local smoke harnesses depend on live services:** scripts under `packages/backend/scripts/run-smoke-*.mjs` require a configured/running deployment and are not tied to CI. Scheduler/workpool regressions can pass unit tests and remain undetected until a manual smoke run.

## Dependency and Toolchain Concerns

- **Medium — TypeScript versions are split:** the root pins `typescript` through `^7.0.2` in `package.json`, while `apps/web/package.json` uses `^5.9.3`; workspace packages without their own TypeScript dependency resolve through root tooling. Different compiler behavior can make local package and web results disagree.
- **Medium — dependency type incompatibility is already patched with casts:** `packages/backend/convex/cockpit.ts` documents an AI SDK v6/v7 model-type mismatch between `@convex-dev/agent@0.6.4` and the repository's `ai@7.0.20`. `skipLibCheck: true` in `tsconfig.base.json` and backend configs can conceal additional incompatibilities.
- **Medium — critical Convex components are pre-1.0:** exact pins in `packages/backend/package.json` reduce surprise, but Workflow, Agent, RAG, Rate Limiter, Action Retrier, Auth, and related components still carry API-churn and upgrade-blocking risk. Every bump needs changelog review, codegen, full tests, and live boot/smoke checks.
- **Low — SheetJS is fetched from a CDN tarball:** `packages/vault/package.json` and `packages/backend/package.json` reference `https://cdn.sheetjs.com/...`. The lockfile provides integrity metadata, but clean installs depend on that external host's availability and supply-chain posture.

## Test and Coverage Gaps

- **High — web behavior has no unit/component-test layer:** `apps/web/package.json` defines only `test:e2e`; complex state in workspace, ops, onboarding, vault, and voice components is covered only indirectly by Playwright or manual UAT.
- **High — E2E is not hermetic or in CI:** `apps/web/playwright.config.ts` does not start a web/backend server, and `apps/web/e2e/README.md` requires a seeded live-local Convex user and two manually running processes. Only desktop Chromium is configured, leaving WebKit, Firefox, and mobile layouts untested.
- **Medium — live-model evaluation debt is explicit:** `.planning/STATE.md` records that the rewritten `offer-architect`, `money-model-designer`, and `lead-engine` skills and new golden fixtures have not run on a live deployment; active rows still carry older bodies until the eval/activation gate is completed.
- **Medium — external integrations lack continuous contract tests:** Gmail OAuth/send, OpenAI Realtime, S3 Object Lock export, and Convex scheduled/workpool behavior rely on mocks, probes, or manual smoke scripts. Provider response-shape and permission changes can reach production without a pre-merge signal.
- **Medium — scale limits are untested:** there are no load/boundary tests demonstrating behavior near Convex read/write limits for vault documents, audit rows, feedback, dead letters, skill versions, or weekly tenant fan-out.
- **Low — production-only legal failure is easy to miss locally:** `apps/web/app/legal.ts` only throws under Vercel production environment, so ordinary local builds do not exercise the actual production gate.

## Prioritized Remediation

1. **P0:** secure/remove the unignored environment backup files, expand `.gitignore`, and add a pre-commit/CI secret scan without printing discovered values.
2. **P0:** implement and enforce `requireOwner` on the ops route and all global optimizer/skill-registry reads and writes; add negative authorization tests with two ordinary tenants.
3. **P0:** design a safe tenant-key migration from parsed `subject` to canonical `tokenIdentifier` (including collision checks and existing-row migration) before changing the isolation linchpin.
4. **P0:** resolve the legal placeholders and prove a production-mode build; validate all production environment variables in one typed configuration boundary.
5. **P1:** replace raw vault list/stats payloads with metadata-only pagination and aggregate counters; cap every caller-controlled time window.
6. **P1:** batch/index the Gmail expiry, proactive review, ingest recovery, feedback eligibility, dead-letter, audit, telemetry, and skill-history scans.
7. **P1:** add a required PR workflow for frozen install, Biome, typecheck, unit tests, production build, secret scan, and a deterministic offline Convex test suite.
8. **P1:** make WORM export readiness observable and fail deployment/health checks when production retention is not configured; exercise real Object Lock behavior periodically.
9. **P2:** complete cockpit cost/decision telemetry, add durable retry/dead-letter state for external notification channels, and standardize sanitized correlation-aware error reporting.
10. **P2:** align TypeScript/AI SDK versions, remove compatibility casts where possible, and split the largest orchestration/UI modules along existing domain seams.
11. **P2:** add hermetic component tests, multi-browser E2E, provider contract probes, and high-volume Convex boundary tests before expanding beyond private-beta volumes.
